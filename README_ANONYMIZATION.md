# Анонимизация документов — руководство

> Что это, как включить и как этим пользоваться. Общая документация продукта — `README.md`
> (глава 19), правила выпуска — `RELEASING.md`, лицензии сторонних частей — `NOTICE.md`,
> решения и фазы — `PLAN_ANONYMIZER_SIDECAR.md`.

## 1. Что делает и чего не делает

* **«Скрыть»** заменяет персональные данные в документе метками `[TYPE_N]`
  (`[PERSON_1]`, `[ORG_2]`, `[PHONE_1]`, `[EMAIL_1]`, …). Полный режим — поиск моделями
  (GLiNER PII + Natasha/Slovnet + регулярные выражения для телефонов, почты, документов,
  банковских реквизитов). Частичный — детерминированный список значений, который вы задаёте сами.
* **«Показать»** возвращает исходный текст по базе меток: либо все метки файла, либо только
  перечисленные.
* **Не делает:** не перехватывает команды ассистентов, не работает как прокси OpenAI/API, не
  ведёт сессий и не хранит пары «оригинал / аноним / результат». Есть только входной файл и
  выходной: `<имя>.anonymized.<ext>` и `<имя>.deanon.<ext>` (суффикс `.anonymized` у входа
  отбрасывается: `a.anonymized.docx` → `a.deanon.docx`).

Форматы: `.docx`, `.xlsx`, `.txt`, `.md`, `.xml` (MS Project). Папка обрабатывается **по верхнему
уровню** — вложенные каталоги не обходятся (так же, как `auto_transcribe.inbox_dir`).

## 2. Установка стека

Стек не входит в архив программы (как и окружение расшифровки): код воркера едет в поставке
(`sidecar\hds_anonymize`), а окружение и модели ставит установщик на машине.

```powershell
# окружение: cpu (процессор) или cuda (видеокарта NVIDIA)
powershell -File installers\build_anonymize_sidecar.ps1 -Profile cpu -SelfTest

# модели в машинный каталог (по умолчанию HDS_MODELS_DIR / %ProgramData%\hermes-disk-search\models)
powershell -File installers\fetch_anonymize_models.ps1 -ModelsDir D:\models

# готовность: интерпретатор, веса, база, адрес аренды GPU
hds anon check
```

* Окружение идемпотентно: маркер `.hds-anonymize-profile` хранит профиль, версию Python и sha256
  `requirements.lock`; `-Force` пересобирает venv.
* В venv **ровно один** `onnxruntime`: профиль `cuda` ставит `onnxruntime-gpu` (CPU-пин из lock
  отфильтровывается), профиль `cpu` — `onnxruntime` из lock.
* Размер: окружение ~3–6 ГБ (в lock есть `torch`, его импортирует GLiNER даже для ONNX-пути),
  модели ~1 ГБ. Время установки — десятки минут при медленной сети.
* Токен Hugging Face **не нужен**: модель `knowledgator/gliner-pii-large-v1.0` публичная.
  `-HfToken`/`HF_TOKEN` поддержан только для лимитов загрузки и не сохраняется.
* macOS: те же две команды в `pwsh`; профиль `cuda` только для NVIDIA (на Apple Silicon — `cpu`).

### Где лежат модели

```
<models>\anonymize\hf-home\hub\models--knowledgator--gliner-pii-large-v1.0\…   (HF-кэш)
<models>\anonymize\navec_news_v1_1B_250K_300d_100q.tar
<models>\anonymize\slovnet_ner_news_v1.tar
<models>\anonymize-models.json                                                 (ревизии + sha256)
```

`-Offline` работает только с локальным кэшем и падает с понятным сообщением, если модели нет.

## 3. Карточка «Анонимизация» в странице управления

`hds ui` → закладка «Анонимизация»:

1. введите путь (файл или папка) и нажмите «Обзор» — сервер покажет файлы верхнего уровня в
   поддерживаемых форматах и что получится на выходе;
2. при необходимости измените выходной каталог и нажмите «Сохранить» (пишется в `config.yaml`);
3. заполните список, если нужно «указанное» (по одному значению или метке на строку);
4. одна из четырёх кнопок — «Скрыть всё», «Скрыть указанное», «Показать всё»,
   «Показать указанное». Кнопки блокируются до конца пачки (один активный акт);
5. прогресс идёт по файлам, затем в блоке «Отчёт» — по каждому файлу: вход → выход, метки
   (`[PERSON_1]×3`), счётчики найденных/ненайденных значений и предупреждения.

Серверные маршруты (админ-доступ, в server-профиле — `admin_op` в журнале аудита):

| Метод и путь | Назначение |
|---|---|
| `GET /api/anonymize/ls?path=…` | обзор входа: файлы, форматы воркера, выходной каталог, путь базы |
| `POST /api/anonymize/run` | акт: `{path, action, items?}`, `action` = `anonymize \| values \| deanonymize \| deanon-values` |
| `GET /api/anonymize/status` | ход и результат последнего акта (поллинг карточкой) |
| `POST /api/config/anonymize-dirs` | `{out_dir}` — сохранить выходной каталог |

Значения PII в ответах API **не появляются**: только метки, типы, число замен и длины списков
`matched`/`unmatched`.

## 4. Командная строка

```powershell
hds anon anonymize "D:\in\договор.docx"          # полный NER (нужны модели)
hds anon values "D:\in\письмо.txt" "Иван Петров" "ООО Ромашка"
hds anon deanon "D:\out\договор.anonymized.docx"
hds anon deanon-values "D:\out\письмо.anonymized.txt" "[PERSON_1]"
hds anon inspect "D:\out\письмо.anonymized.txt"  # метки и их известность базе, без значений
hds anon warmup                                  # прогрев моделей: backend/providers
hds anon check                                   # venv/модели/база/lease
```

Путь может быть папкой — тогда Rust перечисляет файлы верхнего уровня (форматы из `hello`
воркера) и вызывает RPC по одному файлу: прогресс и ошибки идут пофайлово.
`--out-dir <папка>` перекрывает `anonymize.output_dir`.

## 5. База меток и приватность

* База — SQLite WAL в `anonymize.db_path` (по умолчанию `data/anonymize.db`). Её ведёт **только
  воркер**; Rust и UI к базе не обращаются.
* Нумерация **per-type** со склейкой одинаковых пар: одно и то же значение получает один и тот же
  токен (`[PERSON_1]`), разные значения типа — разные номера. Из-за этого метки отличаются от
  прежней отдельной программы `anonymizer_proxy` (там счётчик был общий): файлы, анонимизированные
  ею, этой программой **не деанонимизируются**.
* `inspect` и отчёты показывают только метки/типы/счётчики; значения PII не пишутся ни в журналы,
  ни в audit, ни в ответы API.
* Пока база жива, «Показать» работает; удалили базу — исходные значения не восстановить.
  Сделайте резервную копию `data/anonymize.db` (вместе с `-wal`/`-shm`), если пары важны.
* В server-профиле входные пути должны быть доступны учётной записи службы (LocalSystem): иначе
  акт вернёт ошибку доступа — это ожидаемо, дайте службе права на каталог.

## 6. Настройки (`config.yaml`, секция `anonymize`)

| Ключ | По умолчанию | Что задаёт |
|---|---|---|
| `output_dir` | `data/anonymized` | выходной каталог; исключается из индексации неявно |
| `db_path` | `data/anonymize.db` | база меток (SQLite WAL) |
| `model` | `knowledgator/gliner-pii-large-v1.0` | модель GLiNER PII |
| `threshold` | `0.3` | порог модели (как в исходном проекте; **не** 0.5) |
| `max_input_chars` / `chunk_overlap` | `1500` / `200` | окно модели и перекрытие чанков |
| `timeout_sec` | `300` | таймаут NER-вызова |
| `natasha` | `true` | второй движок (navec/slovnet/pymorphy2) |
| `max_file_mb` | `200` | файлы больше — пропуск с предупреждением |
| `gpu` | `auto` | `auto` — аренда видеопамяти у службы моделей; `off` — всегда процессор |
| `llm_host_url` | `http://127.0.0.1:8010` | адрес службы моделей для аренды |
| `lease_timeout_sec` | `120` | сколько ждать занятый сеанс чата |
| `gpu_reserve_mb` | `2048` | резерв видеопамяти под модель и активации |
| `request_timeout_sec` | `600` | таймаут RPC на один файл |
| `idle_timeout_sec` | `60` | простой воркера до выгрузки |

Секцию можно не создавать руками: карточка дописывает `anonymize:` при первом сохранении.

## 7. Видеокарта: аренда и приоритеты

При `anonymize.gpu: auto` акт идёт так:

1. воркер просит аренду у службы моделей (`POST /internal/anon/enter`);
2. служба выгружает низкоприоритетные роли и **ждёт** занятый сеанс чата не дольше
   `lease_timeout_sec`; если не дождалась — `503 gpu_busy`, акт отклоняется (повторите позже
   или поставьте `gpu: off`);
3. аренда выдаёт лимит памяти, он передаётся в ONNX Runtime (`--gpu-mem-limit-mb`);
4. по завершении акта — `POST /internal/anon/exit`: роли возвращаются.

Служба недоступна (не запущена, старый `llm_host`) — акт идёт на процессоре, в отчёте будет
строка «lease недоступен … GLiNER на CPU (fallback)». Это не ошибка.

## 8. Диагностика и типовые сообщения

* `hds anon check` — интерпретатор, каталог моделей, база, адрес аренды; код возврата 1, если нет
  интерпретатора или весов.
* `hds check` — пункт `anonymize` со сводкой (интерпретатор, модели, база, lease). Если стек не
  установлен — `warn` (не блокирует остальные проверки). Значения видны и в
  `GET /api/diagnostics`.

| Сообщение (kind) | Что значит | Что делать |
|---|---|---|
| `model_missing` | модели NER не установлены/не загрузились | `installers\fetch_anonymize_models.ps1`; полный режим без них недоступен |
| `file_busy` | файл открыт в Word/LibreOffice | закройте документ и повторите |
| `unsupported` | формат вне `docx/xlsx/txt/md/xml` | конвертируйте файл |
| `db_missing` | база меток пуста/отсутствует | «Показать» невозможно: нечего восстанавливать |
| `out_of_dir` | выходной путь вне каталога выхода | проверьте `anonymize.output_dir` |
| `gpu_busy` | видеокарта занята, аренда не дождалась | повторите позже или `anonymize.gpu: off` |
| `internal` | сбой транспорта/воркера | `hds anon warmup`, затем `hds anon check`; журнал в `data/logs/` (если включён) |


## 9. Ограничения и известные особенности

* **Сессий нет** — это осознанное решение: только входной и выходной файл.
* **Паритет NER** с исходным проектом проверяется отдельным набором (golden-сущности, порог 0.3).
  В этом выпуске живьём проверены: карточка и API, обзор папки, «скрыть указанное» и
  «показать» (включая round-trip), отчёт без значений; полный NER требует установленных моделей
  и проверяется на машине с весами.
* **DOCX/XLSX:** анонимизированная копия байт-в-байт не совпадает с оригиналом — добавляется
  маркер и вычищаются метаданные; деанонимизированный **текст** совпадает, структура
  (таблицы/стили/числа) сохраняется.
* **TXT/MD** — байт-в-байт после «скрыть → показать»; **XML** — текст и структура тегов.
* Для TXT/MD/XML маркера в файле нет: признак «уже анонимизирован» — наличие меток, поэтому
  возможен warning на файле с ручными `[TYPE_N]`.
* Гигантские файлы (`max_file_mb`) пропускаются с предупреждением, а не обрабатываются частично.

## 10. Для разработчика

| Что | Где |
|---|---|
| Rust-клиент: запуск воркера, типы, ошибки, обход папки, lease | `crates/hds-anonymize` (`client.rs`, `protocol.rs`, `error.rs`, `settings.rs`, `folder.rs`, `lease.rs`) |
| Карточка UI и API | `crates/hds-ui/src/anonymize.rs`, `lib.rs` (маршруты), `page.rs` (разметка/JS) |
| CLI | `crates/hds-cli/src/cmd/anonymize.rs` |
| Воркер | `sidecar/hds_anonymize` (`worker.py`, `handlers.py`, `mapping_store.py`, `settings.py`, `schemas.py`, копии движков) |
| Пункт `hds check` | `crates/hds-index/src/diag.rs::check_anonymize` |
| Установщики | `installers/build_anonymize_sidecar.ps1`, `installers/fetch_anonymize_models.ps1` |
| План и решения | `PLAN_ANONYMIZER_SIDECAR.md` |

RPC воркера (JSON-RPC 2.0, NDJSON, PROTOCOL 1): `hello`, `warmup`, `inspect`, `anonymize`,
`anonymize_values`, `deanonymize`, `deanonymize_values`, `shutdown`; промежуточные
progress-нотификации без `id` клиент пропускает. Rust передаёт воркеру абсолютные пути и все
параметры аргументами — `config.yaml` воркер не читает.

Проверки: `cargo test --workspace`, `cargo fmt --check`, `cargo clippy --workspace --all-targets
-- -D warnings`; Python — `python -m unittest discover -s sidecar/tests -t sidecar -p
'test_anonymize_*.py'` (28 тестов, модели не нужны: сценарии идут через список значений).
