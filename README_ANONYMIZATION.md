# Анонимизация документов — руководство

> Что это, как включить и как этим пользоваться. Общая документация продукта — `README.md`
> (глава 19), правила выпуска — `RELEASING.md`, лицензии сторонних частей — `NOTICE.md`,
> решения и фазы — `PLAN_ANONYMIZER_SIDECAR.md`.

## 1. Что делает и чего не делает

* **«Скрыть»** заменяет персональные данные в документе метками `[TYPE_N]`
  (`[PERSON_1]`, `[ORG_2]`, `[PHONE_1]`, `[EMAIL_1]`, …). Полный режим — поиск моделями
  (GLiNER PII + Natasha/Slovnet + регулярные выражения для телефонов, почты, документов,
  банковских реквизитов). Частичный — детерминированный список значений, который вы задаёте сами.
* **«Показать»** возвращает исходный текст по базе меток: либо все метки файла, либо только
  перечисленные.
* **Перед анонимизацией** «слипшиеся» ФИО исправляются: `ВолодинВ.В.` → `Володин В. В.` (и
  зеркальная форма `В.В.Володин` → `В. В. Володин`). Без этой правки модели не видят фамилию —
  между ней и инициалами нет границы. Исправления вносятся и в **исходный файл** (до вызова
  NER), счётчик правок попадает в предупреждения акта; деанонимизация возвращает уже
  исправленную запись.
* **Не делает:** не перехватывает команды ассистентов, не работает как прокси OpenAI/API, не
  ведёт сессий и не хранит пары «оригинал / аноним / результат». Есть только входной файл и
  выходной: `<имя>.anonymized.<ext>` и `<имя>.deanon.<ext>` (суффикс `.anonymized` у входа
  отбрасывается: `a.anonymized.docx` → `a.deanon.docx`).

Форматы: `.docx`, `.xlsx`, `.txt`, `.md`, `.xml` (MS Project). Папка обрабатывается **по верхнему
уровню** — вложенные каталоги не обходятся (так же, как `auto_transcribe.inbox_dir`).

## 2. Установка стека

Стек не входит в архив программы (как и окружение расшифровки): код воркера едет в поставке
(`sidecar\hds_anonymize`), а окружение и модели ставит установщик на машине.

```powershell
# окружение: cpu (процессор) или cuda (видеокарта NVIDIA)
powershell -File installers\build_anonymize_sidecar.ps1 -Profile cpu -SelfTest

# модели в машинный каталог (по умолчанию HDS_MODELS_DIR / %ProgramData%\hermes-disk-search\models)
powershell -File installers\fetch_anonymize_models.ps1 -ModelsDir D:\models

# готовность: интерпретатор, веса, база, адрес аренды GPU
hds anon check
```

* Окружение идемпотентно: маркер `.hds-anonymize-profile` хранит профиль, версию Python и sha256
  `requirements.lock`; `-Force` пересобирает venv.
* В venv **ровно один** `onnxruntime`: профиль `cuda` сначала удаляет CPU-колесо
  (`pip uninstall onnxruntime`), затем ставит `onnxruntime-gpu` (CPU-пин из lock отфильтровывается)
  + `nvidia-cublas-cu12`/`nvidia-cuda-runtime-cu12`/`nvidia-cudnn-cu12`/`nvidia-cufft-cu12`;
  профиль `cpu` — `onnxruntime` из lock.
* CUDA-провайдеру ORT нужны **все** CUDA 12 DLL из `nvidia-*-cu12`, включая cuFFT
  (`cufft64_11.dll`): `onnxruntime_providers_cuda.dll` импортирует её статически, и без
  `nvidia-cufft-cu12` провайдер целиком не загружается (Windows: «модуль не найден», Error 126),
  а ORT **молча** работает на `CPUExecutionProvider`. `get_available_providers()` об этом не
  сигнализирует (он перечисляет скомпилированные, а не загруженные провайдеры), поэтому
  `-Profile cuda -SelfTest` дополнительно грузит `onnxruntime_providers_cuda.dll` и завершает
  сборку с ошибкой, если тот не загрузился.
* Смена профиля (`cpu` ↔ `cuda`) пересобирает venv — иначе в нём остаются два дистрибутива
  `onnxruntime` (CPU-колесо и `onnxruntime-gpu` дают один и тот же модуль).
* Размер: окружение ~3–6 ГБ (в lock есть `torch`, его импортирует GLiNER даже для ONNX-пути),
  модели ~1 ГБ. Время установки — десятки минут при медленной сети.
* Токен Hugging Face **не нужен**: модель `knowledgator/gliner-pii-large-v1.0` публичная.
  `-HfToken`/`HF_TOKEN` поддержан только для лимитов загрузки и не сохраняется.
* macOS: те же две команды в `pwsh`; профиль `cuda` только для NVIDIA (на Apple Silicon — `cpu`).

### Где лежат модели

```
<models>\anonymize\hf-home\hub\models--knowledgator--gliner-pii-large-v1.0\…   (HF-кэш)
<models>\anonymize\navec_news_v1_1B_250K_300d_100q.tar
```

## 3. Карточка «Анонимизация» в странице управления

`hds ui` → закладка «Анонимизация»:

1. введите путь (файл или папка) или нажмите «Обзор…» — откроется выбор диска, папок и файлов
   на сервере (браузер не может передать абсолютный путь сам, поэтому листает сервер); после
   выбора сервер покажет файлы верхнего уровня в поддерживаемых форматах и что получится на выходе;
2. при необходимости измените выходной каталог и нажмите «Сохранить» (пишется в `config.yaml`;
   строка «каталог выхода» обновляется сразу);
3. заполните список, если нужно «указанное» (по одному значению или метке на строку): для
   «Скрыть указанное» — значения PII, для «Показать указанное» — токены вида `[PERSON_1]`;
   кнопки «Скрыть всё» и «Показать всё» этот список не используют;
4. одна из четырёх кнопок — «Скрыть всё», «Скрыть указанное», «Показать всё»,
   «Показать указанное». Одновременно выполняется только одно действие: до его завершения
   кнопки заблокированы;
5. прогресс идёт по файлам, затем в блоке «Отчёт» — по каждому файлу: вход → выход, метки
   (`[PERSON_1]×3`), счётчики найденных/ненайденных значений и предупреждения.

Серверные маршруты (админ-доступ, в server-профиле — `admin_op` в журнале аудита):

| Метод и путь | Назначение |
|---|---|
| `GET /api/anonymize/ls?path=…` | обзор входа: файлы, форматы воркера, выходной каталог, путь базы |
| `GET /api/anonymize/browse?path=…` | выбор файла/папки для карточки («Обзор…»): диски, подпапки, файлы поддерживаемых форматов |
| `POST /api/anonymize/run` | акт: `{path, action, items?}`, `action` = `anonymize \| values \| deanonymize \| deanon-values` |
| `GET /api/anonymize/status` | ход и результат последнего акта (поллинг карточкой) |
| `POST /api/config/anonymize-dirs` | `{out_dir}` — сохранить выходной каталог |

Значения PII в ответах API **не появляются**: только метки, типы, число замен и длины списков
`matched`/`unmatched`.

## 4. Командная строка

```powershell
hds anon anonymize "D:\in\договор.docx"          # полный NER (нужны модели)
hds anon values "D:\in\письмо.txt" "Иван Петров" "ООО Ромашка"
hds anon deanon "D:\out\договор.anonymized.docx"
hds anon deanon-values "D:\out\письмо.anonymized.txt" "[PERSON_1]"
hds anon inspect "D:\out\письмо.anonymized.txt"  # метки и их известность базе, без значений
hds anon warmup                                  # прогрев моделей: backend/providers
hds anon check                                   # venv/модели/база/lease
```

Анонимная зона (проект, метки уровня 1 — см. §5):

```powershell
hds anon agent "D:\проект\ТЗ.docx" --project P0001 [--artifact 42] [--out-dir DIR]
hds anon text-image "D:\проект\ТЗ.pdf" --project P0001 [--out-dir DIR]
hds anon deanon "D:\ws\ТЗ.docx" --project P0001   # подстановка с падежными суффиксами
hds anon snapshot P0001                           # rev/метки/формы — только счётчики
hds anon keep [list | add "1С:ERP"]               # список «не анонимизировать» (D19)
hds anon merge P0001 "[PERSON_3]" "[PERSON_5]"    # «Объединить метки» (TR-2.6)
```

`agent` пишет **образ** анонимной зоны: метки проекта с падежными суффиксами
(`[PERSON_3|дат]`), картинки тела заменены `[IMAGE_n]`, метаданные вычищены, в свойства
файла записан маркер `hds-agent/<P>/<artifact_id>`; оригинал не меняется.
`text-image` собирает `<имя>.<ext>.md` для `pdf`/`pptx`/`mpp`: текст извлекает
`hds_extract` (PyMuPDF/python-pptx/mpxj), затем он анонимизируется метками проекта.

Путь может быть папкой — тогда Rust перечисляет файлы верхнего уровня (форматы из `hello`
воркера) и вызывает RPC по одному файлу: прогресс и ошибки идут пофайлово.
`--out-dir <папка>` перекрывает `anonymize.output_dir`.

## 5. База меток и приватность

* База — SQLite WAL в `anonymize.db_path` (по умолчанию `data/anonymize.db`). Её ведёт **только
  воркер** (`sidecar/hds_anonymize/vault.py`); Rust и UI к базе не обращаются.
* **Схема v2 — одна база, два уровня меток.** Уровень 0 (`entities`, `forms`) — сущности и
  исходные значения, их используют карточка и `hds anon`: метки прежнего вида (`[PERSON_1]`,
  без суффиксов). Уровень 1 (`projects`, `labels`, `counters`) — метки проекта для анонимной
  зоны: номера выдаются счётчиком проекта в порядке первого появления и **не** выводятся из
  глобального номера, поэтому проекты не связываются между собой.
* **Словоформы склеиваются по `norm_key`** (`morph.py`): «Иванов Иван Иванович», «Иванову
  Ивану Ивановичу» и «Иванов И. И.» — одна сущность и одна метка. Порождённые падежи хранятся
  отдельно (`origin='derived'`) и нужны для подстановки и фильтра исходящего.
* **Падежный суффикс** ставится только при однозначном определении падежа: `[PERSON_3|дат]`,
  `[ORG_1|твор]`, `[PERSON_2|род,мн]`. Если падеж не определён однозначно — суффикса нет,
  а отчёт помечает такие метки «проверить» (в A0 «в лоб» это 19,7 % форм). В **именах файлов**
  суффикса нет всегда (символ `|` в Windows запрещён).
* `keep_terms` — «не анонимизировать» (D19): **согласованный состав продуктов 1С** (1С:БП/БП,
  1С:ЗУП/ЗУП, 1С:УТ/УТ, 1С:УНФ/УНФ, 1С:КА/КА, 1С:ERP/ЕРП, 1С:УПП, 1С:ДО/ДО,
  1С:Документооборот, 1С:УХ, 1С:ERP УХ, 1С:Розница/РТ, 1С:WMS, 1С:TMS, 1С:ТОИР, 1С:ИТС,
  1С:ЭДО, 1С:БСП, 1С:Fresh/Фреш), прочие продукты проекта, термины (`ТЗ`, `ТЭО`, `ФТТ`,
  `HTTP-сервис`, `RLS`), коды `REQ-…` (`re:`-шаблон). Стартовый список — в `vault.py`,
  расширение — `sidecar/hds_anonymize/keep_terms.example.yaml` (воркеру: `--keep-terms <файл>`)
  и `hds anon keep add`. Запись `cs:ДО`/`cs:КА` сверяется с учётом регистра, чтобы «до»/«ка»
  не «слеплялись» с аббревиатурами; компоненты составных названий (`ERP`, `ЗУП`) тоже
  считаются «своими» — NER режет «1С:ERP» на части.
* `inspect`, `snapshot` и отчёты показывают только метки/типы/счётчики; значения PII не пишутся
  ни в журналы, ни в audit, ни в ответы API. Снимок меток (`vault_snapshot`) отдаётся Rust
  для фильтра исходящего и живёт только в памяти.
* **Старая база (0.23.x) не переносится** (D4, TR-1.3): при первом запуске файл схемы v1
  переименовывается в `anonymize.db.v1-<YYYYMMDD-HHMMSS>.bak`, создаётся пустая база v2.
  Файлы, анонимизированные 0.23.x, этой версией **не деанонимизируются** — держите бэкап базы,
  если такие пары нужны.
* Пока база жива, «Показать» работает; удалили базу — исходные значения не восстановить.
  Сделайте резервную копию `data/anonymize.db` (вместе с `-wal`/`-shm`), если пары важны.
* В server-профиле входные пути должны быть доступны учётной записи службы (LocalSystem): иначе
  акт вернёт ошибку доступа — это ожидаемо, дайте службе права на каталог.

## 7. Видеокарта: аренда и приоритеты

При `anonymize.gpu: auto` акт идёт так:

1. воркер просит аренду у службы моделей (`POST /internal/anon/enter`);
2. служба выгружает низкоприоритетные роли и **ждёт** занятый сеанс чата не дольше
   `lease_timeout_sec`; если не дождалась — `503 gpu_busy`, акт отклоняется (повторите позже
   или поставьте `gpu: off`);
3. аренда выдаёт лимит памяти, он передаётся в ONNX Runtime (`--gpu-mem-limit-mb`);
4. по завершении акта — `POST /internal/anon/exit`: роли возвращаются.

Служба недоступна (не запущена, старый `llm_host`) — акт идёт на процессоре, в отчёте будет
строка «lease недоступен … GLiNER на CPU (fallback)». Это не ошибка.

## 8. Диагностика и типовые сообщения

* `hds anon check` — интерпретатор, каталог моделей, база, адрес аренды; код возврата 1, если нет
  интерпретатора или весов.
* `hds check` — пункт `anonymize` со сводкой (интерпретатор, модели, база, lease). Если стек не
  установлен — `warn` (не блокирует остальные проверки). Значения видны и в
  `GET /api/diagnostics`.
* Фактический контур виден по строкам воркера `lease 'anon' выдан … GLiNER на GPU` и
  `GLiNER ONNX загружен (провайдеры: …)`. Список провайдеров сам по себе **не доказывает** GPU:
  если в логе есть `Error loading "...\onnxruntime_providers_cuda.dll" … depends on
  "cufft64_11.dll"`, CUDA-провайдер не загрузился и акт идёт на CPU. Лечится пересборкой
  окружения: `build_anonymize_sidecar.ps1 -Profile cuda -SelfTest -Force`.

| Сообщение (kind) | Что значит | Что делать |
|---|---|---|
| `model_missing` | модели NER не установлены/не загрузились | `installers\fetch_anonymize_models.ps1`; полный режим без них недоступен |
| `file_busy` | файл открыт в Word/LibreOffice | закройте документ и повторите |
| `unsupported` | формат вне `docx/xlsx/txt/md/xml` | конвертируйте файл |
| `db_missing` | база меток пуста/отсутствует | «Показать» невозможно: нечего восстанавливать |
| `out_of_dir` | выходной путь вне каталога выхода | проверьте `anonymize.output_dir` |
| `gpu_busy` | видеокарта занята, аренда не дождалась | повторите позже или `anonymize.gpu: off` |
| `internal` | сбой транспорта/воркера | `hds anon warmup`, затем `hds anon check`; журнал в `data/logs/` (если включён) |


## 9. Ограничения и известные особенности

* **Сессий нет** — это осознанное решение: только входной и выходной файл.
* **Паритет NER** с исходным проектом проверяется отдельным набором (golden-сущности, порог 0.3).
  В этом выпуске живьём проверены: карточка и API, обзор папки, «скрыть указанное» и
  «показать» (включая round-trip), отчёт без значений; полный NER требует установленных моделей
  и проверяется на машине с весами.
* **DOCX/XLSX:** анонимизированная копия байт-в-байт не совпадает с оригиналом — добавляется
  маркер и вычищаются метаданные; деанонимизированный **текст** совпадает, структура
  (таблицы/стили/числа) сохраняется.
* **TXT/MD** — байт-в-байт после «скрыть → показать»; **XML** — текст и структура тегов.
* Для TXT/MD/XML маркера в файле нет: признак «уже анонимизирован» — наличие меток, поэтому
  возможен warning на файле с ручными `[TYPE_N]`.
* Гигантские файлы (`max_file_mb`) пропускаются с предупреждением, а не обрабатываются частично.
* **Падежный суффикс — не гарантия.** Суффикс ставится только при однозначном разборе; при
  сомнении метка идёт без суффикса, а отчёт пишет «проверить». «Иванову И. И.» (род/вин
  неразличимы) суффикса не получит — это ожидаемо (TR-2.4, П-12).
* **`norm_key` не склеивает частичные упоминания:** «Иванов», «Иванов Иван Иванович» и
  «ООО «Ромашка»» ↔ «Ромашка» остаются разными сущностями; склейка — вручную
  («Объединить метки», TR-2.6). Автоматическая склейка — фаза 2.
* **Образы `pdf`/`pptx`/`mpp` — только текст** (`<имя>.<ext>.md`), только для чтения: правки
  оформляются новым документом рядом (TR-7.3a). Оформление, картинки и подписи PDF в образ не
  попадают.
* **Office-операции** (`office_read`/`office_edit`/`office_create`) правят `docx`/`xlsx`/`pptx`
  в анонимной зоне; для `pptx` в MVP поддерживается только `replace_text` (правки слайдов —
  фаза 2). `python-pptx` входит в lock венва анонимизации.
* **Метки `[IMAGE_n]`** — не сущности: фильтр исходящего обязан пропускать тип `IMAGE`, а
  восстановление картинок делает демон из снимка основания (A4). В режиме agent вырезаются
  картинки тела DOCX (абзацы и ячейки таблиц) и картинки листов XLSX — на их месте появляется
  `[IMAGE_n]`, байты изображений вымываются из пакета вместе со связями; метаданные пакета
  (автор, последний редактор, заголовок, описание) очищаются и в DOCX, и в XLSX.
