### 3.1. A4.1: что именно сделано (факты)

* **Схема** ровно по TR-7.2: `artifacts(id INTEGER PRIMARY KEY, orig_rel TEXT NOT NULL
  UNIQUE, anon_rel TEXT NOT NULL, kind, orig_sha256, anon_sha256_issued,
  anon_sha256_seen, status, ts REAL NOT NULL)` + индексы `anon_rel` и `status`,
  `PRAGMA user_version = 1`, `journal_mode=WAL`, `busy_timeout=30000`,
  `synchronous=NORMAL`. `busy_timeout` ставится **первым** — иначе смена
  `journal_mode` падала бы на блокировке (тот же порядок, что в `hds_core::db`).
* **API** (`ArtifactRegistry`): `open`, `path`, `schema_version`, `insert` (id выделяется
  **до** анонимизации — он уходит в маркер `hds-agent/<P>/<id>`), `upsert` (`ON CONFLICT
  (orig_rel)`, хэши через `COALESCE` — «знаю только часть» не стирает известное),
  `by_id`/`by_orig`/`by_anon`, `set_status`, `set_status_by_orig`, `set_issued`
  (issued = seen, статус), `mark_seen`, `set_base`, `rename_orig` (переименование
  оригинала + образа), `list`, `list_by_status`, `list_pending`, `count`, `delete`.
* **Ошибка БД не валит демон** (TR-7.2): `RegistryError` — `Open/Sql/NotFound`,
  вызывающий превращает её в статус `error` и продолжает; CLI возвращает 1.
* **Совместимость вперёд:** неизвестные `kind`/`status` из более новой версии читаются
  как `Kind::Unknown`/`Status::Unknown` (демон такой записью не управляет), а не
  роняют весь обход. Записываются только значения из плана — `as_str` проверен тестом
  `schema_strings_match_plan`.
* **Путь реестра — зона пользователя**: `<state_dir>\data\agent\registry\<P>.db`;
  `<P>` обязан быть `P` + 4 цифры (`hds_core::roots::is_agent_project`, D21), иначе
  `registry_db` вернёт `None` — `--project ..\..\evil` путь не построит (тест).
* **`hds agent sync --project <P> [--once]`** (A4.1): проверяет `agent.enabled`,
  регистрацию проекта в `projects.json`, открывает/создаёт реестр, печатает путь и
  число записей. Папка проекта не читается и не меняется — обход придёт в A4.2.
* **Тесты** `registry_db`: схема/строки контракта, открытие (каталог+WAL+busy_timeout+
  `user_version`), `insert` (id, roundtrip, конфликт уникальности), `upsert` (id
  стабилен, хэши не стираются), `issued/seen` → `agent_changed`, статусы и
  `list_pending`, переименование/удаление, переоткрытие и «значения из будущего»,
  **два потока-писателя** (2×20 `upsert` → 40 записей, без потерь). Временные каталоги
  — с `AtomicU32`-счётчиком (§5 п.4 хендоффа).

### 3.2. A4.2: что именно сделано (факты)

* **Модуль `mirror`** (`crates/hds-agent/src/mirror.rs`): `walk_files` (рекурсивно,
  детерминированно; `.hds-agent`, `_attachments`, `_conflicts`, `~$*`, `*.tmp`,
  `Thumbs.db` не обходятся; junction/симлинк не обходится, каталог канонизируется
  и обязан остаться внутри корня), `kind_for` (docx/xlsx/txt/md/xml → `image`;
  pdf/pptx/mpp → `text_image`), `wait_stable_at` (2 с/0,5 с/30 с; файл старше
  `settle_age_sec` не ждём), `fit_component` (≤120 символов + 8 hex sha256,
  расширение сохраняется), `unique_name` (` (2)`, ` (3)`), `sha256_file`.
* **Идемпотентность — по sha256**: `orig_sha256` (оригинал) и
  `anon_sha256_issued`/`anon_sha256_seen` (образ). Совпали — `mark_seen` только
  если `seen` менялся, в БД иначе ничего не пишется; `unsupported`/`too_big`
  повторно не перезаписываются. Второй прогон: `changes() == 0`.
* **Переходы**: новый/изменённый оригинал → образ (`Synced`); образ потерян →
  пересоздаётся; образ изменён агентом при неизменном оригинале →
  `AgentChanged` (прямой путь **не** затирает); удалённый оригинал →
  удаление образа и записи, если `seen == issued`, иначе `Orphan`; изменённый
  оригинал при `PendingAccept`/`Conflict` → `Conflict` без перезаписи;
  `Orphan` при возврате оригинала возвращается в `Synced`.
* **Переименование**: файл без записи в реестре, чей sha256 совпал с
  исчезнувшим оригиналом → образ переименовывается (`fs::rename`), запись —
  `rename_orig`; повторной анонимизации нет, `artifact_id` сохраняется.
* **Имена**: RPC `anonymize_path(project_id, path, suffix=false)` — NER по
  компонентам, `project_label_ex(suffix=False)`, санитайзинг (`<>:"/\|?*`,
  управляющие, схлопывание пробелов, хвостовые точки); `suffix=true` —
  **отказ** (в имени нельзя `|`). Обрезка до 120 символов и коллизии — в Rust
  (там же, где MAX_PATH и реестр), а не в Python.
* **Клиент/воркеры**: `Client::anonymize_path`, `anonymize_agent_to`,
  `text_image_to` (явный `out_path` — имя образа задаёт демон); capability
  `anonymize_path` в `hello`; ленивые `LazyAnonymizer`/`LazyExtractor` —
  пустая папка и папка без pdf/pptx/mpp Python не поднимают.
* **CLI**: `hds agent sync --project <P> [--once]` выполняет один проход,
  печатает счётчики и до 10 проблем (путь+причина, без значений, I8);
  `HDS_EXTRACT_WORKER` подменяет скрипт извлечения (как
  `HDS_ANONYMIZE_WORKER` — нужно, когда `HDS_ROOT` указывает на каталог данных).
* **Тесты**: `mirror` — 19 (классификация/служебные имена, длина/коллизии,
  sha256-вектор, `wait_stable` Ready/Deferred/Gone, обход, первый проход и
  статусы, идемпотентность, изменение, переименование, удаление, правка
  агента, orphan, `too_big`, коллизии, ошибка одного файла, конфликт,
  удаление `unsupported`); `settings` +2 (дефолты = пример конфига, `0`/мусор);
  python 9 (`test_anonymize_path.py`) + 1 RPC-тест в `test_anonymize_worker.py`;
  CLI e2e +1 (mock-воркер: образ с меткой, `unsupported`, служебные не
  выпущены, повторный прогон не трогает образ).
* **Стенд** (`tools/parity/out/agent_a42/`): `agent_a0_gen_project.py` — 32
  документа; прогон 1 — 31 образ + 1 текстовый образ (PDF через `hds_extract`),
  1 `unsupported` (`project.json`), PDF-образ содержит `<!-- hds-agent/P0001/7 -->`,
  `<!-- страница 1 -->`, `[ORG_3]`, `[PERSON_2]`, `[MONEY_1]`, keep-terms
  `1С:ERP`/`REQ-001` на месте; прогон 3 — `33 файла, 32 без изменений,
  0 изменений`. Структура каталогов повторена, имена с метками
  (`Устав проекта внедрения [ORG_1].docx`, `Протокол 01 [ORG_8] …`).
* **Отклонения от буквы плана** (осознанные): (1) `HDS_EXTRACT_WORKER` —

### 3.3. A4.3: что именно сделано (факты)

* **Один проход = два пути.** `Mirror::sync_once` вызывает `sync_forward`
  (A4.2) и затем `sync_reverse`; реестр перечитывается после прямого пути,
  поэтому образы, созданные в этом же проходе, обратный путь видит.
* **Маркер.** `read_marker` (Python): DOCX/XLSX — из `docProps`
  (`read_anon_marker`), `*.md`/`*.txt` — первая строка
  `<!-- hds-agent/<P>/<id> -->`. **Изменение A4.2:** текстовые образы
  (`anonymize mode:"agent"` для md/txt) теперь тоже получают маркер первой
  строкой — без него обратный путь считал бы все md-образы новыми файлами
  агента (поймано на стенде).
* **`agent_new`** (маркера нет или он чужого проекта): `deanonymize_path`
  (метки → значения проекта; неизвестные остаются в имени и попадают в
  `problems`) → `safe_components` (нет `..`, `:`, разделителей) →
  `free_project_name` (`имя (агент).ext`, затем ` (агент 2)`) →
  деанонимизация в `.hds-agent\tmp\<hash>.tmp` → `rename` в папку проекта.
  В реестр: `kind=agent_new`, `status=synced`, `orig_sha256` = sha256
  **выпущенного** файла (TR-7.7), `anon_sha256_issued/seen` = sha256 образа.
* **`agent_changed`** (`seen != issued`): проверка основания (sha256
  оригинала = `orig_sha256`; иначе `conflict`, вариант не собирается) →
  снимок `.hds-agent\base\<orig_rel>` (копия оригинала) + карта
  `<orig_rel>.images.json` (`[IMAGE_n]` → часть пакета, В-4) → вариант
  `.hds-agent\pending\<orig_rel>` (`deanonymize` с `restore_from`,
  `images=true`) → `set_issued(seen, PendingAccept)`. Повторная правка
  перезаписывает вариант; основание не меняется.

### 4.1. Вопросы владельцу по §9 хендоффа — расшифровка и принятые дефолты

Вопросы ниже не про код, а про **поведение, которое увидит пользователь**. Для каждого
дано: о чём речь, что меняет выбор, что принято, альтернатива.

**Ответы владельца (19.11.2026):** приняты все семь дефолтов, с двумя уточнениями —

#### В-1. `hds agent sync`: один проход или постоянный демон

*О чём.* Зеркало сравнивает папку проекта и `<P>\workspace`. Это можно делать двумя
способами: (а) обойти один раз, синхронизировать и выйти — флаг `--once`; (б) висеть в
фоне и повторять обход каждые N секунд — тогда пользователь, сохранив документ, через
несколько секунд видит его образ в анонимной зоне, и агенту есть с чем работать, без
ручных «синхронизируй сейчас».

*Что решает выбор.* `--once` нужен в любом случае (тесты, CLI, проверка). Вопрос — про
(б), интервал. 2 с — быстрая реакция, но на папке в тысячи файлов это постоянное чтение
метаданных всего дерева; 5 с — компромисс; 30 с — почти незаметно для диска, но правка
«доходит» до агента полминуты. Автозапуск (Планировщик/служба) в A4 **не** делаем: это
A6, иначе демон придётся ставить и снимать вместе с системой.

*Дефолт.* A4.6: `--once` **и** `--interval SEC` (по умолчанию 5 с); автозапуск — A6.
В A4.1 работает только `--once`.

*Альтернатива.* Вместо опроса — подписка на изменения ФС (ReadDirectoryChangesW):
точнее и дешевле по диску, но добавляет класс ошибок (переименования, junction,
переполнение буфера событий) и удлиняет A4 на день-два. Предлагаю фазу 2.

*Ответ владельца (19.11.2026).* «5 с ок»; подписку на изменения ФС **внести в фазу 2** —
внесено в `PLAN_AGENT_PRIVACY_ZONE.md` §8 (с требованиями: переименования/junction как
события, переполнение буфера — полный обход).

#### В-2. `wait_stable`: сколько ждать, пока файл «успокоится»

*О чём.* Пользователь копирует в папку проекта файл на 80 МБ. Демон может увидеть его
на середине копирования и начать анонимизацию обрезанного docx (ошибка, а в худшем
случае — образ без части текста). Поэтому перед обработкой демон опрашивает **размер и
mtime** и ждёт, пока они не перестанут меняться X секунд; если за Y секунд стабильности
так и не было — файл откладывается до следующего прохода **без** статуса «ошибка»
(чтобы не пугать пользователя).

*Что решает выбор.* X — плата за надёжность: при первом зеркалировании 40 документов
ожидание по 2 с даёт **+80 с** к первому проходу, и это заметно. X=1 с — вдвое быстрее,
риск поймать недописанный файл выше (повторный проход это лечит). Y — «сколько терпим»:
непрерывно дописываемый файл не должен держать демон вечно.

*Дефолт.* X=2 с, опрос 0,5 с, Y=30 с. Плюс оптимизация: если mtime файла на момент
обнаружения старше 5 с, ожидание не нужно — файл уже лежит «спокойно» (это и снимает
те самые +80 с на первом проходе).

*Альтернатива.* X=1 с / Y=60 с; либо «ждать только файлы с mtime моложе 10 с».

*Ответ владельца (19.11.2026).* «2 с ок»; смысл каждой настройки описан в
`config.example.yaml` (блок `agent.sync`) и в таблице §4.3.

#### В-3. Лимит размера для зеркала (`too_big`)

*О чём.* Файл больше лимита в анонимную зону не попадает: он получает статус `too_big`,
в панели «Файлы проекта» (A5) видно, что файл есть, но агенту недоступен. Лимит уже
существует у индекса — `index.max_file_mb` (по умолчанию 200 МБ).

*Что решает выбор.* Один ключ = одно правило: «что не индексируется, то и не
зеркалится»; минус — меняя лимит индекса, пользователь незаметно меняет и зеркало.
Отдельный ключ `agent.sync.max_file_mb` позволяет, например, индексировать до 200 МБ, а
в зеркало пускать 50 МБ: анонимизация 150-мегабайтного docx — это минуты NER и образ,
который агенту всё равно бесполезен.

*Дефолт.* Переиспользовать `index.max_file_mb`, отдельный ключ не вводить (меньше
настроек). Понадобится — добавим аддитивно в A6.

*Ответ владельца (19.11.2026).* «Переиспользовать `index.max_file_mb`».

#### В-4. Восстановление картинок в XLSX (и docx)

*О чём.* В режиме `agent` картинки тела документа агенту не отдаются: вместо них в
тексте стоит метка `[IMAGE_n]` (логотип на титуле, схема в реестре требований). Когда
агент правит такой образ, а пользователь нажимает «Принять», документ собирается
обратно — и картинки должны вернуться на свои места. В docx порядок картинок
детерминирован (идём по документу), поэтому метка восстанавливается по номеру. В XLSX
картинка привязана к **якорю** (лист, строка, колонка); после правок ячеек порядок может
сместиться, поэтому нужна карта «метка → якорь + файл картинки», снятая в момент
вырезания и сохранённая рядом со снимком основания.

*Что решает выбор.* **А (дефолт):** доработать Python (`strip_body_images` /
`_strip_xlsx_images` возвращают карту), хранить её в `.hds-agent\base\<rel>.images.json`
и восстанавливать по карте — логотипы и схемы возвращаются на место; цена ≈ 0,5 дня
Python + тесты. **Б:** в XLSX не восстанавливать, оставить `[IMAGE_n]` текстом и
предупредить пользователя — быстрее, но реестр требований вернётся «с дырками» (картинки
при этом живы в снимке основания).

*Ответ владельца (19.11.2026).* «Карту делать»: `strip_body_images`/`_strip_xlsx_images`
возвращают карту, она сохраняется в `.hds-agent\base\<rel>.images.json` и используется
при сборке варианта (A4.3).

#### В-5. Имена: коллизии и длина

*О чём.* Имена в анонимной зоне — это метки: `Протоколы\Встреча с [PERSON_3].docx`.
Две проблемы. **(1) Коллизии:** разные оригиналы могут дать одинаковое анонимное имя
(после санитайзинга недопустимых символов, при `keep_terms`, когда имя не менялось,
или при слиянии меток `merge_entities`). Тогда второй файл получает суффикс ` (2)`,
третий — ` (3)`. Связь «оригинал ↔ образ» всё равно хранится в реестре, а не
вычисляется из имени. **(2) Длина:** в Windows без `LongPathsEnabled` путь ограничен
~260 символами, а путь образа = `<agent.root>\P0001\workspace\` + вложенность + имя.
Длинное русское имя в 3–4 уровнях папок может не влезть, поэтому имя длиннее 120
символов обрезается, а к нему добавляется 8 hex от sha256 исходного имени — тогда два
разных длинных имени не сольются.

*Что решает выбор.* Порог (120 vs 80 символов) и устраивает ли суффикс ` (2)` — он
виден и агенту, и пользователю, но честно говорит «второй файл с таким именем».

*Ответ владельца (19.11.2026).* «120 ок».

#### В-6. Сообщения агенту при «Отклонить» и «Поручить агенту»

*О чём.* Если пользователь отклонил правку, агент на следующем ходу не должен снова
предлагать то же самое; если «поручил» конфликт — агент должен узнать, что документ
обновился, а его правки лежат в `_conflicts`. Живой сессии в A4 нет (CLI `run` — один
ход на процесс), поэтому сообщение надо куда-то положить. Предлагается очередь
`.hds-agent\messages.jsonl`: построчно JSON (время, проект, путь, вид события, текст).
A4 только пишет; A5 при старте сессии забирает новые сообщения и подкладывает их агенту
как системную заметку.

*Что решает выбор.* Очередь + доставка в A5 — надёжно и не мешает агенту читать файлы.
Альтернатива: писать файл прямо в workspace, чтобы агент увидел его обычным чтением по
правилам — без кода в A5, но полагается на то, что модель догадается прочитать, и
мусорит в анонимной зоне.

*Ответ владельца (19.11.2026).* «Очередь»: `.hds-agent\messages.jsonl`, A4 пишет, A5
доставляет в сессию.

#### В-7. «Сравнить» для docx

*О чём.* Пользователь видит вариант правки агента и хочет понять, что изменилось. Для
XLSX мы сами считаем изменённые ячейки, для md/txt — текстовый diff. Для docx
«правильное» сравнение — встроенное в Word (документ с исправлениями), но это
COM-автоматизация: нужен установленный Word, невидимое окно, капризные ошибки COM.

*Что решает выбор.* **Дефолт:** A4 отдаёт данные (пути основания/оригинала/варианта +
отчёт валидатора), запуск Word-сравнения — A5, где уже есть UI. **Альтернатива:** A4 сам
делает грубое сравнение по абзацам (`python-docx` + `difflib`) и отдаёт список
«было → стало» — пользователь видит изменения без Word, но таблицы и форматирование
такое сравнение не отражает.

*Ответ владельца (19.11.2026).* Данные — в A4; запуск Word-сравнения — A5.

### 4.2. Долги и открытые места (передаются по под-этапам)

1. **A4.1: `--once` — единственный режим.** Флаг `--interval` появится в A4.6 вместе с
   циклом (период — `agent.sync.interval_sec`, решение В-1), остановкой по
   `index.stop`/Ctrl+C и журналом `agent-state\sync.log`. Сейчас команда делает ровно
   один проход, даже без `--once`.
2. **A4.1: проект обязателен.** `sync` без `--project` отказывает (код 2): обход всех
   проектов сразу — A4.6 (там же `--all` или цикл по `projects.json`).
3. **A4.2: реестр чистится только там, где это безопасно.** Запись об исчезнувшем
   оригинале удаляется (`unsupported`/`too_big` — вместе с записью, `synced` — вместе
   с образом, если `seen == issued`); `orphan` живёт до решения пользователя (A5),
   `pending_accept`/`conflict`/`agent_changed`/`accepted` прямой путь не трогает.
   Удаление проекта (TR-8.1) должно удалять `<P>.db` — A5/A6 вместе с кнопкой
   «удалить проект».
4. **A4.3 → A4.4: у `pending_accept` появилось решение.** Вариант собирается
   автоматически, решение — `hds agent result` (ядро `hds_agent::results`):
   «Принять»/«Отклонить»/три исхода конфликта. `issued`/`seen` после решения
   выставляются заново (`set_baseline`), поэтому следующая правка агента снова
   видна; «Сравнить» осталось долгом (§4.2 п.17).
5. **A4.3 → A4.4: `conflict` появился в двух местах и теперь разрешается.**
   Прямой путь ставит `conflict`, если изменились и оригинал, и образ; обратный —
   если оригинал не совпадает с основанием. Исходы — `conflict --choice
   agent|new|delegate` (`agent` = приём с backup и предупреждением, `new` = новая
   версия пользователя, `delegate` = копия варианта в `_conflicts`). Кнопки в UI —
   A5.
6. **A4.2: путь к sidecar — от `project_root()`**, то есть от `HDS_ROOT`, если он
   задан. При `HDS_ROOT`, указывающем на отдельный каталог данных, нужны
   `HDS_ANONYMIZE_WORKER`/`HDS_EXTRACT_WORKER` (или sidecar рядом с этим каталогом).
   A4.6: описать в README и/или определять путь от каталога установки.
7. **A4.2: у зеркала свои правила обхода** (`is_service_dir`/`is_service_file`), а не
   `index_filter`: TR-7.1 перечисляет служебное явно. При появлении новых служебных
   каталогов индекса списки синхронизировать (сейчас пересечение — `.hds-agent`,
   `_conflicts`).
8. **A4.2: sha256 считается каждый проход** для каждого поддерживаемого файла (кэша
   size+mtime нет). Это осознанная простота и надёжность; для тысяч файлов —
   оптимизация в A4.6 быстрым фильтром по размеру/mtime с проверкой sha при
   изменении.
9. **A4.2: смена расширения — не переименование.** Файл `a.docx` → `a.bin` даёт
   удаление образа и запись `unsupported`, хотя sha совпадает: вид артефакта
   определяется расширением (TR-7.3), а «переименование» ищется только среди
   поддерживаемых видов.
10. **A4.3: XLSX-картинки требуют Pillow.** В `venv-anonymize` его нет: карта
    `.images.json` сохраняется, а `deanonymize` возвращает предупреждение и
    оставляет метки. Портативный `sidecar/python` Pillow содержит. A4.4/A5:
    либо гарантировать Pillow в установке, либо восстановление на уровне пакета
    (zip/XML) без Pillow.
11. **A4.3: маркер текстовых образов — первой строкой.** Для md/txt нет docProps;
    маркер добавлен в `anonymize` (mode agent) и вычищается при деанонимизации.
    Если появится новый текстовый формат — правило должно распространиться и на него.
12. **A4.3: `agent_new` текстового образа.** Если агент создал `*.pdf.md`,
    он выпускается в папку проекта как есть (имя и текст деанонимизированы).
    Правило «новый файл агента — документ, а не образ» — A4.5/фаза 2.
13. **A4.3: маркер без записи реестра.** Наш маркер с неизвестным `artifact_id`
    (потеря/восстановление БД) не выпускается повторно — файл пропускается с
    записью в `problems`. Привязка по маркеру (relink) — A5.
14. **A4.3: имя выпускаемого файла не ограничено 120 символами.** Прямой путь
    режет имена образов (MAX_PATH образа), а `free_project_name` использует
    реальное имя как есть. Для очень длинных имён — обрезка с хешем и в проекте
    (A4.4/A5, вместе с UI-проверкой пути).
15. **A4.3: `orphan` вместо «лечения».** Потерянный образ больше не пересоздаётся:
    отличить потерю от удаления агентом нельзя, выбран безопасный путь (оригинал
    цел, решение за пользователем). A5: кнопка «восстановить образ» для случая
    «файл потерян, а не удалён».
16. **A4.3: маркер только у новых текстовых образов.** Образы md/txt, созданные
    до A4.3, маркера первой строкой не имеют. Пока жив реестр, это не важно
    (файл находится по `anon_rel`); но при потере БД такие образы будут
    выпущены как новые файлы агента. A4.6: команда пересоздания образов
    (или `--full`) добавит маркеры всем.

### 4.3. Настройки зеркала `agent.sync` — смысл и значения

Записано по требованию владельца (В-2): смысл настроек описан здесь и в
`config.example.yaml` (блок `agent.sync`), в `README.md` таблица переезжает в A4.6.
Ключи читает `settings::sync_settings(cfg)` в A4.2; все — необязательные, дефолты
совпадают с примером конфига; значения `0`/отрицательные игнорируются (дефолт).

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `agent.sync.interval_sec` | 5 | Период обхода в режиме демона (`hds agent sync` без `--once`). Меньше — быстрее реакция, но чаще чтение метаданных всего дерева; разовый проход — флаг `--once`. В фазе 2 опрос заменяется подпиской на изменения ФС |
| `agent.sync.wait_stable_sec` | 2 | Сколько секунд размер и mtime файла должны оставаться неизменными, чтобы считать файл «успокоившимся». Защита от анонимизации недописанного файла (копирование 80 МБ). Плата: первый проход по большой папке идёт не быстрее `wait_stable_sec` на файл — это снимает `settle_age_sec` |
| `agent.sync.wait_poll_ms` | 500 | Период опроса размера/mtime во время ожидания: меньше — точнее момент готовности и больше обращений к ФС, больше — грубее |
| `agent.sync.wait_max_sec` | 30 | Максимум ожидания одного файла. Не дождались — файл откладывается до следующего прохода, статус «ошибка» **не** ставится: пользователя не пугаем, остальные файлы не задерживаем |
| `agent.sync.settle_age_sec` | 5 | Если файл не менялся дольше этого срока, ожидание пропускается совсем. Именно это делает первый проход быстрым: старые документы обрабатываются сразу, ждём только «свежие» |

`too_big` берётся из `index.max_file_mb` (В-3), отдельного ключа для зеркала нет.

25. **A4.5: `text_lost` сравнивает множества слов.** Повторяемость не учитывается:

27. **A4.5: три извлечения текста на вариант.** Для docx/xlsx вариант вызывает

## 6. Грабли (оплачены — не наступать)

1. **`canonicalize` на Windows** даёт `\\?\C:\…`: перед передачей пути в Node/реестр
   снимать префикс (A3 §4 п.13).
2. **PowerShell 5.1**: `.ps1` — ASCII без BOM, стенды с кириллицей — UTF-8 **с BOM**;
   файлы править `[IO.File]::ReadAllText/WriteAllText` + `UTF8Encoding`. Команды в
   терминал — **без кириллицы**: PS 5.1 читает строку команды в ANSI и портит её
   (проверено на этой доработке: комментарий из here-string пришёл мохнатым; файл
   правился редактором с UTF-8).
3. **Тесты идут параллельно в одном процессе** — временные каталоги с
   `AtomicU32`-счётчиком (не только `process::id()`); CLI-тесты — `common::TempDir`
   (pid+nanos) и `ENV_LOCK` для env.
4. **`git` без `--no-pager` вешает терминал**; длинные прогоны — лог в
   `tools/parity/out/` (`*>`).
5. **`hds watch` держит `index.db`** — не удалять базу под живым watcher'ом; зеркало
   пишет только файлы workspace.
6. **Занятый файл (Word/Excel)** = `os error 32`/`PermissionDenied` — это ситуация 3
   TR-7.6, а не ошибка демона: backup не создавать, вариант оставить в `pending`.
7. **Длинные пути**: `LongPathsEnabled=0`; имена ≤ 120 символов, иначе `MAX_PATH`.
8. **Junction/симлинк**: перед проверкой вложенности — `canonicalize` (AG-11).
9. **Метки в FTS** — один токен (`xperson3x`), формы `[PERSON_3]`/`[PERSON_3|дат]`
   различаются только при деанонимизации; сравнивать префикс, а не точное равенство
   (A3 §4 п.27).
10. **`cargo` пишет в stderr** → в PowerShell это `NativeCommandError`; ориентир —
    `$LASTEXITCODE`, а не красный текст.
11. **`HDS_ROOT` — одновременно каталог состояния и корень sidecar** (`project_root()`
    возвращает его первым). Стенд с отдельным каталогом данных без junction
    `sidecar`/`models`/`hds` даёт «не найден интерпретатор/скрипт воркера» (проверено
    на e2e A4.2); обход — `HDS_ANONYMIZE_PYTHON`/`HDS_ANONYMIZE_WORKER`/
    `HDS_EXTRACT_PYTHON`/`HDS_EXTRACT_WORKER` или junction'ы.
12. **Env стенда живёт в сессии PowerShell** (терминал Cline сохраняется между
    вызовами): `$env:HDS_ROOT` от e2e уронил `host_resident`
    (`server — системный каталог состояния`). Перед `cargo test` снимать
    `HDS_ROOT`/`HDS_CONFIG`/`HDS_*_PYTHON`.
13. **`*>` в PowerShell пишет UTF-16LE**: `Get-Content` без `-Encoding Unicode` даёт
    «мохнатый» текст; для чтения логов — `-Encoding Unicode` или перекодировать.
14. **mock-воркер должен чтить `out_path`**: иначе тест не проверит анонимное имя
    (в A4.2 `text_image` мока исправлен — пишет в `params["out_path"]`).
15. **Текстовый образ без маркера = «новый файл агента».** У md/txt нет docProps,
    поэтому маркер пишется первой строкой; забыть его — значит на первом же
    обратном проходе получить копии всех md-образов в папке проекта
    (поймано на стенде A4.2→A4.3). Проверять: первый проход после регенерации
    стенда должен дать `emitted 0`.
16. **`walk_files` падает, если каталога нет.** Обратный проход обязан проверить
    `workspace.is_dir()`: иначе `hds agent sync` на новом проекте возвращает 1
    (A4.1-тест «пустая папка» это поймал).
17. **Вставка тестов в конец модуля:** `insert_line` легко попадает внутрь
    последнего теста (Rust разрешает `#[test]` во вложенном блоке, но он не
    запускается) — после вставки проверять `cargo fmt --check` и число тестов,
    а не только «ok». Такое уже случалось дважды (A4.2, A4.3).

18. **Занятый файл в тесте — только `share_mode(0x1)`.** `File::open` Rust
    открывает с `FILE_SHARE_DELETE`, поэтому замена проходит и «занятости» не
    видно. Офисный редактор делится только чтением (`FILE_SHARE_READ`), и тогда
    `rename` даёт `os error 32` → `PermissionDenied`. Так и проверяется A4.4
    (`accept_on_busy_file_keeps_everything_as_is`).
19. **`accepted` надо добавить во все наборы статусов сразу.** Прямой путь
    (`is_forward_managed`), обратный (`make_variant`), `has_image`/`remove_missing`:
    пропустишь любой — принятый документ перестанет зеркалиться, а новые правки
    агента не дадут варианта.
20. **`set_issued` не обновляет основание.** Там, где образ пересоздан из
    **другого** оригинала (решения A4.4), нужен `set_baseline`; иначе следующий
    проход вечно «обновляет» образ и «0 изменений» ломается.
21. **Mock-воркер в режиме `agent` метит только «Иванов Иван»/«Иванову Ивану».**
    В CLI-тестах проверять метки можно только на них; другие имена остаются в
    образе как есть (в A4.4 это давало ложные ожидания `[PERSON_2]`).
22. **Кириллица в командной строке PowerShell 5.1 портится** (грабля 2): пути
    стенда брать из `Get-ChildItem` в переменные, а не печатать литералами; логи
    читать с `-Encoding Unicode` (`Tee-Object` пишет UTF-16).
23. **Вставка кода в конец файла — проверять структуру.** `insert_line` +
    маркер-заглушка удобны, но легко получить дубль заголовка теста или
    незакрытую скобку модуля: после каждой пачки — `cargo fmt --check` и число
    тестов (A4.4 поймал `unclosed delimiter`).
24. **Две стороны документа не путать.** В `pending` лежит вариант со
    **значениями**, в `workspace` — образ с **метками**. Метки проверяются по
    образу и снимку; «доля пропавшего текста» — вариант против **основания**
    (`base`). Сравнение образ ↔ основание даёт ложные «потери» на каждой метке.
25. **`[IMAGE_n]` в образе — норма, а не «непомещённая картинка».** Так в образе
    стоит место картинки (В-4). Проверять надо **вариант**: если метка осталась
    в варианте — картинка не восстановлена (или её не было: «нет в карте»).
26. **`serde_json` и `f64`: разбор не гарантирует тот же бит.** `ts` расходился
    на 1 ULP (`…6035585` → `…6035583`), тест падал примерно раз на прогон
    workspace. Сравнивать `ts` с допуском, остальные поля — точно.
27. **Отчёт удалять до `prune_under`.** Иначе каталог, в котором остался один
    `report.json`, не пуст: не удаляется, и `pending` копит пустые папки
    (A4.5 `cleanup_decision`).
28. **Mock-воркер `vault_snapshot` — часть тестов фильтра.** Добавление «лишней»
    метки (`[PERSON_2]`) в мок ломает `refresh::snapshot_is_refreshed_by_vault_rev`
    («до выдачи метки значения нет»): проверено, откатили. Для CLI-тестов
    валидатора хватает `[PERSON_1]`, которой мок метит «Иванов Иван».
