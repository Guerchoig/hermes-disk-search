# RELEASE_NOTES v0.15.0 - автотранскрибация работает end-to-end

> Первый релиз, в котором конвейер «медиафайл во входной папке → готовый транскрипт
> со спикерами» проходит целиком: декодирование контейнеров (mp4/...) мостом движка,
> whisper на GPU, диаризация sortformer, выход в out_dir.

## Что скачивать

| Файл | Нужен? | Что это |
|---|---|---|
| hds-0.15.0-windows-x64.zip (+ .sha256.txt) | **Да, обязательно** | программа: bin\ (Rust), установщик, скилл, манифесты, sidecar-воркер |
| hds-engine-runtime-windows-x64-cuda.zip | Только для **офлайн-установки** | рантайм движка (LLM-хост + ASR); обычный установщик качает его сам по манифесту |
| hds-0.15.0-macos-arm64.zip (+ .sha256.txt) | Только для macOS (best-effort) | то же для macOS; прикладывается, если сборка прошла |
| hds-engine-runtime-macos-arm64-metal.zip | Только для macOS офлайн | рантайм движка для macOS |
| hermes-disk-search-0.15.0-windows.zip / -macos.zip | Нет | архивы исходников (для разработчиков) |

Модели (LLM/whisper/диаризация/CLIP ONNX) и Python-sidecar в архив **не входят** —
установщик скачивает их сам при установке. Патч движка (engine-patch-v2) применяется
установщиком автоматически; отдельно его качать не нужно.

## Новое

### Автотранскрибация медиафайлов работает целиком (инцидент 04.10.2026 закрыт)

* **Мост движка с FFmpeg** — тег engine-patch-v2: пересобран llama-server-bridge.dll
  с LLAMA_SERVER_BRIDGE_ENABLE_FFMPEG=ON. Прежний мост отвечал 501 not_implemented
  на любой не-.wav файл — .mp4 не транскрибировался вовсе, задание крутилось в ретраях.
  Детали и sha256 — engine-patch/README.md (итерация 3).
* **Исправлен выбор устройства транскрибации**: конфиг gpu.device_index (семантика
  «1 = первый GPU») уходил в /internal/transcribe как есть, а хост трактует его как
  bridge-индекс (0 = CUDA0, 1 = CPU). Итог: whisper считал на **CPU**, диаризация
  падала «failed to initialize backend: CUDA1». Теперь индекс маппится так же, как
  для ролей (crates/hds-index/src/transcribe.rs).
* **Сервисные файлы переехали из out_dir**: .orig.md (текст до подстановки имён),
  .speakers.json (карта спикеров) и .bak (копия перед правкой имён) теперь пишутся
  в auto_transcribe.state_dir (по умолчанию data/auto-transcribe) — в выходной
  папке остаётся **только транскрипт**. Sidecar'ы старых прогонов UI по-прежнему
  читает рядом с файлом (совместимость).

### UI: сворачиваемое дерево индекса

* Секция «Дерево индекса» рендерится на details/summary: клик по папке
  сворачивает/разворачивает поддерево, корни раскрыты по умолчанию; кнопки
  «Развернуть всё» / «Свернуть всё»; при усечении (>60 детей) показывается
  «... ещё N папок», а не молчаливое пропадание.

### Процесс релиза

* RELEASING.md: правило «в заметках релиза — таблица, что скачивать руками,
  а что установщик качает сам» (этот файл следует новому правилу).

## Исправления

* .mp4/контейнеры больше не дают 501 not_implemented на транскрибации.
* Диаризация больше не падает с «failed to initialize backend: CUDA1».
* Whisper больше не «тихо» уходит на CPU при gpu.device_index: 1.

## Требования к обновлению

* **Свежая установка** — ничего особенного: установщик применит патч engine-patch-v2
  и скачает модели сам.
* **Обновление с v0.14.x**: запустите из распакованного архива
  installers\fetch_engine_runtime.ps1 -PatchEngine (подтянет мост с FFmpeg) и
  перезапустите резидент llm_host (старый процесс держит прежнюю DLL). Переиндексация
  не требуется. Если в out_dir остались .orig.md/.speakers.json от старых
  прогонов — можно перенести в data\auto-transcribe\ или оставить: UI читает их
  на прежнем месте.
