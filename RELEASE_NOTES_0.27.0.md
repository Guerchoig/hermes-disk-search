**Фаза A6** переводит зону агента из «работает» в «обслуживается»: зеркало
запускается само при входе в систему, состояние проверяется одной командой, настройки
перечитываются без перезапуска, версию документа можно вернуть, образ — пересобрать,
проект — удалить. Журнал решений фиксирует все операции, не содержа ни текста
документов, ни значений из базы меток.

## Что нового

### Автозапуск (A6.2)

1. **`hds agent sync --all`** — один процесс на все проекты `data\agent\projects.json`:
   у каждого свой `sync.lock`, журнал, реестр и воркеры; недоступная папка проекта
   пропускается со строкой `problem`, остальные обрабатываются; повторный запуск при
   живом демоне — «уже запущен» и код 0, поэтому задача и ручной запуск не конфликтуют.
2. **`installers\install_agent_sync_task.ps1`** — задача Планировщика
   `HermesDiskSearchAgentSync` на вход в систему (`-TaskName`, `-Start`, `-Status`,
   `-Remove`, `-StartupFolder`). Если Планировщик недоступен — ярлык в «Автозагрузке»
   через `hidden_launch.vbs`; задача и ярлык взаимно исключаются, `-Remove` снимает
   и то, и другое.

### Диагностика (A6.1)

3. **`hds check`** печатает пункты `agent-*` (12): зона, Node, `dist\worker.mjs`,
   python воркера анонимизации, `anonymize.db` (схема v2), `projects.json` и папки
   проектов, ключ провайдера — **«задан/нет»**, plain-токен `disk-search`, маршрут
   `/mcp/agent/<P>` (health/401/200 — только если порт слушает), индекс зоны, демон
   зеркала (`sync.lock` + хвост `sync.log`), очередь решений.
4. **`hds agent check [--project P] [--json]`** — тот же набор по одному проекту;
   коды 0/1, `--json` — одна строка; при `agent.enabled: false` — одна строка `[--]`.

### Горячее перечитывание конфига (A6.3)

5. Демон сверяет `config.yaml` (mtime + размер) между проходами: `agent.sync.*` и
   `index.max_file_mb` применяются без перезапуска (строка `config reload …`
   в `sync.log`), `agent.enabled: false` останавливает демон с причиной `disabled`.
6. Смена `agent.root` на живой сессии **не применяется**: предупреждение `[!]` и
   строка `config root ignored new=… keep=…`; недописанный файл — строка `error`,
   демон остаётся на прежних настройках.

### Откат, журнал решений, relink (A6.4)

7. **`hds agent result restore --project <P> --path <отн. путь> [--stamp <штамп>]`** —
   «Вернуть» выбранную копию из `.hds-agent\backup\<штамп>`; оригинал заменяется,
   образ пересобирается, в отчёте штамп и sha256; копии не тратятся.
8. **`rebuild`** для `orphan` (образ удалён или оригинал заменён агентом) и
   **`relink`** по маркеру `hds-agent/<P>/<id>` — **только по команде/кнопке**,
   в проходе зеркала не выполняется.
9. **`.hds-agent\decisions.jsonl`** — журнал решений и операций (JSONL, ротация при
   1 МБ, `hds agent history clear` его не трогает); в панели — «Копии…», «Вернуть»,
   «Пересоздать образ», «Показать в Проводнике» (без запуска приложений).

### Удаление проекта (A6.5)

10. **`hds agent project rm <P> [--yes] [--force] [--purge-meta]`** и кнопка
    «Удалить…»: удаляются каталог зоны `<P>\`, реестр `<P>.db`, запись
    `projects.json` и `/projects/<P>` в `secrets.json`. Папка проекта, ключи
    провайдеров, `mcp`, индекс и `index.stop` не трогаются; метки проекта остаются,
    если не указан `--purge-meta`.
11. Живой демон — **отказ** с кодом 1 и подсказкой `hds stop` (принудительно —
    `--force`); повторный `rm` — код 2; в занятый файл команда не ломится.

### Эксплуатационные исправления (A6.6)

12. **AG-23** — атомарность «Принять»: при сбое пересборки образа решение
    откатывается, в журнал пишется `decision_failed`.
13. **AG-25** — `ArtifactRegistry` кэшируется в `AgentApi` и сбрасывается перед
    `project rm` (иначе панель показывала удалённый проект).
14. **AG-26** — относительные имена образов в ленте превращаются в пути оригиналов.
15. **AG-32** — в `state_json` появился блок `history: {session, uncleaned, hint}`:
    если история сессии не очищена, панель предупреждает (значения в
    `agent-state\.cline` до очистки — норма, В-A6-10).

### Замер RAG и значение по умолчанию (A6.8, K1)

16. **Сравнение «с `disk-search` / без него»** на стенде (20 вопросов аналитика и РП,
    по 2 прогона, одна облачная модель `~deepseek/deepseek-flash-latest`):
    с поиском полнота ответа **1,775 из 2** (87,5 % прогонов — «найдены все источники»;
    вопросы «по смыслу» — **2,0 из 2**), без поиска — **0,325** («по смыслу» — 0,333),
    23 хода из 40 упираются в `--max-iterations`. Включённый поиск стоит **+43,7 %
    токенов** (130,9 тыс. против 91,1 тыс. на ход) и даёт ход на 13 с быстрее
    (47,0 с против 60,7 с). Качество самого поиска: `recall@1` 0,75, `recall@5/10/30`
    1,0, MRR 0,863. Методика, числа, ограничения — `tools/parity/AGENT_RAG_K1.md`.
17. **`agent.mcp.disk_search.enabled` по умолчанию — `false`** (решение владельца по
    итогам K1: экономии токенов нет, а стоимость хода выше). Включается явно
    `agent.mcp.disk_search.enabled: true` + `hds agent token <P>` + `hds mcp-http start`;
    без него агент ищет `search_codebase` и читает файлы. Предупреждение `agent-token`
    при выключенном поиске ожидаемо (README §20, §21.3, §21.7).

  mtime пустого `index.stop`, поэтому демон, запущенный после предыдущей остановки,
