## 2. Что сделано по под-этапам

### A5.1 — каркас вкладки и API состояния

* `hds-ui` зависит от `hds-agent`; ленивые фабрики воркеров переехали в
  `hds_agent::factory` (одно место поднятия Python для CLI, демона и вкладки).
* `agent::gate` (в server-профиле 403, D20), `projects_json`,
  `project_add_json` (id `P`+4 цифры, папка внутри `agent.root` запрещена),
  `state_json` (демон по `sync.lock` + `lock_is_stale`, хвост `sync.log`),
  `files_json` (строки реестра: оригинал, образ, вид, статус).
* «Проекты», «Новый проект», «Состояние проекта», «Файлы проекта» во вкладке;
  тесты — `agent::` (unit) и сокет `tests/agent_panel.rs`; стенд — `A51_E2E.md`.

### A5.2 — реплика

* `hds_agent::run`: `RunOptions/RunPlan/TurnReport`, `plan_with`, `prepare`,
  `build_filter`, `open_client_at`; CLI `agent_run` — тонкая обёртка (одна
  реализация плана хода на CLI и вкладку).
* `agent_session::AgentApi/Turn`: `preview` (NER **и** словарный фильтр — иначе
  «Иванову» уезжало открытым), `label`, `keep`, `attach` (файл проекта → путь
  образа, внешний → `workspace\_attachments`), `message` (plan → prepare →
  шлюз → `send_anonymized`), `abort`, `stop`; один активный ход на проект (409).
* Кольцо 500 событий; лимит реплики 20 000 символов; «Не скрывать» пишет в
  общий `keep_terms` (D19, «действует во всех проектах»).

### A5.3 — лента SSE и вопрос агента

* SSE-ветка в `run_http_listener` (без `Content-Length`, `retry: 1500`,
  `: ping` раз в 15 с, закрытие через 5 минут), JSON-фолбэк `?after=` для
  тестов, `curl.exe` и страниц без `EventSource`.
* Деанонимизация события целиком: `text` — значения, `raw` — «как видит
  модель»; пути `workspace` → папки проекта (оба разделителя).
* `ask_user`: `AskState` + `UiAskUser`, `POST /api/agent/answer` (400/404/409),
  таймаут `agent.ask_timeout_sec` = 600 с; по таймауту модели возвращается
  отказ, ход продолжается; «Стоп» снимает вопрос **до** команды воркеру.

### A5.4 — «Результаты» и решения

* `Mirror::compare`: метаданные обеих сторон, отчёт валидатора, построчный
  diff (≤ 200 строк / 2 000 символов); `GET /api/agent/pending|compare`,
  `POST /api/agent/decision` поверх `hds_agent::results` — UI не меняет
  оригиналы сам.
* «Принять» = backup → атомарная замена → пересоздание образа; «Отклонить»
  возвращает образ к оригиналу и уведомляет агента; три исхода конфликта;
  «файл занят» — 409 без потерь, вариант и статус остаются.
* Панель «Результаты»: вариант, вердикт валидатора, «Сравнить…», «Принять»,
  «Отклонить», «Открыть» (путь + буфер обмена, без запуска процессов).

### A5.5 — «Метки проекта»

* RPC `vault_project_labels` (метки, формы, псевдонимы, `occurrences`, журнал
  склеек, `keep`), `POST /api/agent/labels/merge|unmerge`.
* `merge_log` + `unmerge_entities` — аддитивно, без повышения
  `SCHEMA_VERSION` (иначе D4 переименовал бы базу и потерял метки); после
  склейки образы пересобираются по старшей метке, агенту уходит
  `labels_merged` в `messages.jsonl`, в ленту — `notice` без значений.
* «Не скрывать» у формы — глобальный `keep_terms`; точный счётчик вхождений —
  фаза 2.

### A5.6 — «Настройки агента», уведомления фильтра, «Очистить историю»

* `GET/POST /api/agent/settings`: провайдер и модель — `projects.json`;
  ключ — только `secrets.json` (слияние, значение не отдаётся ни в каком
  виде); пороги, фильтр и MCP — секция `agent:` в `config.yaml` (построчный
  редактор, комментарии целы, итог проверяется по каждому пути).
* `take_redactions()` → блок «Уведомления фильтра» (число, метки, источник,
  **без значений**), «Сбросить сводку».
* `POST /api/agent/history/clear`: стоп → выгрузка шлюза → `run::clear_history`
  (тот же путь, что CLI) → отчёт `{session, files, backups, replaced}`.

### A5.7 — живой сценарий, инварианты, отчёт

* Сценарий `a57_e2e.ps1`: 76/76 проверок (`A57_E2E.md`), артефакты `a57-*`;
  mock-провайдер `a57_mock.mjs` берёт имя MCP-инструмента **из `tools`
  запроса**; пробник `a57_probe.py` ищет формы целыми словами (семантика
  фильтра), хеширует оригиналы и `%USERPROFILE%\.cline`.
* Живой прогон нашёл дефект: на **CRLF**-`config.yaml` панель настроек
  дописывала вторую секцию `agent:` и отдавала 500 (`duplicate entry with key
  "agent"`). Исправлено в `config_edit::apply_scalars` (снос `\r` при чтении,
  сохранение стиля переводов строк) + тест
  `agent_scalars_keep_crlf_and_single_section`.
* Инварианты: I2/I3/I4/I6/I8 — чисто; I1 — 22 попадания в 12 образах стенда
  (пропуски NER + метки-общие-слова), облако защищает фильтр (см. §4).


## 3. Контракты фазы (сводка §5 журнала)

| Контракт | Правило |
|---|---|
| **Маршруты `/api/agent/*`** | loopback/CSRF-гейт как у остальных POST (`X-HDS-UI`, `Content-Type: application/json`); в `is_user_route` не входят; в server-профиле 403 (D20) |
| **Значения в HTTP** | вкладка — зона пользователя: лента, предпросмотр, вопрос агента показывают значения; «как видит модель» — метки; журналы, `sync.log`, `messages.jsonl` — без значений (I8) |
| **Секреты** | только `data\agent\secrets.json` через `hds_agent::secrets` (слияние); в `config.yaml` — никогда; в ответах API — «задан/нет» |
| **Решения** | только `hds_agent::results`; UI не заменяет оригиналы сам; «файл занят» — `ResultsError::Busy` → 409 |
| **Статусы файлов** | только `registry_db` (`list`, `list_pending`, `by_orig`); UI не вычисляет статус по наличию файла |
| **Воркер** | только через `Gateway` (процесс, `hello`, `send`, `next_event`, `abort`, `stop`); один активный ход на проект |
| **Деанонимизация** | только `hds_agent::deanon`; своих регулярок меток в UI нет |
| **Метки** | разбор — `hds_core::labels`; падеж — `gram_to_suffix`; в именах файлов суффикса нет |
| **Проекты** | `projects.json` — единственный список; `path` — абсолютная папка пользователя; `id` = `P` + 4 цифры (D21) |
| **Процессы ОС** | UI не запускает процессы и не открывает файлы (В-A5-7); максимум путь в буфер |
| **Фильтр** | снимок по `vault_rev` перед каждым запросом; fail-closed `privacy_filter_unavailable`; срабатывания — `take_redactions()` в ленту |
| **История** | `hds_agent::history`; «Очистить историю» = `Gateway::clear_history`-путь (`run::clear_history`), не правка файлов вручную |
| **Фасад вкладки** | `AgentApi` (сессии, кольцо, вопрос) живёт в `hds ui`; перезапуск UI теряет живую сессию, история возобновляется по `session_id` |
