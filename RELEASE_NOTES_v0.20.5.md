## Что нового и что исправлено

* **Команда снятия авто-перезапуска служб теперь рабочая.** В руководстве (глава 5, раздел «Если
  сервер уже установлен и работает», и глава 7, «Ловушка: остановленная служба поднимается снова»)
  была приведена запись вида `sc.exe failure <имя> reset= 0 actions= ""` прямо в PowerShell. Такая
  запись **не работает**: PowerShell не передаёт сторонней программе пустой аргумент, поэтому
  `actions=` доходит до `sc.exe` без значения, и он отвечает «Недопустимый параметр / Invalid
  Option». Теперь в документе:
  * рабочий вариант для одной службы — через `cmd /c`:
    `cmd /c 'sc.exe failure hermes-disk-search-watch reset= 0 actions= ""'`;
  * рабочий вариант для списка ролей — шаблон команды в переменной и вызов `cmd /c` в цикле
    (для `ui`, `mcp-http`, `watch`, `transcribe`, `llm-host`);
  * объяснение причины — чтобы читатель понимал, почему нельзя «упростить» обратно.
* **Добавлены команды возврата после работ:** автоматический перезапуск —
  `sc.exe failure "hermes-disk-search-ui" reset= 86400 "actions= restart/5000/restart/5000/restart/30000"`
  (эта запись с непустыми аргументами работает и напрямую; то же делает `hds service install <роль>`),
  автоматический запуск — `sc.exe config <имя> start= auto`.
* **Уточнена формулировка про «ловушку»:** автоматический перезапуск срабатывает, если служба
  завершилась с ошибкой, а не при обычной остановке.
* **Тест-предохранитель:** статическая проверка `docs_wrap_the_empty_sc_failure_arg_in_cmd`
  (`crates/hds-cli/tests/install_server_parity.rs`) требует, чтобы любая такая команда в
  `README_SERVER_MULTIUSER.md` шла через `cmd /c` — нерабочая форма больше не вернётся в документ
  незамеченной.

## Требования к обновлению

* Поведение программы не менялось: обновление как обычно (`update.cmd` от администратора на
  Windows, `sudo bash installers/update.command` на macOS), переиндексация не нужна.
* Заметки и руководство версии 0.20.4 (в том числе уже опубликованные) содержат старую форму
  команды — пользуйтесь формой из 0.20.5; сами теги и релизы не переписываются.
* Видимое отличие — `version.txt` и ответ `/health` сообщают `0.20.5`.

## Проверено перед выпуском

* Ошибка воспроизведена живьём на Windows: `sc.exe failure <несуществующая служба> reset= 0 actions= ""`
  напрямую в PowerShell → `Invalid Option`; через `cmd /c` (одной строкой и из шаблона в цикле) →
  ответ `1060` (значит аргументы приняты, до проверки службы дело доходит).
* `cargo fmt --all -- --check`, `cargo clippy --workspace --all-targets -- -D warnings`,
  `cargo test --workspace` — зелёные локально и в CI.
* Изменений в коде, влияющих на работу программы, нет — только руководство и статический тест.
