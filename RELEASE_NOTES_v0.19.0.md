# RELEASE_NOTES v0.19.0 — логистика тонкого клиента: скачать скрипт, получить токен, запустить

> Релиз-фича: **установка клиента без GitHub и без ручного переноса файлов**. Админ выдаёт
> токен, пользователь скачивает **скрипт-установщик из общедоступного места** (для
> скачивания токен не нужен) и запускает его с токеном — скрипт сам забирает пакет
> **с сервера** под платформу клиента, распаковывает и подключает Cline. Заодно закрыто
> требование W7 («версия клиента согласуется с сервером»). Rust-проверки зелёные:
> `cargo fmt --check`, `clippy -D warnings`, `cargo test --workspace` (90 наборов, 0 падений).

## Установка клиента: три шага

```powershell
# 1) НА СЕРВЕРЕ (админ): токен для клиента
hds user add --login laptop --password "<пароль>" [--projects "D:\"]
hds token new --user laptop --ttl-days 90        # plain-токен показывается один раз → отдать пользователю

# 2) НА КЛИЕНТЕ — скачать скрипт-установщик из общедоступного места (токен НЕ нужен):
curl.exe -f https://host/mcp/client-install.ps1 -o client-install.ps1      # или ассетом релиза
# macOS:  curl -f https://host/mcp/client-install.sh -o client-install.sh

# 3) запустить с токеном (права администратора не нужны)
powershell -ExecutionPolicy Bypass -File .\client-install.ps1 -Token <ТОКЕН> -ServerUrl https://host
# macOS:  bash client-install.sh --token <ТОКЕН> --server-url https://host
```

Скрипт: скачает пакет с сервера (под платформу клиента), распакует, снимет «скачано из
интернета»/карантин, проверит `GET /health`, сверит версии, запишет MCP-сервер `disk-search`
(+ правило и скилл) и попросит перезапустить Cline. Вручную то же самое описано в README,
раздел «Клиент (ноутбук)».

## Что нового

* **Скрипты-установщики** `client-install.ps1` / `client-install.sh` — один файл, токен
  аргументом. Сервер отдаёт их **публично** (без токена) по `<mcp-path>/client-install.ps1|sh`;
  те же файлы — ассеты релиза.
* **Раздача клиента с сервера**: `GET <mcp-path>/client-package.zip` за тем же Bearer-гейтом,
  что `/mcp`, внутри опубликованного `/mcp`-префикса (через reverse-proxy работает как есть).
* **Обе платформы в поставке**: в `client/` лежат оба пакета (windows-x64 и macos-arm64);
  сервер выбирает нужный по `?platform=…` → `User-Agent` → платформа сервера, отвечает
  заголовками `X-Client-Package`/`X-Client-Platform`. На релизе оба пакета докладываются в
  оба серверных архива (их `sha256` пересчитывается).
* **Версия продукта**: упаковщики пишут `version.txt`, `/health` отдаёт `version`, мастер
  клиента сверяет версию клиента и сервера и предупреждает при расхождении — закрыто
  требование W7 (`PLAN_SERVER_MULTIUSER.md`).
* **Правила выпуска и CI**: клиентские ассеты (пакеты + скрипты) обязательны для Windows,
  в `release.yml` появился шаг кросс-вложения пакетов; `RELEASING.md` описывает оба канала.

## Требования к обновлению

* Штатное обновление поверх 0.18.x: распаковать архив и запустить `setup.cmd`/`setup.ps1`
  (или `installers\update.ps1`). Переиндексация не требуется.
* Серверу для раздачи клиента нужен **новый** архив: в нём появляется `client\` (оба пакета
  и скрипты) и `version.txt`; раздача работает только у сервера версии 0.19.0+.
* Токены и `data/access.yaml` совместимы: уже выданные токены продолжают работать
  (`hds token new` при необходимости выдаст новые).
