# Hermes Disk Search — сервер для нескольких пользователей: общий поиск, расшифровка видео/аудио и другие службы

Этот документ — про **общий сервер**: одна машина хранит базу поиска и выполняет долгую работу,
а несколько пользователей пользуются результатом со своих компьютеров. Кроме поиска по файлам сервер
может расшифровывать видео/аудио и выполнять другие продолжительные работы: наполнение базы,
слежение за изменениями файлов.

Документ рассчитан на двух читателей:

* **администратора сервера** — он всё устанавливает, заводит пользователей и следит за работой;
* **пользователя, который подключает свой компьютер** — ему нужны две главы: «Подключение
  клиентского ПК» и «Кабинет пользователя». Готовая памятка пользователя лежит рядом с этим
  документом — `installers/client_readme.md` (в клиентском архиве она же лежит как `README.md`);
  при желании администратор может изложить памятку своими словами — всё нужное для этого уже
  собрано в этих двух главах и в главе «Что пользователь делает каждый день».

Про установку программы на **один** компьютер (когда сервер не нужен) читайте второй документ —
`README.md`; он лежит рядом с этим файлом.

## 1. Что это и для кого

Обычная (одиночная) установка подходит, когда программой пользуется один пользователь на одном
компьютере. Серверная установка нужна, когда:

* файлы лежат на дисках одной машины, а работать с ними должны несколько пользователей;
* пользователям нужен доступ к поиску со своих компьютеров по сети;
* разные пользователи должны видеть **разные** файлы: кому-то — папку с договорами, кому-то — архив
  отдела, кому-то — всё;
* нужно, чтобы поиск, наполнение базы и расшифровка видео/аудио работали без участия пользователя,
  пока сервер включён.

Что даёт серверная установка:

* **разграничение доступа по папкам-проектам**: каждый пользователь видит только выданные ему папки;
* **единая база** — наполняется один раз и служит всем, место и вычислительная работа не
  дублируются;
* **постоянные службы** — поиск, слежение за файлами, служба моделей и расшифровка видео/аудио
  поднимаются при включении машины без входа пользователя;
* **выдача доступа** — логин и пароль, а также ключи доступа с ограниченным сроком действия;
* **журнал действий** — видно, кто входил, кто какими инструментами пользовался и что делал
  администратор;
* **соблюдение времени ответа** — при нескольких одновременных запросах запросы встают в очередь,
  а не обрываются.

## 2. Как всё устроено

```
   ПК пользователей ──► [ промежуточная программа с шифрованием ]
   (ИИ-ассистент Cline,         │  (единственное, что видно из сети:
    Hermes Desktop,             │   адрес сервера + ключ доступа)
    браузер)                    ▼
                        ┌────────────────────────── сервер ─────────────────────────┐
                        │ подключение ассистентов      :8787   путь /mcp             │
                        │ страница управления          :8765   (админ и кабинет)     │
                        │ служба моделей               :8010 ответы, :8011 смысловые │
                        │                              отпечатки, :8012 переранжир. │
                        │ служба слежения за файлами   (без адреса)                 │
                        │ служба расшифровки видео/аудио   (без адреса)             │
                        │ база поиска index.db                                        │
                        └───────────────────────────────────────────────────────────┘
```

| Компонент | Где работает | Видна ли из сети | Кому служит |
|---|---|---|---|
| Промежуточная программа с шифрованием (прокси) | на сервере или рядом с ним | да, только она | всем пользователям: принимает подключения и передаёт их серверу |
| Подключение ассистентов | сервер, адрес `8787`, путь `/mcp` | через прокси | ассистентам пользователей (Cline, Hermes) |
| Страница управления | сервер, адрес `8765` | через прокси | администратору; кабинет — пользователям |
| Служба моделей | сервер, адреса `8010`–`8012` | **нет, никогда** | остальным компонентам сервера |
| Служба слежения за файлами | сервер, без адреса | нет | наполнению базы |
| Служба расшифровки видео/аудио | сервер, без адреса | нет | расшифровке видео/аудио |
| База поиска | файл на диске сервера | нет | поиску и ответам всех пользователей |

Все перечисленные компоненты — общие для сервера: их не заводят отдельно на каждого пользователя, и
настраивать их «под пользователя» не нужно. Различаются пользователи учётной записью (логин и
пароль, а также выданный ключ доступа) и набором доступных им папок-проектов — именно это и
определяет, что они видят. Таблица выше нужна, чтобы понять, какой компонент где работает, что
видно из сети и кому он служит.

## 3. Роли и права

| Роль | Что может |
|---|---|
| **Администратор** | видит все файлы; заводит пользователей и выдаёт ключи доступа; запускает и останавливает наполнение базы; управляет службами; открывает страницу управления |
| **Пользователь** | ищет и получает ответы только по выданным ему папкам-проектам; может открыть свой кабинет: поиск, установка клиента, просмотр расшифровок и присвоение имён говорящим |
| **Одиночная установка** (когда общий доступ выключен) | как раньше: без входа и без ограничений по папкам — обычный режим для одного пользователя |

Полезно знать два правила «наоборот»:

* у обычного пользователя **пустой список папок-проектов означает, что он не видит ничего** —
  это защита «по умолчанию запрещено»;
* у администратора пустой список означает «видит всё».

Папка-проект — это единица разграничения доступа. Каждый файл при наполнении базы приписывается
к одному проекту: к тому, чей путь в настройках длиннее всего совпал. Например, при папках
`E:\Archive` и `D:\Work\Sales` файл `D:\Work\Sales\план.xlsx` попадает в проект продаж.

| Ситуация | Что ответит сервер |
|---|---|
| Ключ доступа не передан, просрочен или отозван | «нет доступа» с подсказкой, где получить ключ |
| Ключ передан, но он не администраторский, а действие — администраторское | «недостаточно прав»: отказ выдаётся **до** выполнения действия и записывается в журнал |
| Пользователь без выданных папок что-то ищет | обычное «ничего не найдено»: никакой утечки через текст сообщений нет |
| Общий доступ выключен | ничего из перечисленного не применяется: это одиночный режим |

Подробности про кабинет пользователя и вход в него — глава «Кабинет пользователя»; про журнал
действий — глава «Пользователи, доступ и ключи доступа».

## 4. Что решить до установки

Пройдитесь по списку заранее: после установки менять это можно, но лучше определиться сразу.

1. **Где будет стоять программа.** Обычное место — машинная папка, а не папка пользователя:
   например `C:\Program Files\hermes-disk-search`. Установка в профиль пользователя (`C:\Users\…`)
   опасна: сервер поднимается до входа пользователя, а очистка профиля его сломает. Перенести
   готовую установку можно позже (глава «Рецепты администратора»).
2. **Где будут храниться настройки, база и журналы** — служебная папка сервера:
   `%ProgramData%\hermes-disk-search` на Windows и
   `/Library/Application Support/hermes-disk-search` на Mac. Здесь лежат файл настроек
   `config.yaml`, база `index.db`, файл доступа `data\access.yaml`, записи о работе служб и
   журналы. Папку можно задать другую, но не стоит размещать её в профиле пользователя.
3. **Куда ставить модели и набор движка.** При серверной установке с `-Fetch`/`--fetch` они
   кладутся в служебную папку сервера: `%ProgramData%\hermes-disk-search\models` — распознавание
   речи и разделение по говорящим нового Python-стека (`gigaam`, `hf-home`,
   `gigaam-onnx`), плюс модели для отката (`whisper`, `nemotron3`); `...\engine`
   (набор файлов движка), `...\llama-runtime`
   (чат, смысловые отпечатки, переранжирование); модели поиска по картинкам — в
   `<папка установки>\models\clip_onnx`. Окружение расшифровки (venv, 1,5–7,4 ГБ) ставится
   в `<папка установки>\app\current\sidecar`. Пути закрепляются за службами переменными
   `HDS_MODELS_DIR`, `HDS_ENGINE_DIR`, `LLAMA_RUNTIME_DIR`; уже заданные машинные значения
   установщик не перезаписывает. На Mac — те же подкаталоги внутри `/Library/Application
   Support/hermes-disk-search`. Для **первой** загрузки gated-моделей pyannote нужен токен
   Hugging Face: `-HfToken <токен>` (или `HF_TOKEN`); в работе он не нужен.
4. **Какие папки станут проектами** и кто к ним получит доступ. Пример записи в настройках:
   ```yaml
   index:
     roots:
       - "E:\Archive"                                  # проект по имени младшей папки: Archive
       - { path: "D:\Work\Sales", project: "Sales" }    # явное имя проекта
       - { path: "F:\Reports",    project: "Sales" }    # тот же проект, другая папка
       - "D:\"                                          # весь диск; имя проекта — D:
   ```
5. **Кто будет администратором** и с каким паролем: логин администратора создаётся при установке.
6. **Сколько пользователей будет работать одновременно.** От этого зависит число одновременных
   обращений к ИИ-модели и пределы частоты (глава «Одновременная работа и время ответа»).
7. **Будет ли защищённое подключение из сети.** Если пользователи подключаются не только с самого
   сервера, нужен сертификат и промежуточная программа с шифрованием (глава «Защита сети»).
8. **Сколько на сервере видеокарт** и будут ли ответы давать местные ИИ-модели или облачная
   ИИ-модель. Несколько видеокарт одного производителя раскладываются по частям системы (глава
   «Одновременная работа и время ответа»).
9. **Нужна ли расшифровка видео/аудио** — тогда заранее определите папки «входящие»
   и «исходящие» (глава «Расшифровка видео/аудио»). Профиль расшифровки выбирается по видеокарте:
   NVIDIA → `cuda`, нет карты или **встроенная** AMD/Intel → `cpu`, дискретная AMD/Intel → `dml`.
   Профиль `dml` на дискретной AMD/Intel пока **экспериментальный** (живой приёмки нет); на
   встроенной графике он медленнее процессора. Принудительно: `-TranscribeProfile cuda|cpu|dml`;
   отказ от стека — `-SkipTranscribeStack`, только код без моделей — `-SkipTranscribeModels`.

## 5. Установка сервера на Windows

### Шаг 0. Что понадобится

Windows 10 или Windows 11, 64-битная; права администратора (создание служб без них невозможно);
около **20–30 ГБ** свободного места: программа и модели поиска (~12 ГБ), Python-стек
расшифровки (1,5–7,4 ГБ) и модели расшифровки (~3–4 ГБ), плюс место под базу поиска;
интернет — для разовой загрузки моделей, набора файлов движка и стека расшифровки. Для первой
загрузки gated-моделей pyannote нужен токен Hugging Face.

### Шаг 1. Скачайте архив программы

Со страницы выпусков `https://github.com/Guerchoig/hermes-disk-search/releases/latest` скачайте
`hds-<версия>-windows-x64.zip`. Внутри уже лежат и пакеты для клиентских компьютеров, поэтому
отдельно скачивать их не нужно. Если сервер будет устанавливаться без интернета, скачайте ещё
набор файлов движка под свою видеокарту: `hds-engine-runtime-windows-x64-cuda.zip` (NVIDIA) или
`hds-engine-runtime-windows-x64-vulkan.zip` (AMD и Intel).

### Шаг 2. Распакуйте архив и выберите машинную папку установки

Распакуйте архив в **любую** папку — например, в `C:\Users\<имя>\Downloads\hds-0.20.3-windows-x64`
или в `D:\install\hds-0.20.3`. Это **источник**: после установки его можно удалить.

Сама программа встанет в **машинную** папку, которую вы передадите установщику строкой `-Root`:
например, `C:\Program Files\hermes-disk-search` (или `D:\hds-server`). Не ставьте программу в
папку пользователя (`C:\Users\…`): сервер должен работать до входа пользователя в систему.

Почему для установки нужен отдельный корень: установщик раскладывает поставку **по версиям** —
`app\<версия>` плюс указатель `app\current`, и службы запускаются из `app\current\bin`. Только на
такой раскладке работают обновление и возврат к прежней версии (глава «Обновление и откат
сервера»): обновление подменяет каталог версии за указателем, а точки запуска не переписываются.
Если распаковать архив прямо в машинную папку и **не** указывать `-Root`, установка получится
**плоской** (службы стартуют из `<папка>\bin`): она работает, и обновление само переведёт службы
на раскладку по версиям, но рядом не останется прежней версии для возврата.

### Шаг 3. Посмотрите план установки, ничего не меняя

```powershell
install-server.cmd -WhatIf -Root "C:\Program Files\hermes-disk-search"
```

Двойной щелчок по файлу не подходит: нужно передать аргументы команды. Полный вид команды вместе с
аргументами (права администратора на этом шаге **не** нужны, ничего не изменяется — печатается
только план, будущая раскладка и будущее содержимое файла настроек):

```powershell
installers\install_server.ps1 -WhatIf -Root "C:\Program Files\hermes-disk-search" `
  -StateDir C:\ProgramData\hermes-disk-search `
  -McpHost 0.0.0.0 -McpPort 8787 -UiHost 0.0.0.0 -UiPort 8765 -Parallel 5 `
  -GpuDevice 1 -Roots "D:\;E:\Archive" `
  -EnableAccess -AdminLogin admin -AdminPassword "<пароль>" -NoFetch
```

Содержимое файла настроек печатает **тот же** генератор, который пишет его при установке
(`hds config init` по серверному шаблону `server_config.example.yaml`). Поэтому показанное
совпадает с тем, что будет записано, и заодно проверяется, что настройки разбираются без ошибок.

### Шаг 4. Выполните установку

```powershell
install-server.cmd -Root "C:\Program Files\hermes-disk-search" `
  -StateDir C:\ProgramData\hermes-disk-search `
  -McpHost 0.0.0.0 -McpPort 8787 -UiHost 0.0.0.0 -UiPort 8765 -Parallel 5 `
  -GpuDevice 1 -Roots "D:\;E:\Archive" `
  -EnableAccess -AdminLogin admin -AdminPassword "<пароль>" -Fetch
```

Аргументы команды означают: `-Root` — машинная папка, куда ставится программа (её же указывайте при
обновлении и переносе); `-StateDir` — служебная папка сервера; `-McpHost`/`-McpPort` — адрес и порт
подключения ассистентов; `-UiHost`/`-UiPort` — адрес и порт страницы управления; `-Parallel` —
сколько обращений к ИИ-модели выполнять одновременно; `-GpuDevice` — номер видеокарты
(`0` — процессор, `1` — первая видеокарта); `-Roots` — папки, которые становятся проектами
(через точку с запятой); `-EnableAccess` — включить разграничение доступа; `-AdminLogin` и
`-AdminPassword` — первый администратор; `-Fetch` — догрузить набор движка, ИИ-модели и стек
расшифровки; `-TranscribeProfile auto|cuda|cpu|dml` — профиль расшифровки (по умолчанию `auto`
по видеокарте); `-HfToken <токен>` — токен Hugging Face только на первую загрузку
gated-моделей; `-SkipTranscribeStack` / `-SkipTranscribeModels` — не ставить окружение
расшифровки / не скачивать её модели.

> Для корня-диска в `-Roots` не ставьте обратный слэш перед закрывающей кавычкой: запись
> `-Roots "D:\"` PowerShell 5.1 разбирает как `D:\" …` (обратный слэш экранирует кавычку).
> Пишите `-Roots D:\` без кавычек или `-Roots D:/`.

> При автоматизированном запуске задайте `HDS_NONINTERACTIVE=1`: иначе при ошибке
> `install-server.cmd` ждёт нажатия клавиши.

Повторный запуск установщика безопасен: существующий файл настроек он не перезаписывает, службы
перерегистрирует, а не создаёт заново. Файл настроек собирается из **серверного** шаблона
`server_config.example.yaml` (он лежит в папке установки) и проверяется как YAML до записи: если
шаблон или значение испорчены, установка останавливается с ошибкой, а не оставляет полурабочий
файл. Если файл уже есть, установщик дописывает в него только недостающие значения по умолчанию —
сейчас это список исключений `index.exclude_dirs` (корзина `$RECYCLE.BIN`,
`System Volume Information` и другие служебные каталоги). Поэтому повторный запуск полезен и для
стенда, поставленного раньше: список исключений появится и в нём. Если нужно только подготовить
настройки, без служб и без прав администратора, укажите `-Roles ""`.

### Шаг 5. Что установщик делает по шагам

1. **Раскладка по версиям** — укладывает поставку как `app\<версия>` и ставит указатель
   `app\current` (та же операция, что делает обновление), после чего службы регистрируются на
   `app\current\bin\hds.exe`. Это то, что делает обновление и возврат к прежней версии
   работающими; в сводке установки строка начинается со слова «layout». Если архив распакован
   прямо в машинную папку (`-Root` не указан), раскладка остаётся плоской — в сводке будет
   сказано, что обновление перерегистрирует службы само.
2. **Системные дополнения** — ставит распознаватель текста и ffmpeg сразу для всей машины
   (в профиль пользователя их ставить бессмысленно: служба запускается без входа пользователя) и
   прописывает пути к ним в настройки. Пропустить: `-SkipDeps`.
3. **Служебная папка и файл настроек** — создаёт служебную папку и собирает файл настроек из
   **серверного** шаблона `server_config.example.yaml` командой `hds config init`: серверный профиль,
   включённый доступ, адреса подключения, число одновременных обращений, папки-проекты и список
   служебных каталогов-исключений `index.exclude_dirs`. Результат проверяется как YAML до записи.
   Существующий файл настроек не затирается — в него дописываются только недостающие значения по
   умолчанию.
4. **Закрепление настроек за службами** — записывает путь к файлу настроек и пути к моделям и
   набору движка прямо в данные службы. Это защита от случая, когда в папке установки окажется
   посторонний файл настроек и служба уйдёт в одиночный режим (без входа и с чужой базой).
   Отключить: `-NoConfigPin`. Проверка состояния предупреждает о подменённом файле настроек.
5. **Первый администратор** — заводит учётную запись с указанным логином; пароль хранится только
   в виде необратимого отпечатка, в журналах он не появляется.
6. **Постоянно работающие службы** — создаёт их и включает автозапуск при включении машины.
   Сразу после установки службы обычно **не запускаются**: они поднимутся при перезагрузке или по
   команде (следующий шаг).
7. **Загрузка по ключу `-Fetch`** — набор файлов движка, ИИ-модели и смысловых отпечатков,
   модель уточнения порядка найденного, модели поиска по картинкам, а также **Python-стек
   расшифровки**: окружение `sidecar\venv-transcribe[-dml]` в `app\current\sidecar`, GigaAM-v3,
   wav2vec2-ru и pyannote community-1/segmentation-3.0 в машинную папку моделей
   (для профилей `cpu`/`dml` дополнительно экспортируется ONNX). Модели распознавания речи
   для **отката** (`whisper`) и старый диаризатор **Nemotron-3** тоже скачиваются — они нужны
   только при `transcribe.engine: legacy`. Ошибка загрузки стека не отменяет установку: служба
   продолжит работать, а `hds transcribe-check` покажет, чего не хватает.
8. **Проверка состояния** в конце — итоговая сводка, что готово и что осталось.

Промежуточную программу с шифрованием установщик **не** ставит: это отдельный шаг с сертификатом
(глава «Защита сети», там же готовые образцы настроек).

### Шаг 6. Запустите службы и проверьте сервер

```powershell
hds service start llm-host     # служба моделей
hds service start watch        # слежение за файлами и наполнение базы
hds service start mcp-http     # подключение ассистентов
hds service start ui           # страница управления
hds check                      # сводная проверка состояния
```

Порядок важен: служба моделей должна подняться раньше остальных. При остановке порядок обратный.

В выводе проверки состояния обратите внимание на пункт **«раскладка»**: при версионной установке
там написано, что роли запускаются из `app\current\bin`. Если пункт предупреждает, что раскладка
по версиям есть, а роли запускаются не из неё, — установка собрана из разных копий: перерегистрируйте
роли командой `install-server.cmd` из каталога `app\current`.

Затем выпишите себе ключ доступа администратора (по нему открывается страница управления):

```powershell
hds token new --user admin     # ключ показывается один раз
```

### Шаг 7. Оформление доступа

* заведите пользователей и выдайте им папки-проекты — глава «Пользователи, доступ и ключи доступа»;
* подключите их компьютеры — глава «Подключение клиентского ПК»;
* расскажите им про кабинет — глава «Кабинет пользователя».

### Шаг 8. Обновление, откат и перенос

Ближайшие действия по обновлению не выполняются в этом разделе: **порядок обновления, возврата к
предыдущей версии и переноса готовой установки в другую папку описан в главе «Обновление и откат
сервера»**. Полезно прочитать её сразу после установки: там же сказано, что делать, если
обновление не прошло.

### Если сервер уже установлен и работает

Здесь два разных случая — и инструменты у них разные. Установщик службы **не** останавливает: он
рассчитан на первую установку, когда останавливать нечего. Обновление службы останавливает само
(это его работа).

**А. Надо обновить версию, установка остаётся на месте** — это штатное обновление, ничего вручную
останавливать не нужно: `update.cmd` от администратора сам останавливает службы в порядке
страница управления → подключение ассистентов → слежение за файлами → расшифровка видео/аудио →
служба моделей, подменяет версию, переводит службы на неё и запускает обратно (глава «Обновление и
откат сервера»).

**Б. Надо переустановить «с нуля» (или снести прежнюю установку)** — тогда службы останавливает и
снимает администратор *до* установки, потому что установщик этого не делает. Порядок:

1. Снять автоматический перезапуск — иначе обычная остановка «не удержится» и служба поднимется
   через несколько секунд (глава «Постоянно работающие службы», «Ловушка»). Команду нужно запускать
   **через `cmd /c`**: PowerShell не передаёт сторонней программе пустой аргумент, поэтому привычная
   запись «сбросить счётчик и убрать действия» прямо в PowerShell падает с «недопустимый параметр» —
   пустое значение просто не доходит до `sc.exe`:
   ```powershell
   $noRestart = 'sc.exe failure hermes-disk-search-{0} reset= 0 actions= ""'
   foreach ($r in 'ui','mcp-http','watch','transcribe','llm-host') {
     cmd /c ($noRestart -f $r)
   }
   ```
   Вернуть автоматический перезапуск (например, после работ) — команда с непустыми аргументами
   работает и напрямую:
   ```powershell
   sc.exe failure "hermes-disk-search-ui" reset= 86400 "actions= restart/5000/restart/5000/restart/30000"
   # или просто перерегистрировать роль:  hds service install <роль>
   ```
2. Остановить службы — в порядке, обратном запуску (сначала те, кто пользуется моделями, служба
   моделей — последней):
   ```powershell
   foreach ($r in 'ui','mcp-http','watch','transcribe','llm-host') {
     sc.exe stop "hermes-disk-search-$r"
   }
   # то же через наш бинарь:  hds service stop <роль>   (роль: ui|mcp-http|watch|transcribe|llm-host)
   ```
3. Мягко остановить службу моделей, если она осталась работать отдельным процессом
   (`<папка установки>` — машинная папка, при раскладке по версиям бинарь лежит в
   `app\current\bin`):
   ```powershell
   & "<папка установки>\bin\llm_host.exe" stop     # при раскладке по версиям: ...\app\current\bin\llm_host.exe
   ```
4. Убедиться, что ничего не держит файлы:
   ```powershell
   Get-Process hds,llm_host -ErrorAction SilentlyContinue     # должно быть пусто
   sc.exe query hermes-disk-search-ui                         # STOPPED (или «служба не установлена»)
   ```
5. Если дерево установки дальше удаляется — снять регистрацию служб, чтобы не осталось записей,
   ссылающихся на удалённые файлы (иначе служба уйдёт в цикл перезапуска):
   ```powershell
   foreach ($r in 'ui','mcp-http','watch','transcribe','llm-host') {
     sc.exe delete "hermes-disk-search-$r"      # или:  hds service uninstall <роль>
   }
   ```
6. Выполнить установку (шаги 3–4 этой главы) и запустить службы в правильном порядке:
   ```powershell
   hds service start llm-host     # служба моделей — первой
   hds service start watch
   hds service start mcp-http
   hds service start ui
   hds service start transcribe   # если роль ставилась
   hds check                      # в том числе пункт «раскладка»
   ```

Важно: **служебная папка сервера** (`%ProgramData%\hermes-disk-search`: настройки, база, доступ,
журналы, модели) при переустановке программы не трогается — она общая. Её содержимое удаляется
(или переносится в сторону) только сознательным решением.

Если после установки поверх работающей службы версия не сменилась — значит службу не перезапустили:
`sc.exe config` меняет запись службы, но уже запущенный процесс продолжает работать со старым
файлом. Помогает перезапуск роли — остановить и запустить (`hds service stop <роль>` и затем
`hds service start <роль>`, либо кнопка «Перезапустить» в карточке «Службы» на странице
управления) — или перезагрузка; проверка состояния показывает это пунктом «раскладка».

## 6. Установка сервера на Mac

Раздел самодостаточный: всё, что нужно сделать на Mac, перечислено здесь. Нужны Mac на
процессоре Apple Silicon, права администратора (команда `sudo`) и около 20–30 ГБ свободного
места (включая Python-стек расшифровки; на Mac он ставится best-effort).

### Шаг 1. Скачайте архив программы

Со страницы выпусков `https://github.com/Guerchoig/hermes-disk-search/releases/latest` скачайте
`hds-<версия>-macos-arm64.zip`. Набор файлов движка скачивать не нужно: установщик заберёт его
сам по сведениям о наборе и проверит отпечаток. Пакеты для клиентских компьютеров уже лежат внутри.

### Шаг 2. Распакуйте архив и выберите машинную папку установки

Распакуйте архив в **любую** папку (например, в «Загрузки») — это **источник**, после установки
его можно удалить. Программа встанет в машинную папку, которую вы передадите установщику первым
аргументом: например, `/usr/local/hermes-disk-search`. Не ставьте программу в домашнюю папку:
сервер должен работать до входа пользователя в систему.

Почему для установки нужен отдельный корень: установщик раскладывает поставку **по версиям** —
`app/<версия>` плюс указатель `app/current`, и службы запускаются из `app/current/bin`. Только на
такой раскладке работают обновление и возврат к прежней версии (глава «Обновление и откат
сервера»). Если не передать корень, установка получится **плоской** (службы стартуют из `<папка>/bin`):
она работает, и обновление само переведёт службы на раскладку по версиям, но прежней версии рядом
не останется.

### Шаг 3. Посмотрите план установки, ничего не меняя

```bash
sudo bash installers/install_server.command /usr/local/hermes-disk-search \
  --statedir "/Library/Application Support/hermes-disk-search" \
  --parallel 5 --roots "D:/;E:/Archive" \
  --enable-access --admin-login admin --admin-password "<пароль>" --whatif
```

### Шаг 4. Выполните установку

```bash
sudo bash installers/install_server.command /usr/local/hermes-disk-search \
  --statedir "/Library/Application Support/hermes-disk-search" \
  --parallel 5 --roots "D:/;E:/Archive" \
  --enable-access --admin-login admin --admin-password "<пароль>" --fetch
```

Файл настроек собирается из **серверного** шаблона `server_config.example.yaml` командой
`hds config init` и проверяется как YAML до записи. Существующий файл не перезаписывается, но в
него дописываются недостающие значения по умолчанию — сейчас это список служебных
каталогов-исключений `index.exclude_dirs`. Повторный запуск установщика безопасен.

### Шаг 5. Как называются аргументы команды (сравнение с Windows)

| Что задаёт аргумент команды | Windows | Mac |
|---|---|---|
| Машинная папка программы | `-Root` | первый аргумент команды |
| Служебная папка сервера | `-StateDir` | `--statedir` |
| Адрес и порт подключения ассистентов | `-McpHost`, `-McpPort` | `--mcp-host`, `--mcp-port` |
| Адрес и порт страницы управления | `-UiHost`, `-UiPort` | `--ui-host`, `--ui-port` |
| Сколько обращений к ИИ-модели сразу | `-Parallel` | `--parallel` |
| Номер видеокарты или готовая раскладка | `-GpuDevice`, `-GpuPreset` | `--gpu-device`, `--gpu-preset` |
| Папки-проекты | `-Roots` | `--roots` |
| Включить разграничение доступа | `-EnableAccess` | `--enable-access` |
| Первый администратор | `-AdminLogin`, `-AdminPassword` | `--admin-login`, `--admin-password` |
| Догрузить движок и модели | `-Fetch` / `-NoFetch` | `--fetch` / `--no-fetch` |
| Не ставить системные дополнения | `-SkipDeps` | `--skip-deps` |
| Не закреплять настройки за службами | `-NoConfigPin` | `--no-config-pin` |
| Только план, без изменений | `-WhatIf` | `--whatif` |

### Шаг 6. Что установщик делает по шагам

1. укладывает поставку **по версиям** (`app/<версия>` + указатель `app/current`) и описывает службы
   так, чтобы они запускались из `app/current/bin` — иначе обновление и возврат к прежней версии
   не меняли бы работающие файлы (нужен `pwsh`; без него установка будет плоской);
2. ставит системные дополнения (распознаватель текста и ffmpeg) через менеджер пакетов;
3. создаёт служебную папку `/Library/Application Support/hermes-disk-search` и файл настроек из
   серверного шаблона `server_config.example.yaml` (серверный профиль, включённый доступ, адреса,
   число обращений, папки-проекты, исключения `index.exclude_dirs`); результат проверяется как YAML
   до записи, существующий файл не затирается;
4. создаёт постоянно работающие службы и включает им автоматический запуск при включении машины;
   службы описываются как системные задачи с именами `com.hermes-disk-search.<роль>`;
5. закрепляет настройки за службами (путь к файлу настроек, пути к моделям и движку) прямо в
   описании службы, чтобы служба не подхватила посторонний файл настроек;
6. заводит первого администратора;
7. по ключу `--fetch` догружает набор файлов движка, модели поиска и **Python-стек расшифровки**
   (окружение GigaAM/pyannote + модели; для отката — whisper и Nemotron-3);
8. делает итоговую проверку состояния.

### Шаг 7. Запустите службы и проверьте сервер

Команды выполняются от имени администратора (`sudo`). Если папка `bin` из установки не добавлена
в пути поиска программ, указывайте полный путь, например `/usr/local/hermes-disk-search/app/current/bin/hds`.

```bash
sudo hds service start llm-host     # служба моделей — первая
sudo hds service start watch
sudo hds service start mcp-http
sudo hds service start ui
hds check                           # сводная проверка состояния
hds token new --user admin          # ключ доступа администратора (показывается один раз)
```

В выводе проверки состояния смотрите пункт **«раскладка»**: при версионной установке там написано,
что роли запускаются из `app/current/bin`.

### Шаг 8. Важные замечания для Mac

* сборка для Mac делается «по возможности» и на живой машине пока не проверялась: чек-лист
  проверки — `tools/parity/MAC_CHECKLIST.md`;
* журналы работы — `/Library/Logs/hermes-disk-search/`;
* обновление, возврат к прошлой версии и перенос установки — глава «Обновление и откат сервера»;
* промежуточная программа с шифрованием ставится отдельно: готовые образцы настроек — в папке
  `installers/proxy` (глава «Защита сети»).

## 7. Постоянно работающие службы

Служба — часть программы, которая запускается вместе с машиной, работает без входа пользователя и
сама поднимается, если упала. На сервере таких частей пять:

| Служба | Что делает |
|---|---|
| служба моделей (`llm-host`) | держит модели в памяти и отвечает на запросы остальных частей |
| слежение за файлами (`watch`) | замечает изменения на дисках и наполняет базу |
| подключение ассистентов (`mcp-http`) | принимает запросы от Cline и Hermes Desktop |
| страница управления (`ui`) | отдаёт страницу администратора и кабинет пользователя |
| расшифровка видео/аудио (`transcribe`) | следит за папкой «входящие» и делает расшифровки |

В Windows это службы операционной системы с именами `hermes-disk-search-<роль>`; в них включены
автозапуск и автоматический перезапуск при сбое. На Mac это системные задачи с именами
`com.hermes-disk-search.<роль>`.

### Команды управления

```powershell
hds service status                  # состояние всех служб
hds service status <роль>           # состояние одной службы: watch | mcp-http | ui | llm-host | transcribe
hds service start <роль>            # запустить
hds service stop <роль>             # остановить
hds service install <роль>          # зарегистрировать службу (нужны права администратора)
hds service uninstall <роль>        # снять службу
hds service run <роль>              # режим, в котором службу запускает система (вручную — работает до закрытия окна)
hds service root                    # папка установки служб
```

Создание и снятие служб требуют прав администратора. Прямые команды операционной системы, когда
команда `hds` недоступна:

```powershell
sc.exe query hermes-disk-search-watch      # состояние
sc.exe start hermes-disk-search-watch      # запуск
sc.exe stop  hermes-disk-search-watch      # остановка
sc.exe delete hermes-disk-search-watch     # снятие
```

### Порядок запуска и остановки

Запуск: **служба моделей** → слежение за файлами → подключение ассистентов → страница управления
→ расшифровка видео/аудио. Остановка — в обратном порядке. Этого порядка придерживаются и установщик,
и сценарий обновления.

### Ловушка: остановленная служба поднимается снова

У служб включён автоматический перезапуск при сбое (повтор через 5 секунд) — срабатывает, если
служба завершилась с ошибкой. Поэтому обычная остановка может «не удержаться»: через несколько
секунд служба поднимется опять. Чтобы остановить её по-настоящему, сначала отключите автоматический
перезапуск — **через `cmd /c`**, иначе PowerShell «съест» пустой аргумент `actions= ""` и `sc.exe`
ответит «недопустимый параметр»:

```powershell
cmd /c 'sc.exe failure hermes-disk-search-watch reset= 0 actions= ""'
sc.exe config  hermes-disk-search-watch start= demand
```

Вернуть автоматический запуск — `sc.exe config hermes-disk-search-watch start= auto`; вернуть
автоматический перезапуск — `sc.exe failure "hermes-disk-search-watch" reset= 86400 "actions=
restart/5000/restart/5000/restart/30000"` (эта запись с непустыми аргументами работает напрямую)
или перерегистрация роли: `hds service install <роль>`.

### Управление со страницы управления

На странице управления есть карточка «Службы»: состояние всех служб и кнопки «Зарегистрировать»,
«Снять», «Запустить», «Остановить», «Перезапустить». Для кнопок нужны права администратора.
Если прав нет, страница честно сообщит об этом и подскажет запустить её от администратора или
из службы; если служба ещё не зарегистрирована, будет сказано, что сначала нужно её создать.
Перезапуск страницы управления выполняется отложенно, поэтому сама страница не «зависает».
В одиночном режиме карточка пуста, и кнопок в ней нет.

### Как убедиться, что служба работает

1. `hds service status` — состояние;
2. проверка `http://127.0.0.1:8787/health` отвечает, что это наше приложение, и его версией;
3. проверка состояния `hds check` — по ней видно, отвечают ли модели и видна ли база;
4. журналы — глава «Проверка состояния и журналы».

## 8. Расшифровка видео/аудио

Сервер умеет превращать записи в текст: положите аудио- или видеофайл в папку «входящие» — в
папке «исходящие» появится текстовая расшифровка видео/аудио с разделением по говорящим.

### Настройка

В файле настроек сервера:

```yaml
auto_transcribe:
  enabled: true                     # включить обработку
  inbox_dir: 'D:\media_in'          # сюда кладут записи
  out_dir:   'D:\media_out'         # здесь появляются расшифровки
  source_disposal: delete           # что делать с исходником: delete | keep | move

transcribe:                         # Python-стек: GigaAM-v3 + pyannote community-1
  engine: python                    # python (по умолчанию) | legacy (откат на старый путь)
  profile: auto                     # auto | cuda | cpu | dml
  models_dir: ''                    # '' → HDS_MODELS_DIR (%ProgramData%\hermes-disk-search\models)
  asr:
    variant: e2e_rnnt               # распознавание речи (ru, пунктуация)
    backend: auto                   # auto | torch | onnx (для dml — onnx)
  diarization:
    enabled: true
    max_speakers: 20                # предел меток; число говорящих определяется по записи
  glossary:
    path: ''                        # '' → без замен (пример формата — в README рабочей версии)
  llm:
    enabled: false                  # LLM-правка текста выключена по умолчанию
```

Папки создаются, если их ещё нет. Управлять ими и видеть состояние обработки можно со страницы
управления (закладка «Транскрибация»): список файлов в папке «исходящие», предпросмотр,
перезапуск задания и поля для обеих папок.

### Кто может смотреть и править

* **администратор** — со страницы управления: список расшифровок, предпросмотр, присвоение имён
  говорящим, перезапуск задания;
* **любой пользователь с действительным ключом** — в своём кабинете: тот же список и то же
  присвоение имён (глава «Кабинет пользователя»). Имена с путями и служебными символами
  отклоняются, перед правкой создаётся копия файла с расширением `.bak`, а попытки отказа
  записываются в журнал.

Как выглядит результат: реплики помечены заголовками вида `### SPEAKER_00 [00:00:01 - 00:00:11]`
(метки от `SPEAKER_00`, предел — `transcribe.diarization.max_speakers`, по умолчанию 20), а
реплика, которую не удалось связать с говорящим, — `### UNASSIGNED […]`. Рядом лежат служебные
файлы: `.orig.md` (текст до подстановки имён) и `.speakers.json` (таблица «метка → имя»).

### Важно: расшифровки не попадают в поиск

Папки «входящие» и «исходящие» исключены из наполнения базы. Чтобы расшифровки находились
поиском, **перенесите нужные файлы `.md` вручную** в одну из папок-проектов сервера: тогда их
прочитает наполнение базы. Это осознанное решение: иначе одна и та же запись попала бы в базу
дважды — как медиафайл и как расшифровка видео/аудио.

### Приоритеты выполнения задач при нехватке ресурсов

1. поиск и ответы на вопросы;
2. расшифровка видео/аудио;
3. наполнение базы.

Расшифровка видео/аудио на время задания ставит наполнение базы на паузу и вытесняет модели
наполнения из видеопамяти. Запрос к ассистенту может вытеснить расшифровку видео/аудио, наполнение
базы — нет.

### Управление

* в наборе служб расшифровка видео/аудио входит в число постоянных частей; служба запускается **после**
  службы моделей (она владеет видеокартой). Остановка выполняется мягко, через сигнал;
* команды: `hds transcribe-watch` (работа в режиме службы), `hds transcribe-once "<файл>"`
  (обработать один файл сейчас), `hds transcribe-stop` (аккуратно остановить). Двойной запуск
  не допускается;
* на странице управления карточка службы расшифровки видео/аудио показывает состояние, а также «замок без
  процесса» — признак того, что в прошлый раз служба завершилась аварийно. Проверка состояния
  тоже подсказывает про залипший замок.

### Модели и размеры

Расшифровку выполняет Python-стек: **GigaAM-v3** (распознавание речи, ~1 ГБ), **wav2vec2-ru**
(выравнивание, ~1,2 ГБ) и **pyannote community-1 + segmentation-3.0** (разделение по говорящим,
~1,2 ГБ). Окружение (venv, 1,5–7,4 ГБ в зависимости от профиля) лежит в
`<папка установки>\app\current\sidecar`; модели — в машинной папке
`%ProgramData%\hermes-disk-search\models` (`gigaam`, `hf-home`, `gigaam-onnx`). Каталог можно
переопределить переменной `HDS_MODELS_DIR`.

* **Профили:** `cuda` (NVIDIA, torch + CUDA), `cpu` (ONNX CPU; выбирается, если карты нет или
  она встроенная AMD/Intel), `dml` (ONNX + DirectML для **дискретной** AMD/Intel).
  **`dml` пока экспериментальный**: на встроенной графике медленнее CPU, на дискретной карте
  живой приёмки не было.
* **Токен Hugging Face** нужен только на первую загрузку pyannote (`-HfToken` при установке или
  `HF_TOKEN`); в работе стек читает локальный кэш, сеть не требуется.
* **Догрузить/проверить вручную:**
  ```powershell
  powershell -File installers\build_transcribe_sidecar.ps1 -Profile cuda -SelfTest
  powershell -File installers\fetch_transcribe_models.ps1 -ModelsDir C:\ProgramData\hermes-disk-search\models -HfToken <токен>
  powershell -File installers\export_gigaam_onnx.ps1 -ModelsDir C:\ProgramData\hermes-disk-search\models   # cpu/dml
  ```
  Повторный запуск ничего не перекачивает (ревизии и sha256 закреплены в
  `transcribe-models.json`).
* **Проверка:** `hds transcribe-check` — профиль, вендор видеокарты, движок (CUDA/ONNX), версии,
  наличие моделей и ONNX, токен, `ffmpeg` и его версия, предупреждения. `hds check` показывает
  пункт «транскрибация» и путь воркера.
* Нужен и **ffmpeg** — им запись переводится в звуковой формат: установщик ставит его машинно,
  без него `hds transcribe-check` выдаст предупреждение.
* **Откат:** `transcribe.engine: legacy` возвращает старую цепочку (whisper + Nemotron-3 через
  службу моделей). Для неё нужны старые модели — `installers\fetch_whisper_model.ps1` и
  `installers\fetch_nemotron3_model.ps1`; в обычном серверном `-Fetch` они скачиваются как
  «страховка». В пакете без `-LegacyDiarizer` `DirectML.dll` нет, поэтому legacy-диаризатор
  потребует переходного архива.

На Mac Python-стек ставится best-effort и **на живой машине не проверялся** — macOS-сборка
best-effort, как и раньше.

Уже обработанные файлы повторно не берутся, а число попыток для сбойного файла ограничено.

## 9. Пользователи, доступ и ключи доступа

### Где это хранится

Список пользователей и их доступ — файл `data\access.yaml` в служебной папке сервера (образец —
`data/access.example.yaml` в исходном тексте проекта). Пароли хранятся необратимым
преобразованием (Argon2id), сам ключ доступа — случайная строка, а в файле лежит только её
необратимый отпечаток. Поэтому утерянный ключ нельзя «посмотреть» — можно только выписать новый.
Срок действия ключа по умолчанию 90 дней (ключ `access.token_ttl_days`).

### Завести пользователя и выдать доступ к папкам

```powershell
hds user add --login alice --password "<начальный пароль>" --projects "Sales,Docs"
hds user add --login admin --password "<надёжный пароль>" --admin      # администратор
hds user list                                                          # кто заведён и с каким доступом
hds user grant  --login alice --projects "Sales,Docs,Ops"              # добавить папку-проект
hds user revoke --login alice --projects "Docs"                        # убрать папку-проект
hds user passwd --login alice --password "<новый>"                     # сменить пароль
hds user del    --login alice                                          # удалить пользователя
```

Что важно знать:

* папки-проекты перечисляются через запятую; имена проектов — те, что записаны в настройках
  сервера (глава «Настройки сервера»);
* смена пароля **отзывает все ключи** этого пользователя: он должен получить новый ключ или войти
  заново;
* уборка папки-проекта действует сразу: файлы перестают быть видны с этого момента;
* удаление пользователя убирает и его ключи;
* у схемы хранения есть признак «отключён», но отдельной команды для него нет — если нужно
  закрыть доступ, удалите учётную запись.

### Два способа получить ключ доступа

| Способ | Кто и где | Когда применять |
|---|---|---|
| **Ключ от администратора** (основной) | администратор на сервере: `hds token new --user alice` или кнопка «Выдать токен» в карточке «Доступ» на странице управления | всегда; обязателен для компьютеров вне доверенной сети: пароль пользователю не нужен |
| **Самостоятельный вход** (дополнительный) | сам пользователь: `hds login --login alice --password "<пароль>" --url http://<сервер>:8787` | только в доверенной сети, где можно обращаться к серверу без шифрования |

```powershell
hds token new --user alice            # ключ показывается один раз + срок действия
hds token new --user alice --ttl-days 90
```

Ключ показывается **один раз**: сохраните его и передайте пользователю защищённым способом.

Ограничения самостоятельного входа — их нужно учитывать при выдаче памятки пользователям:

* команда входа обращается к серверу **без шифрования**: указывайте адрес `http://…:8787` и
  только внутри доверенной сети. Через промежуточную программу с шифрованием этот путь по
  умолчанию не публикуется, поэтому «вход по паролю снаружи» не сработает, пока вы явно не
  откроете его;
* путь входа работает только при включённом разграничении доступа;
* частота обращений к этому пути ограничена (защита от подбора пароля), а попытки входа
  записываются в журнал действий.

### Смотреть, отзывать, менять

| Действие | Команда (администратор) | Что происходит |
|---|---|---|
| Посмотреть ключи | `hds token list [--user alice]` | видно отпечаток (первые знаки), кому выдан, срок, истёк ли |
| Отозвать один ключ | `hds token revoke --sha <первые знаки отпечатка>` | доступ по нему прекращается сразу |
| Отозвать все ключи пользователя | `hds token revoke --user alice` | пользователю нужен новый ключ или новый вход |
| Сменить пароль | `hds user passwd --login alice --password "<новый>"` | пароль и все ключи заменяются |
| Убрать папку-проект | `hds user revoke --login alice --projects Docs` | файлы этой папки исчезают из выдачи |
| Удалить пользователя | `hds user del --login alice` | учётная запись и её ключи удаляются |

Просроченный по сроку ключ перестаёт действовать сам: срок проверяется при каждом обращении.

### Журнал действий

Журнал ведётся в служебной папке сервера: `data\logs\audit.jsonl` (одна запись в строке). Файл
растёт и при достижении предела (ключ `audit.max_mb`, по умолчанию 50) переносится в
`audit.jsonl.1`. В серверном режиме журнал включён.

Что записывается: удачный и неудачный вход, отказы в доступе (и на странице управления, и при
обращении к подключению ассистентов), вызовы инструментов («кто, каким инструментом, с какими
папками-проектами»), действия администратора и отзыв ключа. **Что не записывается:** тела
запросов и сами ключи — они в журнал не попадают. Состояние журнала видно в проверке состояния и
на странице управления в карточке диагностики.

## 10. Подключение клиентского ПК

Клиентский ПК — это компьютер пользователя, который пользуется общим поиском. Базы и наполнения на
нём нет: они остаются на сервере, туда же уходят обращения к инструментам поиска. Но сервер не
обязан быть единственным источником ответов: у ассистента на клиентском ПК может быть своя
ИИ-модель — местная или подключённая облачная; тогда с сервера берутся только поиск и найденные
фрагменты, а ответ строит модель на клиенте. Обязательны лишь ИИ-ассистент (Cline Desktop или Cline
в командной строке) и ключ доступа.

### Три шага (рекомендуемый путь)

1. **Администратор выдаёт ключ** и сообщает адрес сервера:
   ```powershell
   hds token new --user alice --ttl-days 90      # ключ показывается один раз
   ```
2. **Пользователь скачивает установочный скрипт** из общедоступного места — ключ для этого **не
   нужен**:
   ```powershell
   curl.exe -f https://host/mcp/client-install.ps1 -o client-install.ps1
   # macOS:  curl -f https://host/mcp/client-install.sh -o client-install.sh
   ```
   Тот же скрипт лежит и на странице выпусков в виде отдельного файла.
3. **Запускает скрипт с ключом** — скрипт сам скачает пакет под платформу компьютера, распакует
   его, снимет пометку «скачано из интернета», подключит Cline и предложит перезапустить его:
   ```powershell
   powershell -ExecutionPolicy Bypass -File .\client-install.ps1 -Token <КЛЮЧ> -ServerUrl https://host
   # macOS:  bash client-install.sh --token <КЛЮЧ> --server-url https://host
   ```
   Права администратора не нужны. Адрес указывается **без** `/mcp`: путь добавляется сам.

### Где пользователю смотреть расшифровки и искать по файлам

Кроме поиска через ассистента у пользователя есть **свой кабинет** — отдельная страница
(глава «Кабинет пользователя»):

* адрес: `<адрес сервера>/ui/user/`, например `https://host/ui/user/`. Внутри сети можно
  открыть и напрямую: `http://<адрес сервера>:8765/ui/user/`;
* вход: логин и пароль, выданные администратором, либо ключ доступа, подставленный в адресе
  как `?token=<ключ>`;
* что там есть, что разрешено и что закрыто — **глава «Кабинет пользователя»**.

Если пользователю удобнее работать через ассистента, ему достаточно установить клиент по трём шагам
выше: отдельные окна для поиска в этом случае не нужны.

### Ручной путь установки клиента

Подходит, если автоматический скрипт использовать нельзя.

1. **Получить пакет для клиентского ПК.** Два равнозначных канала — файл один и тот же:
   * **с сервера** (своим ключом; удобно, когда нет доступа к внешнему хранилищу):
     ```powershell
     curl.exe -f -H "Authorization: Bearer <КЛЮЧ>" -o hds-client.zip https://host/mcp/client-package.zip
     Expand-Archive .\hds-client.zip -DestinationPath .\hds-client -Force
     Get-ChildItem .\hds-client -Recurse | Unblock-File
     ```
   * **со страницы выпусков** — файл `hds-client-<версия>-<платформа>.zip` (для Apple Silicon —
     с `macos-arm64` в имени). Распаковать и снять карантин: `xattr -dr com.apple.quarantine hds-client`.
2. **Подключить Cline мастером:**
   ```powershell
   cd .\hds-client
   .\setup-client.ps1 -ServerUrl https://host -Token <КЛЮЧ>
   # проще двойным щелчком:  setup-client.cmd -ServerUrl https://host -Token <КЛЮЧ>
   # macOS:                  bash install_client.command --server-url https://host --token <КЛЮЧ>
   ```
   Аргументы команды: `-DryRun` — только показать план, ничего не записывая; `-SkipHealth` — не проверять
   связь перед настройкой.
3. **Перезапустить Cline** и задать вопрос по файлам.

### Что записывается на клиентском ПК

| Что | Где | Когда применяется |
|---|---|---|
| Запись о подключении к серверу | `~/.cline/data/settings/cline_mcp_settings.json` и `~/.cline/mcp.json` | при запуске ассистента |
| Правило поведения | `~/.cline/rules/disk-search.md` | всегда, при каждой беседе |
| Подсказка по требованию | `~/.cline/skills/disk-search/SKILL.md` | если модель её запросит |

Адрес сервера записывается внешний (тот, что вы указали), вместе с заголовком с ключом доступа.
Размеры контекста моделей на клиентском ПК не меняются: своей службы моделей там нет. Повторный
запуск мастера ничего не дублирует.

### Как выбрать нужный пакет и как сверяются версии

В поставке сервера лежат пакеты для обеих платформ. Сервер выбирает нужный по указанию
`?platform=windows-x64` или `?platform=macos-arm64`, а если его нет — по сведениям о клиенте,
иначе по своей платформе. Установочные скрипты подставляют платформу сами; вручную, например,
так: `curl.exe -f -H "Authorization: Bearer <КЛЮЧ>" -o hds-client.zip "https://host/mcp/client-package.zip?platform=macos-arm64"`.

Пакет несёт файл `version.txt`, а сервер сообщает свою версию в ответе на проверку
`https://host/health`. Мастер сверяет их и предупреждает при расхождении: значит правило,
подсказка или набор инструментов могут быть устаревшими.

### Проверка и безопасность

* проверка связи: `Invoke-WebRequest 'https://host/health' -UseBasicParsing` → ответ с именем
  приложения и версией;
* ключ доступа — то же, что пароль: не пересылайте его открытыми каналами, не публикуйте в
  заявках и переписке; в журналы он не пишется, мастер передаёт его программе через переменную
  окружения, а не в командной строке;
* без шифрования (адрес `http://`) ключ идёт открытым текстом — используйте `https://`;
* ключ выдан на срок (по умолчанию 90 дней) и проверяется на каждом обращении: просроченный или
  отозванный даёт отказ «нет доступа». В этом случае администратор выписывает новый ключ;
* если проверка связи не отвечает — проверьте, работает ли служба подключения ассистентов на
  сервере и тот ли адрес указан (глава «Проверка состояния и журналы»).

## 11. Кабинет пользователя

Кабинет — это страница для пользователей, которые не администраторы. В ней нет администраторских
разделов, поэтому её можно спокойно показывать сотрудникам: ничего лишнего они там не увидят.

### Как открыть

| Где вы находитесь | Адрес |
|---|---|
| Вне сервера, через защищённое соединение | `https://<адрес сервера>/ui/user/` |
| На самом сервере | `http://127.0.0.1:8765/ui/user/` |
| В локальной сети без шифрования | `http://<адрес сервера>:8765/ui/user/` |

### Как войти

* **логин и пароль** — те, что выдал администратор: страница входа сама их запросит;
* **ключ доступа** — можно передать в адресе как `?token=<ключ>`: страница запомнит его в
  браузере и будет подставлять в дальнейшие обращения;
* если администратор уже оформил вход по ключу, дополнительных действий не нужно.

### Что внутри

1. **Поиск по файлам** — та же выдача, что и через ассистента, но в браузере, и с тем же
   ограничением: видны только папки-проекты самого пользователя.
2. **Установка клиента** — ссылка на общедоступный установочный скрипт, готовые команды с ключом
   пользователя, адрес сервера из настроек и ссылка на проверку версии. Это упрощает подключение
   нового компьютера: копировать команды из переписки не нужно.
3. **Расшифровки и говорящие** — список файлов из папки «исходящие», предпросмотр текста и
   присвоение имён говорящим. Разрешены и замена имён, и правка самого текста расшифровки видео/аудио: перед
   правкой создаётся копия файла с расширением `.bak`, а имена с путями отклоняются.

### Что закрыто

Администраторские разделы (службы, настройки, пользователи и ключи, запуск наполнения базы,
диагностика) в кабинете недоступны: попытка обратиться к ним получает отказ «недостаточно прав»,
и отказ записывается в журнал действий. Это же правило действует и для страницы администратора:
неадминистраторский ключ её не откроет.

В одиночном режиме (когда разграничение доступа выключено) кабинет открыт локально без входа —
это удобно для проверки.

## 12. Защита сети

Наружу публикуются только три пути, и все — через промежуточную программу с шифрованием (прокси):

| Что публикуется | Куда идёт | Нужен ли ключ |
|---|---|---|
| подключение ассистентов (`/mcp`) | `127.0.0.1:8787` | да, ключ доступа |
| установочные скрипты клиента (`/mcp/client-install.ps1` и `.sh`) | `127.0.0.1:8787` | нет: в них нет секретов, ключ пользователь передаёт при запуске |
| проверка связи (`/health`) | `127.0.0.1:8787` | нет: это признак «наш сервер» и версия |
| страница управления и кабинет (`/ui/`) | `127.0.0.1:8765` | да: администратору — админский ключ, пользователю — свой |

**Что не публикуется никогда:** служба моделей (адреса `8010`–`8012`). Эти адреса всегда остаются
доступными только на самом сервере.

Готовые образцы настроек прокси лежат в папке `installers/proxy` — файлы `Caddyfile` и
`nginx.conf`. В них уже открыт наружу только нужный путь. Сертификат оформляет и продлевает
владелец сервера (можно бесплатный или собственный); сама программа работает без шифрования
внутри сервера, шифрование добавляет прокси. Запуск прокси — вручную:

```powershell
caddy run --config installers\proxy\Caddyfile     # или копия nginx.conf в conf.d и nginx -s reload
```

После этого в файле настроек сервера включите доверие к прокси:

```yaml
trusted_proxy: true    # доверять сведениям о настоящем адресе клиента, которые добавил прокси
```

* пока доверие выключено (значение по умолчанию), сведения о настоящем адресе от прокси
  **игнорируются**: клиент, подключившийся напрямую, не может подделать свой адрес;
* при включённом доверии настоящим считается **последняя** запись в списке адресов, добавленная
  нашим прокси: её клиент подделать не может. По этому адресу считаются ограничения частоты и
  ведётся журнал действий;
* схема соединения (`https`) берётся из сведений, добавленных прокси;
* как сервер видит клиента, показывает ответ проверки связи: поле с адресом клиента — это либо
  адрес самого клиента (при прямом подключении), либо адрес прокси, а при включённом доверии —
  настоящий адрес клиента.

### Ограничения защиты

| Ключ настроек | Значение по умолчанию | Что ограничивает |
|---|---|---|
| `http.max_body_kb` | 512 (0 — без предела) | размер одного запроса: крупнее — отказ без чтения тела |
| `http.max_conns` | 32 (0 — без предела) | число одновременных соединений: сверх предела — короткий отказ «занято» |
| `rate_limit.requests_per_min` | 120 | сколько обращений в минуту допускается от одного пользователя (иначе — от одного адреса) |
| `rate_limit.burst` | 30 | допустимый всплеск обращений |
| `rate_limit.login_per_min` | 10 | сколько раз в минуту можно пытаться войти по паролю (защита от подбора) |

Ответы при превышении: «слишком много обращений» с указанием, сколько ждать; «слишком большой
запрос»; «занято». Тексты ошибок единообразны и не раскрывают внутренних путей и версий.

Важное свойство: если в серверной поставке файл настроек окажется нечитаемым, страница
управления **закрывается** (отвечает «нет доступа»), а не открывается всем. Это сделано намеренно
— лучше недоступность, чем открытый доступ.

## 13. Одновременная работа и время ответа

Договорённость, на которую рассчитан сервер: при **пяти одновременных** обзорных вопросах
(«какие есть…») ответ на каждый приходит в пределах пяти минут.

### Сколько обращений выполняется сразу

| Что задаёт | Ключ настроек | Значение по умолчанию на сервере |
|---|---|---|
| Сколько обращений к ИИ-модели идёт одновременно | `llm_server.parallel` | 5 |
| Сколько текста помещается в одно обращение | `llm_server.chat.ctx_per_slot` | 16 384 |
| Сколько обращений выполняется **одновременно** всего | `rate_limit.max_inflight` | 5 |
| Сколько обращений **ждут** своей очереди | `queue.max_depth` | 20 |
| Сколько ждать в очереди, секунд | `queue.wait_timeout_sec` | 240 |

Перед запуском служба моделей считает, поместится ли выбранное в видеопамять: если не помещается,
она **отказывается запускаться и объясняет числами**, что нужно уменьшить — число одновременных
обращений или длину контекста. Молчаливого замедления не бывает. Если наполнение базы идёт
одновременно с ответами на вопросы, держите длину контекста поскромнее — иначе в память которой
части не хватит.

Ключ `rate_limit.max_inflight` не должен быть меньше `llm_server.parallel`: проверка состояния
предупредит о рассогласовании.

### Очередь: тяжёлые вопросы ждут, а не обрываются

Обзорный ответ по файлам — самая тяжёлая работа. Когда все места заняты, обращение **встаёт в
очередь**:

* **справедливое распределение:** между пользователями — по кругу (ключ очереди — логин, если ключ
  доступа не передан — адрес), внутри одного пользователя — по времени прихода. Один пользователь
  не занимает все места, пока ждут другие;
* **пределы очереди:** `queue.max_depth` — сколько пользователей ждут, `queue.wait_timeout_sec` —
  потолок ожидания (держите меньше 300 секунд: столько ждёт ассистент);
* **ответы при перегрузке:** очередь полна — «слишком много обращений» с указанием, сколько
  ждать; ожидание превышено — «не дождался» (тоже с указанием времени). Оба ответа содержат
  подсказку, какой ключ настроек увеличить;
* **обрыв ожидания:** если пользователь закрыл ассистента, место в очереди освобождается;
* политика очереди задаётся ключом `queue.policy`: `rr` — по кругу (по умолчанию), `fifo` —
  строго по времени прихода.

### Личные пределы

Ключ лимитов — **пользователь**, а не выданный ему ключ доступа: если один пользователь работает
одновременно в двух разных сеансах (например, с двух компьютеров или из двух открытых ассистентов),
его сеансы делят одну квоту. Раньше лимиты считались по ключу доступа, и одновременная работа в
двух сеансах давала двойную квоту.

| Ключ настроек | Значение по умолчанию | Что ограничивает |
|---|---|---|
| `rate_limit.max_inflight_per_user` | 2 | сколько обращений по файлам пользователь может вести одновременно: следующее сразу отклоняется с подсказкой |
| `rate_limit.requests_per_min_per_user` | 120 | общая частота обращений одного пользователя |
| `rate_limit.per_token` | выключено | если включить, лимиты считаются по ключу доступа, а не по пользователю |

Личный предел учитывается, только если он строже общего: иначе он ничего не добавляет — обращение
просто ждёт место в очереди.

### Что видно и куда записывается

* в проверке состояния и на странице диагностики есть раздел очереди: сколько ждёт, сколько
  ждали (среднее и «медленное» значение), сколько отказов, кто кого ждёт;
* источник этих чисел — запись, которую процесс подключения ассистентов обновляет раз в две
  секунды. Если запись отсутствует или устарела, проверка состояния сообщит, что подключение
  ассистентов не запущено;
* ожидание в очереди попадает в журнал действий отдельной записью с указанием, сколько пользователь
  ждал.

### Два правила, которые обеспечивают работу под нагрузкой

1. **Наполнение базы уступает.** Пока идёт тяжёлое обращение, наполнение ставится на паузу, а
   ответы не ждут, пока запись в базу закончится: чтение и запись не блокируют друг друга.
2. **Отказ раньше очереди.** Обращение без действительного ключа получает отказ **сразу**, не
   занимая место в очереди, — иначе очередь можно было бы занять «пустыми» обращениями.

### Измерения (для ориентира)

На машине с одной видеокартой 12 ГБ, при пяти одновременных обзорных вопросах:

* пять одновременных обращений, длина контекста 16 384: все ответы получены, медленные — около
  50 секунд;
* три одновременных обращения: медленные — около 49 секунд (часть запросов ждёт);
* два: медленные — около 58 секунд;
* если в это же время идёт полное наполнение базы, медленные ответы растягиваются до пяти минут
  и больше — поэтому наполнение и ответы лучше разводить по времени.

Подробные отчёты о замерах лежат в папке `tools/parity/out/` (например, файлы с `m4_load` в
имени).

### Ограничение

Очередь живёт в процессе подключения ассистентов. Ответ по файлам, запущенный администратором со
страницы управления, ограничивается своими пределами, но в общую очередь не встаёт.

### Когда своей видеокарты не хватает: облачная ИИ-модель

Ответы может давать облачная ИИ-модель, совместимая с распространённым способом обращения к моделям.
Тогда на сервере не поднимается местная ИИ-модель, и освобождается около 8 ГБ видеопамяти.
Поиск, смысловые отпечатки, уточнение порядка найденного и разграничение доступа остаются
местными.

```yaml
chat:
  provider: remote            # local (местная ИИ-модель, по умолчанию) | remote (облачная ИИ-модель)
  base_url: "https://api.example.com/v1"
  api_key: "sk-..."           # ключ доступа к облачной ИИ-модели; "-" = без ключа
  model: "gpt-4o-mini"
```

* ключ к облачной ИИ-модели хранится в файле настроек и **в хранилище версий кода не попадает**;
* проверка состояния показывает отдельную строку про облачную ИИ-модель: если не указан адрес или
  ключ — предупреждение; сам ключ в диагностике не печатается;
* ⚠ **Обезличивание пока не сделано:** текст вопроса и найденные фрагменты уходят облачной ИИ-модели
  как есть. Включайте это только для доверенной ИИ-модели.

### Несколько видеокарт

Сервер может работать с несколькими **дискретными** видеокартами **одного** производителя:
NVIDIA под Windows, AMD под Windows, либо один Mac. **Смешанные производители, а также встроенная
графика не поддерживаются** — проверка состояния сообщит об этом с числами и подсказкой.

Раскладка задаётся явно или готовой схемой:

```yaml
gpu:
  preset: nvidia-n            # none | nvidia-one | nvidia-n | amd-n | apple
  autodetect: false           # по умолчанию подбор ВЫКЛЮЧЕН: раскладка только по явному указанию
  # devices:                  # явная раскладка сильнее готовой схемы
  #   - { index: 1, roles: [chat] }
  #   - { index: 2, roles: [embedding, rerank] }
llm_server:
  # chat: { device: 1 }       # указание карты для конкретной роли — сильнее всего
```

Правила раскладки:

* чат-копии (реплики) должны быть одинаковыми — одна модель, одна длина контекста, разные адреса
  и места;
* смысловые отпечатки и уточнение порядка найденного — **ровно один экземпляр на машину**;
* распознавание речи — по экземпляру на карту;
* нарушение правил — **отказ запуска с числами**: служба моделей не поднимается, пока настройки
  не приведены в порядок;
* наружу публикуется только один адрес ответов (`8010`): запросы распределяются между копиями
  внутри сервера (сначала на менее занятую, затем по кругу). Адреса копий наружу не выходят;
* учёт свободной видеопамяти ведётся **по каждой карте отдельно**: нехватка памяти на одной карте
  не вытесняет роли с другой.

Номера карт — «наши»: `0` — процессор, `1` и далее — ускорители в том порядке, в каком их
показывает команда `llm_host devices`. Порядок может отличаться от привычного в системе,
поэтому сверяйтесь с этой командой.

Готовые схемы раскладывают **уже объявленные** роли: например, копия чата `chat-2` объявляется в
настройках явно.

### Честные ограничения

* работа **нескольких карт** и работа на **Mac** проверены не на живом железе: раскладка принята
  по проверкам отдельных частей и по журналу работ;
* предупреждение о смешанных производителях и встроенной графике уже есть, но живой проверки нет;
* выбор карты под конкретный файл при расшифровке видео/аудио срабатывает, только если
  программа-заказчик **не** указала карту сама. Штатные средства проверки и расшифровки
  видео/аудио карту указывают, поэтому на
  нескольких картах это нужно учитывать: на одной карте разницы нет.

## 14. Настройки сервера

Все настройки лежат в одном файле `config.yaml` в служебной папке сервера. Образец с пояснениями —
**`server_config.example.yaml`** в папке установки: это серверный шаблон, из него установщик и
собирает файл настроек. Одиночный `config.example.yaml` — шаблон для установки на один компьютер;
серверный стенд его не использует (ключи в нём те же, отличия серверного профиля — в таблице ниже).

### Правка настроек

| Что правится | Как | Когда применяется |
|---|---|---|
| Список папок-проектов | на странице управления: **Настройки** → **Сохранить корни**; либо текстовый редактор | после сохранения на странице; при правке файла — после перезапуска служб |
| Исключения по путям (`index.exclude_paths`) | там же: **Сохранить исключения** | так же |
| Служебные каталоги (`index.exclude_dirs`: корзина, `System Volume Information`, `Windows.old`, …) | текстовый редактор; установщик дописывает список сам | после перезапуска службы слежения |
| Папки расшифровки видео/аудио | закладка «Транскрибация»: поля папок → сохранение | так же |
| Число одновременных обращений, длина контекста, пределы частоты | только текстовый редактор | после перезапуска службы моделей и подключения ассистентов |
| Включение разграничения доступа, доверие к прокси, облачная ИИ-модель | только текстовый редактор | после перезапуска соответствующих служб |

При правке через страницу управления пояснения внутри файла сохраняются — файл не «сжимается» в
одну строку. При правке в редакторе держите копию файла: это единственное место, где описано,
какие папки являются проектами.

### Создать или дополнить файл настроек вручную

Установщик делает это сам, но ту же команду можно запустить вручную — например, чтобы добавить
новые значения по умолчанию в настройки давно работающего стенда:

```powershell
hds config init --path "%ProgramData%\hermes-disk-search\config.yaml" --merge-defaults
# macOS:
# hds config init --path "/Library/Application Support/hermes-disk-search/config.yaml" --merge-defaults
```

* существующий файл **не перезаписывается**; `--merge-defaults` только дописывает недостающие
  значения по умолчанию (сейчас это `index.exclude_dirs`), пояснения и ваши правки остаются;
* `--print` — показать, что было бы записано, и ничего не менять;
* `--force` — переписать файл целиком из шаблона (сначала сделайте копию: это единственное место,
  где описаны папки-проекты);
* результат всегда проверяется как YAML **до** записи: испорченный шаблон или значение останавливают
  команду, полурабочий файл не появляется.

### Ключи, которые отличают сервер от одиночной установки

| Раздел и ключ | Значение на сервере | Что задаёт |
|---|---|---|
| `profile` | `server` | набор серверных значений: число одновременных обращений, режим базы, очередь, пределы, журнал |
| `access.enabled` | включено | разграничение доступа. **Сам по себе серверный профиль доступ не включает** — доступ водится только этим ключом |
| `access.token_ttl_days` | 90 | срок действия выданных ключей доступа |
| `index.roots` | папки-проекты | что обрабатывается и какие проекты существуют (пример записи — глава «Что решить до установки») |
| `index.exclude_dirs` | набор служебных каталогов (корзина, `System Volume Information`, `Windows.old`, …) | что не обходится при наполнении базы. Список дописывает установщик; без него в базу попадают файлы корзины |
| `db_path` | полный путь или `data\index.db` | где лежит база поиска |
| `db.busy_timeout_ms` | 5000 | сколько ждать освобождения базы при одновременной работе: с ответами и наполнением сразу |
| `db.journal_mode`, `db.read_only_conns` | `wal`, включено | режим базы, при котором читатели (поиск, ответы) не ждут писателя (наполнение). **Резервную копию можно делать только средствами самой базы** |
| `llm_server.parallel`, `llm_server.chat.ctx_per_slot` | 5 и 16 384 | сколько обращений к ИИ-модели идёт сразу и сколько текста помещается в одно |
| `queue.enabled`, `queue.max_depth`, `queue.wait_timeout_sec`, `queue.policy` | включено, 20, 240, `rr` | очередь тяжёлых ответов и справедливое распределение |
| `rate_limit.*` | 120 в минуту, всплеск 30, вход 10, сразу 5, на пользователя 2 | пределы частоты и одновременности (полный перечень — глава «Защита сети» и «Одновременная работа») |
| `http.max_body_kb`, `http.max_conns`, `http.read_timeout_sec` | 512, 32 | ограничения на размер запроса и число соединений |
| `mcp_http.host`, `mcp_http.port`, `mcp_http.path` | адрес и путь подключения ассистентов | куда обращаются ассистенты пользователей. Значение «слушать всех» (`0.0.0.0`) ставьте только вместе с промежуточной программой с шифрованием |
| `ui.host`, `ui.port` | `127.0.0.1`, 8765 | адрес страницы управления. Наружу — только через прокси |
| `trusted_proxy` | выключено | доверять сведениям о настоящем адресе клиента, которые добавляет прокси |
| `audit.enabled`, `audit.max_mb` | включено, 50 | журнал действий и предел его размера |
| `gpu.policy`, `gpu.device_index`, `gpu.preset`, `gpu.devices` | по решению | какая видеокарта кем используется и кто кому уступает память |
| `gpu.pause_index_on_query`, `gpu.priorities` | включено | наполнение базы уступает тяжёлым ответам |
| `chat.provider`, `chat.base_url`, `chat.api_key`, `chat.model` | `local` | ответы местной или облачной ИИ-моделью |
| `llm.embedding.retention`, `llm.rerank.retention` | держать в памяти | на сервере модели смысловых отпечатков и уточнения порядка не выгружаются и прогреваются при старте: иначе первое обращение после простоя надолго «зависает» |
| `auto_transcribe.*` | по решению | порядок «папка → расшифровка видео/аудио» |

### Какой файл настроек читает каждый компонент — и почему это важно

* **службы** читают тот файл, путь к которому закреплён в их описании (установщик прописывает его
  при установке). Это защита от случая, когда в папке установки окажется посторонний файл
  настроек: тогда служба ушла бы в одиночный режим — без входа, с чужой базой и «пропавшей»
  службой моделей;
* **страница управления** запоминает путь к файлу в момент запуска службы. Поэтому смена
  включения доступа применяется **после перезапуска** службы страницы управления;
* **проверка состояния** сообщает о подменённом файле настроек отдельной строкой. Если такая
  строка появилась, переименуйте лишний `config.yaml` в папке установки;
* **служебная программа чтения документов** (её запускает служба слежения) читает тот же файл, путь к
  которому закреплён за службами. До версии 0.20.6 она искала настройки только в папке установки:
  на серверном стенде такого файла нет, программа завершалась, и наполнение базы падало с сообщением
  «поток вывода закрыт» — исправлено в 0.20.6;
* жёстко задать файл настроек и служебную папку можно переменными `HDS_CONFIG` и `HDS_ROOT`.

### Кто может менять настройки

Изменять папки-проекты, исключения, папки расшифровки видео/аудио и любые другие настройки может **только
администратор** — на странице управления под администраторским ключом. В кабинете пользователя
разделов настройки нет; попытка обратиться к ним получает отказ «недостаточно прав» до выполнения
действия и записывается в журнал. После правки папок-проектов нужен запуск наполнения базы, иначе
новые файлы ещё не приписаны к проектам: до этого они не будут видны никому, кроме администратора.

## 15. Обновление и откат сервера

**Это окно обслуживания:** во время обновления службы останавливаются, и пользователи не могут
пользоваться поиском. Выбирайте время, когда это никому не мешает.

### Обновление одним файлом

1. Скачайте и распакуйте новый архив сервера в **любую** папку.
2. Запустите файл-стартер из распакованного архива от имени администратора:

```powershell
update.cmd                # Windows: сам найдёт корень установки и версию
# macOS (нужен pwsh):  sudo bash installers/update.command
```

Стартер снимает пометку «скачано из интернета», сам определяет корень установки (по описанию
службы) и версию (по файлу `version.txt`), затем передаёт работу сценарию обновления:
**остановка служб** в порядке страница управления → подключение ассистентов → слежение за файлами
→ расшифровка видео/аудио → служба моделей, **подмена версии**, **перевод служб на новую версию**,
**докачка Python-стека расшифровки** (окружение при отсутствии + модели; `-NoModels` — пропустить),
**запуск служб** в обратном порядке и **проверка связи**.

Перевод служб — отдельный шаг, и он обязателен: службы, задания автозапуска и ярлык на рабочем
столе хранят полный путь к программе, а обновление подменяет каталог версии за указателем
`app\current`. Поэтому перед запуском сценарий перерегистрирует точки запуска: для служб —
`sc config` на `app\current\bin\hds.exe` (и заново закрепляет путь к настройкам), для заданий
автозапуска и ярлыка — пересоздаёт их из `app\current`. В выводе это строки `[ok] re-pointed …`.

На время обновления сценарий **снимает автоматический перезапуск** служб, а после переключения
версии возвращает его (в том числе если обновление прервалось ошибкой). Это не украшение: служба,
остановленная при включённом авто-перезапуске, поднимается примерно через 5 секунд, и если это
случится во время копирования версии, она заново создаст `app\current` обычным каталогом — подмена
указателя сорвётся с «Папка не пуста», а стенд останется без служб. В выводе это строки
`[ok] auto-restart suspended: …` и `[ok] auto-restart restored: …`.

Файл настроек обновление **не переписывает**. Новые значения по умолчанию (например, список
служебных каталогов `index.exclude_dirs`) появляются у уже работающего стенда при повторном запуске
установщика (`install-server.cmd`) или вручную — `hds config init --path <файл настроек>
--merge-defaults`; `--print` покажет результат, ничего не меняя (глава «Настройки сервера»).

Полезные аргументы команды: `-WhatIf` — только показать план, ничего не меняя; `-RollbackTo <версия>` —
вернуть предыдущую версию; `-NoModels` — не докачивать модели расшифровки (офлайн: скачайте позже
`installers\fetch_transcribe_models.ps1`); `-TranscribeProfile cuda|cpu|dml` и `-HfToken <токен>` —
профиль и токен для первой загрузки gated-моделей.

### Обновление вручную (все аргументы команды видны)

```powershell
installers\update.ps1 -Root C:\Program Files\hermes-disk-search -Profile server `
    -From dist\hds-1.1.0-windows-x64.zip -Version 1.1.0      # обновление
installers\update.ps1 -Root C:\Program Files\hermes-disk-search -ListVersions
installers\update.ps1 -Root C:\Program Files\hermes-disk-search -Profile server -RollbackTo 1.0.1
```

### Как устроена раскладка версий

В папке установки есть подпапка `app`: в ней лежат папки версий и указатель `app\current` на
активную. Служебная папка сервера (настройки, база, доступ, журналы) и набор моделей при этом
остаются общими и не переписываются. Прошлые версии сохраняются — поэтому откат сводится к
возврату указателя на прежнюю версию.

Подпапка `app` появляется при установке (если установщику передан корень `-Root` — глава
«Установка сервера на Windows») или при первом обновлении. Пока службы зарегистрированы на
`<папка>\bin`, то есть установка плоская, указатель на версию на их работу **не влияет**: именно
поэтому обновление перерегистрирует точки запуска. Посмотреть, из чего запускаются роли, можно
проверкой состояния — пункт «раскладка» (`hds check`), а вручную — `sc.exe qc
hermes-disk-search-ui` (в ответе строка `ПУТЬ_К_ДВОИЧНОМУ_ФАЙЛУ` / `BINARY_PATH_NAME`).

**Что сохраняется при обновлении:** настройки, база поиска, список пользователей и ключи, журналы,
модели. **Что меняется:** исполняемые файлы и служебные сценарии.

### Если обновление не прошло

1. Проверьте состояние: `hds check` и `hds service status`; посмотрите, из чего запускаются роли —
   пункт «раскладка» в `hds check` или `sc.exe qc hermes-disk-search-ui`.
2. Если службы не поднялись или связь не отвечает — верните предыдущую версию:
   `update.cmd -RollbackTo <версия>`.
3. Посмотрите вывод сценария: он печатает, на каком шаге произошёл сбой. Частая причина —
   занятый файл: закройте ассистентов на сервере, остановите службу моделей и повторите.
4. После любой попытки убедитесь, что службы запущены **в правильном порядке** (глава «Постоянно
   работающие службы»).

### Перенос готовой установки в другую папку

Если например сервер оказался установлен в папке пользователя (например, `C:\Users\<имя>\hds-server`),
перенесите его от имени администратора:

```powershell
installers\migrate_to_machine_root.ps1 -From "C:\Users\<имя>\hds-server" -To "C:\Program Files\hermes-disk-search"
```

Что делает сценарий: снимает автоматический перезапуск, останавливает службы, копирует дерево,
пересоздаёт ссылки на общие папки, переносит модели и набор движка из профиля в служебную папку
сервера (для набора движка оставляет обратную ссылку, чтобы стороннее приложение продолжало
работать), закрепляет переменные окружения за службами, перерегистрирует службы на новый путь и
делает проверку. Служебная папка сервера при этом не трогается, а при сбое службы возвращаются в
работу.

### Обновление клиентских ПК

Клиентский пакет нужен той же версии, что сервер: при расхождении мастер предупреждает, что
правило, подсказка или набор инструментов могут быть устаревшими. После обновления сервера либо
разошлите пользователям новый пакет, либо предложите им повторить установку одним и тем же скриптом
(он всегда берёт пакет той версии, что стоит на сервере).

## 16. Проверка состояния и журналы

### Проверка состояния

```powershell
hds check            # понятный пользователю вывод
hds check --json     # машинный вывод
hds service status   # отдельно: состояние и автозапуск всех служб
hds transcribe-check # готовность расшифровки (алиас: hds whisper-check)
```

Что проверяется на сервере:

* **профиль** — серверный ли режим, включено ли разграничение доступа, заданы ли адреса;
* **база поиска** — доступна ли, в каком режиме записи работает, сколько ждёт освобождения;
* **папки-проекты** — существуют ли, доступны ли, приписаны ли к ним файлы;
* **модели** — ответы, смысловые отпечатки, уточнение порядка найденного: подняты ли, отвечает ли
  служба моделей;
* **службы** — состояние каждой из пяти частей и включён ли автозапуск;
* **раскладка** — из чего запускаются службы (и задания автозапуска, если они есть): из
  `app\current\bin` (обновление и возврат к прежней версии работают) или из простого `<папка>\bin`
  (обновление само переведёт их на версию); предупреждение — если каталог версий есть, а запуск
  идёт не из него;
* **доступ** — сколько пользователей и ключей, есть ли просроченные;
* **журнал действий** — включён ли, где лежит, какого размера;
* **пределы и очередь** — настроенные и фактические значения, нет ли рассогласования, сколько
  ждёт и сколько ждали, сколько отказов. Если запись о состоянии очереди не обновляется, будет
  сказано, что подключение ассистентов не запущено;
* **видеокарты** — какие используются, какими ролями, сколько свободной видеопамяти, уместная
  готовая схема раскладки; предупреждение при смешанных картах или встроенной графике;
* **подменённый файл настроек** — если в папке установки обнаружен посторонний `config.yaml`;
* **служба расшифровки видео/аудио** — работает ли и не осталось ли файла-замка после сбоя.

### Журналы

| Что | Где лежит |
|---|---|
| Журнал действий (кто входил, кто что вызывал, что делал администратор) | служебная папка сервера, `data\logs\audit.jsonl` (+ `audit.jsonl.1` после ротации) |
| Журнал службы моделей | служебная папка сервера, `data\logs\llm-host.log` |
| Журналы служб на Mac | служебная папка сервера, `data/logs/<роль>.out.log` и `<роль>.err.log` |
| Журналы страницы управления | служебная папка сервера; на Windows дополнительно `%LOCALAPPDATA%\hermes-disk-search` (системная учётная запись), на Mac — `/Library/Logs/hermes-disk-search` |
| Ход наполнения базы | служебная папка сервера, `data\…` и файл-признак работы рядом с базой |

### Типичные неполадки сервера

| Что видно | Почему и что делать |
|---|---|
| Подключение ассистентов не отвечает | `hds service status mcp-http`; проверьте `http://127.0.0.1:8787/health`; отказ «нет доступа» в ответе означает, что ключ не передан или просрочен |
| Страница управления отвечает «нет доступа» | это норма при включённом разграничении: откройте её с администраторским ключом (адрес с `?token=<ключ>`) |
| Страница открывается **без** ключа, показывает «не ту» базу, пишет, что служба моделей не найдена | в папке установки оказался посторонний `config.yaml`: переименуйте его (это делает установщик) или закрепите файл настроек и перезапустите службу страницы управления |
| В настройках службы «распознаватель текста не найден» | служба запускается без обычного набора путей: укажите в настройках полный путь к распознавателю и к языковым наборам (установщик делает это сам) |
| Сервер установлен в папке пользователя | перенесите установку в машинную папку — глава «Обновление и откат сервера» |
| Наполнение базы «стоит» | смотрите файл-признак работы: если он помечен как «приостановлено», значит лежит файл `index.pause` — снимите паузу на странице управления |
| Выдача ключа не удалась с отказом доступа | проверьте права на служебную папку сервера: учётной записи администратора нужно право изменять в ней файлы |
| Остановленная служба поднимается снова через несколько секунд | включён автоматический перезапуск — отключите его (глава «Постоянно работающие службы») |
| Служба не находит модели или набор движка | проверьте ссылки на общие папки и переменные, закреплённые за службами (установщик делает это сам, перенос — тоже) |
| Чтение документов падает («поток вывода закрыт») | служебная программа чтения документов не нашла файл настроек — дефект версии 0.20.5, исправлен в 0.20.6: обновитесь (`update.cmd`). На 0.20.6 проверьте, что файл настроек на месте и путь к нему закреплён за службами (`hds check`) |
| В базе появились файлы из корзины, ошибки на путях `$RECYCLE.BIN` / `System Volume Information` | в настройках нет списка `index.exclude_dirs` (стенды, поставленные до 0.20.6). Запустите установщик повторно или выполните `hds config init --path <файл настроек> --merge-defaults`, затем перезапустите службу слежения |
| Ключ доступа не действует сразу после выдачи | проверьте срок и то, что ключ передан целиком; в журнале действий будет запись об отказе |

Если вы просите о помощи, приложите вывод `hds check`, состояние служб и свежие строки журналов.

## 17. Что пользователь делает каждый день

Это глава для пользователей, которые пользуются общим сервером. Её содержание целиком вошло в
памятку пользователя — `installers/client_readme.md` (см. главу «Что ещё почитать»); при желании
администратор может скопировать текст и отсюда.

### Как искать и спрашивать

Ассистент (Cline или Hermes Desktop) обращается к общему серверу сам — отдельные окна для поиска
не нужны. Напишите вопрос обычным текстом:

* «найди техническое задание по складу» — поиск по имени, теме и содержимому;
* «какие сроки указаны в договоре с подрядчиком» — ответ по найденным местам со ссылками на
  источники: видно файл, а для записей — момент времени.

Что полезно знать:

* **видно только доступные вам папки** — то, что вам не выдано, не появится ни в списке, ни в цитатах;
* **одна выдача — это фрагменты, а не список файлов**: на обзорный вопрос ассистента стоит просить
  сделать несколько запросов разными словами — русскими, английскими, сокращениями;
* чем конкретнее вопрос, тем точнее ответ;
* ответы приходят не мгновенно: модель читает найденное и пишет текст на сервере. Обычно это
  десятки секунд, для обзорного вопроса — до нескольких минут;
* если ответ обрывается, повторите вопрос точнее или попросите пересказать короче.

### Что доступно, а что закрыто

| Действие | Доступно пользователю | Что будет при попытке |
|---|---|---|
| Поиск по своим папкам | да | — |
| Ответ по своим файлам | да | — |
| Состояние базы (что и когда обработано) | да | — |
| Запуск и остановка наполнения базы | нет | отказ «требуются права администратора» |
| Пересборка папки заново | нет | отказ «требуются права администратора» |
| Настройки сервера | нет | отказ «недостаточно прав», попытка записывается в журнал |

### Кабинет и расшифровки

Свой кабинет — отдельная страница (`<адрес сервера>/ui/user/`): поиск в браузере, установка
клиента на новый компьютер и работа с расшифровками. Вход — логин и пароль или ключ, выданный
администратором.

Расшифровки: положите запись в общую папку «входящие» (её адрес сообщит администратор) — в папке
«исходящие» появится текст с разделением по говорящим. Имена говорящим присваиваются в кабинете
(или на странице администратора). Помните: **сами расшифровки в поиск не попадают** — чтобы они
искались, их нужно перенести в папку, которая участвует в поиске.

### Если что-то не работает

| Что видно | Что делать |
|---|---|
| «Нет доступа» | ключ не передан, просрочен или отозван: попросите у администратора новый |
| «Слишком много обращений» | подождите указанное время: предел частоты считается на пользователя |
| «Очередь полна» или «не дождался» | все места заняты: повторите запрос через минуту-две |
| Поиск ничего не находит | попробуйте другие слова и синонимы; уточните, в какой папке искать; возможно, эти файлы вам не выданы |
| Ответ приходит очень медленно | так бывает под нагрузкой; повторите позже или задайте вопрос точнее |
| Ассистент не видит поиск | проверьте, что клиент установлен и Cline перезапущен после установки |

Если ничего не помогло — обратитесь к администратору и приложите время, текст вопроса и текст
ошибки.

## 18. Рецепты администратора

Короткие последовательности для частых случаев. Подставьте свои пути и имена.

### 1. Первый запуск сервера с нуля

```powershell
# 1) распаковать архив в ЛЮБУЮ папку (источник), затем — от администратора:
install-server.cmd -Root "C:\Program Files\hermes-disk-search" -WhatIf    # посмотреть план
install-server.cmd -Root "C:\Program Files\hermes-disk-search" `
  -StateDir C:\ProgramData\hermes-disk-search `
  -McpHost 0.0.0.0 -McpPort 8787 -UiHost 0.0.0.0 -UiPort 8765 `
  -Parallel 5 -GpuDevice 1 -Roots "D:\;E:\Archive" `
  -EnableAccess -AdminLogin admin -AdminPassword "<пароль>" -Fetch
# в сводке должно быть: "layout: version <версия> …" и "[ok] service <роль> …"

hds service start llm-host; hds service start watch
hds service start mcp-http; hds service start ui
hds check                                      # убедиться, что всё в порядке (в т.ч. пункт «раскладка»)
hds token new --user admin                     # ключ для страницы управления
```

### 2. Завести пользователя и подключить его компьютер

```powershell
hds user add --login alice --password "<пароль>" --projects "Sales,Docs"
hds token new --user alice --ttl-days 90       # ключ показывается один раз
# на компьютере пользователя:
#   curl.exe -f https://host/mcp/client-install.ps1 -o client-install.ps1
#   powershell -ExecutionPolicy Bypass -File .\client-install.ps1 -Token <ключ> -ServerUrl https://host
# затем перезапустить Cline
```

### 3. Выдать новый ключ взамен утерянного или просроченного

```powershell
hds token list --user alice                    # посмотреть, что выдано и не просрочено ли
hds token revoke --user alice                  # отозвать все прежние
hds token new --user alice --ttl-days 90       # выдать новый и передать пользователю
```

### 4. Закрыть доступ

```powershell
hds user revoke --login alice --projects "Docs"    # забрать одну папку: файлы исчезают сразу
hds user del --login alice                         # закрыть доступ полностью (ключи тоже удаляются)
hds user passwd --login alice --password "<новый>" # сменить пароль: все ключи отзываются
```

### 5. Добавить папку-проект и наполнить базу

1. На странице управления: **Настройки** → добавить папку (для неименованного проекта имя берётся
   из младшей папки) → **Сохранить корни**.
2. Выдать доступ тем, кому она нужна: `hds user grant --login alice --projects "NewProject"`.
3. Запустить наполнение: кнопка **Старт** на странице или `hds index`. Первый прогон по большому
   диску лучше делать ночью.

### 6. Посмотреть, кто что делал

```powershell
Get-Content "$env:ProgramData\hermes-disk-search\data\logs\audit.jsonl" -Tail 50
```

В записях есть время, адрес клиента, логин, событие (вход, отказ, вызов инструмента, действие
администратора, отзыв ключа). Текстов запросов и ключей там нет.

### 7. Обновить сервер и откатить при неудаче

```powershell
update.cmd -WhatIf                    # предпросмотр нового архива
update.cmd                            # обновление (от администратора)
update.cmd -RollbackTo <версия>       # возврат к предыдущей версии
```

Обновление и откат сами переводят службы на нужную версию (`[ok] re-pointed …`). Если после
обновления пункт «раскладка» в `hds check` предупреждает, что роли запускаются не из `app\current`,
— перерегистрируйте их командой `install-server.cmd` из каталога `app\current`.

### 8. Перенести установку в машинную папку

```powershell
installers\migrate_to_machine_root.ps1 -From "C:\Users\<имя>\hds-server" -To "C:\Program Files\hermes-disk-search"
```

### 9. Узнать, что мешает быстрым ответам

```powershell
hds check                  # разделы про очередь, пределы и видеокарты
llm_host status            # что поднято и сколько занято видеопамяти
llm_host devices           # какие видеокарты видит служба моделей
```

Смотрите: не рассогласованы ли число одновременных обращений и предел очереди; не идёт ли в это
время наполнение базы; не заняты ли места одним пользователем (личный предел).

### 10. Включить защищённое соединение

1. Установить промежуточную программу с шифрованием и применить готовый образец из
   `installers/proxy` (в нём открыт наружу только нужный путь).
2. Проверить, что она обращается к серверу по `127.0.0.1:8787` и `127.0.0.1:8765`.
3. В настройках сервера включить `trusted_proxy: true` и перезапустить службы подключения
   ассистентов и страницы управления.
4. Проверить: `https://host/health` отвечает, в ответе видно настоящий адрес клиента; отказ «нет
   доступа» приходит без ключа, и запись об этом появляется в журнале.

### 11. Выдать памятку пользователям

Отдельных действий не нужно: готовая памятка уже лежит в поставке — `installers/client_readme.md`
(в клиентском архиве она же лежит как `README.md`). Скопируйте её пользователям. Если нужен свой
текст, возьмите за основу главы «Подключение клиентского ПК», «Кабинет пользователя» и «Что
пользователь делает каждый день»: в них нет ничего администраторского, а нужное для работы
изложено целиком (там же готовые разделы «Что доступно, а что закрыто» и «Если что-то не работает»).

## 19. Что умеет сейчас и что осталось

### Что умеет

* **разграничение доступа по папкам-проектам:** каждый файл принадлежит проекту, пользователь видит
  только выданные ему проекты — во всех ветках поиска, включая ответы по файлам;
* **пользователи и ключи доступа:** логин и пароль, выдача ключей со сроком действия, отзыв, смена
  пароля, журнал действий;
* **серверный режим:** служебная папка сервера, постоянные службы с автозапуском, работа без
  входа пользователя;
* **защита сети:** выход только через промежуточную программу с шифрованием, ограничение размера
  запросов и числа соединений, ограничение частоты обращений, отказ в доступе как поведение по
  умолчанию;
* **одновременная работа и очередь:** несколько обращений сразу, справедливое распределение
  очереди между пользователями, личные пределы, понятные ответы при перегрузке;
* **ответы облачной ИИ-моделью** вместо местной — если видеокарта не тянет;
* **несколько видеокарт** одного производителя с раскладкой ролей;
* **управление службами и выдача ключей со страницы управления**;
* **установка сервера одной командой**: файл настроек собирается из серверного шаблона и проверяется
  до записи; обновление одним файлом и возврат к предыдущей версии;
* **пакет для клиентского ПК**, который сервер выдаёт сам;
* **расшифровка видео/аудио как постоянная служба** и кабинет пользователя для работы с расшифровками
  и поиска в браузере.

### Известные ограничения (осознанные)

* у учётной записи есть признак «отключён», но отдельной команды для него нет: чтобы закрыть
  доступ, удалите учётную запись;
* адреса службы моделей (`8010`–`8012`) не защищены проверкой доступа: их нельзя публиковать
  наружу, для пользователей открыт только путь подключения ассистентов;
* **обезличивание при ответах облачной ИИ-моделью не сделано:** текст вопроса и найденные
  фрагменты уходят наружу как есть;
* при тесной видеопамяти возможны отдельные долгие ответы: первое обращение под нагрузкой может
  задержаться из-за загрузки модели смысловых отпечатков. На серверном профиле это сглажено —
  такие модели держатся в памяти и поднимаются заранее;
* работа **нескольких карт** и работа на **Mac** на живом железе пока не проверялись;
* выбор видеокарты под конкретный файл при расшифровке видео/аудио срабатывает, только если
  программа-заказчик не указала карту сама;
* проверка **через защищённое соединение на машине с сертификатом** ещё не выполнялась:
  подтверждены отказ без ключа, работа с ключом внутри сети и публикация нужных путей.

### Что планируется сделать дальше

* сводная проверка работоспособности сервера одной страницей: служба моделей, база, слежение за
  файлами, диски;
* резервное копирование базы и восстановление из копии (напоминаем: копировать файл базы «на
  горячую» нельзя);
* расширенная диагностика и обновление с малым простоем;
* проверки под нагрузкой на одной и двух видеокартах и на Mac;
* обезличивание при работе с облачной ИИ-моделью.

## 20. Перечень команд

Команды выполняются из папки установки: `.\bin\hds.exe <команда>` на Windows (в примерах ниже —
просто `hds`), `<папка установки>/bin/hds <команда>` на Mac. Справка — `hds --help`.

Программа живёт в подпапке версии: `<папка установки>\app\current\bin`. Указатель `app\current` —
это активная версия; обновление и возврат к прежней версии подменяют именно его. Корень установки
задаётся при установке (`-Root` на Windows, первый аргумент на Mac) — см. главу «Установка сервера
на Windows».

### Где что лежит

| Что | Сервер | Одиночная установка |
|---|---|---|
| Программа | папка установки (`app\current\bin` при раскладке по версиям) | папка установки |
| Настройки | служебная папка сервера: `%ProgramData%\hermes-disk-search\config.yaml` | `config.yaml` в папке установки |
| База, доступ, журналы | там же: `index.db`, `data\access.yaml`, `data\logs\` | рядом с программой |
| На клиентском ПК | ничего из перечисленного: база, доступ и журналы — только на сервере | — |

| `POST /auth/login` — вход по паролю | все, если доступ включён | «неверные данные» |
| `POST /api/auth/login` — вход в кабинет | все, если доступ включён | то же |
| `POST <путь подключения ассистентов>` — работа ассистента | владельцы действительного ключа | «нет доступа» с подсказкой |
| `GET /health` — проверка связи | все | — (это признак «наш сервер» и его версия) |
| Страница управления `/` и `/ui/` | администратор | «нет доступа»; неадминистратору — «недостаточно прав» |
| Кабинет `/ui/user/` | любой действительный ключ или вход по паролю | «нет доступа» |
| `<путь>/client-install.ps1` и `.sh` | все | — (в скрипте нет секретов) |
| `<путь>/client-package.zip` | владелец действительного ключа | «нет доступа» |

Ответы при перегрузке: «слишком много обращений», «очередь полна», «не дождался» — все с
указанием, сколько подождать перед повтором.
