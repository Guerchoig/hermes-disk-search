# hermes-disk-search v0.2.1

Патч-релиз: стабильность индексации и наблюдателя. Новых фич нет — только исправления.

## Исправления

- **Watcher больше не падает при старте**: сверка индекса с дисками (reconcile)
  упиралась в битые/недописанные Office-файлы (`zipfile.BadZipFile`) и
  обрывала весь процесс наблюдателя — теперь ошибка изоляции: файл помечается
  статусом `error` в БД, индексация и наблюдение продолжаются;
- **Служебные lock-файлы Office (`~$*.xlsx` и т.п.) пропускаются** — раньше
  доходили до openpyxl/docx и вызывали падение всей индексации;
- **UI: защита от двойного запуска** — на Windows два сервера могли молча
  делить порт 8765 (SO_REUSEADDR), и браузер открывал «мёртвую» страницу
  после зависания старого экземпляра; теперь порт предварительно проверяется;
- **Исправлен дедлок в отчёте прогресса** — вложенный захват не-рентерабельного
  замка в `heartbeat_data()`/`_status_line()` зависал индексацию и UI-статус
  (последствия недоделанного рефакторинга конвейера эмбеддингов, конвейер
  откачен к надёжной обработке по одному файлу);
- `ProgressReporter`: инициализация `_seen_ts`/`total` (AttributeError при
  heartbeat без пре-подсчёта);
- статусная строка перестала ронять индексацию в консолях/pipe без юникода
  (cp1251: `UnicodeEncodeError` на символах ⏱/▶/✓ — вывод перекодируется);
- исправлен перепутанный порядок аргументов в `process_file` → `_commit_file`.

## Требования к обновлению

- Перезапустить watcher (или ПК); Hermes Desktop перезапускать не требуется;
- Изменений схемы БД нет; переиндексация `index --full` не требуется —
  индекс совместим, битые файлы дообработаются инкрементально;
- Регрессионные тесты: 74, все зелёные (`python -m unittest discover -s tests`).
