### AG-20 (high). Служебные сообщения `.hds-agent\messages.jsonl` пишутся, но никогда не доставляются агенту (TR-7.6, В-6)

**Файлы:** `crates/hds-agent/src/results.rs:28-31,449-475` (очередь и `append_message`),
`crates/hds-ui/src/agent_session.rs:1126-1167` (`open_session`), `crates/hds-agent/src/run.rs` (нет чтения очереди),
`crates/hds-cli/src/cmd/agent_run.rs:147-151,1140-1141` (читается только история сессии).

**Что не так.** `decide` и склейки меток (`labels_merge_json`/`labels_unmerge_json`) только
дописывают строки в `.hds-agent\messages.jsonl` (`DocumentRejected`, `ConflictDelegated`,
`LabelsMerged`, `LabelsUnmerged`). Поиск по коду не нашёл ни одного читателя этого файла:
ни `open_session` на возобновлении сессии, ни `plan_with`/`prepare`, ни `run::clear_history`,
ни новый `message` в UI очередь не читают и не удаляют. Агент о «Отклонено», «перенеси правки
из `_conflicts`» и «метки теперь обозначаются старшей» не узнаёт — цепочка «пользователь →
агент» разорвана после вкладки A5. В-6 («A4 пишет, A5 доставляет») по факту остался на
половине: A5 пишет вторую половину очереди, но доставка не сделана нигде.

**Почему плохо (TR/I).** TR-7.6: при «Отклонить» и «Поручить агенту» дежурное сообщение —
часть контракта, а не украшение: без него агент считает образ актуальным, хотя он восстановлен
из оригинала или пересоздан из новой версии. Для склеек меток сообщение — единственный способ
агента понять, что младшая метка теперь обозначается старшей. Рукописная пометка в A5.5
«доставка — следующий ход» (AGENT_A5_STAGES.md §3.5) не сопровождается кодом.

**Как проверить.** Решение `reject`/`conflict` → файл `messages.jsonl` растёт (тесты это проверяют);
следующий ход (`POST /api/agent/message` или `hds agent run`) в запросе к провайдеру
`MOCK_REQUESTS` не содержит текста сообщений; файл после хода не укорачивается/не удаляется.

**Как исправить.** В `open_session` (UI) и в CLI-пути `run` при старте/возобновлении сессии:
прочитать очередь, анонимизировать существующим фильтром/снимком (текст уже только метки, но
прогон через фильтр нужен как страховка), подмешать как системную реплику/контекст перед
`gateway.open`, после успешной отправки удалить/обрезать файл. Нужен тест «сообщение в очереди →
следующий ход содержит его текст → файл пуст».

**Цена.** Малая: один читатель + тест; доставка без него — молчаливая потеря управляющего сигнала.

### AG-21 (medium-high). Образы систематически содержат формы, которые NER не выделил (I1)

**Файлы:** `sidecar/hds_anonymize/handlers.py:199-303` (`anonymize`: NER → `project_label_ex`),
`sidecar/hds_anonymize/handlers.py:801-878` (`anonymize_text`: то же), `sidecar/hds_anonymize/handlers.py:882-940`
(`anonymize_path`: NER компонентов), `crates/hds-agent/src/mirror.rs:1084-1110` (`write_image`).

**Что не так.** Сборка образа — только NER по тексту документа. Словарный проход по уже известным
формам проекта (`Vault.project_mappings()`/`snapshot()['labels']`) при сборке не делается:
если NER не выделил значение (слабая модель на короткой строке, падежная форма, склеенное ФИО),
оно остаётся в образе открытым. Независимый скан подтвердил и усилил находку A5.7:
зона — **28 попаданий в 15 образах** (было 22/12), свежий образ того же оригинала — **5**.
По типам это не один сбой: `[ORG_*]` дают 17 попаданий, остальные — `[PERSON_*]`,
`[POSITION_*]`, `[SURNAME_*]`, `[PASSPORT_1]`.

**Почему плохо (TR/I).** I1 формально разрешает «дублирование истории», но инвариант требует,
чтобы агент и его вход были в анонимной зоне: образ — это вход агента. Облако защищено
фильтром (I2 = 0), поэтому утечки наружу нет, но агент читает частично открытое содержание
и может пересказать его в ответах/письмах; деанонимизатор не знает, что форма открыта.
Отчёт A5 это честно фиксирует как долг — но это не «остаточный риск», а дефект фазы A4:
словарная компонента уже есть (`project_mappings`, снапшот — тот же переиспользованный источник,
что у фильтра).

**Как проверить.** `a57_probe.py forms` → `scan zone --skip=agent-state,agent-config`
(выполнено в этом ревью, §2): попадания — только в образах `workspace`, не в `agent-state`.
Свежий образ, собранный из того же оригинала после e2e, даёт 5 попаданий.

**Как исправить.** Два слоя минимум: (1) после NER прогнать `replace_by_value` по
`project_mappings(project_id)` (с границами слова, как в фильтре) — та же семантика, что у
`Filter::Dictionary`; (2) при появлении/изменении меток (склейка, «Скрыть ещё…») пересобирать
образы, где встречается значение, — механизм уже есть (`refresh_label_images` для склеек,
расширить на `label_for_value`). Тест: оригинал с известной формой, которую NER заведомо не
выделяет на короткой строке, → образ без формы.

**Цена.** Средняя. Без этого A6 будет надстраивать автозапуск поверх зоны с открытыми именами.

**Как исправить.** `cmd_token` должен писать токен через `serde_json::Value` со слиянием
(как `Secrets::save`), либо `save_at` должен перечитывать файл и сохранять неизвестные ключи.

### AG-23 (medium). `Mirror::decide` неатомарен: сбой посреди решения оставляет рассинхронизацию реестра и файла (TR-7.6)

**Файлы:** `crates/hds-agent/src/results.rs:500-520` (`accept_variant`), `:522-545` (`reject_variant`),
`:547-638` (`resolve_conflict`/`replace_with_variant`), `:646-699` (`rebuild_image`, `cleanup_decision`).

**Что не так.** Порядок «backup → замена → статус → образ → очистка» соблюдается, но без
транзакционности: если `rebuild_image` падает после замены оригинала (воркер NER недоступен),
оригинал уже заменён, статус уже `accepted`, а образ — старый; `cleanup_decision` тогда не
выполняется, и вариант/основание остаются при статусе `accepted`. Следующий прямой путь
(`is_forward_managed(Accepted) == true`) пересоздаст образ из нового оригинала, но молча, без
сообщения агенту. Аналогично `reject` при сбое `rebuild_image` оставляет вариант и статус
`pending_accept` без следа в `messages.jsonl`.

**Почему плохо.** Пользователь видит «Принять — ошибка», а файл уже заменён. Тесты покрывают
счастливый путь и «файл занят» (замена не удалась — ничего не потеряно), но не сбой воркера
после успешной замены.

**Как проверить.** Mock-воркер, падающий на втором акте (`anonymize_agent`), → `accept`:
оригинал равен варианту, статус `accepted`, образ старый, `pending` не пуст.

**Как исправить.** Компенсирующая логика: при ошибке после замены — откат из backup (или явный
статус `error` + сообщение в `messages.jsonl` + отчёт пользователю «оригинал заменён, образ не
пересоздан — выполните `hds agent sync`»). Тест на падение воркера между шагами.

**Цена.** Средняя (нужна одна ветка компенсации и тест).

## 4. Что сделано хорошо (чтобы не потерять при доработках)

* **Один Python на UI и на демон.** `LazyAnonymizer`/`LazyExtractor` поднимаются лениво и живут
  между проходами; `AgentApi::client` — один клиент на процесс UI; `with_client_mirror` делит
  его с панелью меток, второго Python на ту же `anonymize.db` нет (A5.4 §6 п.37 закрыт кодом).
* **Идемпотентность по sha256.** `orig_sha256`/`issued`/`seen` + `mark_seen` только при изменении;
  повторный `sync --once` — 0 изменений (подтверждено в этом ревью: `agent_sync` 10/10,
  стенд `changes=0` в A57).
* **Конкурентный реестр.** WAL + `busy_timeout=30000` первым `PRAGMA`; тест `two_writers_do_not_lose_rows`
  (40 строк из двух потоков) зелёный и в этом ревью.
* **Неизвестные значения из БД не роняют демон.** `Kind::Unknown`/`Status::Unknown` читаются,
  но не управляются; `reopen_keeps_rows_and_unknown_values_survive` зелёный.
* **Защита от петель `issued`/`seen`.** Маркер `hds-agent/<P>/<id>` + `by_id` + пропуск своего
  маркера в обратном пути; образ агента не перезаписывается прямым путём.
* **«Файл занят» без потерь.** `replace_file` → `PermissionDenied` → `Busy` + откат backup;
  вариант и статус не меняются (TR-7.6 случай 3).
* **Три исхода конфликта — один `decide`.** CLI и вкладка зовут одно ядро `Mirror::decide`;
  `ConflictChoice::{Agent,New,Delegate}` + `copy_variant_to_conflicts` (копируется образ с метками,
  не вариант со значениями — I1/I8).
* **Fail-closed сохранён.** `refresh_if_needed` перед каждым `egress_check` (`vault_rev` → снимок
  при смене), `next_event` дренирует `redacted` первым; Node-тесты 23/23 в этом ревью.
* **Предпросмотр = фактически отправленное.** `preview` прогоняет `egress_preview` (тот же фильтр
  точки `model`), поэтому «что увидит модель» не расходится с реальностью.
* **Ключ только «задан/нет».** `GET /api/agent/settings` не отдаёт значения ключей; `Secrets::save`
  со слиянием + `load_text`/`dig`-проверка каждого пути в `set_agent_values` (A5.7 CRLF-фикс
  подтверждён тестом `agent_scalars_keep_crlf_and_single_section` в этом прогоне).
* **SSE + JSON-фолбэк из одного источника.** `stream_events` и `events_json` построены на
  `AgentApi::events_json`; `Last-Event-ID`, heartbeat `: ping`, закрытие при исчезновении хода.
* **Нет вторых регулярок меток.** `labels.rs`, `validator.rs`, `deanon.rs`, UI — все через
  `hds_core::labels` (AG-1 закрыт на уровне архитектуры).
