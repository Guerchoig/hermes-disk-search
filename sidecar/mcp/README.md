# Свои MCP-серверы в анонимной зоне (`mcp.servers`)

Агент `hds` запускает MCP-серверы из файла
`<P>\agent-config\.cline\data\settings\cline_mcp_settings.json`. Этот файл hds
собирает сам при каждом `hds agent run`: встроенные `disk-search`, `tavily` и
`1c-buddy` плюс **дополнительные серверы из `data/agent/secrets.json`** — общий
блок `mcp.servers`. Так администратор подключает `1c-buddy` или любой другой
MCP-сервер, не меняя код и не пересобирая поставку.

Токен и путь к `.env` — **свои у каждого**: в поставке лежит только шаблон без
секретов. Значения из `mcp.servers` попадают в словарь фильтра PII, поэтому
секрет в `headers`/`env` блокирует запрос, а не уходит наружу.

## Что в шаблоне

`mcp.example.json` — фрагмент `secrets.json` с двумя примерами:

| Имя | Транспорт | Что задаёт |
|---|---|---|
| `1c-buddy` | `stdio` | `command` (путь к `1c-buddy-mcp.exe`) и `args: ["--env-file", "<путь к .env>"]`; токен 1c-buddy лежит в `.env`, не в `secrets.json` |
| `example-http` | `streamableHttp` | `url` и заголовок `Authorization`; замените `<ваш токен>` на реальный |

Поля совпадают с элементом `mcpServers` в `cline_mcp_settings.json`, поэтому
hds вставляет блок как есть. Допустимые транспорты — `stdio`, `streamableHttp`,
`sse` (значение `http` эта версия SDK не принимает).

## Как подключить

1. Скопируйте блок `mcp` из `mcp.example.json` в
   `data/agent/secrets.json` (файл рядом с `projects.json`; путь можно
   переопределить переменной `HDS_AGENT_SECRETS`). Если блок `mcp` уже есть —
   добавьте в него `servers`, не затирая `providers` и `projects`.
2. Замените плейсхолдеры: путь к исполняемому файлу сервера, путь к `.env` и
   токен. `.env` — файл самого MCP-сервера (например, `1c-buddy`), hds его
   читает только через `args`.
3. Проверьте план — hds покажет имена серверов, но не значения:

   ```powershell
   .\hds.exe agent run --project P0001 --dry-run
   ```

   В выводе `mcp.servers` должны появиться `1c-buddy` и `example-http`.
4. Запустите ход:

   ```powershell
   .\hds.exe agent run --project P0001 --prompt "Проверь, что сервер отвечает"
   ```

   Инструменты сервера видны модели как `<имя>__<инструмент>`. Вызовы проходят
   через `mcp_out`/`mcp_in` фильтра: значения заменяются метками, секрет
   блокирует запрос.

## Правила и ограничения

* **Встроенный сервер сильнее.** Если в `secrets.json` есть
  `mcp.onec_buddy.command` (или `agent.mcp.onec_buddy.command`), hds считает
  `1c-buddy` встроенным и запись из `mcp.servers` с тем же именем не
  перетирает его. Остальные имена (`disk-search`, `tavily`) зарезервированы.
* **Только объекты.** Запись `mcp.servers.<имя>` должна быть JSON-объектом;
  строки и массивы игнорируются.
* **Секреты — в словаре фильтра.** `api_key`, `token`, `password`, значения
  `headers` и `env` попадают в словарь PII: если такое значение встретится в
  реплике или аргументах инструмента, запрос блокируется
  (`privacy_filter_unavailable`).
* **Токен проекта не в шаблоне.** `disk-search` подключается hds сам — маршрут
  `/mcp/agent/<P>` и токен проекта берутся из `secrets.json`; в `mcp.servers`
  их дублировать не нужно.
* **Проверка после правки.** `hds agent run --dry-run` не запускает серверы и
  не печатает значения — только имена. Реальный запуск сервера проверяется
  обычным `hds agent run`.
