# RELEASE_NOTES v0.17.0 — веб-интерфейс для администрирования: модель чата, управление MCP

> Релиз фич: UI перепрофилирован в панель администрирования (группы запросов
> убраны), смена модели чата из общего llama-рантайма с аккуратным перезапуском
> llm-host, запуск/остановка общего MCP-сервера из UI, корректный учёт
> шардированных GGUF. Rust-проверки зелёные: `cargo fmt --check`,
> `clippy -D warnings`, `cargo test --workspace`.

## Новое: UI — панель администрирования

* **Группы «Поиск» и «Вопрос (ответ по файлам)» убраны.** UI предназначен
  для администрирования; запросы выполняются агентами (Cline/Hermes),
  MCP-инструментами и CLI (`hds search`, `hds ask`), дублировать их в
  интерфейсе незачем. API `/api/search` и `/api/ask` сохранены.
* **Карточка «Модель чата (общий llama-рантайм)»**: список GGUF из
  `models\chat` общего рантайма машины (с размерами и активной моделью из
  `current.json`). Кнопка «Сменить и перезапустить llm-host» записывает
  манифест и перезапускает резидента **аккуратно**: штатный `/internal/stop`,
  ожидание остановки, разбор устаревшего pid-файла и принудительное
  завершение зависшего процесса — «блокеров» после смены не остаётся.
  Первый ответ после смены — с задержкой (модель грузится лениво).
  Если `llm_server.chat.model` не `shared:chat`, карточка предупреждает,
  что смена манифеста на эту роль не повлияет.
* **Карточка «MCP-сервер disk-search (агенты)»**: текущий статус (работает /
  порт занят чужим сервисом / остановлен, pid, URL) и кнопки
  Запустить/Остановить/Перезапустить общего streamable-http инстанса —
  тот же код управления, что `hds mcp-http` (CLI). Результат сверяется
  с фактом на порту.
* **Автозапуск MCP переведён на `mcp-http start`** (раньше — `mcp-http run`):
  менеджер пишет `data\mcp_http.pid` и завершается, поэтому «Остановить»/
  «Перезапустить» из UI работают и для инстанса, поднятого при входе в
  систему. Дублей не бывает: живой инстанс на порту переиспользуется.

## Новое: шардированные GGUF

* **В списке моделей шарды группируются в одну запись** — имя первого
  фрагмента (`…-00001-of-00003.gguf`), суммарный размер, пометка «N частей».
  Выбрать не-первый фрагмент нельзя: llama.cpp грузит модель по первому
  фрагменту и сам подтягивает остальные части из того же каталога.
* **Бюджет VRAM считает суммарный размер шардов.** Раньше «размер модели»
  брался по одному файлу — для шардированной модели оценка занижалась
  в N раз, и диспетчер мог пустить её в VRAM без должного запаса.

## Требования к обновлению

* Штатное обновление поверх 0.16.x: распаковать архив, `setup.cmd`/`setup.ps1`
  (или `installers\update.ps1`); переиндексация не требуется.
* После обновления перезапустите llm-host (кнопка в UI).
* **Автозапуск**: перерегистрируйте задачи один раз
  (`powershell -NoProfile -ExecutionPolicy Bypass -File install_autostart.ps1`),
  чтобы задача MCP встала на `mcp-http start` — иначе кнопки управления
  MCP в UI не смогут остановить инстанс автозапуска.
