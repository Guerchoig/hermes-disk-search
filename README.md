# Hermes Disk Search — поиск и ответы по своим файлам на одном компьютере

Эта программа ищет файлы на дисках компьютера — по имени, по теме и по содержимому, — а также
отвечает на вопросы по найденному. Всё считается на самой машине: ни документы, ни вопросы
никуда не отправляются. Интернет нужен один раз, при установке, — чтобы загрузить модели.

Работать с программой можно двумя способами:

* **страница управления в браузере** — повседневная работа и настройка;
* **командная строка** — отдельные действия и случаи, когда нужна автоматизация.

Этот документ описывает программу, установленную на **одном компьютере**, которым пользуетесь
вы один. Если поиск нужен сразу нескольким людям через общий сервер, читайте второй документ —
`README_SERVER_MULTIUSER.md`; он лежит рядом с этим файлом.

## 1. Что это за программа и что она умеет

Возможности простыми словами:

* **поиск по файлам** — по имени, по теме и по содержимому документов; отдельно ищутся
  картинки — по тому, что на них изображено;
* **ответ по своим файлам** — программа находит подходящие места в документах и составляет по
  ним связный ответ со ссылками на источники: видно файл, а для документов ещё страницу, а для
  записей — момент времени;
* **расшифровка записей** — если положить аудио- или видеофайл в назначенную папку, программа
  сама сделает текстовую расшифровку с разделением по говорящим;
* **слежение за файлами** — изменения на дисках подхватываются в фоне, поэтому заново запускать
  поиск после правок не нужно;
* **подключение ИИ-ассистентов** — Cline и Hermes Desktop могут обращаться к поиску как к
  своему инструменту, и тогда вы задаёте вопросы обычным текстом прямо в них.

Программа состоит из нескольких частей, которые работают незаметно для вас: страница
управления, база поиска, служба моделей на видеокарте, служба слежения за файлами и небольшая
служебная программа для чтения документов. Что делает каждая часть и как они связаны — в главе
«Как это работает».

## 2. Что нужно от компьютера

| Что | Требование |
|---|---|
| Основная система | Windows 10 или Windows 11, 64-битная |
| Дополнительная система | Mac на процессоре Apple Silicon (чипы серии M): программа для неё собирается, но на живой машине пока не проверялась |
| Видеокарта | **не обязательна**. Без видеокарты NVIDIA программа работает, но медленнее. Рекомендуется NVIDIA с объёмом памяти 8 ГБ и более |
| Свободное место | около 12 ГБ на программу и модели, плюс место под базу поиска (зависит от объёма дисков) |
| Интернет | нужен один раз, при установке: загрузить модели и набор файлов движка |
| Права администратора | не нужны. Для автозапуска установщик спросит согласие и создаст задания в планировщике заданий Windows |
| Java 11 и новее | нужна **только** для файлов Microsoft Project (`.mpp`). Без неё остальные форматы читаются как обычно |
| Распознавание текста на картинках | по желанию: ставится распознаватель Tesseract |
| Расшифровка записей | по желанию: догружаются модель распознавания речи и модель разделения по говорящим |

## 3. Установка на Windows: по шагам, от скачивания до первого поиска

Общий порядок для обычного случая: скачали файлы → распаковали → запустили `setup.cmd` → он всё
поставит сам → задали папки для поиска → запустили наполнение базы.

### Шаг 1. Скачайте файлы со страницы выпусков

Откройте `https://github.com/Guerchoig/hermes-disk-search/releases/latest` и скачайте архивы.
В именах файлов ниже подставьте свою версию вместо `0.14.0`.

| Файл | Нужен ли | Что это |
|---|---|---|
| `hds-<версия>-windows-x64.zip` (около 210 МБ) | да | сама программа: папка `bin` с исполняемыми файлами, установщик `setup.cmd`, папка `installers` со служебными сценариями, служебная программа `sidecar`, сведения о наборе движка в папке `runtime-manifests`, ярлыки, образец настроек `config.example.yaml` |
| `hds-<версия>-windows-x64.zip.sha256.txt` | по желанию | контрольный отпечаток архива — чтобы проверить, что он скачался целиком (шаг 2) |
| `hds-engine-runtime-windows-x64-cuda.zip` (около 570 МБ) | только для установки без интернета | набор файлов движка: он отвечает за модели ответов и за распознавание речи. Предназначен для видеокарт NVIDIA. Для машин без NVIDIA есть такой же набор `hds-engine-runtime-windows-x64-vulkan.zip` (около 90 МБ). При обычной установке эти архивы не нужны: установщик скачает нужный сам по сведениям из папки `runtime-manifests` |
| `hermes-disk-search-<версия>-windows.zip` | нет | исходный текст программы — только если вы собираете её сами |

Модели в архив не входят: установщик загрузит их сам. Это модель ответов, модель смысловых
отпечатков и модель переранжирования — вместе около 9 ГБ, а также по желанию модель
распознавания речи (около 1,5 ГБ) и модели поиска по картинкам (около 850 МБ). Все они ложатся
в общую папку моделей компьютера `%LOCALAPPDATA%\llama-runtime\models\`.

### Шаг 2 (необязательно). Проверьте, что архив скачался целиком

```powershell
Get-FileHash .\hds-0.14.0-windows-x64.zip -Algorithm SHA256   # отпечаток скачанного архива
Get-Content .\hds-0.14.0-windows-x64.zip.sha256.txt           # ожидаемый отпечаток из выпуска
```

Строка во втором файле начинается с ожидаемого отпечатка. Сравните его с выводом первой
команды: значения должны совпасть.

### Шаг 3. Распакуйте архив в отдельную папку

Например, в `D:\hds` (щелчок правой кнопкой по архиву → «Извлечь всё…»). Подойдёт любая папка;
права администратора не нужны. **Не распаковывайте архив поверх работающей программы**: Windows
не даст заменить запущенный файл. Для обновления есть отдельный порядок действий — глава
«Обновление и удаление».

### Шаг 4. Запустите `setup.cmd` двойным щелчком

Файл-запускатель снимает с содержимого архива пометку «скачано из интернета» (иначе Windows
потребует подпись для сценариев PowerShell) и передаёт работу установщику. Вопросов при обычной
установке больше не задаётся: нужное ставится автоматически, а отказаться можно отдельным
указанием при запуске.

| Что ставится | Что это даёт | Как отказаться |
|---|---|---|
| Библиотеки Microsoft Visual C++ и ffmpeg | запуск программы и чтение медиафайлов | нельзя отключить |
| Распознаватель текста Tesseract | текст на картинках и сканах | `-SkipOcr` |
| Набор файлов движка (около 90–200 МБ) | модели ответов и распознавание речи | `-SkipEngine` |
| Модели (около 9 ГБ) | поиск по содержимому и ответы по файлам | `-SkipModels` |
| Модель распознавания речи, модели поиска по картинкам, модель разделения по говорящим | расшифровка записей, поиск картинок по содержанию, метки говорящих | `-SkipWhisper`, `-SkipClip`, `-SkipDiarization` |
| Порядок «папка → расшифровка» | текстовая расшифровка записей; папки создаются, если их ещё нет | `-SkipTranscribe` |
| Задания автозапуска и задача для страницы управления | служба слежения за файлами, служба моделей и подключение ассистентов поднимаются сами | `-NoAutostart` |
| Подключение Cline и Hermes, ярлык «Hermes Disk Search», файл настроек | готовность к работе сразу после установки | `-SkipIntegrations` |
| Проверка состояния в конце установки | видно, что установлено, а что осталось | нельзя отключить |

Первый запуск занимает от 10 до 40 минут: почти всё время уходит на загрузку моделей. Если
установка идёт без участия человека (например, на удалённой машине), добавьте
`-NonInteractive` — сценарий не будет ждать нажатия клавиши.

### Шаг 5. Проверьте результат

```powershell
cd D:\hds
.\bin\hds.exe check
```

В выводе будет список компонентов с пометками. Пометка «в порядке» должна стоять у базы данных,
папок поиска, модели ответов, модели смысловых отпечатков, распознавания текста, ffmpeg, разбора
русских слов, чтения файлов Microsoft Project, модели переранжирования, видеокарты и службы
моделей. Строки про распознавание речи и Vulkan помечены как «проверяется вручную» — это норма.
Если модели ответов и смысловых отпечатков помечены как недоступные, значит не запущена служба
моделей (шаг 7).

### Шаг 6 (при необходимости). Установка без интернета

На машине с интернетом скачайте архив программы **и** набор файлов движка под свою видеокарту:
`hds-engine-runtime-windows-x64-cuda.zip` для NVIDIA или
`hds-engine-runtime-windows-x64-vulkan.zip` для AMD и Intel. Распакуйте программу (шаг 3),
положите набор движка туда, где его ищет служба моделей, и запустите установщик, пропустив
загрузку движка и моделей:

```powershell
# распаковать набор движка в ожидаемое место
$engine = Join-Path $env:APPDATA 'OpenResearchTools\TranscribeOffline\Engine'
New-Item -ItemType Directory -Force $engine | Out-Null
Expand-Archive .\hds-engine-runtime-windows-x64-cuda.zip -DestinationPath $engine -Force
# для машины без NVIDIA — тот же путь, но архив с vulkan в имени

# поставить всё, кроме скачиваемого движка и моделей
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -SkipEngine -SkipModels
```

Модели можно принести на сменном носителе и разложить вручную в
`%LOCALAPPDATA%\llama-runtime\models\` по ролям: `chat\` — модель ответов, `embedding\` — модель
смысловых отпечатков, `rerank\` — модель переранжирования. Для модели ответов нужен
дополнительно файл `chat\current.json` с именем файла модели: проще всего получить его, один
раз запустив сценарий `installers\fetch_llm_models.ps1` там, где интернет есть.

### Шаг 7. Служба моделей (если вы отказались от автозапуска)

Служба моделей держит модели в памяти и занимает видеокарту. Запустить её в отдельном окне:

```powershell
.\bin\llm_host.exe run
```

Либо поставить ей автозапуск:

```powershell
powershell -File installers\install_llm_host_task.ps1 -Start
```

Модели загружаются при первом обращении, поэтому первый ответ после запуска будет с задержкой.
Состояние службы (какие модели подняты, сколько занято видеопамяти) показывает команда
`.\bin\llm_host.exe status`, а список видеокарт — `.\bin\llm_host.exe devices`.

### Шаг 8. Задайте папки для поиска и запустите наполнение базы

Папки, которые нужно обработать, перечисляются в файле настроек `config.yaml`, в разделе
`index.roots` (в образце настроек указан весь диск `D:\`). Удобнее всего задать их на странице
управления — см. главу «Повседневная работа», подглаву «Страница управления в браузере». Можно
и сразу запустить ярлык **«Индексация дисков»** на рабочем столе (или сценарий
`.\run_index.ps1`): тогда будут обработаны папки, уже записанные в настройках.

Первое наполнение базы для диска с сотнями тысяч файлов идёт **часами**: чтение документов,
распознавание текста на картинках, расчёт смысловых отпечатков. Обычно это запускают на ночь.
Ход работы виден на странице управления; прервать можно кнопкой «Стоп» или служебным файлом
`index.stop`. Повторные запуски догоняют только изменения, а служба слежения за файлами
подхватывает правки в фоне.

### Шаг 9. Откройте страницу управления

Ярлык **«Hermes Disk Search»** на рабочем столе (или сценарий `.\run_ui.ps1`) открывает страницу
управления в браузере: `http://127.0.0.1:8765`. Если ярлыка нет или страница не открылась,
запустите `.\bin\hds.exe ui` в командной строке и откройте этот адрес вручную; причина неудачи
записана в журнал `%LOCALAPPDATA%\hermes-disk-search\ui.err.log`.

Порядок действий на странице:

1. **Настройки** → перечислить папки для поиска → **Сохранить корни**;
2. там же — исключения (мусорные каталоги: временные файлы программ, служебные папки) → **Сохранить исключения**;
3. **Состояние** → **Старт** (или **Полная**, если нужно пересобрать базу с нуля); **Пауза** и
   **Продолжить** позволяют на время разгрузить диск;
4. **Модель ответов** — выбрать модель из общего набора; **Служба моделей** — запуск, остановка
   и состояние.

Подробнее обо всех блоках — глава «Повседневная работа», подглава «Страница управления в
браузере».

### Шаг 10. Подключение ИИ-ассистента (по желанию)

Установщик уже подключил Cline и Hermes Desktop, если они есть на машине. Поставили их позже —
повторите подключение:

```powershell
cd D:\hds
.\install_hermes.ps1
.\install_cline.ps1
```

После подключения перезапустите ассистента: он читает настройки моделей и подключений при
запуске. Синхронизировать настройки в любой момент можно кнопкой «Синхронизировать настройки
Cline» на странице управления или командой `.\bin\hds.exe cline-sync`.

### Шаг 11. Обновление и удаление — коротко

Обновление выполняется отдельным процессом, а не «поверх работающей программы»: распакуйте новый
архив в любую папку и запустите `update.cmd` двойным щелчком. Подробности, включая возврат к
предыдущей версии и полное удаление, — в главе «Обновление и удаление».

## 4. Установка на Mac

Раздел самодостаточный: всё, что нужно сделать на Mac, перечислено здесь.

### Шаг 1. Скачайте программу

Со страницы выпусков `https://github.com/Guerchoig/hermes-disk-search/releases/latest` скачайте
архив `hds-<версия>-macos-arm64.zip`. Набор файлов движка скачивать не нужно: установщик заберёт
его сам по сведениям из папки `runtime-manifests` и проверит отпечаток.

### Шаг 2. Распакуйте архив

Например, в папку `~/hds`.

### Шаг 3. Запустите установщик

Двойной щелчок по файлу `install_macos.command`. Если система откажется запускать файл из
загруженного архива (карантин), нажмите на него правой кнопкой → «Открыть», либо выполните в
терминале `bash install_macos.command`.

### Шаг 4. Что установщик делает по шагам

1. снимает карантин с содержимого архива;
2. копирует исполняемые файлы в `~/.local/bin` и подсказывает, что делать с путями поиска
   программ, если этой папки там ещё нет;
3. создаёт файл настроек `config.yaml` из образца, если файла ещё нет;
4. загружает набор файлов движка в `~/Library/Application Support/OpenResearchTools/TranscribeOffline/Engine`;
5. создаёт ярлыки на рабочем столе («Hermes Disk Search» — страница управления, «Индексация
   дисков» — наполнение базы) и приложение «HDS Индексация» в `~/Applications`;
6. ставит автозапуск: `local.hds.watch` (слежение за файлами), `local.hds.mcp` (подключение
   ассистентов), `local.hds.llmhost` (служба моделей) — файлы в `~/Library/LaunchAgents`;
   отключить автозапуск можно, запустив установщик с указанием `HDS_NO_AUTOSTART=1`;
7. загружает модели и в конце выполняет проверку состояния.

### Шаг 5. Проверьте результат

```bash
~/.local/bin/hds check
```

Пометки в выводе означают то же, что и на Windows (шаг 5 главы про установку на Windows):
пометка «в порядке» должна стоять у базы данных, папок поиска, модели ответов, модели смысловых
отпечатков, распознавания текста, ffmpeg, разбора русских слов, чтения файлов Microsoft Project,
модели переранжирования, видеокарты и службы моделей. Строки про распознавание речи и Vulkan
помечены как «проверяется вручную» — это норма.

### Шаг 6. Задайте папки для поиска и запустите наполнение базы

Ярлык **«Hermes Disk Search»** на рабочем столе открывает страницу управления
`http://127.0.0.1:8765`. Там задаются папки для поиска (**Настройки** → **Сохранить корни**),
исключения и запуск обработки (**Состояние** → **Старт**). Можно поступить и проще: запустить
ярлык **«Индексация дисков»** — тогда обрабатываются папки, записанные в файле настроек
`config.yaml` (раздел `index.roots`).

Первое наполнение базы для диска с сотнями тысяч файлов идёт часами, обычно его запускают на
ночь. Повторные запуски догоняют только изменения.

### Шаг 7. Служба моделей

На Mac она поднимается автозапуском. Проверить состояние и запустить вручную:

```bash
~/.local/bin/llm_host status    # какие модели подняты, сколько занято видеопамяти
~/.local/bin/llm_host run       # запуск в отдельном окне терминала
```

### Шаг 8. Обновление

Распаковав новый архив, выполните:

```bash
sudo bash installers/update.command                        # обновление
sudo bash installers/update.command -RollbackTo <версия>   # возврат к предыдущей версии
```

Сценарию нужен установленный PowerShell 7 (команда `pwsh`). Если программа поставлена не как
служба, а обычным способом, добавьте указание корня: `-Root <папка>`.

### Шаг 9. Удаление

Удалите папку с программой, приложение `~/Applications/HDS Индексация`, файлы автозапуска
`~/Library/LaunchAgents/local.hds.*`, а по желанию — модели и набор файлов движка (папки внутри
`~/Library/Application Support`) и журналы в `~/Library/Logs/hermes-disk-search`.

### Шаг 10. Важное уточнение

Сборка для Mac делается «по возможности» и на живой машине пока не проверялась; порядок проверки
описан в чек-листе `tools/parity/MAC_CHECKLIST.md`. Журналы страницы управления и автозапуска
лежат в `~/Library/Logs/hermes-disk-search/`.

## 5. Что где лежит на диске

В таблице «папка установки» — та папка, куда вы распаковали архив (в примерах `D:\hds` на
Windows и `~/hds` на Mac).

| Что | Где на Windows | Где на Mac | Можно ли удалять |
|---|---|---|---|
| Программа | папка установки: `bin` с исполняемыми файлами, `installers`, `sidecar` | папка установки + копии исполняемых файлов в `~/.local/bin` | да, если удаляете программу целиком (глава «Обновление и удаление») |
| Файл настроек `config.yaml` | в папке установки | в папке установки | нет: пропадут папки поиска, исключения и все параметры |
| База поиска `index.db` | в папке установки (точный путь задаёт ключ `db_path`) | там же | да, но базу придётся собирать заново — это часы работы |
| Модели общего набора: ответы, смысловые отпечатки, переранжирование (около 9 ГБ) | `%LOCALAPPDATA%\llama-runtime\models` | `~/Library/Application Support/llama-runtime/models` | да, скачаются заново |
| Модели распознавания речи и разделения по говорящим | `%APPDATA%\OpenResearchTools\models` | `~/Library/Application Support/OpenResearchTools/models` | да, скачаются заново |
| Набор файлов движка | `%APPDATA%\OpenResearchTools\TranscribeOffline\Engine` | `~/Library/Application Support/OpenResearchTools/TranscribeOffline/Engine` | да, скачается заново |
| Журналы страницы управления | `%LOCALAPPDATA%\hermes-disk-search` | `~/Library/Logs/hermes-disk-search` | да |
| Ярлыки и автозапуск | рабочий стол; задания планировщика `HermesDiskSearch*` | рабочий стол; файлы `~/Library/LaunchAgents/local.hds.*` | да, но пропадёт автозапуск |
| Служебные файлы (признак работы, пауза, остановка) | в папке установки | в папке установки | смотря какой — см. главу «База поиска и служебные файлы» |

## 6. Как это работает

По шагам и без технических подробностей:

1. **Обход дисков.** Программа идёт по папкам, перечисленным в настройках, и пропускает то, что
   её не касается: исключения, слишком большие файлы, временные и служебные файлы.
2. **Чтение содержимого.** Из документов вынимается текст — в том числе с картинок и сканов,
   если включён распознаватель. Из записей получается расшифровка.
3. **Разбивка на фрагменты.** Длинный текст делится на небольшие части: так поиск находит
   точное место, а не «файл целиком».
4. **Смысловые отпечатки.** Для каждой части считается числовой слепок смысла. Он позволяет
   находить близкие по смыслу места, даже если в запросе использованы другие слова.
5. **База поиска.** Всё вместе хранится в одном файле `index.db`.

Поиск соединяет два подхода: сравнение слов (быстро и точно по терминам) и сравнение смысловых
отпечатков (находит перефразированное). Ответ по файлам — это найденные фрагменты плюс текст,
который составляет модель ответов; в тексте есть ссылки на источники, по которым видно, откуда
взята каждая мысль.

Части программы и их роли:

| Часть | Адрес | Зачем она нужна |
|---|---|---|
| Страница управления | `127.0.0.1:8765` | настройка, состояние, запуск и остановка обработки |
| Служба моделей | `127.0.0.1:8010` — ответы, `127.0.0.1:8011` — смысловые отпечатки, `127.0.0.1:8012` — переранжирование | держит модели в памяти и отвечает на запросы остальных частей |
| Подключение ассистентов | `127.0.0.1:8787`, путь `/mcp` | единая точка, через которую Cline и Hermes обращаются к поиску |
| Служба слежения за файлами | без адреса | следит за изменениями на дисках в фоне |
| Служебная программа чтения документов | без адреса | читает офисные файлы, PDF, картинки; она же разбирает русские слова для поиска по словам |

Адреса `8010`–`8012` и `8787` открыты только на этом же компьютере: снаружи их не видно, и
менять это не нужно.

## 7. Повседневная работа

### 7.1. Поиск из командной строки

Поиск ничего не генерирует и отвечает за доли секунды:

```powershell
hds search "техническое задание" --limit 8
hds search "SAP" --kinds docx,pdf --limit 20
hds search "отчёт" --json
```

Уточнения означают следующее: `--limit` — сколько результатов показать; `--kinds` — какие виды
файлов учитывать (например `text`, `pdf`, `docx`); `--json` — вывод в машинном виде, удобный для
дальнейшей обработки. Команды запускаются из папки установки, то есть в виде
`.\bin\hds.exe search "техническое задание"` — полный список команд с пояснениями собран в главе
«Перечень команд».

### 7.2. Ответ на вопрос по своим файлам

```powershell
hds ask "какие требования к срокам?" --limit 8
hds ask "какие есть технические задания" --limit 30 --json
```

Ответ собирает модель на вашем компьютере: она читает найденные фрагменты и пишет связный текст.
Один ответ занимает от нескольких десятков секунд до нескольких минут — это нормально и зависит
от объёма найденного и от видеокарты. В тексте есть ссылки вида `[1]`, `[2]`, по ним видно, из
какого файла взята каждая мысль.

Уточнение `--limit` задаёт глубину выборки: для обзорных вопросов вида «какие есть…» ставьте
15–30, для точного вопроса достаточно 8.

### 7.3. Работа через ИИ-ассистента

Если ассистент подключён (глава «Подключение ИИ-ассистентов»), вы просто пишете ему вопрос
обычным текстом, а он сам вызывает поиск и отвечает со ссылками на файлы. Что полезно знать:

* **одна выдача — это фрагменты, а не список файлов.** Поэтому на обзорный вопрос вида «найди
  все…» ассистент должен сделать несколько запросов разными словами; так и просите его в
  задании, если ответ кажется неполным;
* чем конкретнее вопрос, тем точнее ответ: «какие сроки указаны в договоре с подрядчиком» лучше,
  чем «расскажи про договоры»;
* у ассистента есть ограничение на длину ответа за один ход, поэтому длинные ответы он выдаёт
  частями;
* на медленных машинах (видеокарта встроенная) включите режим экономии: в файле настроек
  `config.yaml` задайте `cline.slow_machine: true` и выполните `hds cline-sync` — ассистент
  получит правило бережливого поиска (один вызов за ход, мало результатов, без обращения к
  интернету).

### 7.4. Страница управления в браузере

**Как открыть.** Проще всего — ярлык **«Hermes Disk Search»** на рабочем столе: он поднимает
страницу управления и открывает браузер по адресу `http://127.0.0.1:8765`. Если ярлыка нет,
запустите вручную:

```powershell
cd D:\hds
.\run_ui.ps1
# или напрямую:
.\bin\hds.exe ui
```

и откройте адрес `http://127.0.0.1:8765` в браузере. Если страница не открылась, смотрите журнал
`%LOCALAPPDATA%\hermes-disk-search\ui.err.log`. На Mac страница открывается ярлыком «Hermes Disk
Search», а вручную — командой `~/.local/bin/hds ui`.

**Порядок действий при первом запуске.**

1. **Настройки** → перечислить папки для поиска → **Сохранить корни**.
2. Там же — **исключения** (мусорные каталоги: временные файлы программ, служебные папки) →
   **Сохранить исключения**. Файл настроек правится на странице с сохранением пояснений в нём.
3. **Состояние** → **Старт** (обычная обработка) или **Полная** (пересобрать базу с нуля).
   **Пауза** и **Продолжить** позволяют на время разгрузить диск или уступить его другим
   задачам.
4. **Служба моделей** — состояние, запуск и остановка; там же **модель ответов** — выбор из
   общего набора моделей на компьютере (после выбора служба перезапускается, ход загрузки виден
   на карточке).
5. **Подключение ассистентов** — состояние и запуск; **Настройки Cline** → «Синхронизировать
   настройки Cline», если вы пользуетесь этим ассистентом.
6. **Расшифровка записей** — на отдельной закладке; о ней — следующая глава.

Страница управления — это пульт настройки, а не окно поиска: поиск и вопросы выполняются через
ассистента или командную строку, как описано выше.

### 7.5. Пауза и остановка обработки

Обработкой можно управлять кнопками на странице управления (**Пауза**, **Продолжить**,
**Стоп**), а можно теми же действиями через служебные файлы в папке установки:

| Файл | Что означает |
|---|---|
| `index.pause` | обработка приостановлена: программа обходит диск и ждёт, пока файл не уберут |
| `index.stop` | сигнал аккуратно закончить текущую обработку |
| `index.heartbeat.json` | запись о ходе работы: сколько сделано и не стоит ли она на паузе |

Если кажется, что обработка «стоит», откройте этот последний файл: признак `"paused": true`
означает, что лежит файл `index.pause`. При этом служба моделей могла поставить паузу сама —
чтобы не мешать ответам на вопросы. Она снимает её, когда ответы закончатся; если пауза осталась
«насовсем», удалите файл `index.pause` вручную.

**Важное различие:** служба слежения за файлами (её состояние видно на странице управления, блок
«Служба слежения за файлами») файлы `index.pause` и `index.stop` **не читает**: её обход
останавливается только остановкой самой службы — кнопками на странице управления или командой
`hds watch` не запускать. Служба моделей и служба слежения — независимые части: одна
перезапускается своей кнопкой, вторая своей.

### 7.6. Обслуживание базы поиска

```powershell
hds status                             # сколько файлов и фрагментов, сколько ошибок
hds reindex "D:\Договоры"               # обработать заново папку или файл
hds reindex-fts                        # перестроить поиск по словам
hds forget "D:\Старое"                  # убрать папку или файл из базы
hds clip-index                         # дозаполнить поиск по картинкам
hds db-move --to "E:\hds\index.db"      # перенести базу в другое место
hds index --full                       # пересобрать данные целиком
hds index --roots "D:\;E:\Архив"        # разово обработать другие папки
hds index --kinds text,pdf              # ограничить виды файлов
hds index --limit 20 --no-prune         # пробный прогон: 20 файлов, ничего не удаляя
hds index --rechunk                    # заново нарезать текст (после смены размера фрагмента)
```

Когда что применять:

* после правки нескольких файлов ничего запускать не нужно — служба слежения подхватит
  изменения сама;
* поиск по словам перестраивают после изменения правил разбора русских слов (`reindex-fts`);
* вид файлов и размер фрагмента лучше менять сразу после установки: смена размера фрагмента
  требует повторной нарезки текста (`--rechunk`), то есть длительной обработки.

## 8. Расшифровка записей (распознавание речи в папках)

Отдельная возможность: положить аудио- или видеофайл в назначенную папку — и получить текстовую
расшифровку с разделением по говорящим. Работает по порядку «папка → папка».

### Настройка

В файле настроек `config.yaml` есть раздел `auto_transcribe`:

```yaml
auto_transcribe:
  enabled: true              # включить обработку
  inbox_dir: 'D:\media_in'   # сюда кладём записи
  out_dir:   'D:\media_out'  # здесь появляются расшифровки
```

Папки исключаются из обхода поиска автоматически: и сами записи, и полученные расшифровки в
базу поиска не попадают.

### Что происходит с файлом

1. служба видит в папке «входящие» **готовый** (дописанный) файл;
2. одним обращением к движку выполняются распознавание речи и разделение по говорящим;
3. полученный текст сохраняется в папку «исходящие» как файл с расширением `.md`;
4. исходная запись удаляется — **только если расшифровка прошла успешно**. Поведение задаётся
   ключом `source_disposal`: `delete` (удалять, по умолчанию), `keep` (оставлять), `move`
   (переносить в папку `source_disposal_dir`).

Повторно один и тот же файл не обрабатывается: ведётся журнал уже обработанных файлов, а число
попыток ограничено.

### Вид расшифровки и имена говорящих

Реплики размечены заголовками: `### SPEAKER_00 [00:00:01 - 00:00:11]` — то есть говорящий и
время. Реплика, которую не удалось связать с говорящим, помечается как `### UNASSIGNED […]`.
Рядом со расшифровкой в служебной папке лежат два файла: `.orig.md` — текст до подстановки имён
и `.speakers.json` — таблица соответствия «метка → имя». Перед любой правкой расшифровки
создаётся её копия с расширением `.bak`, поэтому испортить текст случайно нельзя.

Имена говорящим присваиваются на странице управления, закладка **«Расшифровка записей»**:

* список расшифровок в папке «исходящие» с предпросмотром текста;
* таблица «Говорящий — Имя»: заполненные строки подставляются в текст, пустые остаются как есть;
* кнопка **«Присвоить имена говорящим»**, кнопка **«Перезапустить задание»** и поля для папок
  «входящие» и «исходящие» (сохраняются в файл настроек). Рядом с каждым полем показано,
  исключена ли эта папка из обхода поиска.

### Если расшифровки нужно искать

**Важно:** полученные текстовые расшифровки в поиск сами не попадают — папка «исходящие»
специально исключена из обхода, чтобы расшифровка не читалась как документ и не попадала в
базу вторично. Если расшифровки должны находиться поиском, **перенесите нужные файлы `.md`
вручную** в одну из папок, которые входят в список папок поиска (`index.roots`). Только после
этого они будут прочитаны и попадут в базу — при следующем запуске обработки или автоматически,
когда служба слежения заметит новые файлы.

### Управление и порядок важности

* Служба расшифровки запускается автозапуском. Вручную — команды `hds transcribe-watch` (работать
  в режиме службы), `hds transcribe-once "D:\media_in\запись.m4a"` (обработать один файл прямо
  сейчас, не дожидаясь очереди), `hds transcribe-stop` (аккуратно остановить службу).
  Двойной запуск невозможен: его не допускает служебный файл-замок `transcribe.lock`. Если замок
  остался после сбоя, об этом сообщает проверка состояния.
* Управлять расшифровкой можно и со страницы управления: там показано состояние (работает,
  остановлена, «замок без процесса») и есть кнопки **Запустить**, **Остановить**,
  **Перезапустить**.
* Порядок важности при нехватке видеопамяти: сначала поиск и ответы на вопросы, затем
  расшифровка, затем наполнение базы. Расшифровка ставит наполнение базы на паузу; запрос к
  ассистенту может вытеснить расшифровку, а наполнение базы — нет.
* Если возможность включена, но ещё не запускалась ни одна запись, запуск честно предупредит об
  этом: пока не появится файл в папке «входящие», службе нечего делать.
* Для расшифровки нужна отдельная модель разделения по говорящим (около 449 МБ). Без неё задание
  не выполняется: догрузить её можно сценарием
  `powershell -File installers\fetch_diarization_model.ps1`.

## 9. Подключение ИИ-ассистентов (Cline, Hermes Desktop)

Подключённый ассистент умеет обращаться к поиску как к своему инструменту: вы пишете вопрос
обычным текстом, а он сам находит файлы и отвечает со ссылками. Никаких дополнительных окон для
поиска при этом не нужно.

### Как подключить

Обычно делать ничего не нужно: установщик подключает Cline и Hermes Desktop, если они уже есть
на машине. Если вы поставили их позже — повторите подключение в любой момент:

```powershell
cd D:\hds
.\install_hermes.ps1     # Hermes Desktop
.\install_cline.ps1      # Cline (настольная версия или работа в командной строке)
```

На Mac — `bash installers/install_hermes_macos.sh` и `bash installers/install_cline_macos.sh`.
Повторный запуск ничего не дублирует. После подключения **перезапустите ассистента**: настройки
подключений и моделей читаются при его запуске.

### Что записывается на диск

| Что | Где | Когда применяется |
|---|---|---|
| Запись о поиске как инструменте | `%USERPROFILE%\.cline\data\settings\cline_mcp_settings.json` и `%USERPROFILE%\.cline\mcp.json` | при запуске ассистента |
| Правило поведения | `~/.cline/rules/disk-search.md` | всегда: правило добавляется в задание каждой беседы |
| Подсказка по требованию | `~/.cline/skills/disk-search/SKILL.md` | только если модель сама её запросит |
| Размеры контекста моделей | `~/.cline/data/settings/models.json` | при запуске ассистента |

Размеры контекста показывают ассистенту, сколько текста помещается в одно обращение. Без этого
он сжимает историю беседы раньше, чем это нужно, и теряет найденное. Поэтому синхронизацию
настроек стоит повторять после смены модели или числа одновременных обращений.

### Зачем и правило, и подсказка

Программа отдаёт ассистенту вступительный текст при подключении, но не все ассистенты его
используют: Cline, например, не добавляет его в задание. Поэтому смысл продублирован двумя
файлами, и оба ставит одна команда. Правило работает всегда и доносит главное: **одна выдача —
это фрагменты, а не список файлов**, и на обзорный вопрос нужно несколько запросов разными
словами. Подсказка срабатывает по требованию и содержит более подробные советы.

### Инструменты, которые видит ассистент

| Инструмент | Что делает |
|---|---|
| поиск файлов (`search_local_files`) | ищет по имени, теме и содержимому |
| ответ по моим файлам (`ask_my_files`) | собирает ответ по найденным фрагментам со ссылками |
| состояние базы (`index_status`) | показывает, что и когда обработано, есть ли ошибки |
| запуск наполнения базы (`start_indexing`) | запускает обход дисков |
| остановка наполнения базы (`stop_indexing`) | аккуратно останавливает обход |
| пересборка папки (`reindex_path`) | обрабатывает заново указанный файл или папку |

### Синхронизация настроек

```powershell
hds cline-sync              # записать настройки заново
hds cline-sync --dry-run    # только показать, что будет изменено
```

То же делает кнопка «Синхронизировать настройки Cline» на странице управления. Отчёт говорит,
что изменилось, и напоминает о перезапуске ассистента.

### Потолок длины ответа

Общую длину одного ответа задаёт ключ `chat.max_tokens`. Если он мал, ответы обрываются на
полуслове; для ответов по файлам есть отдельный, более короткий потолок `chat.rag_max_tokens`.
Оба ключа описаны в главе «Настройки».

## 10. Служба моделей на видеокарте (llm-host)

**Это не ассистент и не собеседник.** Служба моделей — служебная часть программы: она держит
модели в памяти (занимая видеокарту) и отвечает на запросы других частей по внутренним адресам.
Своих вопросов ей задать нельзя, окна у неё нет.

Что она держит:

| Что | Адрес | Для чего |
|---|---|---|
| Модель ответов | `127.0.0.1:8010` | составление ответов по файлам |
| Модель смысловых отпечатков | `127.0.0.1:8011` | поиск по смыслу во время обхода дисков и при поиске |
| Модель переранжирования | `127.0.0.1:8012` | уточнение порядка найденного |
| Распознавание речи | без отдельного адреса | расшифровка записей |

Команды (запускаются из папки установки):

```powershell
.\bin\llm_host.exe run            # запустить службу в отдельном окне
.\bin\llm_host.exe status         # что поднято, сколько занято видеопамяти
.\bin\llm_host.exe devices        # список видеокарт и их номера
.\bin\llm_host.exe load chat      # поднять одну роль заранее
.\bin\llm_host.exe unload chat    # выгрузить роль
.\bin\llm_host.exe stop           # аккуратно остановить службу
```

Модели загружаются при первом обращении, поэтому первый ответ идёт медленнее последующих.

**Кто уступает видеопамять.** Ключ `gpu.policy` задаёт порядок: `query_priority` — ответы на
вопросы важнее обхода дисков (обход ставится на паузу на время ответа), `indexing_priority` —
наоборот, `manual` — решаете вы сами. Пауза, выставленная вами вручную, службой не снимается.

**Сколько обращений одновременно.** Для одиночного компьютера по умолчанию — одно: ответы идут
по очереди, чтобы не переполнить видеопамять. Изменить это можно ключами `llm_server.parallel`
(сколько обращений сразу) и `llm_server.chat.ctx_per_slot` (сколько текста помещается в одно
обращение). Перед запуском служба проверяет, поместится ли выбранное в память, и при нехватке
отказывается запускаться, показывая числа и подсказывая, что уменьшить. Молчаливого замедления
не бывает.

**Если видеокарты нет** — служба работает на Vulkan или на процессоре: медленнее, но полностью
работоспособно. Можно взять модель ответов поменьше.

**Автозапуск:** задание в планировщике заданий Windows (ярлык создаёт установщик), либо команда
`powershell -File installers\install_llm_host_task.ps1 -Start`. На Mac — файл автозапуска
`local.hds.llmhost`.

## 11. Чтение документов, таблиц и картинок

Основную работу выполняют части, написанные на языке Rust. Но для чтения готовых офисных
форматов и для разбора русских слов используется отдельная небольшая служебная программа на
Python — её называют `sidecar`. Причина простая: для этих задач есть проверенные библиотеки,
переписывать их не имеет смысла.

Что программа умеет читать:

| Вид файлов | Что извлекается |
|---|---|
| Обычный текст, текстовые документы | сам текст |
| PDF | текст постранично; для сканов — распознавание текста как изображения |
| Документы, таблицы и презентации Word, Excel, PowerPoint | текст с разбивкой по листам и страницам |
| Картинки и сканы | текст на изображении (если включён распознаватель Tesseract) |
| Файлы Microsoft Project (`.mpp`) | задачи и их свойства (нужна Java 11 и новее) |
| Аудио и видео | не читаются: их текст даёт расшифровка записей (глава 8) |

Как эта программа устроена и почему это безопасно:

* она работает отдельным процессом и общается с основной программой сообщениями, а не внутри
  общего процесса: сбой при чтении одного файла не роняет всю программу;
* основная программа запускает её по необходимости и сама ей управляет; если чтение не
  требуется, процесс не работает;
* в поставке эта программа уже собрана вместе со своей средой выполнения — отдельно ставить
  Python не нужно. Требуется он только тем, кто собирает программу из исходного текста.

Пересобрать её можно так:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File installers\build_sidecar.ps1 `
    -OutDir dist\sidecar -SelfTest
```

Ключи `-SelfTest` достаточно, чтобы убедиться: собранная программа отвечает на проверочный
запрос.

Если в проверке состояния строка про разбор русских слов или про чтение файлов Microsoft Project
помечена не как «в порядке», смотрите главу «Если что-то не получилось»: чаще всего дело в
отсутствующей Java (для `.mpp`) или в распознавателе текста, который не найден службой.

## 12. Настройки

Все настройки лежат в одном текстовом файле `config.yaml` в папке установки. Полный образец со
всеми ключами и пояснениями — файл `config.example.yaml` (он же попадает в архив выпуска).
Файл настроек правится с сохранением пояснений двумя способами: на странице управления
(**Настройки** → списки папок и исключений, закладка расшифровки → папки обработки) или в
текстовом редакторе — тогда программу нужно перезапустить.

Ниже — разделы и ключи, которые меняют чаще всего.

| Раздел и ключ | Что делает |
|---|---|
| `index.roots` | папки, которые обрабатываются. Можно указать всю папку диска (`D:\`) |
| `index.exclude_dirs`, `index.exclude_paths` | что пропускать (временные файлы программ, служебные каталоги, папки с обновлениями) |
| `index.max_file_mb`, `index.max_media_mb` | предельные размеры файлов; крупнее — не читаются |
| `index.ocr` | включить распознавание текста на картинках и сканах |
| `index.ocr_lang` | языки распознавания (`rus`, `eng`, …) |
| `index.ocr_tesseract_cmd`, `index.ocr_tessdata` | где лежит распознаватель и языковые наборы (нужны, если программа работает как служба) |
| `index.max_chunks` | предельное число фрагментов на один файл |
| `db_path` | путь к файлу базы поиска. Для версионной установки лучше указывать полный путь |
| `chunk.size`, `chunk.overlap` | размер фрагмента текста и перекрытие между соседними фрагментами |
| `embedding.base_url`, `embedding.model`, `embedding.dim` | адрес службы моделей и модель для смысловых отпечатков (обычно менять не нужно) |
| `chat.base_url`, `chat.model` | какой моделью составлять ответы |
| `chat.thinking` | разрешать ли модели «размышлять» перед ответом (`off` — быстрее, `auto` — по обстоятельствам) |
| `chat.temperature` | степень свободы формулировок: меньше — точнее и суше |
| `chat.max_tokens` | потолок длины одного ответа. Слишком мало — ответы обрываются |
| `chat.rag_max_tokens` | отдельный, более короткий потолок для ответов по файлам |
| `chat.max_context_chars` | сколько текста из найденного помещается в одно обращение к модели |
| `chat.provider`, `chat.api_key` | ответы может давать внешняя служба вместо местной модели (нужен ключ к ней). Тогда вопрос и найденные фрагменты уходят наружу — обезличивание пока не сделано, поэтому включайте это только для доверенной службы |
| `search.vec_k`, `search.fts_k`, `search.rrf_k` | сколько кандидатов брать при поиске по смыслу и по словам и как их объединять |
| `rerank.enabled`, `rerank.url`, `rerank.model` | уточнение порядка найденного отдельной моделью |
| `watch.debounce_seconds`, `watch.reconcile_on_start` | как служба слежения ждёт окончания правки файла и что пересматривает при старте |
| `gpu.policy`, `gpu.device_index`, `gpu.n_gpu_layers` | какой видеокартой пользоваться и кто кому уступает память (0 — процессор, 1 — первая видеокарта) |
| `gpu.reserve_mb`, `gpu.evict_idle_sec` | запас видеопамяти, который не занимаем, и когда выгружать простаивающие модели |
| `llm_server.host`, `llm_server.chat.ctx_per_slot`, `llm_server.parallel` | адрес службы моделей, длина контекста одного обращения и сколько обращений выполнять одновременно |
| `mcp_http.host`, `mcp_http.port`, `mcp_http.path` | адрес и путь подключения ассистентов |
| `ui.host`, `ui.port` | адрес страницы управления (по умолчанию `127.0.0.1` и `8765`) |
| `auto_transcribe.*` | порядок «папка → папка» для расшифровки записей (глава 8) |
| `cline.slow_machine` | бережливый режим для ассистента на медленных машинах |
| `extract.idle_timeout` | через сколько секунд простоя закрывать служебную программу чтения документов |
| `profile` | `desktop` — обычный одиночный режим (значение по умолчанию) |

Переменные окружения, которые иногда нужны при запуске вручную: `HDS_CONFIG` — путь к другому
файлу настроек, `HDS_ROOT` — другая папка данных, `HDS_ENGINE_DIR` — другой набор файлов
движка, `HDS_EXTRACT_PYTHON` — другой Python для служебной программы.

## 13. База поиска и служебные файлы

### Из чего состоит база

База поиска — один файл `index.db`. Внутри неё:

* перечень обработанных файлов и их свойства (путь, размер, время правки, вид, состояние);
* фрагменты текста, на которые разбиты документы;
* поиск по словам — с разбором русских слов, поэтому «договор» находится и по слову «договоры»;
* смысловые отпечатки фрагментов — числа, по которым ищется близкое по смыслу;
* отдельный набор чисел для поиска картинок по изображению.

База открывается в надёжном режиме записи: рядом с ней могут появляться служебные файлы
`index.db-wal` и `index.db-shm` — это нормально, удалять их вручную нельзя. **Копировать базу
копированием файла во время работы нельзя** — получится повреждённая копия. Для переноса
используйте команду `hds db-move`, а для резервной копии — средства самой базы (`VACUUM INTO`
или `.backup` в программе `sqlite3`), иначе обязательно останавливайте все части программы перед
копированием.

Поиск и ответы читают базу, не мешая её наполнению: можно искать, пока идёт обработка дисков.

### Служебные файлы в папке установки

| Файл | Что означает |
|---|---|
| `index.pause` | обработка приостановлена; убрать файл — работа продолжится |
| `index.stop` | сигнал закончить обработку после текущего файла |
| `index.heartbeat.json` | ход работы: сколько сделано, не на паузе ли обработка |
| `watch.lock` | запись о работе службы слежения за файлами (защита от второго запуска) |
| `data\llm-host.pid`, `data\logs\` | запись о работе службы моделей и журналы |
| `transcribe.lock`, `transcribe.stop` | то же для службы расшифровки записей |

### Если база создана другой версией программы

Состав базы со временем меняется. Если программа обнаружит, что база создана более старой
версией и ей не подходит, она пересоздаст её (сообщение об этом появится в выводе). После этого
нужен полный обход дисков: `hds index --full`. Перед обновлением крупных версий стоит заранее
запланировать такой прогон, например на ночь.

## 14. Обновление и удаление

### Обновление

Обновлять программу «поверх работающей» нельзя: Windows не даёт заменить запущенный файл. Поэтому
используется раскладка по версиям: в папке установки есть подпапка `app` со вложенными папками
версий и указателем `app\current` на активную. Настройки, база и модели при этом общие и не
переписываются.

**Порядок действий (Windows).**

1. Скачайте и распакуйте новый архив в **любую** папку (можно временную).
2. В распакованной папке запустите двойным щелчком файл **`update.cmd`**. Он сам снимет пометку
   «скачано из интернета», сам найдёт папку установки и её версию, остановит задания автозапуска
   и службу моделей, поставит новую версию, переключит указатель и запустит всё обратно.
3. Проверьте состояние: `.\bin\hds.exe check` (или ярлык проверки на странице управления).

**Возврат к предыдущей версии** — прошлые версии сохраняются, поэтому откат выполняется той же
программой из распакованного архива:

```powershell
update.cmd -RollbackTo <версия>     # например, 0.20.1
```

Посмотреть, какие версии установлены, и выполнить то же вручную можно через служебный сценарий:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File installers\update.ps1 -Root D:\hds -ListVersions
powershell -NoProfile -ExecutionPolicy Bypass -File installers\update.ps1 -Root D:\hds -From <архив> -Version <версия>
```

На Mac обновление выполняет `installers/update.command` (глава «Установка на Mac», шаг 8).

**Что сохраняется при обновлении:** файл настроек, база поиска, модели, журналы. Что меняется:
исполняемые файлы и служебные сценарии.

**Если обновление не прошло:** вернитесь к прошлой версии (`-RollbackTo`) и посмотрите вывод
сценария — он печатает, на каком шаге произошёл сбой. Частая причина на Windows — занятый файл:
закрыть ассистента, остановить службу моделей и повторить.

### Установка конкретной версии в отдельную папку

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File installers\install_app_version.ps1 `
    -From hds-0.20.2-windows-x64.zip -Version 0.20.2 -Root D:\hds -SetCurrent
```

Полезно, если нужно держать несколько версий рядом. При такой раскладке путь к базе в настройках
лучше указывать полным (или как `data\index.db`): относительный путь привяжет базу к конкретной
версии, и она перестанет быть общей.

### Удаление

1. Удалите папку с программой (в примерах `D:\hds` или `~/hds`).
2. Удалите ярлыки с рабочего стола и задания автозапуска: в планировщике заданий Windows —
   задания с именами `HermesDiskSearch*`; на Mac — файлы `~/Library/LaunchAgents/local.hds.*`.
3. По желанию освободите место: модели — `%LOCALAPPDATA%\llama-runtime`, набор файлов движка —
   `%APPDATA%\OpenResearchTools`, журналы и служебные данные — `%LOCALAPPDATA%\hermes-disk-search`
   (на Mac пути из главы «Что где лежит на диске»).
4. Удалите базу `index.db`, если она вам больше не нужна.

Перед удалением закройте ассистента и остановите службу моделей — иначе часть файлов будет занята.

## 15. Перечень команд

Все команды запускаются из папки установки как `.\bin\hds.exe <команда>` (на Mac —
`~/.local/bin/hds <команда>`). Общая справка — `hds --help`, справка по команде — `hds <команда> --help`.

### Поиск и ответы

| Команда | Что делает |
|---|---|
| `hds search "слова" --limit 8` | поиск по имени, теме и содержимому; `--kinds` ограничивает виды файлов, `--json` даёт машинный вывод |
| `hds ask "вопрос" --limit 8` | ответ по найденным фрагментам со ссылками на источники |
| `hds status` | состояние базы: сколько файлов по видам, сколько фрагментов, сколько ошибок |
| `hds check` | проверка состояния всех частей и компонентов (с ключом `--json` — машинный вывод) |

### Наполнение базы

| Команда | Что делает |
|---|---|
| `hds index` | обработка папок из настроек; повторный запуск догоняет изменения |
| `hds index --full` | обработать всё заново, не пропуская по времени правки |
| `hds index --roots "D:\;E:\Архив"` | разово обработать указанные папки |
| `hds index --kinds text,pdf` | ограничить виды файлов |
| `hds index --limit 20 --no-prune` | пробный прогон на 20 файлах, ничего не удаляя |
| `hds index --rechunk` | заново нарезать текст (после смены размера фрагмента) |
| `hds index --progress-sec 10 --quiet` | как часто показывать ход работы; `--quiet` — без вывода |
| `hds watch [--roots "D:\"]` | служба слежения за файлами (в фоне) |
| `hds reindex <путь> [--no-force]` | обработать заново один файл или папку |
| `hds reindex-fts` | перестроить поиск по словам (после смены разбора русских слов) |
| `hds forget <путь>` | убрать файл или папку из базы |
| `hds clip-index` | дозаполнить поиск по картинкам |
| `hds stop` | сигнал закончить обработку (служебный файл `index.stop`) |
| `hds db-move --to <путь>` | перенести базу в другое место |

## 16. Если что-то не получилось

| Что видно | Почему и что делать |
|---|---|
| Windows предупреждает о неизвестном издателе при запуске программы | сборка не подписана: нажмите «Подробности» → «Выполнить в любом случае» |
| PowerShell отказывается выполнять сценарий («выполнение сценариев отключено» или «требуется подпись») | запускайте установку и обновление через файл-запускатель (`setup.cmd`, `update.cmd`). Для прямого запуска сценария добавьте: `powershell -NoProfile -ExecutionPolicy Bypass -File setup.ps1` |
| Проверка состояния: модели ответов и смысловых отпечатков недоступны | не запущена служба моделей: `.\bin\llm_host.exe run` |
| Первый ответ очень долгий, дальше быстрее | модели загружаются в память при первом обращении — это нормально, последующие ответы быстрее |
| Обработка дисков стоит на месте | проверьте `index.heartbeat.json`: признак `"paused": true` означает, что лежит файл `index.pause`. Снимите паузу кнопкой «Продолжить» на странице управления или удалите файл |
| Страница управления не открывается | запустите `.\bin\hds.exe ui` в командной строке; затем откройте `http://127.0.0.1:8765`. Причина неудачи — в журнале `%LOCALAPPDATA%\hermes-disk-search\ui.err.log` |
| На странице управления «распознаватель текста не найден» | включите распознавание текста и выполните `installers\configure_ocr.py` |
| Файлы Microsoft Project (`.mpp`) не читаются | нужна Java 11 и новее |
| Узел подключения ассистентов не отвечает, адрес занят | `hds mcp-http status` — посмотрите, что занимает адрес `8787`, освободите его и выполните `hds mcp-http restart` |
| Программа ffmpeg не находится после установки | откройте новое окно командной строки: путь к программам обновляется при запуске окна |
| Видеокарты NVIDIA нет | программа работает: движок уходит на Vulkan или на процессор, но медленнее. Можно взять модель ответов поменьше |
| Ответы ассистента обрываются на полуслове | увеличьте `chat.max_tokens`, а если обрывается сама выдача — `chat.max_context_chars` |
| Простые вопросы идут, а обзорные — нет | попросите ассистента сделать несколько запросов разными словами: одна выдача — это фрагменты, а не список файлов |
| Ассистент «не успевает» и запрос обрывается по времени | включите режим экономии: `cline.slow_machine: true` в настройках и затем `hds cline-sync` |
| Расшифровки записей не находятся поиском | перенесите нужные файлы `.md` из папки «исходящие» вручную в папку, которая входит в список папок поиска (глава 8) |
| Расшифровка не запускается | проверьте, включена ли она (`auto_transcribe.enabled`), есть ли модель разделения по говорящим (около 449 МБ) и не остался ли файл-замок от сбоя: `hds check` подскажет |
| После обновления поиск пуст | проверьте, не пересоздана ли база: в этом случае нужен полный обход `hds index --full` |

## 17. Проверка состояния и журналы

Проверка состояния — первое, что стоит выполнять при любых сомнениях:

```powershell
hds check            # понятный человеку вывод
hds check --json     # машинный вывод
```

Что она проверяет:

* **профиль работы** — одиночный режим или серверный;
* **база поиска** — доступна ли, какой режим записи используется;
* **папки поиска** — существуют ли указанные папки, доступны ли для чтения;
* **модель ответов, смысловых отпечатков и переранжирования** — подняты ли, отвечает ли служба
  моделей;
* **распознавание текста** — найден ли распознаватель и языковые наборы;
* **чтение документов и файлов Microsoft Project** — работает ли служебная программа, есть ли
  Java;
* **видеокарта** — какая используется, сколько памяти занято, кто её занимает: программа или
  посторонний процесс;
* **служба расшифровки** — работает ли, не остался ли файл-замок от сбоя;
* **очередь и ограничения** — сколько обращений выполняется и сколько ждёт (подробно это описано
  в серверном документе);
* **строки «проверяется вручную»** — то, что нельзя проверить автоматически: распознавание речи
  и работа без видеокарты.

Журналы:

| Что | Windows | Mac |
|---|---|---|
| Страница управления | `%LOCALAPPDATA%\hermes-disk-search\ui.log` и `ui.err.log` | `~/Library/Logs/hermes-disk-search/` |
| Служба моделей | `data\logs\llm-host.log` в папке установки | там же |
| Действия (кто что делал) | `data\logs\audit.jsonl` — ведётся в серверном режиме | там же |

Если вы просите о помощи, приложите вывод `hds check`, свежие строки журналов и описание того,
что делали перед сбоем.

## 18. Для разработчика

### Из чего состоит программа

Исходный текст разложен по папкам с понятными назначениями:

| Папка | Что внутри |
|---|---|
| `crates/hds-core` | настройки, база данных, обмен по сети, список пользователей и ключей доступа, диагностика |
| `crates/hds-extract` | связь со служебной программой чтения документов |
| `crates/hds-index` | обход дисков, слежение за файлами, расшифровка записей, диагностика |
| `crates/hds-llama` | работа с движком и служба моделей |
| `crates/hds-clip` | поиск картинок по изображению |
| `crates/hds-search` | поиск по словам и по смыслу, составление ответа, переранжирование |
| `crates/hds-mcp` | подключение ассистентов |
| `crates/hds-ui` | страница управления |
| `crates/hds-cli` | командная строка `hds` |

Служебная программа чтения документов на Python — папка `hds` (исходный текст) и `sidecar`
(собранный вид).

### Сборка и проверки

```powershell
cargo build --release -p hds-cli -p hds-mcp -p hds-llama
cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
```

Часть автоматических проверок помечена как требующая живой среды и при обычном прогоне
пропускается. Если сборка падает с отказом в доступе к исполняемому файлу — его держит
запущенная служба моделей: остановите её перед сборкой.

### Выпускной архив

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File installers\build_rust_release.ps1 -Version 0.1.0
```

Ключ `-SkipBuild` использует уже собранные файлы. Состав архива, порядок выпуска и требования к
нему описаны в `RELEASING.md`; сборка выпуска проверяется в непрерывной интеграции (файл
`.github/workflows/release.yml`).

### Наши исправления движка

Программа работает на стороннем движке, для которого мы несём собственный набор исправлений
(без них часть поведения службы моделей работает неверно). Подробности и порядок самостоятельной
сборки — в `engine-patch/README.md`. Поставить или снять исправления:

```powershell
powershell -File installers\fetch_engine_runtime.ps1 -PatchEngine
powershell -File installers\fetch_engine_runtime.ps1 -RollbackEnginePatch
```

### Что осталось на Python

Только служебная программа чтения документов и разбора русских слов. Остальные части были
перенесены на язык Rust; журнал этого перехода и текущие состояния — `STATUS.md` и
`MIGRATION_PLAN_RUST.md`.

### Заметки об окружении

* сценарии PowerShell сохранены в однобайтовой кодировке и содержат только латиницу: русские
  подписи в них искажаются;
* в тексте сценариев имя переменной пишется в фигурных скобках: `${name}`, иначе символ «:»
  после имени будет понят разбором как имя диска;
* поиск русских слов средством `Select-String` работает ненадёжно — надёжнее открыть файл и
  прочитать его целиком;
* работа с хранилищем версий кода: всегда указывайте `--no-pager`, иначе вывод останавливается
  на страницах.

### Лицензии сторонних частей

Движок, библиотеки CUDA, ffmpeg, распознаватель текста, библиотека чтения PDF, средства работы с
Microsoft Project, модели и их лицензии перечислены в `NOTICE.md`.
