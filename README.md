# Hermes Disk Search — поиск и ответы по своим файлам на одном компьютере

Эта программа ищет файлы на дисках компьютера — по имени, по теме и по содержимому, — а также
отвечает на вопросы по найденному. Всё считается на самой машине: ни документы, ни вопросы
никуда не отправляются. Интернет нужен один раз, при установке, — чтобы загрузить модели.

Работать с программой можно двумя способами:

* **страница управления в браузере** — повседневная работа и настройка;
* **командная строка** — отдельные действия и случаи, когда нужна автоматизация.

Этот документ описывает программу, установленную на **одном компьютере**, которым пользуетесь
вы один. Если поиск нужен сразу нескольким пользователям через общий сервер, читайте второй документ —
`README_SERVER_MULTIUSER.md`; он лежит рядом с этим файлом.

## 1. Что это за программа и что она умеет

Возможности простыми словами:

* **поиск по файлам** — по имени, по теме и по содержимому документов; отдельно ищутся
  картинки — по тому, что на них изображено;
* **ответ по своим файлам** — программа находит подходящие места в документах и составляет по
  ним связный ответ со ссылками на источники: видно файл, а для документов ещё страницу, а для
  записей — момент времени;
* **расшифровка видео/аудио** — если положить аудио- или видеофайл в назначенную папку, программа
  сама сделает текстовую расшифровку видео/аудио с разделением по говорящим;
* **анонимизация документов** — документ можно «скрыть»: имена, организации, адреса, телефоны
  и другие персональные данные заменяются метками вида `[PERSON_1]`, а обратная операция
  возвращает исходный текст из базы меток; работает на этом же компьютере (глава 19);
* **слежение за файлами** — изменения на дисках подхватываются в фоне, поэтому заново запускать
  поиск после правок не нужно;
* **подключение ИИ-ассистентов** — Cline и Hermes Desktop могут обращаться к поиску как к
  своему инструменту, и тогда вы задаёте вопросы обычным текстом прямо в них.

Программа состоит из нескольких компонентов, которые работают незаметно для вас: страница
управления, база поиска, служба моделей на видеокарте, служба слежения за файлами и небольшая
служебная программа для чтения документов. Что делает каждый компонент и как они связаны — в главе
«Как это работает».

## 2. Что нужно от компьютера

| Что | Требование |
|---|---|
| Основная система | Windows 10 или Windows 11, 64-битная |
| Дополнительная система | Mac на процессоре Apple Silicon (чипы серии M): программа для неё собирается, но на живой машине пока не проверялась |
| Видеокарта | **не обязательна**. NVIDIA — основной путь (расшифровка на CUDA, рекомендуется 8 ГБ и более). AMD/Intel — профиль DirectML; на **встроенной** графике он медленнее процессора, поэтому там выбирается профиль CPU. Без видеокарты всё работает медленнее |
| Свободное место | около **20–30 ГБ**: программа и модели поиска (~12 ГБ), Python-стек расшифровки (1,5–7,4 ГБ в зависимости от профиля), плюс место под базу поиска |
| Интернет | нужен один раз, при установке: загрузить модели, набор файлов движка и Python-стек расшифровки |
| Права администратора | не нужны. Для автозапуска установщик спросит согласие и создаст задания в планировщике заданий Windows |
| Java 11 и новее | нужна **только** для файлов Microsoft Project (`.mpp`). Без неё остальные форматы читаются как обычно |
| Распознавание текста на картинках | по желанию: ставится распознаватель Tesseract |
| Расшифровка видео/аудио | по желанию: ставятся Python-стек (GigaAM-v3 + pyannote, 1,5–7,4 ГБ) и модели (~3–4 ГБ); профиль выбирается по видеокарте |

## 3. Установка на Windows: по шагам, от скачивания до первого поиска

Общий порядок для обычного случая: скачали файлы → распаковали → запустили `setup.cmd` → он всё
поставит сам → задали папки для поиска → запустили наполнение базы.

### Шаг 1. Скачайте файлы со страницы выпусков

Откройте `https://github.com/Guerchoig/hermes-disk-search/releases/latest` и скачайте архивы.
В именах файлов ниже подставьте свою версию вместо `0.14.0`.

| Файл | Нужен ли | Что это |
|---|---|---|
| `hds-<версия>-windows-x64.zip` (около 210 МБ) | да | сама программа: папка `bin` с исполняемыми файлами, установщик `setup.cmd`, папка `installers` со служебными сценариями, служебная программа `sidecar`, сведения о наборе движка в папке `runtime-manifests`, ярлыки, образец настроек `config.example.yaml` |
| `hds-<версия>-windows-x64.zip.sha256.txt` | по желанию | контрольный отпечаток архива — чтобы проверить, что он скачался целиком (шаг 2) |
| `hds-engine-runtime-windows-x64-cuda.zip` (около 570 МБ) | только для установки без интернета | набор файлов движка: он отвечает за ИИ-модели и за распознавание речи. Предназначен для видеокарт NVIDIA. Для машин без NVIDIA есть такой же набор `hds-engine-runtime-windows-x64-vulkan.zip` (около 90 МБ). При обычной установке эти архивы не нужны: установщик скачает нужный сам по сведениям из папки `runtime-manifests` |
| `hermes-disk-search-<версия>-windows.zip` | нет | исходный текст программы — только если вы собираете её сами |

Модели в архив не входят: установщик загрузит их сам. Это ИИ-модель, модель смысловых
отпечатков и модель переранжирования — вместе около 9 ГБ, а также по желанию модель
распознавания речи (около 1,5 ГБ) и модели поиска по картинкам (около 850 МБ). Все они ложатся
в общую папку моделей компьютера `%LOCALAPPDATA%\llama-runtime\models\`.

### Шаг 2 (необязательно). Проверьте, что архив скачался целиком

```powershell
Get-FileHash .\hds-0.14.0-windows-x64.zip -Algorithm SHA256   # отпечаток скачанного архива
Get-Content .\hds-0.14.0-windows-x64.zip.sha256.txt           # ожидаемый отпечаток из выпуска
```

Строка во втором файле начинается с ожидаемого отпечатка. Сравните его с выводом первой
команды: значения должны совпасть.

### Шаг 3. Распакуйте архив в отдельную папку

Например, в `D:\hds` (щелчок правой кнопкой по архиву → «Извлечь всё…»). Подойдёт любая папка;
права администратора не нужны. **Не распаковывайте архив поверх работающей программы**: Windows
не даст заменить запущенный файл. Для обновления есть отдельный порядок действий — глава
«Обновление и удаление».

### Шаг 4. Запустите `setup.cmd` двойным щелчком

Файл-стартер снимает с содержимого архива пометку «скачано из интернета» (иначе Windows
потребует подпись для сценариев PowerShell) и передаёт работу установщику. Вопросов при обычной
установке больше не задаётся: нужное ставится автоматически, а отказаться можно отдельным
указанием при запуске.

| Что ставится | Что это даёт | Как отказаться |
|---|---|---|
| Библиотеки Microsoft Visual C++ и ffmpeg | запуск программы и чтение медиафайлов | нельзя отключить |
| Распознаватель текста Tesseract | текст на картинках и сканах | `-SkipOcr` |
| Набор файлов движка (около 90–200 МБ) | ИИ-модели и распознавание речи | `-SkipEngine` |
| Модели (около 9 ГБ) | поиск по содержимому и ответы по файлам | `-SkipModels` |
| **Python-стек расшифровки** (GigaAM-v3 + pyannote, 1,5–7,4 ГБ) | распознавание речи и разделение по говорящим; профиль выбирается по видеокарте (`-TranscribeProfile cuda\|cpu\|dml`) | `-SkipTranscribeStack` |
| **Модели расшифровки** (GigaAM ~1 ГБ, wav2vec2 ~1,2 ГБ, pyannote ~1,2 ГБ) | загружаются в машинную папку моделей; для gated-моделей нужен токен Hugging Face (`-HfToken` или переменная `HF_TOKEN`) | `-SkipTranscribeModels` |
| Модели поиска по картинкам | поиск картинок по содержанию | `-SkipClip` |
| Старые модели распознавания/диаризации (whisper GGML, Nemotron-3, Sortformer) | **только для отката** `transcribe.engine: legacy` | `-SkipWhisper`, `-SkipDiarization` |
| Порядок «папка → расшифровка видео/аудио» | текстовая расшифровка видео/аудио; папки создаются, если их ещё нет | `-SkipTranscribe` |
| Задания автозапуска и задача для страницы управления | служба слежения за файлами, служба моделей и подключение ассистентов поднимаются сами | `-NoAutostart` |
| Подключение Cline и Hermes, ярлык «Hermes Disk Search», файл настроек | готовность к работе сразу после установки | `-SkipIntegrations` |
| Проверка состояния в конце установки | видно, что установлено, а что осталось | нельзя отключить |

Первый запуск занимает от 10 до 40 минут: почти всё время уходит на загрузку моделей. Если
установка идёт без участия пользователя (например, на удалённой машине), добавьте
`-NonInteractive` — сценарий не будет ждать нажатия клавиши.

### Шаг 5. Проверьте результат

```powershell
cd D:\hds
.\bin\hds.exe check
```

В выводе будет список компонентов с пометками. Пометка «в порядке» должна стоять у базы данных,
папок поиска, ИИ-модели, модели смысловых отпечатков, распознавания текста, ffmpeg, разбора
русских слов, чтения файлов Microsoft Project, модели переранжирования, видеокарты и службы
моделей. Строки про распознавание речи и Vulkan помечены как «проверяется вручную» — это норма.
Если ИИ-модели и модели смысловых отпечатков помечены как недоступные, значит не запущена служба
моделей (шаг 7).

### Шаг 6 (при необходимости). Установка без интернета

На машине с интернетом скачайте архив программы **и** набор файлов движка под свою видеокарту:
`hds-engine-runtime-windows-x64-cuda.zip` для NVIDIA или
`hds-engine-runtime-windows-x64-vulkan.zip` для AMD и Intel. Распакуйте программу (шаг 3),
положите набор движка туда, где его ищет служба моделей, и запустите установщик, пропустив
загрузку движка и моделей:

```powershell
# распаковать набор движка в ожидаемое место
$engine = Join-Path $env:APPDATA 'OpenResearchTools\TranscribeOffline\Engine'
New-Item -ItemType Directory -Force $engine | Out-Null
Expand-Archive .\hds-engine-runtime-windows-x64-cuda.zip -DestinationPath $engine -Force
# для машины без NVIDIA — тот же путь, но архив с vulkan в имени

# поставить всё, кроме скачиваемого движка и моделей
powershell -NoProfile -ExecutionPolicy Bypass -File .\setup.ps1 -SkipEngine -SkipModels
```

Модели можно принести на сменном носителе и разложить вручную в
`%LOCALAPPDATA%\llama-runtime\models\` по ролям: `chat\` — ИИ-модель, `embedding\` — модель
смысловых отпечатков, `rerank\` — модель переранжирования. Для ИИ-модели нужен
дополнительно файл `chat\current.json` с именем файла модели: проще всего получить его, один
раз запустив сценарий `installers\fetch_llm_models.ps1` там, где интернет есть.

### Шаг 7. Служба моделей (если вы отказались от автозапуска)

Служба моделей держит модели в памяти и занимает видеокарту. Запустить её в отдельном окне:

```powershell
.\bin\llm_host.exe run
```

Либо поставить ей автозапуск:

```powershell
powershell -File installers\install_llm_host_task.ps1 -Start
```

Модели загружаются при первом обращении, поэтому первый ответ после запуска будет с задержкой.
Состояние службы (какие модели подняты, сколько занято видеопамяти) показывает команда
`.\bin\llm_host.exe status`, а список видеокарт — `.\bin\llm_host.exe devices`.

### Шаг 8. Задайте папки для поиска и запустите наполнение базы

Папки, которые нужно обработать, перечисляются в файле настроек `config.yaml`, в разделе
`index.roots` (в образце настроек указан весь диск `D:\`). Удобнее всего задать их на странице
управления — см. главу «Повседневная работа», подглаву «Страница управления в браузере». Можно
и сразу запустить ярлык **«Индексация дисков»** на рабочем столе (или сценарий
`.\run_index.ps1`): тогда будут обработаны папки, уже записанные в настройках.

Первое наполнение базы для диска с сотнями тысяч файлов идёт **часами**: чтение документов,
распознавание текста на картинках, расчёт смысловых отпечатков. Обычно это запускают на ночь.
Ход работы виден на странице управления; прервать можно кнопкой «Стоп» или служебным файлом
`index.stop`. Повторные запуски догоняют только изменения, а служба слежения за файлами
подхватывает правки в фоне.

### Шаг 9. Откройте страницу управления

Ярлык **«Hermes Disk Search»** на рабочем столе (или сценарий `.\run_ui.ps1`) открывает страницу
управления в браузере: `http://127.0.0.1:8765`. Если ярлыка нет или страница не открылась,
запустите `.\bin\hds.exe ui` в командной строке и откройте этот адрес вручную; причина неудачи
записана в журнал `%LOCALAPPDATA%\hermes-disk-search\ui.err.log`.

Порядок действий на странице:

1. **Настройки** → перечислить папки для поиска → **Сохранить корни**;
2. там же — исключения (мусорные каталоги: временные файлы программ, служебные папки) → **Сохранить исключения**;
3. **Состояние** → **Старт** (или **Полная**, если нужно пересобрать базу с нуля); **Пауза** и
   **Продолжить** позволяют на время разгрузить диск;
4. **ИИ-модель** — выбрать модель из общего набора; **Служба моделей** — запуск, остановка
   и состояние.

Подробнее обо всех блоках — глава «Повседневная работа», подглава «Страница управления в
браузере».

### Шаг 10. Подключение ИИ-ассистента (по желанию)

Установщик уже подключил Cline и Hermes Desktop, если они есть на машине. Поставили их позже —
повторите подключение:

```powershell
cd D:\hds
.\install_hermes.ps1
.\install_cline.ps1
```

После подключения перезапустите ассистента: он читает настройки моделей и подключений при
запуске. Синхронизировать настройки в любой момент можно кнопкой «Синхронизировать настройки
Cline» на странице управления или командой `.\bin\hds.exe cline-sync`.

### Шаг 11. Обновление и удаление — коротко

Обновление выполняется отдельным процессом, а не «поверх работающей программы»: распакуйте новый
архив в любую папку и запустите `update.cmd` двойным щелчком. Он сам остановит работающие части
программы, поставит новую версию, **пересоздаст задания автозапуска и ярлык на рабочем столе по
новой версии** и запустит всё обратно. Подробности, включая возврат к предыдущей версии и полное
удаление, — в главе «Обновление и удаление».

## 4. Установка на Mac

Раздел самодостаточный: всё, что нужно сделать на Mac, перечислено здесь.

### Шаг 1. Скачайте программу

Со страницы выпусков `https://github.com/Guerchoig/hermes-disk-search/releases/latest` скачайте
архив `hds-<версия>-macos-arm64.zip`. Набор файлов движка скачивать не нужно: установщик заберёт
его сам по сведениям из папки `runtime-manifests` и проверит отпечаток.

### Шаг 2. Распакуйте архив

Например, в папку `~/hds`.

### Шаг 3. Запустите установщик

Двойной щелчок по файлу `install_macos.command`. Если система откажется запускать файл из
загруженного архива (карантин), нажмите на него правой кнопкой → «Открыть», либо выполните в
терминале `bash install_macos.command`.

### Шаг 4. Что установщик делает по шагам

1. снимает карантин с содержимого архива;
2. копирует исполняемые файлы в `~/.local/bin` и подсказывает, что делать с путями поиска
   программ, если этой папки там ещё нет;
3. создаёт файл настроек `config.yaml` из образца, если файла ещё нет;
4. загружает набор файлов движка в `~/Library/Application Support/OpenResearchTools/TranscribeOffline/Engine`;
5. создаёт ярлыки на рабочем столе («Hermes Disk Search» — страница управления, «Индексация
   дисков» — наполнение базы) и приложение «HDS Индексация» в `~/Applications`;
6. ставит автозапуск: `local.hds.watch` (слежение за файлами), `local.hds.mcp` (подключение
   ассистентов), `local.hds.llmhost` (служба моделей) — файлы в `~/Library/LaunchAgents`;
   отключить автозапуск можно, запустив установщик с указанием `HDS_NO_AUTOSTART=1`;
7. загружает модели и в конце выполняет проверку состояния.

### Шаг 5. Проверьте результат

```bash
~/.local/bin/hds check
```

Пометки в выводе означают то же, что и на Windows (шаг 5 главы про установку на Windows):
пометка «в порядке» должна стоять у базы данных, папок поиска, ИИ-модели, модели смысловых
отпечатков, распознавания текста, ffmpeg, разбора русских слов, чтения файлов Microsoft Project,
модели переранжирования, видеокарты и службы моделей. Строки про распознавание речи и Vulkan
помечены как «проверяется вручную» — это норма.

### Шаг 6. Задайте папки для поиска и запустите наполнение базы

Ярлык **«Hermes Disk Search»** на рабочем столе открывает страницу управления
`http://127.0.0.1:8765`. Там задаются папки для поиска (**Настройки** → **Сохранить корни**),
исключения и запуск обработки (**Состояние** → **Старт**). Можно поступить и проще: запустить
ярлык **«Индексация дисков»** — тогда обрабатываются папки, записанные в файле настроек
`config.yaml` (раздел `index.roots`).

Первое наполнение базы для диска с сотнями тысяч файлов идёт часами, обычно его запускают на
ночь. Повторные запуски догоняют только изменения.

### Шаг 7. Служба моделей

На Mac она поднимается автозапуском. Проверить состояние и запустить вручную:

```bash
~/.local/bin/llm_host status    # какие модели подняты, сколько занято видеопамяти
~/.local/bin/llm_host run       # запуск в отдельном окне терминала
```

### Шаг 8. Обновление

Распаковав новый архив, выполните:

```bash
sudo bash installers/update.command                        # обновление
sudo bash installers/update.command -RollbackTo <версия>   # возврат к предыдущей версии
```

Сценарию нужен установленный PowerShell 7 (команда `pwsh`). Если программа поставлена не как
служба, а обычным способом, добавьте указание корня: `-Root <папка>`.

### Шаг 9. Удаление

Удалите папку с программой, приложение `~/Applications/HDS Индексация`, файлы автозапуска
`~/Library/LaunchAgents/local.hds.*`, а по желанию — модели и набор файлов движка (папки внутри
`~/Library/Application Support`) и журналы в `~/Library/Logs/hermes-disk-search`.

### Шаг 10. Важное замечание

Сборка для Mac делается «по возможности» и на живой машине пока не проверялась; порядок проверки
описан в чек-листе `tools/parity/MAC_CHECKLIST.md`. Журналы страницы управления и автозапуска
лежат в `~/Library/Logs/hermes-disk-search/`.

## 5. Что где лежит на диске

В таблице «папка установки» — та папка, куда вы распаковали архив (в примерах `D:\hds` на
Windows и `~/hds` на Mac).

| Что | Где на Windows | Где на Mac | Можно ли удалять |
|---|---|---|---|
| Программа | папка установки: `bin` с исполняемыми файлами, `installers`, `sidecar` | папка установки + копии исполняемых файлов в `~/.local/bin` | да, если удаляете программу целиком (глава «Обновление и удаление») |
| Файл настроек `config.yaml` | в папке установки | в папке установки | нет: пропадут папки поиска, исключения и все параметры |
| База поиска `index.db` | в папке установки (точный путь задаёт ключ `db_path`) | там же | да, но базу придётся собирать заново — это часы работы |
| Модели общего набора: ответы, смысловые отпечатки, переранжирование (около 9 ГБ) | `%LOCALAPPDATA%\llama-runtime\models` | `~/Library/Application Support/llama-runtime/models` | да, скачаются заново |
| Модели распознавания речи и разделения по говорящим | `%APPDATA%\OpenResearchTools\models` | `~/Library/Application Support/OpenResearchTools/models` | да, скачаются заново |
| Набор файлов движка | `%APPDATA%\OpenResearchTools\TranscribeOffline\Engine` | `~/Library/Application Support/OpenResearchTools/TranscribeOffline/Engine` | да, скачается заново |
| Журналы страницы управления | `%LOCALAPPDATA%\hermes-disk-search` | `~/Library/Logs/hermes-disk-search` | да |
| Ярлыки и автозапуск | рабочий стол; задания планировщика `HermesDiskSearch*` | рабочий стол; файлы `~/Library/LaunchAgents/local.hds.*` | да, но пропадёт автозапуск |
| Служебные файлы (признак работы, пауза, остановка) | в папке установки | в папке установки | смотря какой — см. главу «База поиска и служебные файлы» |
| Файлы ИИ-агента в анонимной зоне (`agent.root`, по умолчанию `D:\hds-anon`; пример — `D:\hds-anon\P0001\workspace`) | `<agent.root>\P0001\workspace` — обезличенные копии документов проекта; `agent-config` и `agent-state` рядом — настройки и история агента | там же | да, но пропадут проект, его история и настройки; база меток при этом остаётся в `data\anonymize.db` |

## 6. Как это работает

По шагам и без технических подробностей:

1. **Обход дисков.** Программа идёт по папкам, перечисленным в настройках, и пропускает то, что
   её не касается: исключения, слишком большие файлы, временные и служебные файлы.
2. **Чтение содержимого.** Из документов вынимается текст — в том числе с картинок и сканов,
   если включён распознаватель. Из записей получается расшифровка видео/аудио.
3. **Разбивка на фрагменты.** Длинный текст делится на небольшие части: так поиск находит
   точное место, а не «файл целиком».
4. **Смысловые отпечатки.** Для каждой части считается числовой слепок смысла. Он позволяет
   находить близкие по смыслу места, даже если в запросе использованы другие слова.
5. **База поиска.** Всё вместе хранится в одном файле `index.db`.

Поиск соединяет два подхода: сравнение слов (быстро и точно по терминам) и сравнение смысловых
отпечатков (находит перефразированное). Ответ по файлам — это найденные фрагменты плюс текст,
который составляет ИИ-модель; в тексте есть ссылки на источники, по которым видно, откуда
взята каждая мысль.

Компоненты программы и их роли:

| Компонент | Адрес | Зачем она нужна |
|---|---|---|
| Страница управления | `127.0.0.1:8765` | настройка, состояние, запуск и остановка обработки |
| Служба моделей | `127.0.0.1:8010` — ответы, `127.0.0.1:8011` — смысловые отпечатки, `127.0.0.1:8012` — переранжирование | держит модели в памяти и отвечает на запросы остальных компонентов |
| Подключение ассистентов | `127.0.0.1:8787`, путь `/mcp` | единая точка, через которую Cline и Hermes обращаются к поиску |
| Служба слежения за файлами | без адреса | следит за изменениями на дисках в фоне |
| Служебная программа чтения документов | без адреса | читает офисные файлы, PDF, картинки; она же разбирает русские слова для поиска по словам |

Адреса `8010`–`8012` и `8787` открыты только на этом же компьютере: снаружи их не видно, и
менять это не нужно.

## 7. Повседневная работа

### 7.1. Поиск из командной строки

Поиск ничего не генерирует и отвечает за доли секунды:

```powershell
hds search "техническое задание" --limit 8
hds search "SAP" --kinds docx,pdf --limit 20
hds search "отчёт" --json
```

Аргументы команды означают следующее: `--limit` — сколько результатов показать; `--kinds` — какие виды
файлов учитывать (например `text`, `pdf`, `docx`); `--json` — вывод в машинном виде, удобный для
дальнейшей обработки. Команды запускаются из папки установки, то есть в виде
`.\bin\hds.exe search "техническое задание"` — полный список команд с пояснениями собран в главе
«Перечень команд».

### 7.2. Ответ на вопрос по своим файлам

```powershell
hds ask "какие требования к срокам?" --limit 8
hds ask "какие есть технические задания" --limit 30 --json
```

Ответ собирает модель на вашем компьютере: она читает найденные фрагменты и пишет связный текст.
Один ответ занимает от нескольких десятков секунд до нескольких минут — это нормально и зависит
от объёма найденного и от видеокарты. В тексте есть ссылки вида `[1]`, `[2]`, по ним видно, из
какого файла взята каждая мысль.

Аргумент команды `--limit` задаёт глубину выборки: для обзорных вопросов вида «какие есть…» ставьте
15–30, для точного вопроса достаточно 8.

### 7.3. Работа через ИИ-ассистента

Если ассистент подключён (глава «Подключение ИИ-ассистентов»), вы просто пишете ему вопрос
обычным текстом, а он сам вызывает поиск и отвечает со ссылками на файлы. Что полезно знать:

* **одна выдача — это фрагменты, а не список файлов.** Поэтому на обзорный вопрос вида «найди
  все…» ассистент должен сделать несколько запросов разными словами; так и просите его в
  задании, если ответ кажется неполным;
* чем конкретнее вопрос, тем точнее ответ: «какие сроки указаны в договоре с подрядчиком» лучше,
  чем «расскажи про договоры»;
* у ассистента есть ограничение на длину ответа за один ход, поэтому длинные ответы он выдаёт
  частями;
* на медленных машинах (видеокарта встроенная) включите режим экономии: в файле настроек
  `config.yaml` задайте `cline.slow_machine: true` и выполните `hds cline-sync` — ассистент
  получит правило бережливого поиска (один вызов за ход, мало результатов, без обращения к
  интернету).

### 7.4. Страница управления в браузере

**Как открыть.** Проще всего — ярлык **«Hermes Disk Search»** на рабочем столе: он поднимает
страницу управления и открывает браузер по адресу `http://127.0.0.1:8765`. Если ярлыка нет,
запустите вручную:

```powershell
cd D:\hds
.\run_ui.ps1
# или напрямую:
.\bin\hds.exe ui
```

и откройте адрес `http://127.0.0.1:8765` в браузере. Если страница не открылась, смотрите журнал
`%LOCALAPPDATA%\hermes-disk-search\ui.err.log`. На Mac страница открывается ярлыком «Hermes Disk
Search», а вручную — командой `~/.local/bin/hds ui`.

**Порядок действий при первом запуске.**

1. **Настройки** → перечислить папки для поиска → **Сохранить корни**.
2. Там же — **исключения** (мусорные каталоги: временные файлы программ, служебные папки) →
   **Сохранить исключения**. Файл настроек правится на странице с сохранением пояснений в нём.
3. **Состояние** → **Старт** (обычная обработка) или **Полная** (пересобрать базу с нуля).
   **Пауза** и **Продолжить** позволяют на время разгрузить диск или уступить его другим
   задачам.
4. **Служба моделей** — состояние, запуск и остановка; там же **ИИ-модель** — выбор из
   общего набора моделей на компьютере (после выбора служба перезапускается, ход загрузки виден
   на карточке).
5. **Подключение ассистентов** — состояние и запуск; **Настройки Cline** → «Синхронизировать
   настройки Cline», если вы пользуетесь этим ассистентом.
6. **Расшифровка видео/аудио** — на отдельной закладке «Транскрибация»; о ней — следующая глава.

Страница управления — это пульт настройки, а не окно поиска: поиск и вопросы выполняются через
ассистента или командную строку, как описано выше.

### 7.5. Пауза и остановка обработки

Обработкой можно управлять кнопками на странице управления (**Пауза**, **Продолжить**,
**Стоп**), а можно теми же действиями через служебные файлы в папке установки:

| Файл | Что означает |
|---|---|
| `index.pause` | обработка приостановлена: программа обходит диск и ждёт, пока файл не уберут |
| `index.stop` | сигнал аккуратно закончить текущую обработку |
| `index.heartbeat.json` | запись о ходе работы: сколько сделано и не стоит ли она на паузе |

Если кажется, что обработка «стоит», откройте этот последний файл: признак `"paused": true`
означает, что лежит файл `index.pause`. При этом служба моделей могла поставить паузу сама —
чтобы не мешать ответам на вопросы. Она снимает её, когда ответы закончатся; если пауза осталась
«насовсем», удалите файл `index.pause` вручную.

**Важное различие:** служба слежения за файлами (её состояние видно на странице управления, блок
«Служба слежения за файлами») файлы `index.pause` и `index.stop` **не читает**: её обход
останавливается только остановкой самой службы — кнопками на странице управления или командой
`hds watch` не запускать. Служба моделей и служба слежения — независимые части: одна
перезапускается своей кнопкой, вторая своей.

### 7.6. Обслуживание базы поиска

```powershell
hds status                             # сколько файлов и фрагментов, сколько ошибок
hds reindex "D:\Договоры"               # обработать заново папку или файл
hds reindex-fts                        # перестроить поиск по словам
hds forget "D:\Старое"                  # убрать папку или файл из базы
hds clip-index                         # дозаполнить поиск по картинкам
hds db-move --to "E:\hds\index.db"      # перенести базу в другое место
hds index --full                       # пересобрать данные целиком
hds index --roots "D:\;E:\Архив"        # разово обработать другие папки
hds index --kinds text,pdf              # ограничить виды файлов
hds index --limit 20 --no-prune         # пробный прогон: 20 файлов, ничего не удаляя
hds index --rechunk                    # заново нарезать текст (после смены размера фрагмента)
```

Когда что применять:

* после правки нескольких файлов ничего запускать не нужно — служба слежения подхватит
  изменения сама;
* поиск по словам перестраивают после изменения правил разбора русских слов (`reindex-fts`);
* вид файлов и размер фрагмента лучше менять сразу после установки: смена размера фрагмента
  требует повторной нарезки текста (`--rechunk`), то есть длительной обработки.

## 8. Расшифровка видео/аудио (распознавание речи в папках)

Отдельная возможность: положить аудио- или видеофайл в назначенную папку — и получить текстовую
расшифровку видео/аудио с разделением по говорящим. Работает по порядку «папка → расшифровка
видео/аудио».

### Настройка

Расшифровку выполняет отдельный Python-стек **GigaAM-v3** (распознавание речи) +
**pyannote community-1** (разделение по говорящим). Он ставится установщиком и
работает в своём окружении (`sidecar\venv-transcribe`), чтобы не мешать чтению
документов и поиску.

В файле настроек `config.yaml`:

```yaml
auto_transcribe:
  enabled: true              # включить обработку
  inbox_dir: 'D:\media_in'   # сюда кладём записи
  out_dir:   'D:\media_out'  # здесь появляются расшифровки
  source_disposal: delete    # delete | keep | move (что делать с исходником)

transcribe:
  engine: python             # python — новый стек (по умолчанию); legacy — откат
  profile: auto              # auto | cuda | cpu | dml (auto: NVIDIA→cuda, iGPU AMD/Intel→cpu)
  models_dir: ''             # '' → HDS_MODELS_DIR / машинная папка установщика
  asr:
    variant: e2e_rnnt        # основной вариант GigaAM-v3 (ru, пунктуация)
    backend: auto            # auto | torch | onnx (для профиля dml — onnx)
  align:
    mode: native             # native | whisperx | hybrid (whisperx — только если установлен)
  diarization:
    enabled: true
    max_speakers: 20         # предел; число говорящих определяется автоматически
  glossary:
    path: ''                 # '' → без замен; пример формата — ниже
  llm:
    enabled: false           # LLM-правка текста выключена по умолчанию
```

* **Профиль** выбирает установщик: NVIDIA → `cuda` (torch + CUDA), нет видеокарты
  или встроенная AMD/Intel → `cpu` (ONNX CPU), дискретная AMD/Intel → `dml`
  (ONNX + DirectML). **Профиль `dml` на дискретной AMD/Intel пока экспериментальный**:
  на встроенной графике он измеримо медленнее CPU, на дискретной карте живьём не
  проверялся. Меняется ключом `transcribe.profile` (или `-TranscribeProfile` при
  установке) с пересборкой окружения.
* **Модели** лежат в машинной папке (`%ProgramData%\hermes-disk-search\models` на
  сервере, `%APPDATA%\OpenResearchTools\models` на рабочей машине); HF-кэш —
  `<models_dir>\hf-home`. Обновлять модели вручную не нужно, ревизии закреплены.
* **Токен Hugging Face** нужен только на **первую** загрузку gated-моделей
  (`pyannote/community-1`, `segmentation-3.0`): передайте `-HfToken` установщику
  или переменную `HF_TOKEN`. В работе токен не нужен — стек читает локальный кэш.

Папки исключаются из обхода поиска автоматически: и сами записи, и полученные расшифровки в
базу поиска не попадают.

### Что происходит с файлом

1. служба видит в папке «входящие» **готовый** (дописанный) файл;
2. запись **один раз** переводится во внутренний звуковой формат (16 кГц, моно): по нему идёт
   распознавание речи **GigaAM-v3** (с пунктуацией; тишина отбрасывается по VAD — модель на
   тишине «выдумывает» фразы) и разделение по говорящим **pyannote community-1**
   (до **20** меток, число говорящих определяется по записи);
3. полученный текст сохраняется в папку «исходящие» как файл с расширением `.md`;
4. исходная запись удаляется — **только если расшифровка видео/аудио прошла успешно**. Поведение задаётся
   ключом `source_disposal`: `delete` (удалять, по умолчанию), `keep` (оставлять), `move`
   (переносить в папку `source_disposal_dir`).

Повторно один и тот же файл не обрабатывается: ведётся журнал уже обработанных файлов, а число
попыток ограничено.

### Вид расшифровки видео/аудио и имена говорящих

Реплики размечены заголовками: `### SPEAKER_00 [00:00:01 - 00:00:11]` — то есть говорящий и
время. Метки идут от `SPEAKER_00`; предел — `transcribe.diarization.max_speakers` (по умолчанию 20).
Реплика,
которую не удалось связать с говорящим, помечается как `### UNASSIGNED […]`.
Рядом с расшифровкой видео/аудио в служебной папке лежат два файла: `.orig.md` — текст до подстановки имён
и `.speakers.json` — таблица соответствия «метка → имя». Перед любой правкой расшифровки видео/аудио
создаётся её копия с расширением `.bak`, поэтому испортить текст случайно нельзя.

Имена говорящим присваиваются на странице управления, закладка **«Транскрибация»**:

* список расшифровок в папке «исходящие» с предпросмотром текста;
* таблица «Говорящий — Имя»: заполненные строки подставляются в текст, пустые остаются как есть;
* кнопка **«Присвоить имена говорящим»**, кнопка **«Перезапустить задание»** и поля для папок
  «входящие» и «исходящие» (сохраняются в файл настроек). Рядом с каждым полем показано,
  исключена ли эта папка из обхода поиска.

### Если расшифровки нужно искать

**Важно:** полученные текстовые расшифровки в поиск сами не попадают — папка «исходящие»
специально исключена из обхода, чтобы расшифровка видео/аудио не читалась как документ и не попадала в
базу вторично. Если расшифровки должны находиться поиском, **перенесите нужные файлы `.md`
вручную** в одну из папок, которые входят в список папок поиска (`index.roots`). Только после
этого они будут прочитаны и попадут в базу — при следующем запуске обработки или автоматически,
когда служба слежения заметит новые файлы.

### Управление и приоритеты

* Служба расшифровки видео/аудио запускается автозапуском. Вручную — команды `hds transcribe-watch`
  (работать в режиме службы), `hds transcribe-once "D:\media_in\запись.m4a"` (обработать один файл прямо
  сейчас, не дожидаясь очереди), `hds transcribe-stop` (аккуратно остановить службу).
  Двойной запуск невозможен: его не допускает служебный файл-замок `transcribe.lock`. Если замок
  остался после сбоя, об этом сообщает проверка состояния.
* Управлять расшифровкой видео/аудио можно и со страницы управления: там показано состояние (работает,
  остановлена, «замок без процесса») и есть кнопки **Запустить**, **Остановить**,
  **Перезапустить**.
* Приоритеты выполнения задач при нехватке видеопамяти: сначала поиск и ответы на вопросы, затем
  расшифровка видео/аудио, затем наполнение базы. Расшифровка видео/аудио ставит наполнение базы на
  паузу; запрос к ассистенту может вытеснить расшифровку видео/аудио, а наполнение базы — нет.
* Если возможность включена, но ещё не запускалась ни одна запись, запуск честно предупредит об
  этом: пока не появится файл в папке «входящие», службе нечего делать.
* Модели расшифровки (GigaAM, wav2vec2, pyannote) **не входят** в архив: их заранее скачивает
  установщик. Вручную: `powershell -File installers\fetch_transcribe_models.ps1 -ModelsDir <папка>`
  (для первой загрузки gated-моделей — `-HfToken`). Для профилей `cpu`/`dml` дополнительно
  экспортируется ONNX: `installers\export_gigaam_onnx.ps1 -ModelsDir <папка>`.
* Проверить готовность: `hds transcribe-check` (старое имя `hds whisper-check` сохранилось) —
  профиль и вендор видеокарты, движок (CUDA/ONNX), версии, наличие каждой модели и ONNX, токен,
  `ffmpeg` и версия, предупреждения; плюс `hds check` (пункт «транскрибация», модели и путь
  воркера). `hds transcribe-watch --dry-run` показывает, что именно запросит конвейер.
* **Профиль `dml` (дискретная AMD/Intel) — экспериментальный**: на встроенной графике DirectML
  медленнее CPU, на дискретной карте живьём не проверен. Для встроенной AMD/Intel установщик
  выбирает `cpu`.
* Нужен **ffmpeg** (переводит запись в звуковой формат): установщик ставит его машинно, вручную —
  `winget install --scope machine -e --id Gyan.FFmpeg` (Mac — `brew install ffmpeg`).
* Язык распознавания — `transcribe.asr.language` (`ru` по умолчанию; пустая строка — авто).
  Старый ключ `index.whisper_language` продолжает читаться для режима `legacy`.
* Одна запись ограничена **6 часами** (`transcribe.max_duration_hours`): на Python-пути жёсткого
  ограничения WAV нет, но 6 часов звука — это ~1,4 ГБ памяти плюс модели; больше — только явным
  ключом.
* **Глоссарий и LLM-правки:** `transcribe.glossary.path` — файл терминов (пример формата —
  `sidecar\hds_transcribe\glossary.example.yaml`); замены детерминированные, спорные случаи
  помечаются для ручной проверки в `<имя>.edits.json`. LLM-правка (`transcribe.llm.enabled`)
  **выключена** по умолчанию.
* **Откат:** `transcribe.engine: legacy` возвращает прежнюю цепочку (whisper + Nemotron-3 через
  `llm_host`) без миграции базы и файлов; старые модели должны быть установлены
  (`installers\fetch_whisper_model.ps1`, `fetch_nemotron3_model.ps1`). В обычном пакете 0.22+
  legacy-диаризатор Nemotron **не поставляется** (`DirectML.dll` не входит) — для полного
  отката нужен переходный архив, собранный с `-LegacyDiarizer`.
* **macOS:** Python-стек ставится best-effort, на живой машине не проверялся (как и остальная
  macOS-сборка).

## 9. Подключение ИИ-ассистентов (Cline, Hermes Desktop)

Подключённый ассистент умеет обращаться к поиску как к своему инструменту: вы пишете вопрос
обычным текстом, а он сам находит файлы и отвечает со ссылками. Никаких дополнительных окон для
поиска при этом не нужно.

### Как подключить

Обычно делать ничего не нужно: установщик подключает Cline и Hermes Desktop, если они уже есть
на машине. Если вы поставили их позже — повторите подключение в любой момент:

```powershell
cd D:\hds
.\install_hermes.ps1     # Hermes Desktop
.\install_cline.ps1      # Cline (настольная версия или работа в командной строке)
```

На Mac — `bash installers/install_hermes_macos.sh` и `bash installers/install_cline_macos.sh`.
Повторный запуск ничего не дублирует. После подключения **перезапустите ассистента**: настройки
подключений и моделей читаются при его запуске.

### Что записывается на диск

| Что | Где | Когда применяется |
|---|---|---|
| Запись о поиске как инструменте | `%USERPROFILE%\.cline\data\settings\cline_mcp_settings.json` и `%USERPROFILE%\.cline\mcp.json` | при запуске ассистента |
| Правило поведения | `~/.cline/rules/disk-search.md` | всегда: правило добавляется в задание каждой беседы |
| Подсказка по требованию | `~/.cline/skills/disk-search/SKILL.md` | только если модель сама её запросит |
| Размеры контекста моделей | `~/.cline/data/settings/models.json` | при запуске ассистента |

Размеры контекста показывают ассистенту, сколько текста помещается в одно обращение. Без этого
он сжимает историю беседы раньше, чем это нужно, и теряет найденное. Поэтому синхронизацию
настроек стоит повторять после смены модели или числа одновременных обращений.

### Зачем и правило, и подсказка

Программа отдаёт ассистенту вступительный текст при подключении, но не все ассистенты его
используют: Cline, например, не добавляет его в задание. Поэтому смысл продублирован двумя
файлами, и оба ставит одна команда. Правило работает всегда и доносит главное: **одна выдача —
это фрагменты, а не список файлов**, и на обзорный вопрос нужно несколько запросов разными
словами. Подсказка срабатывает по требованию и содержит более подробные советы.

### Инструменты, которые видит ассистент

| Инструмент | Что делает |
|---|---|
| поиск файлов (`search_local_files`) | ищет по имени, теме и содержимому |
| ответ по моим файлам (`ask_my_files`) | собирает ответ по найденным фрагментам со ссылками |
| состояние базы (`index_status`) | показывает, что и когда обработано, есть ли ошибки |
| запуск наполнения базы (`start_indexing`) | запускает обход дисков |
| остановка наполнения базы (`stop_indexing`) | аккуратно останавливает обход |
| пересборка папки (`reindex_path`) | обрабатывает заново указанный файл или папку |

### Синхронизация настроек

```powershell
hds cline-sync              # записать настройки заново
hds cline-sync --dry-run    # только показать, что будет изменено
```

То же делает кнопка «Синхронизировать настройки Cline» на странице управления. Отчёт говорит,
что изменилось, и напоминает о перезапуске ассистента.

### Потолок длины ответа

Общую длину одного ответа задаёт ключ `chat.max_tokens`. Если он мал, ответы обрываются на
полуслове; для ответов по файлам есть отдельный, более короткий потолок `chat.rag_max_tokens`.
Оба ключа описаны в главе «Настройки».

## 10. Служба моделей на видеокарте (llm-host)

**Это не ассистент и не собеседник.** Служба моделей — служебный компонент программы: она держит
модели в памяти (занимая видеокарту) и отвечает на запросы других компонентов по внутренним адресам.
Своих вопросов ей задать нельзя, окна у неё нет.

Что она держит:

| Что | Адрес | Для чего |
|---|---|---|
| ИИ-модель | `127.0.0.1:8010` | составление ответов по файлам |
| Модель смысловых отпечатков | `127.0.0.1:8011` | поиск по смыслу во время обхода дисков и при поиске |
| Модель переранжирования | `127.0.0.1:8012` | уточнение порядка найденного |
| Распознавание речи | без отдельного адреса | расшифровка видео/аудио |

Команды (запускаются из папки установки):

```powershell
.\bin\llm_host.exe run            # запустить службу в отдельном окне
.\bin\llm_host.exe status         # что поднято, сколько занято видеопамяти
.\bin\llm_host.exe devices        # список видеокарт и их номера
.\bin\llm_host.exe load chat      # поднять одну роль заранее
.\bin\llm_host.exe unload chat    # выгрузить роль
.\bin\llm_host.exe stop           # аккуратно остановить службу
```

Модели загружаются при первом обращении, поэтому первый ответ идёт медленнее последующих.

**Кто уступает видеопамять.** Ключ `gpu.policy` задаёт порядок: `query_priority` — ответы на
вопросы важнее обхода дисков (обход ставится на паузу на время ответа), `indexing_priority` —
наоборот, `manual` — решаете вы сами. Пауза, выставленная вами вручную, службой не снимается.

**Сколько обращений одновременно.** Для одиночного компьютера по умолчанию — одно: ответы идут
по очереди, чтобы не переполнить видеопамять. Изменить это можно ключами `llm_server.parallel`
(сколько обращений сразу) и `llm_server.chat.ctx_per_slot` (сколько текста помещается в одно
обращение). Перед запуском служба проверяет, поместится ли выбранное в память, и при нехватке
отказывается запускаться, показывая числа и подсказывая, что уменьшить. Молчаливого замедления
не бывает.

**Если видеокарты нет** — служба работает на Vulkan или на процессоре: медленнее, но полностью
работоспособно. Можно взять ИИ-модель поменьше.

**Автозапуск:** задание в планировщике заданий Windows (ярлык создаёт установщик), либо команда
`powershell -File installers\install_llm_host_task.ps1 -Start`. На Mac — файл автозапуска
`local.hds.llmhost`.

## 11. Чтение документов, таблиц и картинок

Основную работу выполняют части, написанные на языке Rust. Но для чтения готовых офисных
форматов и для разбора русских слов используется отдельная небольшая служебная программа на
Python — её называют `sidecar`. Причина простая: для этих задач есть проверенные библиотеки,
переписывать их не имеет смысла.

Что программа умеет читать:

| Вид файлов | Что извлекается |
|---|---|
| Обычный текст, текстовые документы | сам текст |
| PDF | текст постранично; для сканов — распознавание текста как изображения |
| Документы, таблицы и презентации Word, Excel, PowerPoint | текст с разбивкой по листам и страницам |
| Картинки и сканы | текст на изображении (если включён распознаватель Tesseract) |
| Файлы Microsoft Project (`.mpp`) | задачи и их свойства (нужна Java 11 и новее) |
| Аудио и видео | не читаются: их текст даёт расшифровка видео/аудио (глава 8) |

Как эта программа устроена и почему это безопасно:

* она работает отдельным процессом и общается с основной программой сообщениями, а не внутри
  общего процесса: сбой при чтении одного файла не роняет всю программу;
* основная программа запускает её по необходимости и сама ей управляет; если чтение не
  требуется, процесс не работает;
* в поставке эта программа уже собрана вместе со своей средой выполнения — отдельно ставить
  Python не нужно. Требуется он только тем, кто собирает программу из исходного текста.

Пересобрать её можно так:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File installers\build_sidecar.ps1 `
    -OutDir dist\sidecar -SelfTest
```

Ключи `-SelfTest` достаточно, чтобы убедиться: собранная программа отвечает на проверочный
запрос.

Если в проверке состояния строка про разбор русских слов или про чтение файлов Microsoft Project
помечена не как «в порядке», смотрите главу «Если что-то не получилось»: чаще всего дело в
отсутствующей Java (для `.mpp`) или в распознавателе текста, который не найден службой.

## 12. Настройки

Все настройки лежат в одном текстовом файле `config.yaml` в папке установки. Полный образец со
всеми ключами и пояснениями — файл `config.example.yaml` (он же попадает в архив выпуска).
Файл настроек правится с сохранением пояснений двумя способами: на странице управления
(**Настройки** → списки папок и исключений, закладка **«Транскрибация»** → папки обработки) или в
текстовом редакторе — тогда программу нужно перезапустить.

На серверном стенде файл настроек собирается из отдельного серверного шаблона
(`server_config.example.yaml`) командой `hds config init`; подробности — `README_SERVER_MULTIUSER.md`,
глава «Настройки сервера».

Ниже — разделы и ключи, которые меняют чаще всего.

| Раздел и ключ | Что делает |
|---|---|
| `index.roots` | папки, которые обрабатываются. Можно указать всю папку диска (`D:\`) |
| `index.exclude_dirs`, `index.exclude_paths` | что пропускать (временные файлы программ, служебные каталоги, папки с обновлениями) |
| `index.max_file_mb`, `index.max_media_mb` | предельные размеры файлов; крупнее — не читаются |
| `index.ocr` | включить распознавание текста на картинках и сканах |
| `index.ocr_lang` | языки распознавания (`rus`, `eng`, …) |
| `index.ocr_tesseract_cmd`, `index.ocr_tessdata` | где лежит распознаватель и языковые наборы (нужны, если программа работает как служба) |
| `index.max_chunks` | предельное число фрагментов на один файл |
| `db_path` | путь к файлу базы поиска. Для версионной установки лучше указывать полный путь |
| `chunk.size`, `chunk.overlap` | размер фрагмента текста и перекрытие между соседними фрагментами |
| `embedding.base_url`, `embedding.model`, `embedding.dim` | адрес службы моделей и модель для смысловых отпечатков (обычно менять не нужно) |
| `chat.base_url`, `chat.model` | какой моделью составлять ответы |
| `chat.thinking` | разрешать ли модели «размышлять» перед ответом (`off` — быстрее, `auto` — по обстоятельствам) |
| `chat.temperature` | степень свободы формулировок: меньше — точнее и суше |
| `chat.max_tokens` | потолок длины одного ответа. Слишком мало — ответы обрываются |
| `chat.rag_max_tokens` | отдельный, более короткий потолок для ответов по файлам |
| `chat.max_context_chars` | сколько текста из найденного помещается в одно обращение к модели |
| `chat.provider`, `chat.api_key` | ответы может давать облачная ИИ-модель вместо местной (нужен ключ к ней). Тогда вопрос и найденные фрагменты уходят наружу — обезличивание пока не сделано, поэтому включайте это только для доверенной ИИ-модели |
| `search.vec_k`, `search.fts_k`, `search.rrf_k` | сколько кандидатов брать при поиске по смыслу и по словам и как их объединять |
| `rerank.enabled`, `rerank.url`, `rerank.model` | уточнение порядка найденного отдельной моделью |
| `watch.debounce_seconds`, `watch.reconcile_on_start` | как служба слежения ждёт окончания правки файла и что пересматривает при старте |
| `gpu.policy`, `gpu.device_index`, `gpu.n_gpu_layers` | какой видеокартой пользоваться и кто кому уступает память (0 — процессор, 1 — первая видеокарта) |
| `gpu.reserve_mb`, `gpu.evict_idle_sec` | запас видеопамяти, который не занимаем, и когда выгружать простаивающие модели |
| `llm_server.host`, `llm_server.chat.ctx_per_slot`, `llm_server.parallel` | адрес службы моделей, длина контекста одного обращения и сколько обращений выполнять одновременно |
| `mcp_http.host`, `mcp_http.port`, `mcp_http.path` | адрес и путь подключения ассистентов |
| `ui.host`, `ui.port` | адрес страницы управления (по умолчанию `127.0.0.1` и `8765`) |
| `auto_transcribe.*` | порядок «папка → расшифровка видео/аудио» (глава 8) |
| `cline.slow_machine` | бережливый режим для ассистента на медленных машинах |
| `extract.idle_timeout` | через сколько секунд простоя закрывать служебную программу чтения документов |
| `profile` | `desktop` — обычный одиночный режим (значение по умолчанию) |
| `agent.enabled`, `agent.root` | режим анонимной зоны: индекс только по `<agent.root>\P<NNNN>\workspace`; `index.roots` игнорируются, страница настроек корни не меняет |

Переменные окружения, которые иногда нужны при запуске вручную: `HDS_CONFIG` — путь к другому
файлу настроек, `HDS_ROOT` — другая папка данных, `HDS_ENGINE_DIR` — другой набор файлов
движка, `HDS_EXTRACT_PYTHON` — другой Python для служебной программы,
`HDS_AGENT_SECRETS` — другой файл токенов проектов анонимной зоны (по умолчанию
`data\agent\secrets.json`).

### Анонимная зона агента (ИИ-агент по обезличенным копиям)

Режим для сценария «ИИ-агент в анонимной зоне» (`PLAN_AGENT_PRIVACY_ZONE.md`): поиск идёт не по
оригиналам, а по обезличенным копиям документов — в них вместо ФИО, организаций и реквизитов стоят
метки `[PERSON_3]`, `[ORG_21]`. Метки связаны с исходными значениями только в базе меток
(`data\anonymize.db`), которая агенту недоступна.

1. В `config.yaml` задайте `agent.enabled: true` и `agent.root` — папка **вне** профиля
   пользователя (например `D:\hds-anon`). Внутри появляются проекты `P0001`, `P0002`, … — каждый со
   своим `workspace` (что индексировать) и служебными `agent-config`, `agent-state` (не
   индексируются).
2. `hds agent init` — останавливает слежение, удаляет прежний `index.db` и выход прежней карточки
   анонимизации, создаёт пустую базу и строит индекс заново (команда спрашивает подтверждение,
   `--yes` — без вопроса). **Прежний индекс удаляется** (решение D9). Выход анонимизации
   (`anonymize.output_dir`) удаляется, только если он лежит внутри `<каталог данных>\data` или внутри
   `<agent.root>`; если там указан общий или сетевой каталог, команда откажется удалять его без
   явного `--force`.
3. `hds agent token P0001` — выдаёт токен проекта. В `data\agent\secrets.json` сохраняются и хэш
   (его проверяет маршрут), и сам токен: агенту он нужен для заголовка `Authorization` в
   настройках MCP. Сам токен печатается один раз на экран. Без `--ttl-days` токен бессрочный.
4. Агент подключается к `POST http://127.0.0.1:8787/mcp/agent/P0001` с заголовком
   `Authorization: Bearer <токен>`. На этом маршруте доступны только `search_local_files` и
   `index_status`; `ask_my_files` и управление индексацией не публикуются, а выдача всегда
   ограничена одним проектом (чужой или просроченный токен → 401).

Метки ищутся как обычные слова: `[PERSON_3]` находит ровно этого человека, `[PERSON_30]` — другого;
падежный суффикс (`[PERSON_3|дат]`) на поиск не влияет. Если в проекте есть ещё не
проиндексированные файлы, `search_local_files` добавляет к выдаче предупреждение, а `index_status`
показывает их число по проекту.

## 13. База поиска и служебные файлы

### Из чего состоит база

База поиска — один файл `index.db`. Внутри неё:

* перечень обработанных файлов и их свойства (путь, размер, время правки, вид, состояние);
* фрагменты текста, на которые разбиты документы;
* поиск по словам — с разбором русских слов, поэтому «договор» находится и по слову «договоры»;
* смысловые отпечатки фрагментов — числа, по которым ищется близкое по смыслу;
* отдельный набор чисел для поиска картинок по изображению.

База открывается в надёжном режиме записи: рядом с ней могут появляться служебные файлы
`index.db-wal` и `index.db-shm` — это нормально, удалять их вручную нельзя. **Копировать базу
копированием файла во время работы нельзя** — получится повреждённая копия. Для переноса
используйте команду `hds db-move`, а для резервной копии — средства самой базы (`VACUUM INTO`
или `.backup` в программе `sqlite3`), иначе обязательно останавливайте все компоненты программы перед
копированием.

Поиск и ответы читают базу, не мешая её наполнению: можно искать, пока идёт обработка дисков.

### Служебные файлы в папке установки

| Файл | Что означает |
|---|---|
| `index.pause` | обработка приостановлена; убрать файл — работа продолжится |
| `index.stop` | сигнал закончить обработку после текущего файла |
| `index.heartbeat.json` | ход работы: сколько сделано, не на паузе ли обработка |
| `watch.lock` | запись о работе службы слежения за файлами (защита от второго запуска) |
| `data\llm-host.pid`, `data\logs\` | запись о работе службы моделей и журналы |
| `transcribe.lock`, `transcribe.stop` | то же для службы расшифровки видео/аудио |

### Если база создана другой версией программы

Состав базы со временем меняется. Если программа обнаружит, что база создана более старой
версией и ей не подходит, она пересоздаст её (сообщение об этом появится в выводе). После этого
нужен полный обход дисков: `hds index --full`. Перед обновлением крупных версий стоит заранее
запланировать такой прогон, например на ночь.

## 14. Обновление и удаление

### Обновление

Обновлять программу «поверх работающей» нельзя: Windows не даёт заменить запущенный файл. Поэтому
используется раскладка по версиям: в папке установки есть подпапка `app` со вложенными папками
версий и указателем `app\current` на активную. Настройки, база и модели при этом общие и не
переписываются. Если папки `app` ещё нет (первая установка была обычной, «плоской»), она появится
при первом обновлении.

**Порядок действий (Windows).**

1. Скачайте и распакуйте новый архив в **любую** папку (можно временную).
2. В распакованной папке запустите двойным щелчком файл **`update.cmd`**. Он сам снимет пометку
   «скачано из интернета», сам найдёт папку установки и её версию, остановит задания автозапуска
   и службу моделей, поставит новую версию, переключит указатель, **пересоздаст задания
   автозапуска и ярлык на рабочем столе по новой версии**, **докачает Python-стек расшифровки**
   (окружение при отсутствии + модели; уже скачанные пропустит) и запустит всё обратно.
   Пересоздание обязательно: задания и ярлык хранят полный путь к программе, а обновление
   подменяет только каталог версии — иначе после обновления запускались бы прежние файлы.
   Докачка идемпотентна; если нужно обновиться без интернета — `update.cmd -NoModels`
   (тогда запустите `installers\fetch_transcribe_models.ps1` позже: до этого задания расшифровки
   падают, а `hds transcribe-check` показывает, чего не хватает).
3. Проверьте состояние: папка установки → `app\current\bin\hds.exe check` (или ярлык проверки на
   странице управления). В выводе есть строка «раскладка»: у правильной установки там сказано,
   что программа запускается из `app\current\bin`.

**Возврат к предыдущей версии** — прошлые версии сохраняются, поэтому откат выполняется той же
программой из распакованного архива:

```powershell
update.cmd -RollbackTo <версия>     # например, 0.20.2
```

Посмотреть, какие версии установлены, и выполнить то же вручную можно через служебный сценарий:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File installers\update.ps1 -Root D:\hds -ListVersions
powershell -NoProfile -ExecutionPolicy Bypass -File installers\update.ps1 -Root D:\hds -From <архив> -Version <версия>
```

Если у установки нет папки `app`, `-ListVersions` скажет об этом прямо и напомнит, что первое
обновление создаст её и переведёт задания автозапуска на версию само.

На Mac обновление выполняет `installers/update.command` (глава «Установка на Mac», шаг 8).

**Что сохраняется при обновлении:** файл настроек, база поиска, модели, журналы. Что меняется:
исполняемые файлы и служебные сценарии.

**Если обновление не прошло:** вернитесь к прошлой версии (`-RollbackTo`) и посмотрите вывод
сценария — он печатает, на каком шаге произошёл сбой. Частая причина на Windows — занятый файл:
закрыть ассистента, остановить службу моделей и повторить.

### Установка конкретной версии в отдельную папку

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File installers\install_app_version.ps1 `
    -From hds-0.20.2-windows-x64.zip -Version 0.20.2 -Root D:\hds -SetCurrent
```

Полезно, если нужно держать несколько версий рядом. При такой раскладке путь к базе в настройках
лучше указывать полным (или как `data\index.db`): относительный путь привяжет базу к конкретной
версии, и она перестанет быть общей.

### Удаление

1. Удалите папку с программой (в примерах `D:\hds` или `~/hds`).
2. Удалите ярлыки с рабочего стола и задания автозапуска: в планировщике заданий Windows —
   задания с именами `HermesDiskSearch*`; на Mac — файлы `~/Library/LaunchAgents/local.hds.*`.
3. По желанию освободите место: модели — `%LOCALAPPDATA%\llama-runtime`, набор файлов движка —
   `%APPDATA%\OpenResearchTools`, журналы и служебные данные — `%LOCALAPPDATA%\hermes-disk-search`
   (на Mac пути из главы «Что где лежит на диске»).
4. Удалите базу `index.db`, если она вам больше не нужна.

Перед удалением закройте ассистента и остановите службу моделей — иначе часть файлов будет занята.

## 15. Перечень команд

Все команды запускаются из папки установки как `.\bin\hds.exe <команда>` (на Mac —
`~/.local/bin/hds <команда>`). Общая справка — `hds --help`, справка по команде — `hds <команда> --help`.

### Поиск и ответы

| Команда | Что делает |
|---|---|
| `hds search "слова" --limit 8` | поиск по имени, теме и содержимому; `--kinds` ограничивает виды файлов, `--json` даёт машинный вывод |
| `hds ask "вопрос" --limit 8` | ответ по найденным фрагментам со ссылками на источники |
| `hds status` | состояние базы: сколько файлов по видам, сколько фрагментов, сколько ошибок |
| `hds check` | проверка состояния всех компонентов (с ключом `--json` — машинный вывод) |

### Наполнение базы

| Команда | Что делает |
|---|---|
| `hds index` | обработка папок из настроек; повторный запуск догоняет изменения |
| `hds index --full` | обработать всё заново, не пропуская по времени правки |
| `hds index --roots "D:\;E:\Архив"` | разово обработать указанные папки |
| `hds index --kinds text,pdf` | ограничить виды файлов |
| `hds index --limit 20 --no-prune` | пробный прогон на 20 файлах, ничего не удаляя |
| `hds index --rechunk` | заново нарезать текст (после смены размера фрагмента) |
| `hds index --progress-sec 10 --quiet` | как часто показывать ход работы; `--quiet` — без вывода |
| `hds watch [--roots "D:\"]` | служба слежения за файлами (в фоне) |
| `hds reindex <путь> [--no-force]` | обработать заново один файл или папку |
| `hds reindex-fts` | перестроить поиск по словам (после смены разбора русских слов) |
| `hds forget <путь>` | убрать файл или папку из базы |
| `hds clip-index` | дозаполнить поиск по картинкам |
| `hds stop` | сигнал закончить обработку (служебный файл `index.stop`) |
| `hds db-move --to <путь>` | перенести базу в другое место |
| `hds agent init [--yes] [--root DIR] [--no-index] [--force]` | анонимная зона: сброс индекса (стоп слежения, удаление `index.db` и выхода анонимизации), пустая база и первичная индексация `<agent.root>\P*\workspace`; чужой каталог выхода удаляется только с `--force` |
| `hds agent token <P> [--ttl-days N]` | токен проекта для маршрута `/mcp/agent/<P>`: в файл — хэш, сам токен печатается один раз |

### Ответы, расшифровка видео/аудио, видеокарта

| Команда | Что делает |
|---|---|
| `hds transcribe-watch` | служба расшифровки видео/аудио (в фоне); `--dry-run` — проверка без запуска |

| `llm_host run` / `stop` / `status` / `devices` | служба моделей: запуск, остановка, состояние, список видеокарт |
| `llm_host load <роль>` / `unload <роль>` | заранее поднять или выгрузить модель (роли: `chat`, `embedding`, `rerank`, `whisper`, `transcribe`) |

### Анонимизация документов

| Команда | Что делает |
|---|---|

### Агент в анонимной зоне

| Команда | Что делает |
|---|---|
| `hds agent project add <P> --name <имя> --path <папка> [--provider <имя>] [--model <модель>]` | завести проект в реестре `data\agent\projects.json`; провайдер по умолчанию `openrouter`, модель — из решения В-12 |

| `hds agent run --project <P> [--prompt <текст>] [--session <ID>] [--max-iterations N] [--subagents] [--json] [--quiet] [--dry-run]` | ход агента по проекту; без `--prompt` реплика читается со stdin; `--session` возобновляет сессию вместе с историей; `--dry-run` печатает план (снимок vault, MCP, правила) и не запускает воркер |

| `hds agent result accept\|reject\|conflict --project <P> --path <отн. путь> [--choice agent\|new\|delegate]` | решение по варианту агента из `.hds-agent\pending`: «Принять» (копия в `backup` и замена оригинала), «Отклонить» (сообщение агенту), «Конфликт» — три исхода |

| На странице управления «распознаватель текста не найден» | включите распознавание текста и выполните `installers\configure_ocr.py` |
| Файлы Microsoft Project (`.mpp`) не читаются | нужна Java 11 и новее |
| Узел подключения ассистентов не отвечает, адрес занят | `hds mcp-http status` — посмотрите, что занимает адрес `8787`, освободите его и выполните `hds mcp-http restart` |
| Программа ffmpeg не находится после установки | откройте новое окно командной строки: путь к программам обновляется при запуске окна |

| Расшифровки видео/аудио не находятся поиском | перенесите нужные файлы `.md` из папки «исходящие» вручную в папку, которая входит в список папок поиска (глава 8) |
| Расшифровка видео/аудио не запускается | проверьте, включена ли она (`auto_transcribe.enabled`), есть ли модель разделения по говорящим (около 449 МБ) и не остался ли файл-замок от сбоя: `hds check` подскажет |
| После обновления поиск пуст | проверьте, не пересоздана ли база: в этом случае нужен полный обход `hds index --full` |

## 17. Проверка состояния и журналы

Проверка состояния — первое, что стоит выполнять при любых сомнениях:

```powershell
hds check            # понятный пользователю вывод
hds check --json     # машинный вывод
```

Что она проверяет:

* **профиль работы** — одиночный режим или серверный;
* **раскладка** — из какой копии запускается программа: `app\current\bin` — раскладка по версиям
  (обновление и возврат к прежней версии подменяют её указателем), `<папка>\bin` — простая
  установка, обновление переведёт программу на раскладку по версиям само;
* **база поиска** — доступна ли, какой режим записи используется;
* **папки поиска** — существуют ли указанные папки, доступны ли для чтения;
* **ИИ-модель, модели смысловых отпечатков и переранжирования** — подняты ли, отвечает ли служба
  моделей;
* **распознавание текста** — найден ли распознаватель и языковые наборы;
* **чтение документов и файлов Microsoft Project** — работает ли служебная программа, есть ли
  Java;
* **видеокарта** — какая используется, сколько памяти занято, кто её занимает: программа или
  посторонний процесс;
* **служба расшифровки видео/аудио** — работает ли, не остался ли файл-замок от сбоя;
* **очередь и ограничения** — сколько обращений выполняется и сколько ждёт (подробно это описано
  в серверном документе);
* **строки «проверяется вручную»** — то, что нельзя проверить автоматически: распознавание речи
  и работа без видеокарты.

Журналы:

| Что | Windows | Mac |
|---|---|---|
| Страница управления | `%LOCALAPPDATA%\hermes-disk-search\ui.log` и `ui.err.log` | `~/Library/Logs/hermes-disk-search/` |
| Служба моделей | `data\logs\llm-host.log` в папке установки | там же |
| Действия (кто что делал) | `data\logs\audit.jsonl` — ведётся в серверном режиме | там же |

Если вы просите о помощи, приложите вывод `hds check`, свежие строки журналов и описание того,
что делали перед сбоем.

Служебные программы на Python — папка `hds` (исходный текст чтения документов) и `sidecar`
(три воркера: `hds_extract` — документы, `hds_transcribe` — расшифровка, `hds_anonymize` —
анонимизация; общий транспорт `hds_sidecar`).

### Python-стек расшифровки (P5)

* Окружения: `sidecar\venv-transcribe` (профили `cuda`/`cpu`) или
  `sidecar\venv-transcribe-dml` (ONNX + `onnxruntime-directml`); создаются от портативного
  CPython `sidecar\python`. Ровно **один** профиль на дерево — `onnxruntime` и
  `onnxruntime-directml` не живут вместе.
* Сборка/модели:
  ```powershell
  installers\build_transcribe_sidecar.ps1 -Profile cuda -SelfTest
  installers\export_gigaam_onnx.ps1 -ModelsDir D:\models -Verify   # cpu/dml
  installers\fetch_transcribe_models.ps1 -ModelsDir D:\models -HfToken <token>
  ```
* Модели: `<models>\gigaam`, `<models>\hf-home`, `<models>\gigaam-onnx\<вариант>`;
  манифест с закреплёнными ревизиями и sha256 — `<models>\transcribe-models.json`.
  Рантайм работает офлайн (`HF_HUB_OFFLINE=1`), токен нужен только на первую загрузку.
* Диагностика: `hds transcribe-check` (профиль, вендор GPU, EP, версии, модели, ONNX, токен,
  ffmpeg, RTF/VRAM последних заданий) и `hds check`.
* Отчёты и замеры этапов — `tools/parity/out/py_transcribe/` (`P*_REPORT.md`, логи; каталог
  не входит в репозиторий).
* **DML (дискретная AMD/Intel) — экспериментальный профиль**: на встроенной AMD/Intel DirectML
  медленнее CPU; живой приёмки на дискретной карте нет. Python-DML (`onnxruntime-directml`)
  не связан со старым Rust-диаризатором Nemotron.

### Python-стек анонимизации (P5–P6)

* Окружение: `sidecar\venv-anonymize` от портативного CPython `sidecar\python`, профили
  `cpu` (onnxruntime) и `cuda` (onnxruntime-gpu); ровно **один** `onnxruntime` на дерево,
  поэтому CPU-пин из lock при `cuda` отфильтровывается.
  Сборка: `installers\build_anonymize_sidecar.ps1 -Profile cpu|cuda -SelfTest` (идемпотентно,
  маркер — профиль + sha256 lock).
* Модели: `installers\fetch_anonymize_models.ps1 -ModelsDir <models>` — GLiNER PII
  (`knowledgator/gliner-pii-large-v1.0`) в `<models>\anonymize\hf-home` (структура HF-кэша),
  `navec_news_v1_1B_250K_300d_100q.tar` и `slovnet_ner_news_v1.tar` рядом; манифест
  `<models>\anonymize-models.json` с ревизиями и sha256. Модель **публичная** — токен HF не нужен.
* База меток — `anonymize.db_path` (`data/anonymize.db`, SQLite WAL). Rust к базе не обращается:
  токены выдаёт и хранит воркер; нумерация per-type с дедупом по (значение, тип).
* Видеопамять: при `anonymize.gpu: auto` акт берёт аренду у службы моделей
  (`/internal/anon/enter|exit`), при недоступности — работа на процессоре с предупреждением
  в отчёте. Роль `anon` выгружает low-priority роли и ждёт занятый сеанс чата.
* Диагностика: `hds anon check` (venv/модели/база/адрес аренды) и пункт `anonymize` в `hds check`.
* Отчёты и замеры — `tools/parity/out/` (каталог не входит в репозиторий).

## 19. Анонимизация документов

**Что это.** Документ можно «скрыть»: программа находит персональные данные (имена, организации,
адреса, телефоны, почту, паспортные и банковские данные) и заменяет их метками вида
`[PERSON_1]`, `[ORG_2]`, `[PHONE_1]`. Обратная операция возвращает исходный текст по базе меток.
Всё считается на этом компьютере: ни документ, ни найденное никуда не отправляются.

**Форматы:** `.docx`, `.xlsx`, `.txt`, `.md`, `.xml` (MS Project). Папка обрабатывается по
верхнему уровню — вложенные каталоги не обходятся.

**Где это в программе.**

* страница управления → закладка **«Анонимизация»**: поле пути, кнопка «Обзор», список
  найденных файлов, выходной каталог и четыре кнопки — «Скрыть всё», «Скрыть указанное»,
  «Показать всё», «Показать указанное»; прогресс и отчёт по файлам;
* командная строка — `hds anon …` (глава 15).

«Скрыть указанное» / «Показать указанное» принимают список: значения или метки — по одному на
строку (в командной строке — аргументами). Эти действия не требуют моделей.

**Куда попадают файлы.** Выходной каталог — `anonymize.output_dir` (по умолчанию
`data/anonymized`); его можно изменить в карточке и сохранить. Имена:
`<имя>.anonymized.<расширение>` после «скрыть» и `<имя>.deanon.<расширение>` после «показать»
(суффикс `.anonymized` у входа отбрасывается). Каталог выхода исключается из поиска
автоматически: анонимизированные копии в базу не попадают.

**Как включить полный режим («Скрыть всё»).** Нужны окружение и модели — они ставятся отдельно,
одной командой каждое (нужен интернет, около 3–6 ГБ на окружение и ~1 ГБ на модели):

```powershell
# 1) окружение: cpu (по умолчанию) или cuda — тогда поиск идёт на видеокарте
powershell -File installers\build_anonymize_sidecar.ps1 -Profile cpu -SelfTest
# 2) модели: GLiNER PII + navec + slovnet в машинный каталог моделей
powershell -File installers\fetch_anonymize_models.ps1 -ModelsDir D:\models
# 3) проверка готовности
hds anon check
```

Токен Hugging Face **не требуется** — модель публичная. Профиль `cuda` использует
`onnxruntime-gpu` и берёт видеопамять через службу моделей (роль `anon`): если карта занята
ответом на вопрос, акт подождёт, а при недоступной службе пройдёт на процессоре — об этом будет
строка в отчёте.

**Что важно знать.**

* **сессий нет:** программа не хранит пары «оригинал / аноним / результат». Нужен исходный текст —
  держите его сами; «Показать» работает, пока жива база меток `data/anonymize.db`;
* **значения не показываются:** ни в карточке, ни в журналах — только метки, их типы и число
  замен. Разведка файла (`hds anon inspect`) тоже показывает только метки;
* **повторная обработка:** если файл уже анонимизирован, «Скрыть всё» выполнится, но с
  предупреждением; «Скрыть указанное» на таком файле — обычный сценарий;
* **файлы из прежней отдельной программы** (`anonymizer_proxy`) этим выпуском не
  деанонимизируются: схема нумерации меток другая (per-type с дедупликацией), база не
  переносится;
* **Word/LibreOffice:** если файл открыт и занят, акт вернёт понятную ошибку «файл занят» —
  закройте документ и повторите;
* полный режим требует установленных моделей; без них «Скрыть всё» честно сообщает
  «модели не установлены», а «указанное» и «показать» работают.

Подробнее (в том числе для администратора сервера и разработчика) — `README_ANONYMIZATION.md`.

## 20. ИИ-агент в анонимной зоне

**Что это.** Отдельный режим, в котором ИИ-агент работает не с оригиналами документов, а с
их **обезличенными копиями**. В копиях вместо ФИО, организаций, адресов и реквизитов стоят
метки вида `[PERSON_1]`, `[ORG_2]`, `[REQ_3]`; база соответствий «метка → значение» лежит в
`data\anonymize.db` и агенту недоступна. Поэтому даже облачная модель, которой агент отправляет
запросы, видит текст без персональных данных.

Чем это отличается от обычного чата с ИИ-ассистентом (глава 12): ассистент читает файлы
напрямую и может отправить наружу всё, что в них есть. Агент в анонимной зоне читает только
свою папку `workspace` с обезличенными копиями, а на выходе каждого запроса стоит фильтр,
который заменяет значения метками и блокирует запрос, если в тексте встретился ключ провайдера.

### Включение

1. В `config.yaml` включите режим и задайте папку зоны вне профиля пользователя:

   ```yaml
   agent:
     enabled: true
     root: 'D:\hds-anon'
   ```

   `agent.root` — корень зоны; в нём появятся каталоги проектов `P0001`, `P0002`, … Каждый
   проект — это `workspace` (обезличенные копии, которые агент видит), `agent-config`
   (настройки агента, подменённый `HOME`) и `agent-state` (данные SDK и история).

2. Постройте индекс по обезличенным копиям: `hds agent init` (глава 15). Команда пересоздаёт
   `index.db` и индексирует `<agent.root>\P*\workspace`. Прежний индекс при этом заменяется —
   это решение D9, поэтому команда спрашивает подтверждение.

3. Положите ключ провайдера **только** в `data\agent\secrets.json` — в `config.yaml` и в
   окружении его быть не должно. Минимальный файл:

   ```json
   {
     "providers": {
       "openrouter": { "api_key": "<ваш ключ>", "base_url": "https://openrouter.ai/api/v1" }
     }
   }
   ```

   Для другого провайдера (`openai`, `anthropic`, `ollama`, …) укажите своё имя и адрес; список
   поддерживаемых видов задаёт `agent_run::provider_kind`.

4. Заведите проект и запустите ход:

   ```powershell
   hds agent project add P0001 --name "Пилот" --path "D:\Проекты\Внедрение ERP"
   hds agent run --project P0001 --prompt "Собери короткую сводку по договорам"
   ```

   `--path` — папка проекта **в зоне пользователя** (не `workspace`): по ней hds показывает
   найденные файлы путями пользователя. Провайдер по умолчанию — `openrouter`, модель —
   `~deepseek/deepseek-flash-latest` (решение В-12); их можно переопределить ключами
   `--provider` и `--model` при `project add`.

### Зеркало папки проекта

`hds agent sync --project P0001` переносит папку проекта в анонимную зону и обратно:

* **прямой путь.** Документы проекта получают обезличенные копии в
  `<agent.root>\P0001\workspace` — та же структура папок, имена с метками
  (`Протоколы\Встреча с [PERSON_3].docx`); `pdf/pptx/mpp` становятся текстовым
  образом `*.pdf.md`. Файл, который ещё дописывается, зеркало ждёт
  (`agent.sync.wait_stable_sec`), а не анонимизирует половину;
* **обратный путь.** Агент правит образ — деанонимизированный вариант попадает в
  `.hds-agent\pending\<имя>` вместе со снимком основания и отчётом валидатора;
  оригинал при этом **не меняется** до решения пользователя;
* **новый файл агента** (`workspace\Отчёт [PERSON_1].md`) появляется в папке проекта
  сразу, на своём месте, с настоящим именем (`Отчёт Иванов Иван.md`): отдельной папки
  «Входящие» нет;
* повторный проход по неизменённой папке — **0 изменений**; связь «оригинал ↔ образ»
  хранится в реестре `data\agent\registry\<P>.db`, а не вычисляется из имени.

В папке проекта рядом с документами появляется служебная папка `.hds-agent`. Индекс её
не видит, зеркало её не обходит:

| Что | Зачем |
|---|---|
| `.hds-agent\pending\<отн. путь>` | вариант изменённого документа до решения пользователя: деанонимизированный, с восстановленными свойствами и картинками |
| `.hds-agent\pending\<отн. путь>.report.json` | отчёт валидатора к варианту (`rel`, `anon_rel`, `ts`, `rev`, `verdict`, `checks`) |
| `.hds-agent\base\<отн. путь>` | снимок основания — копия файла, по которой построен образ; из неё берутся `docProps` и картинки при сборке варианта |
| `.hds-agent\backup\<дата-время>\<отн. путь>` | копия оригинала перед «Принять»: если что-то пошло не так, файл можно вернуть |
| `.hds-agent\messages.jsonl` | очередь сообщений агенту (`document_rejected`, `conflict_delegated`, `labels_merged`, `labels_unmerged`) — только метки и пути |

### Вариант, отчёт и решение

Перед сборкой варианта валидатор проверяет четыре вещи и кладёт рядом отчёт
`pending\<отн. путь>.report.json`:

| Проверка (`checks[].name`) | Что ловит |
|---|---|
| `labels_outside_project` | метки, которых нет в базе меток проекта: агент выдумал метку или перенёс её из другого проекта |
| `label_grammar` | несогласованный падеж: `[PERSON_1\|дат]` вместо формы, которую дала база |
| `unplaced_images` | `[IMAGE_n]`, для которых в основании нет картинки: метка осталась текстом |
| `text_lost` | вариант потерял больше 40 % слов исходного текста |

`verdict` — `ok` или `check`. **`check` ничего не блокирует**: вариант лежит в
`.hds-agent\pending`, статус `pending_accept`, решение принимает пользователь. Отчёт
удаляется вместе с вариантом.

Решения — `hds agent result ...` (путь — относительный, как в папке проекта):

| Решение | Что происходит |
|---|---|
| `accept` | сначала копия в `.hds-agent\backup\<дата-время>\`, затем замена оригинала, затем пересоздание образа; вариант и отчёт удаляются |
| `reject` | оригинал не трогается, образ пересобирается из оригинала, в `.hds-agent\messages.jsonl` — сообщение `document_rejected`: агент поймёт, что правку не приняли |
| `conflict --choice agent` | оставить вариант агента |
| `conflict --choice new` | оставить то, что пользователь сделал сам, вариант — в `.hds-agent\_conflicts` |
| `conflict --choice delegate` | ничего не менять, агенту уходит `conflict_delegated` |

**«Файл занят»** — не ошибка зеркала: если Word или Excel держит оригинал открытым
(`os error 32`), «Принять» честно сообщает «файл занят», копия не делается, вариант
остаётся в `pending`. Закройте документ и повторите.

### Режим демона

`hds agent sync --project P0001 --interval 5` — зеркало работает в фоне, без `--once`:

* период — `--interval SEC` или `agent.sync.interval_sec` (по умолчанию 5 с).
  `--interval 0`, отрицательное число, не число и `--once` вместе с `--interval` —
  отказ с кодом 2;
* один проход — ровно тот же, что у `hds agent sync --once`; зеркало, реестр и
  воркеры поднимаются один раз и живут между проходами;
* остановка — `hds stop` (создаёт `<root>\index.stop`, как для индексатора), Ctrl+C или
  закрытие терминала. Сигнал `index.stop` один на индексатор и зеркало: `hds stop`
  останавливает и то, что работает; демон проверяет сигнал каждые 0,5 с, поэтому
  останавливается не дольше чем за полсекунды после текущего файла; `index.stop` и
  `sync.lock` снимаются;
* второй демон по тому же проекту не запустится: lock `sync.lock` в
  `<agent.root>\P0001\agent-state` — отдельный от `watch.lock` индексатора, они не мешают
  друг другу. Занятый lock — сообщение «уже запущен» и код 0;
* ошибка прохода (нет доступа к папке, упал воркер) демон не убивает: строка `error`
  в журнал — и следующий проход.

Журнал — `<agent.root>\P0001\agent-state\sync.log` (пишется и в режиме `--once`):

```
2026-11-20 14:08:29 start mode=daemon project=P0001 interval=1s source=D:\Проекты\Внедрение ERP workspace=D:\hds-anon\P0001\workspace
2026-11-20 14:08:29 pass scanned=34 created=0 updated=0 unchanged=33 ... changes=0 problems=0
2026-11-20 14:08:47 pass scanned=34 created=0 updated=0 unchanged=32 ... agent_changed=1 ... variants=1 changes=2 problems=0
2026-11-20 14:08:48 stop reason=index.stop passes=4 changes=3
```

Только пути, метки, статусы и числа — ни содержимого документов, ни значений из базы
меток (I8). Проблем за проход пишется не больше десяти; журнал больше 1 МБ при старте
уезжает в `sync.log.1`.

Автозапуск демона при входе в систему — этап A6; подписка на изменения файловой системы
вместо опроса по таймеру — фаза 2. Ctrl+C строку `stop` не пишет (процесс завершается
сразу), но `sync.lock` после него снимается следующим запуском как устаревший.

Настройки зеркала — блок `agent.sync` в `config.yaml` (все ключи необязательные; `0`,
отрицательные и нечисловые значения игнорируются — остаётся значение по умолчанию):

| Ключ | По умолчанию | Смысл |
|---|---|---|
| `agent.sync.interval_sec` | 5 | Период обхода в режиме демона (`hds agent sync --interval`). Меньше — быстрее реакция, но чаще чтение метаданных всего дерева; разовый проход — флаг `--once` |
| `agent.sync.wait_stable_sec` | 2 | Сколько секунд размер и время изменения файла должны оставаться неизменными, чтобы считать файл «успокоившимся». Защита от анонимизации недописанного файла (копирование 80 МБ) |
| `agent.sync.wait_poll_ms` | 500 | Период опроса размера и времени изменения во время ожидания: меньше — точнее момент готовности, больше — грубее и меньше обращений к диску |
| `agent.sync.wait_max_sec` | 30 | Максимум ожидания одного файла. Не дождались — файл откладывается до следующего прохода, статус «ошибка» **не** ставится: пользователя не пугаем, остальные файлы не задерживаем |
| `agent.sync.settle_age_sec` | 5 | Файл, не изменявшийся дольше этого, не ждём вовсе: первый проход по большой папке не тормозит на `wait_stable_sec` для каждого документа |

### Что не зеркалится

* `.hds-agent` — служебная папка проекта: иначе варианты и снимки основания поехали бы
  в анонимную зону;
* `~$*` (файлы блокировки Word/Excel), `*.tmp`, `Thumbs.db`;
* `_attachments` и `_conflicts` — служебные папки `workspace`, они не выпускаются
  в папку проекта;
* файлы неподдерживаемых видов (`unsupported`) и файлы больше `index.max_file_mb`
  (`too_big`): в реестре они видны со своим статусом, образа у них нет;
* junction и символические ссылки: обход не выходит за корень проекта;
* сама папка проекта в индекс не попадает: индекс строится по
  `<agent.root>\P*\workspace` (`hds agent init`).

### Вкладка «Агент»

В `hds ui` (`http://127.0.0.1:8765`) есть вкладка **«Агент»**: проекты, состояние зеркала,
файлы реестра, **реплика** — предпросмотр «что увидит модель», «Скрыть ещё…», «Не скрывать»,
вложения и отправка хода, — **лента событий** с вопросом агента, **панель «Результаты»**
с решениями по вариантам, **панель «Метки проекта»** со склейкой меток, **«Настройки агента»**
и «Очистить историю» (A5.1–A5.6).

* **Проекты** — список из `data\agent\projects.json`: папка, провайдер и модель, число
  файлов и число вариантов, ждущих решения;
* **Новый проект** — имя и папка проекта; идентификатор `P0001`, `P0002`, … выдаётся
  автоматически. Папка должна быть абсолютной, существующей и лежать **вне** `agent.root`
  (после создания запустите зеркало: `hds agent sync --project P0001`);
* **Состояние проекта** — включена ли анонимная зона, работает ли демон зеркала (по
  `sync.lock` в `<P>\agent-state`), последние 20 строк `sync.log`;
* **Файлы проекта** — таблица «оригинал → образ → вид → статус» по реестру
  `data\agent\registry\<P>.db`;
* **Реплика** — поле ввода и блок «Что увидит модель»: кнопка «Что увидит модель» показывает
  текст ровно в том виде, в каком он уйдёт провайдеру (метки вместо значений, папка проекта —
  `[SYS_n]`), «Скрыть ещё…» по выделению выдаёт метку для нового значения, «Не скрывать»
  вносит значение в общую базу `keep_terms` (действует во всех проектах, D19), «Вложить файл…»
  подставляет путь образа (файл из папки проекта — по реестру, файл вне папки — копия в
  `<P>\workspace\_attachments`). «Отправить» требует сначала предпросмотр; «Стоп» прерывает
  ход. Один активный ход на проект: вторая отправка получает 409.
* **Лента хода** — поток событий (`GET /api/agent/events`, `text/event-stream`): рассуждения
  модели (свёрнутый блок), вызовы инструментов и их вывод (до 20 000 символов, тоже свёрнуто),
  ответ, предупреждения фильтра (`redacted` — только метки) и итог хода. В ленте видны
  **значения**, пути — папки проекта; переключатель **«как видит модель»** показывает то же
  событие с метками. Лента не растёт бесконечно: в DOM не больше 500 событий.
* **Вопрос агента** (`ask_user`) — агент может спросить пользователя, не выходя из вкладки:
  вопрос появляется в ленте **со значением** (метки разворачивает шлюз, интерфейс их не
  разбирает), в панели «Вопрос агента» есть поле ответа. Ответ уходит агенту как обычный текст
  и на выходе фильтруется: провайдер получает метки, а не значения. Таймаут ожидания —
  `agent.ask_timeout_sec` (по умолчанию 600 с): по истечении модели возвращается отказ, ход
  продолжается. «Стоп» снимает висящий вопрос и прерывает ход.
* **Результаты** — варианты, которые агент собрал из изменённых образов: таблица
  «вариант → статус → отчёт → действия». Колонка «Отчёт» — вердикт валидатора (TR-7.8): `ок`
  или «проверить» и число проверок (метки вне проекта, падеж, непомещённые картинки, доля
  пропавшего текста). «Сравнить…» показывает метаданные обеих сторон (пути, размеры, sha256),
  отчёт валидатора целиком и построчный diff (лимит — 200 строк / 2 000 символов; Word-compare
  и ячеечный diff xlsx — фаза 2). «Принять» заменяет оригинал вариантом, копия прежней версии
  уходит в `.hds-agent\backup\<дата-время>\`, образ пересоздаётся из нового оригинала;
  «Отклонить» возвращает образ к оригиналу и уведомляет агента. При конфликте (оригинал
  изменился, пока агент работал) доступны три исхода: «Оставить вариант агента» (правки
  пользователя — в backup, с предупреждением), «Взять новую версию» и «Поручить агенту»
  (анонимная копия варианта — в `<P>\workspace\_conflicts`). Если оригинал открыт в Word/Excel,
  сервер отвечает «файл занят», вариант и статус остаются на месте; после закрытия файла
  решение повторяют. Решения выполняет то же ядро `hds_agent::results`, что и
  `hds agent result`, поэтому UI не меняет оригиналы сам.
* **Метки проекта** — таблица «метка → значение (формы) → где встречается». NER не
  склеивает частичные упоминания: «Иванов», «Иванов Иван Иванович» и «И. И. Иванов» —
  разные метки (`[PERSON_3]`, `[PERSON_5]`, `[PERSON_8]`), и агент видит трёх разных
  людей. Отметьте строки **одного типа** и нажмите «Объединить выбранные»: старшей
  становится метка с наибольшим числом файлов (при равенстве — первая отмеченная),
  формы младших переезжают в неё, младшие номера остаются псевдонимами — уже
  выпущенные файлы с `[PERSON_5]` по-прежнему деанонимизируются, — образы
  пересобираются (в workspace остаётся старшая метка), а агенту уходит сообщение
  «метки [PERSON_5] теперь обозначаются [PERSON_3]». «Разъединить» отменяет
  **ошибочную** склейку, но только ту, что записана в журнале (после A5.5); склейки
  до A5.5 необратимы, об этом сказано в панели. «Не скрывать» у формы вносит значение
  в общую базу `keep_terms` (D19, действует во всех проектах) — метка при этом не
  удаляется. «Где встречается» — по тексту образов (тело документа, без заголовков
  docx); число файлов и форм, точный счётчик вхождений — фаза 2. Варианты в `pending`
  и конфликты при склейке не пересобираются — панель пишет их в «пропущено», решение
  принимается в «Результатах».
* **Настройки агента** — таблица «параметр → значение → изменить». Провайдер и модель
  проекта пишутся в `data\agent\projects.json`, ключ провайдера — **только** в
  `data\agent\secrets.json` (в `config.yaml` ключей нет никогда), а пороги фильтра, журнал
  исходящего и MCP — в секцию `agent:` файла `config.yaml`: правка идёт построчным
  редактором, поэтому комментарии и остальные ключи остаются как были (итоговый YAML
  проверяется). Про ключ панель показывает только «задан/нет» — ни значения, ни хвоста
  маски в ответах API нет. Смена ключа, провайдера, модели, фильтра или MCP выгружает
  процесс агента: следующий ход откроет сессию заново (в ответе `reopened: true`), поэтому
  панель спрашивает подтверждение. `max_live_projects` применится после перезапуска
  `hds ui` (о чём панель предупреждает).
* **Уведомления фильтра** — блок под лентой. Срабатывание значит, что значение уже лежало
  в истории агента открытым (NER пропустил его при анонимизации файла или реплики): каждый
  запрос фильтр чинит, но исправлять надо и сохранённую историю. Блок показывает число
  срабатываний, метки и источник словаря (**без значений**), «Сбросить сводку» очищает
  счётчики.
* **«Очистить историю»** — кнопка в блоке уведомлений и в настройках. Что делает:
  останавливает ход (если он идёт), выгружает процесс, прогоняет файлы истории
  `<P>\agent-state\.cline\data\sessions\<сессия>\` через тот же словарь фильтра (значения →
  метки) и **возобновляет сессию** следующим ходом. Рядом с каждым файлом остаётся бэкап
  (`*.json.bak`) — его можно удалить вручную; отчёт содержит сессию, пути файлов и
  бэкапов, число замен. Проверка истории перед завершением сессии (без нажатия кнопки) —
  A6.

Маршруты `/api/agent/*` защищены как остальные API: loopback и CSRF-заголовок; в
серверном профиле вкладка недоступна (403, D20) — в том числе для потока событий.
Лента отдаётся потоком SSE (кадры `id:`/`event: item`, `retry: 1500`, heartbeat `: ping`
раз в 15 с, соединение закрывается через 5 минут и переподключается само); для тестов,
`curl.exe` и страниц без `EventSource` сохранён JSON-фолбэк
(`GET /api/agent/events?project=P0001&after=<seq>`): кольцо на 500 событий, `busy`,
`session`, `seq`. Ответ на вопрос агента — `POST /api/agent/answer` с `{project, ask_id,
answer}` (400 — пустой ответ, 404 — вопроса нет, 409 — номер устарел).
Панель «Результаты» — `GET /api/agent/pending?project=…` (варианты `pending_accept` и
`conflict`, отчёт валидатора, признаки варианта/основания/копий в `_conflicts`),
`GET /api/agent/compare?project=…&rel=…` (метаданные обеих сторон, отчёт, diff) и
`POST /api/agent/decision {project, rel, decision, choice?}` (`decision` —
`accept|reject|conflict`, для конфликта `choice` — `agent|new|delegate`; 400 — тело,
решение или путь, 404 — нет проекта, записи в реестре или варианта, 409 — решать нечего,
файл занят или нужен выбор конфликта, 503 — зона выключена). После решения в ленту
приходит событие `notice` (путь и исход, без содержимого документа).
Панель «Метки проекта» — `GET /api/agent/labels?project=…` (метки с формами,
псевдонимами, `occurrences` — файлы, где метка есть в образе, и журналом склеек),
`POST /api/agent/labels/merge {project, keep, drop}` (400 — нет `drop`/`keep`, разные
типы, одна метка; 404 — метка не принадлежит проекту; 409 — метка уже псевдоним; 503 —
зона выключена) и `POST /api/agent/labels/unmerge {project, merge_id}` (400 — нет
`merge_id`; 404 — склейка не найдена, в том числе для склеек до A5.5; 409 — склейка
изменилась). «Не скрывать» из панели идёт прежним `POST /api/agent/keep`. После
склейки и разъединения образы пересобираются, выполняется один проход зеркала,
сообщение ложится в `.hds-agent\messages.jsonl` (`labels_merged`/`labels_unmerged`),
а в ленту приходит `notice` «метки склеены: …» — без значений (I8).
Панель «Настройки агента» — `GET /api/agent/settings?project=…` (проект, провайдер,
модель, `key.set` — только признак, `providers`, секция `agent:`, живые процессы и пути
`config.yaml`/`secrets.json`) и `POST /api/agent/settings {project, provider?, model?,
api_key?, base_url?, enabled?, root?, subagents?, unknown?, egress_log?,
filter_max_stale_sec?, ask_timeout_sec?, request_timeout_sec?, max_live_projects?, proxy?,
disk_search_enabled?, onec_enabled?, onec_command?, tavily_enabled?, tavily_command?}`
(400 — нет `project`, пустой ключ, порог вне диапазона, `unknown` не `label|block`,
относительный корень; 404 — нет проекта; 500 — не удалось записать `config.yaml`).
Ключ пишется только в `secrets.json` — слиянием с тем, что лежит на диске (`mcp.servers`
и незнакомые ключи не теряются); `config.yaml` правится построчно, комментарии целы.
Ответ — то же тело, что у GET, плюс `applied`, `reopened`, `unloaded`, `warnings`.
«Очистить историю» — `POST /api/agent/history/clear {project, session?}` (400 —
идентификатор сессии не по правилам; 404 — нет проекта, состояния или сессии; 409 —
ход идёт, а остановить его не удалось; 503 — зона выключена); ответ
`{session, files, backups, replaced, files_count, backups_count}` — пути и числа без
значений, событие `notice` в ленту.
В ответах — пути, статусы и числа; ключ провайдера в ответы не попадает.


### Что уходит наружу

* **Только метки, не значения.** Фильтр на входе заменяет известные ему значения метками
  проекта, а на выходе — восстанавливает значения обратно; к провайдеру уходит обезличенный
  текст. Аудит срабатываний (`audit.enabled`) по умолчанию **выключен**; если он нужен,
  включайте его в `config.yaml` явно — записи аудита содержат метки, не значения.
* **Ключ в тексте блокирует запрос.** Если в реплике или в документе встретился ключ
  провайдера (или другой секрет из `secrets.json`), запрос не уходит: ход завершается ошибкой
  `privacy_filter_unavailable`. Это поведение fail-closed, а не сбой.
* **Снимок базы меток устаревает.** Если снимок старше `agent.filter.max_stale_sec` (по
  умолчанию 300 с), фильтр отказывает, а не пропускает запрос без проверки (решение В-14).

### Что агент не читает

* **Настоящий профиль Cline.** Агент запускается с подменённым `HOME`/`APPDATA` на
  `<P>\agent-config`, поэтому `%USERPROFILE%\.cline`, настройки и плагины вашего Cline он не
  видит. Профиль пользователя до и после прогона не меняется — это проверено приёмкой.
* **Плагины.** Плагины профиля агента отключены (`pluginPaths` пуст, а `plugin_issues`
  показывает, что было пропущено).
* **`run_commands` и `fetch_web_content`.** Эти инструменты агенту не выдаются: оболочка и
  произвольные запросы в интернет обошли бы фильтр. MCP-серверы (`disk-search`, `tavily`,
  `1c-buddy`) и `office_*` работают через хук `hds-guard`, а файловые операции ограничены
  папкой `workspace`.
* **`ask_user`.** Вопрос пользователю работает во вкладке (A5.3): агент задаёт вопрос, он
  появляется в ленте уже деанонимизированным, ответ отправляется из панели «Вопрос агента» и
  уходит модели через фильтр (значения заменяются метками). В CLI-прогоне (`hds agent run`)
  вопроса нет — там нет интерфейса, и инструмент отвечает отказом.

### Ограничения

* **Один проект на процесс.** Реестр `AgentRegistry` (с выгрузкой по простою) реализован, но к
  CLI-прогону пока не подключён: `hds agent run` поднимает один проект и завершает процесс.
  Выгрузка по простою и `max_live_projects` заработают во вкладке A5.
* **Значения жизненного цикла.** `agent.max_live_projects: 2` и `agent.idle_unload_min: 30`
  (решение В-16); `agent.egress_log: false` — журнал исходящих запросов по умолчанию выключен.
* **Таймаут хода.** `agent.request_timeout_sec` (по умолчанию 120 с); при превышении ход
  завершается ошибкой, а не зависает.
* **`hds check` пока не проверяет Node.** Портативный Node и `dist\worker.mjs` в проверку
  `hds check` не входят — это задача этапа A6. До тех пор целостность воркера проверяет
  `installers\build_agent_sidecar.ps1 -SelfTest`.

### Свой MCP-сервер (1c-buddy и другие)

Агент умеет подключать внешние MCP-серверы сверх встроенных. Готовый шаблон лежит в поставке:
`sidecar\mcp\mcp.example.json` (рядом — `sidecar\mcp\README.md`). Скопируйте блок `mcp` в
`data\agent\secrets.json` и замените плейсхолдеры:

```json
{
  "mcp": {
    "servers": {
      "1c-buddy": {
        "type": "stdio",
        "command": "<путь к 1c-buddy-mcp.exe>",
        "args": ["--env-file", "<путь к .env>"],
        "env": {}
      },
      "example-http": {
        "type": "streamableHttp",
        "url": "https://example.com/mcp",
        "headers": { "Authorization": "Bearer <ваш токен>" }
      }
    }
  }
}
```

Правила: `type` — `stdio` (тогда нужны `command` и, при необходимости, `args`/`env`) или
`streamableHttp`/`http` (тогда `url` и `headers`). Токен 1c-buddy храните в `.env` и передавайте
через `--env-file`; в `secrets.json` токена быть не должно. Встроенные имена `disk-search`,
`tavily` и `1c-buddy` зарезервированы: если в `mcp.servers` окажется сервер с тем же именем,
победит встроенный.

Проверка: `hds agent run --project P0001 --dry-run` покажет список серверов в `mcp.servers`
(без значений), а обычный `hds agent run` запустит ход с подключённым сервером. Ключи и
заголовки из `mcp.servers` попадают в словарь фильтра, поэтому секрет в `headers`/`env`
блокирует запрос, как и ключ провайдера.
