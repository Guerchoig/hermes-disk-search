# Релиз v0.5.9

## Исправления

### MCP-сервер не работал в Cline/Hermes — блокировка БД при каждом вызове инструмента
`db.connect()` при **каждом** подключении выполнял probe-INSERT в `chunks_vec` и безусловный
upsert в meta. Пока watcher писал в базу, каждый вызов MCP-инструмента конкурировал за
write-lock (busy_timeout=5 сек) и падал с `database-is-locked` — клиенты видели ошибки
инструментов и переставали пользоваться сервером. Теперь probe и meta-запись выполняются
только когда сохранённая `vec_dim` отличается от текущей; `busy_timeout` повышен до 30 сек.

### `ask_my_files` падал по таймауту 60 сек в Cline
Вызов MCP-инструмента прерывался: `MCP request to disk-search (tools/call) timed out after 60s`.
`ask_my_files` выполняет RAG с локальной LLM (поиск + генерация + разовая загрузка весов в
LM Studio), что регулярно превышает клиентский таймаут по умолчанию. Исправления:
- конфиг Cline теперь пишется с `timeout=300` (на реальной машине 45–50 сек — с запасом);
- генерация ограничена `chat.max_tokens` (по умолчанию 600) с запросом компактных ответов;
- RAG limit по умолчанию снижен 12 → 8;
- скилл обновлён: `ask_my_files` может занимать 1–3 мин — ждать, не откатываться на
  grep/терминал; для `search` предпочитать limit 8–12.

### Конфигурация Cline Desktop
`cline_mcp_merge.py` теперь пишет современный формат конфига Cline Desktop
(transport-only) с `autoApprove` для всех 6 инструментов — раньше пустой `autoApprove`
заставлял Cline запрашивать подтверждение на каждый вызов, и модель избегала disk-search.

## Требования к обновлению

- После обновления переустановить/перемёржить конфиг MCP (запустить
  `installers/cline_mcp_merge.py`), чтобы применились `timeout=300` и `autoApprove`.
- Переиндексация не требуется (`index --full` не нужен).
