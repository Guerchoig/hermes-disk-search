# hermes-disk-search v0.7.0

## Новое

- **Структурный чанкер** (Фаза 2): рекурсивное разбиение «абзац → строка →
  предложение → слово», целевой размер чанка снижен до 800 символов (≈400
  токенов — лучше для точечных запросов); перекрытие соседних чанков — целыми
  предложениями вместо «хвоста 200 символов».
- **Точные метаданные**: чанк больше не склеивает страницы PDF и реплики
  транскриптов — номер страницы и таймкод каждого чанка верны.
- **Путь заголовков** md и DOCX («# Раздел / ## Подраздел») попадает в начало
  каждого чанка секции — заголовки теперь участвуют в поиске.
- **Контроль бюджета токенов эмбеддинга**: текст длиннее контекста модели
  (8192 токена) обрезается индексатором по границе строки с логом — вместо
  молчаливого усечения LM Studio.
- Новая команда **`python -m hds.cli index --rechunk`** — перечанковка уже
  проиндексированных текстовых файлов (текст/офис/PDF/mpp) без OCR и
  транскрипции, с пере-эмбеддингом затронутых файлов.
- Улучшено слияние поиска (Фаза 3 в этом же релизе): веса веток
  `search.fts_weight` / `search.vec_weight`, запрос «сначала AND, при пустом
  результате OR», префиксный матчинг последнего токена (`токен*`), сниппет
  не режет предложение посередине; параметры редактируются в веб-интерфейсе.

## Требуется после обновления

- Чтобы применить новый чанкер к существующему индексу:
  **`python -m hds.cli index --rechunk`** (только текстовые типы; OCR/транскрипция
  не запускаются; пере-эмбеддинг затронутых файлов — планировать на ночь).
- Если ещё не запускали `reindex-fts` (v0.6.0) — запустите.

## Совместимость

- Схема БД не меняется; `config.yaml` совместим (новые ключи `chunk.size: 800`,
  `chunk.overlap: 120`, `search.fts_weight`, `search.vec_weight` — опциональны).
