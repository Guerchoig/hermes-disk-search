# RELEASE_NOTES v0.20.0 — автотранскрибация как служба пакета + кабинет пользователя

> Релиз-фича: **автотранскрибация+диаризация стала полноправной службой пакета** (5-я роль
> `transcribe`: SCM `hermes-disk-search-transcribe` с зависимостью от `llm-host`, в desktop —
> задача Планировщика), медиа убрано из индексации (ASR живёт только в конвейере «папка →
> `.md`»), а у не-админов появился **свой UI** `/ui/user/`: вход по логину/паролю, поиск по
> своим проектам, установка клиента Cline и транскрипты/спикеры. Rust-проверки зелёные:
> `cargo fmt --check`, `clippy -D warnings`, `cargo test --workspace` (0 падений);
> живая приёмка кабинета — `tools/parity/out/r5/`.

## Что нового

* **Служба `transcribe`** (`hds service start|stop|status transcribe`): SCM-служба
  `hermes-disk-search-transcribe` с `depend= hermes-disk-search-llm-host` (стартует после
  владельца GPU), кооперативная остановка через `transcribe.stop` — `sc stop` не оставляет
  залипший `transcribe.lock`/`index.pause`. Серверный установщик ставит роль и качает
  sortformer; в desktop задачу `HermesDiskSearchTranscribe` ставит `install_autostart.ps1`,
  а `setup.ps1` получил блок **«Automatic transcription»** (модели + папки конвейера в `config.yaml`).
* **CLI-контракт:** `hds transcribe-watch --help` больше не запускает демон (печатает справку,
  код 0), появился `--dry-run` (проверка конфига/каталогов/моделей).
* **Медиа вне индексации:** индексатор пропускает аудио/видео как `skipped_media` — ASR в
  индексации больше нет (ключ `index.transcribe` — legacy, `hds check` подскажет убрать).
  Папки конвейера (`inbox_dir`/`out_dir`/`state_dir`) исключаются из индексации **неявно**,
  в UI у полей появился индикатор «исключена из индексации ✓/✗».
* **Службы не доставляют `.md` в индекс** (решение владельца §8.1): перенос выходов в
  индексируемые папки — вручную; `index_outputs` — legacy.
* **Кабинет пользователя `/ui/user/`** (не-админский UI): вход по логину/паролю
  (`POST /api/auth/login` — тот же контракт, что у `hds login` и MCP `/auth/login`,
  с антибрутфорсом `login_per_min` по IP) или токеном от админа (`?token=…`); три блока —
  поиск (выдача фильтруется проектами токена), установка клиента Cline (скрипт + ссылка на
  `/health` для сверки версии) и транскрипты/спикеры. Права (решение §8 №5): не-админ может
  **и править `.md`, и присваивать имена спикерам** (копия `.bak`, sidecar, path-safety);
  админские маршруты → `403`, без токена → `401` (оба отказа — в аудите).
* **UI:** карточка «Демон автотранскрибации» показывает **форму** управления
  (`service`/`task`/`process`) и состояние роли SCM; в server-профиле действия уходят в SCM.
* **Reverse-proxy:** образцы публикуют `/mcp`, `/ui` (админская + кабинет) и публичную пробу
  `/health`; UI понимает и префикс `/ui`, и корень.
* **Мелкие исправления:** `.md` с BOM (сохранённый Блокнотом) снова распознаёт метки спикеров.

## Требования к обновлению

* Штатное обновление поверх 0.19.x: распаковать архив и запустить `setup.cmd`/`setup.ps1`
  (или `installers\update.ps1`). Переиндексация не требуется: медиа и раньше не давало текста в индекс.
* **Серверным стендам** — добавить роль: `hds service install transcribe` (или
  `installers\install_server.ps1 -Roles …,transcribe`), чтобы автотранскрибация шла службой,
  а не задачей планировщика. Служба чинится после `llm-host`.
* Уберите `index.transcribe` из `config.yaml` (или поставьте `false`) — ключ ничего не делает,
  `hds check` помечает его как legacy. Транскрибация настраивается в `auto_transcribe.*`.
* Токены и `data/access.yaml` совместимы с 0.19.x; кабинет `/ui/user/` использует те же токены
  и учётки (пароль нужен только для самостоятельного входа).
* Наружу (через прокси) публикуйте `/mcp`, `/ui` и `/health` — обновлённые образцы:
  `installers/proxy/{Caddyfile,nginx.conf}`.
