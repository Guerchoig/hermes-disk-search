# Экономный режим поиска на медленной машине (интегрированная графика)

Если на этой машине LLM работает на интегрированной графике (Vulkan/Metal iGPU)
или скорость генерации низкая (меньше ~10 ток/с) — соблюдай жёсткую экономию:

1. **Один вызов инструмента за ход.** Вызвал `search_local_files`/`ask_my_files` —
   в ЭТОМ же ответе дай пользователю результат/вывод; следующий вызов — только
   после его ответа. Серия вызовов в одном ходе не успевает за таймаутом клиента.
2. **`limit` ≤ 5** и одна формулировка запроса за ход. Несколько запросов с
   синонимами — только по явной просьбе пользователя, каждый — отдельным ходом.
3. **`ask_my_files` — с малым `limit` (≤ 8)** и никогда в одном ходе с поиском:
   его ответ генерирует LLM, это самая долгая операция.
4. **Не вызывай web_search** (если включён): на этой машине он почти гарантированно
   приводит ход к таймауту.
5. **Короткие ответы**: без больших таблиц и пересказов — каждый выводимый токен
   на этой машине занимает секунды.
6. Не запускай длинных задач (индексация, обходы, повторные поиски) в одном ходе
   с поиском — разбивай на шаги и завершай ход.
