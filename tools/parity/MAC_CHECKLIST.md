# MAC_CHECKLIST.md — постпроектная проверка macOS-сборки

> Зачем: по решению заказчика (29.09.2026, `MIGRATION_PLAN_RUST.MD` §10.0) mac-часть пишется в
> объёме v1.0, но **не проверяется на исполнении**: нет Apple Silicon машины, а macOS-раннеры
> в CI не выделяются (бюджет). Поэтому mac-артефакт публикуется с явной пометкой «не проверено»,
> а проверка выполняется один раз — когда появится Mac (после завершения проекта).
>
> Кому: владельцу Apple Silicon Mac (M1/M2/M3/M4). Время: ~1 час.
> Требуется: macOS 14+, 16 ГБ RAM и больше, ~10 ГБ свободного диска, интернет.
> Что заполнить: для каждого пункта — ✅/❌ и краткое наблюдение; при ❌ — версия macOS, шаг,
> текст ошибки. Результат — в `tools/parity/MAC_CHECKLIST_RESULT.md` (создать при прогоне).

## 0. Подготовка

- [ ] 0.1 Скачать релизный артефакт `hds-<ver>-macos-arm64.zip` (браузером — специально,
  чтобы проверить карантин) и `SHA256SUMS.txt`.
- [ ] 0.2 Сверить `shasum -a 256 hds-<ver>-macos-arm64.zip` с файлом сумм.
- [ ] 0.3 Убедиться, что атрибут карантина присутствует: `xattr -l <файл>` → `com.apple.quarantine`.

## 1. Установка (`install_macos.command`)

- [ ] 1.1 Запуск двойным щелчком **без** предварительного снятия карантина: что именно
  показывает Gatekeeper; сработал ли штатный обход из инструкции (правый клик → «Открыть» /
  `xattr -dr`).
- [ ] 1.2 Установка до конца: скрипт не требует прав администратора, не пишет в системные каталоги.
- [ ] 1.3 Появились ли ярлыки/пункты меню, описанные в §10.1/§10.4 плана.
- [ ] 1.4 `bin/hds check` — все компоненты «OK»; отдельно: путь к рантайму движка найден
  (`%APPDATA%`-аналог: `~/Library/Application Support/...`), Metal виден.
- [ ] 1.5 Диалоги доступа TCC: при первом обращении к папкам, которые индексируются —
  появляется запрос? Что будет, если отказать (инструмент должен деградировать, не падать).

## 2. LLM-хост и GPU (главное, что нельзя проверить в CI)

- [ ] 2.1 `bin/hdsw llm-host status --json` — инстансы и **Metal-проба**: значения
  `recommendedMaxWorkingSetSize` (~65–75 % RAM) и `currentAllocatedSize` есть и не нулевые.
- [ ] 2.2 Загрузка chat-инстанса: **рост `currentAllocatedSize`** (аналог NVML-критерия A-1)
  и кратное ускорение против принудительного CPU-режима (`gpu` не задан).
- [ ] 2.3 `bin/hdsw llm-host devices` — перечисление устройств содержит Metal; в логе
  видно, что слои реально offloaded (не «CPU-only»).
- [ ] 2.4 Фасад `:8010–8012`: `curl :8010/v1/models`, `/health`, `/props`,
  `curl :8011/v1/embeddings`, `curl :8012/v1/rerank` — форматы совпадают с ожидаемыми в §8.7.
- [ ] 2.5 `model: "chat"` — ответ без блоков размышлений; `model: "chat-think"` — с ними.
- [ ] 2.6 **Давление по памяти**: загрузить модель, близкую к бюджету `recommendedMaxWorkingSetSize`,
  и зафиксировать поведение (сообщение «нужно X / доступно Y», отсутствие молчаливой деградации).
- [ ] 2.7 Одновременно chat + embedding + индексация: индексация встаёт на паузу, ошибок нет,
  после запроса возобновляется (ARB-сценарии вживую).

## 3. Индексация и поиск

- [ ] 3.1 Индексация пилотной папки (например, `~/Documents`, 200–500 файлов, среди них
  есть кириллические имена): завершилась без ошибок, `hds status` показывает чанки.
- [ ] 3.2 `hds search` по контрольным запросам — результаты осмысленные; совпадают с
  Windows-эталонами на тех же файлах (если файлы общие).
- [ ] 3.3 Watcher: создать/переименовать/удалить файл — индекс обновляется; после перезагрузки
  Mac агент (LaunchAgent) поднимается сам и watcher работает.
- [ ] 3.4 Сон/пробуждение: при закрытии и открытии крышки индексация и watcher корректно
  продолжают работу (без «залипших» блокировок).

## 4. Медиа (ASR через движок, Metal)

- [ ] 4.1 Транскрипция короткого аудиофайла **с кириллическим именем в кириллическом каталоге**:
  текст получен, таймкоды корректны, имя выходного файла не «мозаика» (ASCII-стейджинг, §8.3).
- [ ] 4.2 Транскрипция видео (1–2 минуты): время обработки, отсутствие падений на выходе
  (риск R33 — проверяется, что Rust-владелец завершается с кодом 0).
- [ ] 4.3 CLIP-поиск по картинкам (если включён в конфиге) — «цветы»/«накладная» находят
  релевантные изображения.

## 5. Стабильность

- [ ] 5.1 Оставить `llm-host` + watcher на сутки: вернуться — процессы живы, памяти
  не «утекло» (сравнить `currentAllocatedSize` и RSS через сутки), ошибок в логах нет.
- [ ] 5.2 Термотроттлинг/питание: при длительной индексации не наблюдается деградации,
  ломающей работу (на ноутбуке — от батареи и от сети).

## 6. Итог прогона

- [ ] 6.1 Записать результат в `tools/parity/MAC_CHECKLIST_RESULT.md`: дата, модель Mac,
  версия macOS, версия HDS/движка, по каждому пункту ✅/❌ и наблюдения.
- [ ] 6.2 Если есть ❌ — завести пункты в бэклог mac-фазы и (при необходимости) снять
  «не проверено» с README только после их закрытия.
