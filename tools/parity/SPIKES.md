**Итог:** GO, но с двумя изменениями плана — (1) приоритет отдать W2 (VRAM-диспетчер) как
носителю основной ценности, W1 — быстрый дешёвый шаг рядом; (2) критерии и цели пересчитать

### 14.7. Найдено попутно: штатный старт роли `chat` не работает (несовпадение путей моделей)

При возврате системы в исходное состояние выяснилось, что «официальный» способ поднять чат-роль
на этой машине **падает**:

```
> python -m hds.llama_server start chat
{"chat": {"error": "GGUF-модель роли 'chat' не найдена:
  C:\Users\Sasha\hermes-disk-search\models\chat\qwen3.5-9b-Q6_K.gguf.
  Скачайте её (installers\ensure_llama_runtime.ps1 -Models chat ...) или укажите другой путь
  в llm_server.chat.model"}}
```

При этом модель на машине **есть** — но в общем рантайме:
`C:\Users\Sasha\AppData\Local\llama-runtime\models\chat\Qwen3.5-9B-Q6_K.gguf` (именно оттуда
работал процесс, который был запущен до остановки: `llama-server.exe -m …\llama-runtime\models\chat\… --alias qwen3.5-9b --port 8010 --ctx-size 32768 --cache-type-k q8_0 --cache-type-v q8_0 -ngl 99`).

Чат был восстановлен вручную **той же командой**, что была у прежнего процесса (порт 8010
отвечает 200), но сама нестыковка путей — дефект менеджера ролей.

**Почему это важно для W2** (§8.6/§8.6.2 основного плана, `PLAN_W2_LLM_HOST.md` §4 A2):
1. Маппинг `shared:<role>` → `models/<role>/current.json` должен разрешаться **в общем рантайме
   (`%LOCALAPPDATA%\llama-runtime` / `~/Library/Application Support/llama-runtime`)**, а не в
   каталоге проекта. Порт `hds/llama_runtime.py` (`runtime_dir`, `models_dir`, `current_file`,
   `read_current`, `resolve_model`) обязан воспроизвести именно это поведение — иначе после
   миграции чат «не найдёт» модель при живых файлах.
2. `hds check` в новой реализации должен явно показывать, **где** ищется модель каждой роли и
   что найдено фактически (одна строка на роль) — сейчас диагностика этого не говорит.
3. Тест W2: «`current.json` указывает на модель в общем рантайме → инстанс поднимается» +
   негативный кейс «файла нет → понятное сообщение с двумя путями (куда скачать, где искать)».

Воспроизведение: `python -m hds.llama_server start chat` при `llm_server.chat.model: shared:chat`
и «пустом» `<project>/models/chat`. На Windows это воспроизводится стабильно.
