## Что нового

### Разделение по говорящим: до 8 человек вместо 4

* Новый движок — **NVIDIA Nemotron-3-Diarization (Sortformer v3)** через `parakeet-rs` и ONNX
  Runtime: одна запись может быть размечена на **8 говорящих** (`SPEAKER_00`…`SPEAKER_07`), прежняя
  модель знала 4 + `UNASSIGNED`. На проверочных записях (18/56/77 минут) метки получили
  **5/8/8** говорящих.
* **Один проход декодирования**: запись переводится в звуковой формат (16 кГц, моно) один раз — этот
  же звук идёт и в распознавание речи, и в разделение по говорящим. Ведущая тишина отбрасывается
  **только** для распознавания: ИИ-модель на тишине «выдумывает» фразы («Thank you», «Obrigado»).
  Дополнительно энергетический фильтр выкидывает реплики, целиком лежащие в тишине.
* **Язык распознавания** фиксируется ключом `index.whisper_language` (по умолчанию `ru` — без него
  whisper выдавал английский текст на русских записях); пустая строка — автоопределение.
* **Скорость** (18-минутная запись): разделение по говорящим — 12.8 с на видеокарте и 51 с на
  процессоре; на 77-минутной записи — 45 с, весь файл — 3.6 минуты (декод 2.6 с + распознавание
  172 с + разделение 42 с).
* **Качество** на внутреннем эталоне (без коротких филлеров): атрибуция **74.4 %** (порог плана
  71.8 %); метрики относительные, абсолютный DER не публикуем (эталон шумный).

### Настройки, диагностика, установка

* Новая секция `diarization` (`backend: nemotron3 | sortformer | off`, `nemotron3.device`,
  `chunk_min`, `min_audio_min`, `onset/offset`, `asr.trim_leading_silence`,
  `asr.drop_silent_segments`). `auto_transcribe.diarization_backend` уходит в тело запроса только
  при **явном** ключе (и тогда сильнее секции `diarization`); без ключа backend выбирает хост.
  Существующие конфиги не перезаписываются: если секции нет, хост выберет Nemotron-3 при наличии
  модели и прохождении sha256, иначе — sortformer с предупреждением в журнале.
* `hds check` — пункт «диаризация» показывает движок (из настроек или автоподбор), путь модели,
  **сошёлся ли sha256**, устройство обработки (`auto → directml`) и найден ли `ffmpeg`; при явном
  `nemotron3` без модели — критическая ошибка с командой установщика. `hds whisper-check` печатает то
  же (текстом и в `--json`, новые ключи аддитивные).
* Установщик: `setup.cmd` и `install-server.cmd -Fetch` качают модель Nemotron-3 в машинную папку
  моделей и проверяют размер и sha256; повторный запуск ничего не качает, `-Force` перекачивает.
  `-SkipDiarization` пропускает обе модели разделения по говорящим. В пакет добавлен
  `bin\DirectML.dll` (без него разделение по говорящим не поднималось бы на машинах без Windows SDK).
* Лицензии: модель — **OpenMDW 1.1**, `parakeet-rs` — MIT OR Apache-2.0, ONNX Runtime — MIT,
  DirectML — условия Microsoft (только в Windows-пакете), sortformer — NVIDIA Open Model License.
  Модель в репозиторий и архив не входит (подробно — `NOTICE.md`).
* Совместимость: `POST /internal/transcribe` и `.md` — без изменений; `sortformer` и прежние ключи
  `auto_transcribe.diarization*` продолжают работать (запасной вариант).

### Исправления по код-ревью (21.10.2026)

* **Паника** при редком сочетании (длинный сегмент ASR с 1–2 словами и частая смена говорящих)
  устранена: задание больше не теряется, слова не теряются (F1).
* Автотранскрибация **не навязывает backend**: `auto_transcribe.diarization_backend` уходит в
  запрос только при явном ключе, иначе backend выбирает хост; `hds check`,
  `hds whisper-check` и `hds transcribe-watch --dry-run` показывают фактический запрос
  конвейера (F2).
* Обновление **докачивает модель** Nemotron-3 (идемпотентно; `-NoModels` — пропустить; ошибка
  загрузки не валит обновление) (F3).
* Демон автотранскрибации больше не предупреждает про sortformer, когда выбран `nemotron3` (F4);
  `hds check` не хеширует 400 МБ модели, если backend не `nemotron3` (F5); битая модель не
  перехешируется на каждом задании (F6); CLIP и диаризация в одном процессе используют **одно**
  ONNX-окружение (F7); запись длиннее 6 ч получает понятную ошибку до обработки, WAV/RF64
  отвергается с подсказкой (F8); `auto_transcribe.diarization_required` доходит до хоста (F9).
* Ответ nemotron-ветки возвращает фактический `mode: "transcript"` (диаризация всегда даёт `.md`)
  (F10); `onset/offset` вне `0..=1` отвергаются с предупреждением/ошибкой (F12); живой тест
  запускается только через `HDS_DIAR_MODEL`/`HDS_TEST_DIAR_WAV` (F13); комментарии про каталоги
  моделей синхронизированы с порядком автопоиска (F14); у whisper — свой staging-каталог на запрос
  (F15).


## Требования к обновлению

* Обновление обычное: `update.cmd` от администратора на Windows, `sudo bash installers/update.command`
  на macOS. Версия меняется по `version.txt` и в ответе `/health` — `0.21.0`.
* **Переиндексация не требуется**: база, настройки и формат поиска не менялись.
* **Нужна модель Nemotron-3** (400 МБ): при обновлении её **докачивает сам** `update.cmd` /
  `installers/update.command` (идемпотентно, после переключения версии; `-NoModels` — пропустить),
  `install-server.cmd -Fetch` — тоже; вручную — `powershell -File installers\fetch_nemotron3_model.ps1`
  (проверяет sha256). Модель кладётся в `<папка моделей>\nemotron3\`; службам она видна через
  `HDS_MODELS_DIR`. Если докачка не удалась (нет сети), обновление всё равно успешно — запустите
  сценарий вручную: до этого расшифровка записей падает, `hds check` показывает команду.
* **Нужен `ffmpeg`** (машинная установка): без него расшифровка записей не работает — `hds check`
  покажет это в пункте «диаризация». Windows: `winget install --scope machine -e --id Gyan.FFmpeg`,
  macOS: `brew install ffmpeg`.
* Старые конфиги подходят без правок: без секции `diarization` выбирается Nemotron-3 (если модель на
  месте), иначе — прежний sortformer. Хотите остаться на прежнем движке — `diarization.backend:
  sortformer`; при **явном** `auto_transcribe.diarization_backend` в вашем конфиге его значение
  перекрывает секцию — поставьте там `sortformer` (или удалите ключ, чтобы решал хост).
  `hds check`, `hds whisper-check` и `hds transcribe-watch --dry-run` показывают и хостовый выбор, и
  фактический запрос конвейера.
* **macOS:** разделение по говорящим идёт через CoreML с запасным вариантом CPU, но на живой машине
  **не проверялось** (сборка для macOS — best-effort, как и раньше).

  `transcribe-watch --dry-run` показывают согласованный backend, а при `off`/`sortformer` модель
  не хешируется.
* Живые прогоны на 18 / 56 / 77 минут (RTX 3060): 5 / 8 / 8 говорящих, **0** реплик, целиком
  лежащих в тишине (по точным таймкодам), **0** «Thank you»/«Obrigado»/«Lukoyle», таймкоды в

* Установщик модели: загрузка 400.5 МБ (52.7 с), повторный запуск — мгновенный пропуск, `-Force` —
  перекачивание, битый файл отвергается; `hds check` находит модель в каноническом каталоге.
* Упаковка: в архиве `bin\DirectML.dll`, скрипт `installers\fetch_nemotron3_model.ps1`, весов
  моделей нет (проверка в сборочном скрипте).
* **Не проверено:** macOS/CoreML (машины нет).
* **Память задания** (проверено 21.10.2026 по требованию владельца): на 77-минутной записи прирост
  памяти процесса — 1.56 ГБ, но это **стоимость распознавания речи**, а не разделения по говорящим:
  задание без разделения пикует выше (9.52 против 9.25 ГБ), а сама диаризация добавляет ≈0.4 ГБ
  (633 МБ на 77 минут, если запускать её отдельно). Утечки нет: серия заданий подряд выходит на
  плато (пики 8.44 → 8.64 → 8.65 ГБ, база +23 МБ за задание). Расход растёт линейно с длиной записи
  (≈20 МБ на минуту) — столько занимают модель и буферы звука в движке; после снятия чанкинга
  диаризация даёт 633 МБ вместо 2073 МБ, что и было целью. Ограничение по памяти владельцем снято.
