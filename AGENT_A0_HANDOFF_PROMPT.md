## 0. Что происходит (коротко)

Проект `hermes-disk-search` (**hds**) — локальный поиск и ИИ-инструменты для аналитиков и
менеджеров проектов внедрения 1С (работа с проектными документами, не с кодом). Новая
функция по плану: **ИИ-агент в анонимной зоне**. Агент — headless-ядро Cline
(`@cline/sdk`, Node) в отдельном процессе `hds_agent`. Он работает только с анонимизированными
копиями документов (метки `[PERSON_3]` вместо ФИО). Все исходящие данные (облачная модель,
MCP `tavily` и `1c-buddy`) проходят словарный фильтр hds. Пользователь работает во вкладке
«Агент» в `hds ui` и видит всё с настоящими значениями.

**Фаза A0** — эксперименты (спайки), которые подтверждают или опровергают ключевые
допущения плана **до** начала разработки. Продуктового кода в A0 **нет**. Результат —
отчёт `tools/parity/AGENT_SPIKES.md` с ответом «да/нет» по каждому пункту, цифрами и
предлагаемыми правками плана.

### S1. Изоляция конфигурации SDK — **стоп-точка**
Вопрос: в `backendMode: "local"` с переопределёнными `HOME`/`USERPROFILE`/`APPDATA`/
`LOCALAPPDATA` (→ `out/agent_a0/s1/home/...`) и заданными каталогами данных SDK читает
ли ядро `%USERPROFILE%\.cline`, пишет ли туда, поднимает ли hub-демон, ходит ли в сеть
вне провайдера (телеметрия, feature-flags, обновления, `cline.bot`).
Как проверить (без Procmon):
* снимок дерева `%USERPROFILE%\.cline\` и каталога расширения Cline
  (`%APPDATA%\Code\User\globalStorage\<подкаталог, где есть settings\cline_mcp_settings.json>`)
  до и после прогона: список файлов, размеры, sha256, `LastWriteTime` — разница должна
  быть пустой;
* перехват файловой системы внутри Node: обёртка `fs`/`fs.promises` через
  `--import` (лог путей open/read/write/mkdir); в логе — ни одного пути под реальным
  профилем пользователя;
* сеть: подменённый `fetch` + `undici` `setGlobalDispatcher` с журналом всех
  соединений + `Get-NetTCPConnection -OwningProcess <pid>` во время прогона; разрешены
  только loopback (mock-провайдер, `:8787`);
* процессы: дерево потомков Node (`Get-CimInstance Win32_Process`) — нет hub-демона;
* опции `ClineCore.create`/`start`, которые реально задают каталоги (искать в `.d.ts`:
  `dataDir`, `sessionsDir`, `configDir`, `workspaceRoot`, `hub`, переменные окружения
  `CLINE_*` — `grep` по `node_modules/@cline/**/dist/*.js`).
«Да» = ни одного обращения к профилю пользователя и ни одного внешнего соединения.
Если «нет» — найти, чем это закрывается (опция, env, подмена модуля), и описать.

### S2. Все HTTP-запросы провайдеров — через переданный `fetch` — **стоп-точка**
Провайдеры: `openrouter`, OpenAI-совместимый с произвольным `baseUrl` (как российские
провайдеры), `anthropic`. Для каждого — `baseUrl` на mock-провайдер (для `anthropic` —
mock формата Messages API), счётчик вызовов нашего `fetch` и счётчик запросов,
пришедших на mock. «Да» = счётчики равны для всех трёх (включая стрим и повторы при
ошибке 500/429). Отдельно — как задаётся `baseUrl` у каждого провайдера в 0.2.0.
Дымовой прогон на реальном OpenRouter (1 запрос «скажи привет») — только с согласия
владельца.

### S3. Хуки `beforeTool` / `afterTool` и fail-closed
* `beforeTool` вызывается для встроенных инструментов (`read_files`, `editor`,
  `apply_patch`, `search_codebase`) **и** для MCP-инструментов (`tavily_search`);
* `{skip: true, reason}` блокирует вызов, модель получает `reason` (видно в следующем
  запросе на mock);
* подмена `input` работает (mock видит изменённые аргументы в истории);
* `afterTool` подменяет `result` (модель видит подменённый результат);
* хук, который бросает исключение или превышает таймаут (3 с), — вызов **блокируется**
  (найти точное значение `hookErrorMode`); описать, что видит модель.
Плюс прототип проверки путей TR-3.4: `..\..\`, абсолютный путь, junction внутри
workspace (`New-Item -ItemType Junction`), UNC, `file:stream` — все отклоняются.

### S4. Отключение `run_commands` и `fetch_web_content`
Через `toolPolicies` (или иной механизм 0.2.0) эти инструменты **не попадают в список
`tools`** запроса к модели (проверить тело запроса на mock), а не просто требуют
подтверждения. Если убрать их из списка нельзя — блокировка в `beforeTool` плюс фиксация
этого факта в отчёте.

### S5. Суб-агенты наследуют ограничения (не стоп-точка)
`enableSpawnAgent: true`: mock скриптует вызов суб-агента. Проверить, что запросы
суб-агента к модели идут через наш `fetch`, его вызовы инструментов проходят через
`beforeTool`, он видит тот же `cwd` и те же MCP, а его события видны в `subscribe`. Если
что-то из этого «нет» — суб-агенты остаются выключенными (D17), это не блокирует план.

   боевым индексатором**. Поэтому на время S10: убедиться, что боевая индексация не

   подождать или временно остановить `hds watch` — по правилам `cline-rules/dev-machine.md`
   и вернуть после). После работы снять `HDS_CONFIG` (§6 «Грабли»).
4. **Эталон** — `s10/golden.jsonl`: 15–20 вопросов аналитика и РП (поиск факта, поиск по
   смыслу, сверка, противоречия, вопросы по метке), у каждого — эталонный ответ и
   список файлов-источников (и страница или раздел). Вопросы составить по
   **оригиналам**, а для поиска переписать их в анонимную форму (имена → метки из
   `inspect`), как это будет делать шлюз.
5. **Замер** — скрипт `tools/parity/agent_a0_rag_eval.py`: для каждого вопроса
   `hds search <запрос> --limit 30 --json` (с тем же временным `HDS_CONFIG`) →
   `recall@5`, `recall@10`, `recall@30`, MRR по эталонным файлам; отдельно по типам
   вопросов и по типам файлов; плюс **поиск по метке** (`[PERSON_3]`) — сколько ложных
   срабатываний даёт токенизация FTS5 (факт для TR-4.6).
«Да» = поиск по анонимным образам в целом работает (ориентир: `recall@10` ≥ 0,7 на
вопросах «поиск по смыслу»). Если существенно хуже — гипотезы, почему (метки ломают
эмбеддинги? режет токенизатор? текстовые образы pdf/pptx?).

## 6. Грабли окружения (из опыта проекта)

* PowerShell 5.1: аргументы с кириллицей и пустые аргументы передаются ненадёжно;
  `Select-String` по кириллице в файлах без BOM ищет плохо — читать файлы целиком.
* Вывод `hds.exe` в консоли — кракозябры (UTF-8 в OEM-консоли); для разбора
  использовать `--json` или `[Console]::OutputEncoding = [Text.Encoding]::UTF8`.
* Переменные окружения (`HDS_CONFIG`, `HDS_MODELS_DIR`, ключи) **живут между вызовами**
  в одной сессии терминала. Задавать их внутри одной команды
  (`$env:X='…'; …; Remove-Item Env:X`) или снимать после работы; иначе следующий
  `hds`/тест увидит чужой конфиг (так уже ломались тесты `hds-llama`).
* `git` — всегда `--no-pager`.
* `target\release\*.exe` могут быть заняты запущенными службами; в A0 сборка Rust не
  нужна — используются готовые бинарники.
* `hds anon` обходит только верхний уровень папки.
* Если для S8 нужен GPU, а `llm_host` держит модели — аренда `anon` сама вытеснит
  простаивающие роли; останавливать резидента не нужно. Если всё же остановили —
  вернуть (`llm_host run` или задача Планировщика, `installers/install_llm_host_task.ps1`).
