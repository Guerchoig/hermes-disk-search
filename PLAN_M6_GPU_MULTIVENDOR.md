## 2. Границы M6

> **Ревизия 2 (10.10.2026, решение владельца).** Прод-конфигурации — **вендор-гомогенные**:
> несколько **дискретных** GPU одного семейства (NVIDIA под Windows **или** AMD под
> Windows), либо **один Mac с Metal**. Смешанные вендоры (AMD+NVIDIA на одной машине) и
> iGPU/UMA — **не поддерживаются**. Поставка — **отдельными сборками** (NVIDIA / AMD /
> Metal). Железа для проверки нескольких карт нет → мультикарточность принимается
> юнит-проверками + явным хвостом. Имя файла (`..._MULTIVENDOR`) сохранено ради
> непрерывности ссылок; фактический предмет — «раскладка ролей по картам одного вендора».

**Входит:**
- раскладка ролей по картам одного семейства (`gpu.devices` + `llm_server.<role>.device`);
- **несколько чат-инстансов (реплик)** — под одновременные запросы разных пользователей:
  реплики на разных картах или несколько реплик на одной мощной карте (24 ГБ);
- **индексация (`embedding` + `rerank`) — единственный экземпляр на машину**; принцип
  «один набор моделей индексации обрабатывает одновременно один файл» сохраняется;
- **транскрибация (`whisper`) — экземпляр на каждую карту допускается** (каждый экземпляр —
  один файл за раз) как «лёгкая добавка» к чат-моделям карты;
- VRAM-бюджет и вытеснение **по каждой карте** (роли другой карты не вытесняются);
- вендор-специфичные пресеты раскладки, валидация, `hds check` с картами/ролями/числами;
- рантайм-приёмка (приоритет — **транскрибация**: владелец пользуется ею в работе);
- доклад (README/статус/журнал).

**Не входит:**
- смешанные вендоры и iGPU/UMA — вне области поддержки (в `hds check` — warn);
- балансировка одной модели по нескольким картам сверх `manual_devices_csv` (split) —
  проверяем, но не развиваем;
- AMD-smi как отдельная зависимость (остаёмся на DXGI/движке);
- внешний чат (сделан в M5); анонимизация (W9);
- живая проверка Apple Silicon и мультикарточности — **нет железа** (подготовка + хвост).


## 3. Технические решения (контракты)

### 3.1. Конфиг раскладки (по §8.1, обратная совместимость обязательна)
```yaml
gpu:
  device_index: 1            # КОМПАТ: «одна карта на все роли» (как сейчас)
  devices:                   # НОВОЕ: раскладка по картам (сильнее device_index)
    - { index: 1, roles: [chat] }               # NVIDIA (CUDA)
    - { index: 2, roles: [embedding, rerank] }  # AMD (Vulkan)
  # llm_server.<role>.device: 2   — альтернативная форма: карта у роли
```
- `index` — **наш** индекс (`device.rs`: 0 = CPU, 1 = первый ускоритель движка) —
  тот же смысл, что у `device_index`; резолв в `manual_devices_csv` — существующий.
- Приоритет: `devices[].roles` / `llm_server.<role>.device` **сильнее** `gpu.device_index`;
  роли, которых нет ни там, ни там, берут `device_index`.
- Валидация (fail-fast с числами, не молча): индекс вне диапазона найденных ускорителей;
  одна роль на двух картах; неизвестная роль в `roles`; пустой `devices` при заданном
  `device_index` (>0) — warn, поведение прежнее.
### 3.2. Резолв раскладки (реестр/хост)
- `plan_role` получает устройство роли из раскладки: `DeviceSelection::Csv(bridge_index)`
  вместо общего `selection_from_config_index(config.gpu.device_index, …)`.
- Планировщик печатает backend карты роли (`CUDA`/`Vulkan`/`CPU`) в `llm-host status`
  и в `PlannedInstance::summary` — это ключевое свидетельство приёмки.
- Недоступная/несуществующая карта у роли — **явная ошибка роли** (`RolePlan::Failed`
  с числами: «карта 2 не найдена, найдено 1 ускоритель: …»), не молчаливый фолбэк на CPU
  (`allow_cpu=false` сохраняем для GPU-ролей).

### 3.3. VRAM по картам (бюджет и вытеснение)
- Бюджет, fit-гейт и вытеснение считаются **для карты роли** (`bridge_device_index` роли),
  а не для «целевого» устройства: `bind_device_probes` уже даёт пробу на карту, в т.ч. через
  DXGI (AMD/Intel); нет пробы — «нет замера» (как сейчас), решение по числам движка.
- `reserve_mb` / `external_vram_mb` применяются к каждой карте (документируем явно).
- Вытеснение — в пределах карты: роли другой карты не вытесняются чужой нехваткой VRAM.
- На одной карте арифметика должна совпасть с текущей (проверяем замером до/после).

### 3.4. Пресеты и автодетект (W4, без магии; ревизия 2)
- Пресеты (вендор-гомогенные): `NVIDIA: одна карта` (всё на карту 1; масштаб — `n_parallel`
  и/или вторая чат-реплика `chat-2`); `NVIDIA: N карт` (чат-реплика на каждую карту,
  `embedding`/`rerank` — одним экземпляром на выделенной карте, `whisper` — на каждой);
  `AMD: N карт` — то же на Vulkan-бэкенде; `Apple Silicon` (все роли Metal) — macOS.
- **Контракт (T4, зафиксировано 10.10.2026):** `gpu.preset: none|nvidia-one|nvidia-n|amd-n|apple`
  и `gpu.autodetect: false` (по умолчанию). Приоритет источников раскладки:
  `llm_server.<role>.device` → `gpu.devices` → `gpu.preset` → `gpu.autodetect` → компат
  `gpu.device_index`. Пресет раскладывает **существующие** роли конфига (реплики
  `chat-N`/`whisper-N` объявляются явно, как в §3.5); `nvidia-one`/`apple` — всё на первую
  карту, `nvidia-n`/`amd-n` — чат-реплики и `whisper` round-robin по картам, индексация — на
  выделенной (последней) карте. Fail-fast с числами: пресет без карт или на «чужих» вендором
  картах (напр. `nvidia-n` при одних AMD). Образец — `config.example.yaml` (блок `gpu:`).
- Автодетект (по умолчанию **выключен**): при `true` и пустых `gpu.devices`/`gpu.preset`
  подбирает пресет по вендорам/числу карт (только вендор-гомогенный набор; смешанные
  вендоры/UMA — не поддерживаются, §2); любая раскладка и пресет печатаются с числами
  (`llm-host` лог, `llm_host_plan`, пункт `gpu_roles` в `hds check`), секретов не печатаем.

### 3.5. Роли, реплики и «лёгкие добавки» (ревизия 2, 10.10.2026)
- **Чат-реплики — одинаковые.** Реплики одной карты/машины используют одну модель и
  контекст (различаются портом и слотами) — это масштаб под N одновременных пользователей,
  а не разные модели. Каждая реплика — свой порт; реплики живут на одной карте (делят её
  VRAM) или на разных. «Две чат-модели на одной карте 24 ГБ» = две такие реплики.
- **Индексация — ровно один экземпляр на машину.** `embedding` и `rerank` назначаются не
  более чем на одну карту и существуют в одном экземпляре; вторая попытка назначения —
  **ошибка конфига** (fail-fast с числами). Роли идут с `n_parallel = 1`: «один набор
  моделей индексации обрабатывает один файл одновременно».
- **Транскрибация — по экземпляру на карту** (допустимо). Каждый экземпляр обрабатывает
  один файл за раз; выбор экземпляра под файл — по свободности карты (числа печатаются
  в логе/статусе), без «умных» эвристик.
- **Лёгкие добавки к чат-моделям.** По умолчанию индексация/транскрибация ставятся на
  карты рядом с чат-моделями (по свободной VRAM), а не на отдельную карту; вытеснение —
  в пределах карты роли и только по политике приоритетов (`gpu.policy`); чат-реплики не
  вытесняются чужой нехваткой VRAM.
- Валидация (§3.1) дополняется правилами: одна роль — на одной карте; чат-реплики —
  уникальные имена/порты; `embedding`/`rerank` — ровно один экземпляр; `whisper` — не
  более одного экземпляра на карту.

### 3.6. Маршрутизация реплик, транскрибация, приоритеты (решения 10.10.2026)
- **Один вход + внутренняя маршрутизация** (рекомендация исполнителя, согласована владельцем):
  наружу остаётся **один фасад** `llm-host` (`chat` → порт 8010, как сейчас), а запросы
  раскидываются по свободным репликам внутри хоста (**least-busy**, при равенстве —
  round-robin), с учётом очереди/слотов. Почему так, а не «список портов наружу»:
  (а) клиенты (MCP/UI/агенты) уже ходят на один порт — конфиг и интеграции не разрастаются;
  (б) авторизация, аудит, rate-limit и очередь остаются в одной точке (M2/M3/M4);
  (в) только хост видит фактическую занятость (слоты, очередь, VRAM) — снаружи балансировать
  нечем. Порты реплик (`8010+N`) — внутренние/диагностические; в `hds check`/`status` они
  печатаются как справочные (карта, слоты, загрузка), но публикуются одним фасадом.
- **Транскрибация: один файл — одна карта.** Split одного файла по нескольким картам
  **отвергнут**: whisper-инстанс движка исполняется на одном устройстве, а «разрезание»
  одного файла потребовало бы собственной синхронизации (энкодер/декодер, кросс-картовые
  буферы) — сложность не оправдана (файлы приходят редко; на проде ожидается ≤2 карт).
  Карту под файл выбирает **`auto_transcribe`** по свободной VRAM/незанятости карты (числа —
  в логе), отдельный слой балансировки не вводим. Разные файлы **могут** обрабатываться
  параллельно на разных картах (по одному инстансу на карту) — единственный практический
  выигрыш от нескольких карт при очереди файлов.
- **Индексация — «лёгкая добавка»** рядом с чат-репликой (не выделенная карта). Если
  свободной VRAM на её карте нет — индексация **ждёт/паузится** (штатный `index.pause`),
  **чат-реплики не вытесняются** (приоритет чата в `gpu.policy` сохраняем).

## 7. Риски
| Риск | Митигация |
|---|---|
| Движок не грузит Vulkan в нашей сборке (`-Backend cuda`) | T0 первым шагом: проверка перечисления устройств + сборка Vulkan в копии рантайма; при неудаче — фолбэк «одна карта» и явный warn |
| Смешанные вендоры (AMD+NVIDIA на одной машине), iGPU/UMA | **Вне области поддержки** (решение владельца 10.10.2026): warn в `hds check`; раскладка не применяется |
| Несколько карт одного семейства нельзя проверить (нет железа) | Юнит-тесты на расчёт по картам + явный хвост «проверка на машине с N картами»; числа одной карты = регрессия M4/M5 |
| Дискретной AMD-карты на станции нет (только iGPU) | AMD-путь проверяется частично (сборка Vulkan-бэкенда + роль на Vulkan-устройстве); ограничение честно фиксируется в докладе |
| Реплики чата делят VRAM одной карты | Бюджет/вытеснение — по карте; чат-реплики не вытесняются чужой нехваткой (политика `gpu.policy` + проверка числами) |

| Раскладка по картам ломает бюджет/вытеснение | Сравнение чисел на одной карте до/после (регрессия M4/M5), юнит-тесты на расчёт по карте |
| AMD-карта = iGPU (общая память) с иной моделью VRAM | Всё решаем по пробам (NVML/DXGI) и числам движка; «нет замера» — честное сообщение, не догадка |
| Apple Silicon нельзя проверить на этой станции | Этап принимается без живой проверки Metal; хвост явно переносится (машина с Mac) |
| Пресеты/автодетект дают «умный» выбор, который ломает SLA | Автодетект выключен по умолчанию, любая раскладка печатается с числами и подтверждается вручную |
