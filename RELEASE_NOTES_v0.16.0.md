# RELEASE_NOTES v0.16.0 — VRAM-диспетчер работает на любых GPU (NVIDIA/AMD/Intel/Metal)

> Релиз фич: привязка измерений VRAM к устройствам, вендор-нейтральный
> измеритель, исправления интеграции с Cline. Rust-проверки зелёные:
> `cargo fmt --check`, `clippy -D warnings`, `cargo test --workspace`.

## Новое: VRAM-диспетчер на любых GPU

* **Измерение VRAM привязано к устройству движка.** Раньше замер шёл по
  «карте NVML», а роль выбиралась на первый ускоритель движка — на машинах
  с двумя GPU (iGPU + дискретная) измерялся один GPU, а модель грузилась на
  другой, и диспетчер принимал решения по чужим цифрам (живой инцидент:
  RTX «свободно 3569 МиБ» против цели на AMD с 31 ГиБ свободных → ложный
  «не хватает VRAM»). Теперь пробы сопоставляются с устройствами движка по
  имени (`desc` от движка совпадает с именами NVML/DXGI), сопоставление
  строгое (нормализация + удаление `(TM)/(R)`; `RTX 3060` ≠ `RTX 3060 Ti`),
  решения идут по **целевому** устройству: `free = min(проба, числа движка)`.
* **Вендор-нейтральный измеритель DXGI** (`IDXGIAdapter3::QueryVideoMemoryInfo`,
  dxgi.dll — документированный Microsoft механизм «OS-provided video memory
  budget»): работает на AMD/Intel/NVIDIA, включая интегрированную графику.
  На машинах без NVIDIA бюджет берётся из DXGI; выбор адаптера — по
  наибольшему dedicated-сегменту. Проверено на железе: сверка NVML↔DXGI на
  одной машине (RTX 3060 + AMD Radeon(TM) Graphics), включая UMA-поведение
  (бюджет iGPU ~48 ГиБ — «разрешено ОС», heap движка 16 ГиБ — реальная
  граница; решение берёт минимум).
* **Вердикт «замера нет» больше не отклоняет запрос.** Дизайн диспетчера —
  «нет замера ⇒ решает движок» (`Verdict::Unknown` + EnsureLoaded), но хост
  трактовал Unknown как отказ с вводящим в заблуждение «свободно ?». Теперь
  запрос проходит, а честное «нет замера» видно в логе/статусе.
* **CPU для транскрибации стал достижим**: `auto_transcribe.whisper_gpu: -2`
  (и меньше) — принудительный CPU; `-1` сохраняет смысл «как gpu.device_index».
  Раньше все отрицательные значения молча заменялись GPU из конфига.
* Устройства в `llm-host devices` показывают описание GPU (`desc=AMD Radeon(TM)
  Graphics`) и обновлённую оговорку (решения — по NVML/DXGI-пробам устройства,
  иначе по числам движка); `llm-host status` печатает строку «измерение
  целевого устройства …» — видно, ЧЬЯ память мерится для прогноза.

## Исправления (с v0.15.0)

* **CI-сборка `llm_host.exe` не стартовала на других машинах** («конфиг
  D:\a\...: os error 2»): корень проекта резолвился build-time — теперь
  runtime-резолв по расположению exe (`HDS_ROOT` → `bin\x.exe` → fallback).
* **Фасад `:8010` отвечает на CORS-preflight (OPTIONS)** — раньше 404;
  вебвью Cline (Electron) требует префлайт для запроса каталога моделей
  с заголовком `Authorization`.
* **«Синхронизировать настройки Cline» больше не требует ручного ввода
  модели**: cline-sync сам создаёт записи `chat`/`chat-think` в `models.json`
  (окна контекста слотов, capabilities) и заменяет фантомный
  `defaultModelId: "gpt-4o"` (статическая заглушка каталога Cline) на `chat`.
* **Установщик предупреждает о Cline Desktop < 0.0.43** (старые сборки не
  создают каталог моделей вовсе; порог — по живым проверкам 05.10.2026).
* `publish_clip_models.ps1` переживает stderr-вывод `gh` в PowerShell 5.1
  (EAP Stop) — публикация тега `clip-onnx-v1` проходит целиком (сам тег
  теперь опубликован; кнопка «Скачать CLIP-модели» при установке работает).

## Требования к обновлению

* Штатное обновление поверх 0.15.x: распаковать архив, `setup.cmd`/`setup.ps1`
  (или `installers\update.ps1`); переиндексация не требуется.
* Машины **без NVIDIA** (AMD/Intel): убедитесь, что установлен Vulkan-рантайм
  движка (установщик ставит сам; офлайн — качайте
  `hds-engine-runtime-windows-x64-vulkan.zip`). После обновления перезапустите
  llm-host: в `data\logs\llm-host.log` появится строка
  `пробы VRAM по устройствам: …`.
* Cline Desktop старше 0.0.43 — обновите (см. выше); после синхронизации
  настроек Cline перезапустите Cline.

## Ограничения и следующие шаги (документированы в коде)

* macOS Metal-проба VRAM (`recommendedMaxWorkingSetSize − currentAllocatedSize`)
  не реализована (нет машины Apple Silicon для проверки, W2-7): на Mac решения
  идут по числам движка/«нет замера» — транскрибация и поиск работают.
* На UMA/iGPU бюджет DXGI может превышать heap бэкенда движка — решение уже
  берёт `min(проба, движок)`, что исключает «разрешили, а движок не смог».
