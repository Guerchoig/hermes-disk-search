# hermes-disk-search v0.8.0

## Новое

- **Реранкер для ask_my_files** (по умолчанию выключен): cross-encoder
  `bge-reranker-v2-m3` (GGUF Q8_0, ~600 МБ) в отдельном процессе llama-server
  (`/v1/rerank`; LM Studio `/rerank` не реализует). `hds/rag.py` ищет пул
  топ-20, реранкер переставляет и отбирает топ-8 перед генерацией ответа.
  Конфиг: `rerank.enabled/url/model/timeout/max_latency`; включается галочкой
  в веб-интерфейсе. Деградация без падения: если реранкер недоступен или
  латентность выше лимита (`rerank.max_latency`, слабый CPU) — ответ формируется
  из результатов без реранкинга, состояние видно в `check`.
- Гибридный поиск: веса веток `search.fts_weight` / `search.vec_weight`, запрос
  «сначала AND, при пустом результате OR», префиксный матчинг последнего
  токена (`токен*`), сниппет не режет предложение посередине.

## Требуется после обновления

- Реранкер опционален: скачайте `bge-reranker-v2-m3-Q8_0.gguf`, запустите
  llama-server с `--reranking --pooling rank --port 8012` (см. README,
  раздел «rerank») и включите галочку «Реранкер» в веб-интерфейсе.
- По-прежнему рекомендуются `reindex-fts` (v0.6.0) и `index --rechunk` (v0.7.0)
  для применения морфологии и структурного чанкера к старым данным.

## Совместимость

- Схема БД не меняется; `config.yaml` совместим (секция `rerank` опциональна,
  по умолчанию всё выключено).
